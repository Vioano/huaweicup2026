## 8–18 分钟这一段，建议按四层讲

### 第一层：我们到底在研究什么

先画最重要的一条链：

**case JSON → 我们的方案 → 官方映射 → result**

官方映射内部：

**Task/COPY 构造 → Step1 → Step2 → Step3 → 全局事件模拟 → Makespan/流量/Cache 等结果**

然后解释四个词：

**官方映射**：不是 `plan → Makespan`，而是 plan 到整个官方执行行为的完整确定性映射。

**映射族**：Q1/Q2/Q3、1–5 核、容量/带宽/Cache 等参数变化后形成的一族相关映射。

**Guard**：一个局部变化导致执行机制发生离散切换的条件，例如刚好开始 spill、Cache hit→miss、COPY 出现等。

**Regime**：一组 guard/active decisions 保持相同的行为区域。我们怀疑同一个 regime 内可能比较简单，跨 regime 时才会突然复杂。

这里顺手把**多核尺度轴**讲清：

> 2、3、4、5 核不是四个完全独立问题，而可以看成同一个系统沿核数轴变化。

---

### 第二层：怎么“解剖”官方映射

先引入 **primitive operation**：

> split、merge、move、reorder 等最小方案编辑。

然后讲：

**Edit size**：到底改了几个 Task、几个 assignment、几个 order relation，不能只说“小改动”。

**局部响应 / 离散雅可比**：做一个 primitive 后，不只看 Makespan 差，而看整个行为链哪些东西变了。

例如：

> split 一个 Task  
> → COPY 变没变？  
> → Step1 变没变？  
> → spill 变没变？  
> → Pipe FIFO 变没变？  
> → release time 变没变？  
> → DDR contention 变没变？  
> → Makespan 最后变多少？

**耦合度**：一次局部编辑会影响多少层、传播多远。

**敏感方向**：编辑本身很小，但稳定地产生很大行为变化的操作方向。

核心一句话：

> 我们想知道，这个巨大的方案空间里，是不是实际上只有少数方向真正“有杠杆”。

---

### 第三层：能不能压缩这个搜索空间

解释：

**行为等价**：两个 JSON 不同不重要；如果在我们关心的观察和未来操作下无法区分，它们才真正可以算同一个状态。

**行为商**：把大量行为等价的方案合并成一个类。

**最小充分状态**：为了预测未来操作效果，究竟最少需要保存哪些信息。

这里强调：

> 我们目前只是提出这些问题，没有证明一定能压缩。

如果最后发现所有方案行为都不同，quotient 几乎没有压缩，那这条路线就砍掉。

然后讲：

**局部评估器集**：不再幻想一个万能 surrogate，而是一群只负责特定 regime 的小 evaluator；不确定就拒答，回到 E1/E0。

---

### 第四层：怎么反过来构造算法

这里讲算法侧。

**生成完备 / 可达完备**：

> 底层 primitive 理论上最好具有足够表达力，使方案空间能够被组合到达。

但强调：

> “能到达全部” ≠ “实际要搜全部”。

**Macro operation**：

> 从稳定敏感方向、峰值机制中蒸馏出的高层复合操作。

然后重点讲今天的新概念：

**Peak Witness / 峰值见证**：

> 例如 case008 + 4 核 + resource-word + 63768 cycles，是一个极端优秀实例。

**Peak Mechanism / 峰值机制**：

> 不是这个数字本身，而是解释为什么“某类图结构 + 某种操作 + 某种 q/k/regime”会稳定产生巨大收益的条件性规律。

所以研究路径是：

**峰值见证 → 邻近劣解 → 行为差分 → 图结构特征 → guard → 一般机制 → macro**

特别强调：

> **图 JSON 本身是一等变量。**

不是只研究参数，而要研究为什么偏偏这张图能激活这种策略。

最后讲两个词：

**Core-count continuation**：从好 \(k\) 核方案延拓到 \(k+1\) 核，而不是每个核数从零搜索。

**Algorithm distillation**：研究阶段可以慢、透明；最后把验证过的结构压缩成真正比赛 solver。

## 18–23 分钟最好只讲两个真实案例

第一个讲 **case008 高峰值**：

> 4 核 Q2/Q3 已出现 7× 以上 speedup 的 witness。

不要把重点放在“7.6 很牛”，而放在：

> 为什么这张图的资源结构能让 resource-word 产生这么大的收益？  
> 这种结构在别的图有没有？  
> 3 核和 5 核还在吗？  
> 到 Q1 为什么可能失效？

第二个讲一个**负例**：

比如 Q1 中：

> 降 spill 不一定更快；  
> 减少 COPY 不一定更快；  
> merge 可能改善，也可能严重退化。

用这个告诉全队：

> **我们现在不允许用单一 proxy 代替官方 Makespan。**

这两个例子足够把整个 coherent 框架讲活。

## 23–27 分钟：明确接下来三层工作

画三个横向泳道：

**离线结构研究**
→ 测响应、guard、峰值、图特征、行为商。

**在线求解器**
→ primitive、macro、continuation、搜索策略。

**Evaluator / infrastructure**
→ E1/native replay、并发调度、缓存、精确验证。

然后说明：

> 三层不是三支互不相关的队伍。

应该是：

**离线研究发现机制 → solver 把机制变成 macro → evaluator 提供便宜可靠的真值 → 新实验又反哺结构研究。**

我建议你现场定四条规矩：
