$$P_i=P(\text{国一}\mid \text{选择题 }i),

$$P(\text{把题做完}\mid \text{选择题 }i).

## 1. 你真正想最大化的是“相对能力差”

假设第 $i$ 道题上，你们团队最终能够达到的水平是 $S_i^{\text{you}}$，普通强队平均水平是 $S_i^{\text{others}}$。

真正值得最大化的不是

$$S_i^{\text{you}},
\tag{3}$$

而是

$$\Delta_i
=
S_i^{\text{you}}
-
S_i^{\text{others}}.
\tag{4}$$

比如有两道题：

- C 题很简单，你们能做到 95 分；

- 别人也能做到 90 分。

那么

$$\Delta_C=5.
\tag{5}$$

另一道 A 题看起来非常变态：

- 你们最后可能只能做到 82 分；

- 大多数队只能做到 50 分。

那么

$$\Delta_A=32.
\tag{6}$$

显然第二种情况更适合冲顶奖。

所以你其实不是在赌“我能不能把最难题做到完美”，而是在赌：

> **复杂度增加时，我的能力下降速度，比其他队伍慢。**

这才是你的策略的数学本质。

# 2. AI 确实改变了复杂题的收益曲线

过去遇到一个陌生算法，例如：

- mixed integer programming；

- 图优化；

- Kalman filter；

- PDE 数值求解；

- 贝叶斯优化；

- 信号处理；

- CP-SAT；

- 某种专用启发式算法；

队伍可能卡半天：

> “这个怎么写？”

现在这类问题基本可以立即解决。

甚至完全可以同时启动五条路线：

> Agent A：MILP
> Agent B：遗传算法
> Agent C：模拟退火
> Agent D：problem-specific heuristic
> Agent E：查论文 + 找 benchmark

然后另一个 Agent 统一跑实验。

因此以前复杂题的问题空间可能是：

$$\text{复杂问题}
\rightarrow
\text{大量人工学习成本}
\rightarrow
\text{无法完成}.
\tag{7}$$

现在变成：

$$\text{复杂问题}
\rightarrow
\text{任务分解}
\rightarrow
\text{多个 Agent 并行探索}
\rightarrow
\text{实验筛选}
\rightarrow
\text{集成}.
\tag{8}$$

于是 bottleneck 就从“个人掌握多少算法”，移动到了**系统组织能力**。

这一点和你最近一直在想的 Graph Engineering / Agent orchestration，其实非常接近。

# 3. 但“看起来最难”还需要加一个筛选条件

有几种难度非常适合 AI。

### 第一类：搜索空间大

例如：

- 路径规划；

- 调度；

- 资源分配；

- 图优化；

- 组合优化。

这是最理想的。

因为可以让 AI 写很多 solver，再靠实验筛选。

---

### 第二类：实现复杂

例如：

- 数据处理链条非常长；

- 有多个模型；

- 需要很多 preprocessing；

- 大量仿真。

过去程序工程量本身就是门槛。

现在反而是优势。

因为普通队看到：

> “卧槽，要写这么多代码。”

会直接换题。

而你看到的可能是：

> “很好，可以拆成十五个独立任务。”

这就出现了非常大的相对优势。

---

### 第三类：跨领域

例如：

> 物理 + optimization + ML

或者：

> 信号处理 + 时序预测 + 控制

这种也特别好。

因为传统团队经常只会其中一个方向。

而 LLM 可以迅速补齐知识。

# 4. 有一种“难题”反而不要碰

这是你策略里最值得防的坑。

有些题难，不是因为计算复杂，而是因为：

> **信息不足。**

例如：

- 专业背景要求特别深；

- 很多关键参数题目不给；

- 数据质量极差；

- 很多判断依赖行业经验；

- objective 本身都说不清楚。

这种题的难度无法靠算力解决。

可以粗略区分成：

$$D
=
D_{\text{search}}
+
D_{\text{engineering}}
+
D_{\text{knowledge}}
+
D_{\text{ambiguity}}.
\tag{9}$$

AI 最容易压缩的是：

$$D_{\text{search}},
\quad
D_{\text{engineering}},
\quad
D_{\text{knowledge}}^{\text{shallow}}.
\tag{10}$$

但它很难消灭：

$$D_{\text{ambiguity}}.
\tag{11}$$

如果题本身就没有明确答案，数据又不足，那么几十个 Agent 一起 hallucinate 并不会更强。

# 6. 你甚至可以把选题本身做成模型

比赛开题以后，可以快速给每题评估五个量：

$$X_i=
(
H_i,
A_i,
V_i,
P_i,
C_i
),
\tag{12}$$

其中：

- $H_i$：对普通队的 hardness；

- $A_i$：AI amplification，AI 能把多少难度吃掉；

- $V_i$：verifiability，结果有多容易验证；

- $P_i$：parallelizability，可以多大程度并行；

- $C_i$：coordination cost，你们自己的协调成本。

于是可以定义一个很粗糙但很实用的“狩猎指数”：

$$R_i
=
H_i
\cdot
A_i
\cdot
V_i
\cdot
P_i
-
\lambda C_i.
\tag{13}$$

不要太在意这个公式的具体形式，它表达的是一个思想：

**最好的题不是最难，而是“难度可以被你们的工具链高度杠杆化”的题。**

# 7. 这甚至会导致一个有趣的反常识

AI 普及以后，**中等难度题可能反而越来越卷。**

因为所有队都能：

> Claude/GPT → 建模 → Python → 图表 → LaTeX。

所以以前需要一定技术门槛才能做到的“还不错论文”，现在大量队伍都能产出。

结果就是中部拥挤。

反而最硬核的题，如果它需要：

- 很复杂的工程组织；

- 多模型实验；

- 大量 ablation；

- 自己构造 benchmark；

- 多算法比较；

- 反复迭代；

单纯“让 ChatGPT 帮我做数学建模”的队伍仍然做不好。

所以 AI 的出现，未必会把比赛变得更平均，甚至可能形成：

> **模型能力趋同，Harness 能力分化。**

而你说的“团队内部工程调度能力”，我认为很可能就是接下来数学建模比赛里一个越来越重要、但很多队还没意识到的隐藏变量。

> 特征工程 → XGBoost / NN / ensemble → CV → 调参

### 国一论文首先不是“模型堆得高级”，而是几乎没有明显短板

很多数学建模论文的典型状态是：

“第一问套模型，第二问机器学习，第三问再来一个优化算法，然后画很多漂亮图。”

这种现在有 AI 之后太容易做了。

> **问题定义 → 数学抽象 → 方法选择理由 → 算法实现 → 实验 → baseline → 误差/鲁棒性 → 结论。**

评委看完之后应该没有一个明显的问题：

> “你为什么这么建模？”

> “为什么不用更简单的方法？”

> “你的方法真的比 baseline 好吗？”

> “结果是不是偶然？”

> “换一组数据还能不能工作？”

> “这个参数为什么取这个值？”

如果其中两三个问题回答不了，我不会认为它是稳国一的稿子。

## 而“答辩水平”最重要的变化是：必须有一个非常清楚的核心贡献

我甚至希望能用一句话说清楚：

> **我们发现了 X，因此设计了 Y，相比标准方法在 Z 指标上产生了稳定的改善。**

而不是：

> 我们使用 A、B、C、D、E 五种算法解决了问题。

后者是典型建模比赛论文，前者才开始像 research paper。

可以把顶级论文的竞争力粗略写成

$$Q
=
Q_{\mathrm{correct}}
\cdot
Q_{\mathrm{novel}}
\cdot
Q_{\mathrm{evidence}}
\cdot
Q_{\mathrm{communication}},
\tag{14}$$

这里我故意用乘法而不是加法。

因为如果算法很创新但结果不可信，没用；结果非常好但方法讲不清楚，也很危险；模型和实验都很好但犯了数据泄漏之类的基本错误，可能直接掉档。

### 如果目标是数模之星，我会进一步做一件非常关键的事：建立“接近最优”的证据

这往往就是“优秀国一”和“本题前两名”的区别之一。

比如，对于小型子图，可以构造：

- MILP / CP-SAT 精确解；

- branch-and-bound；

- exhaustive search；

- relaxation lower bound。

然后比较你的 heuristic。

假设精确解 objective 为 $J^\star$，你的算法结果为 $J$，就可以报告 optimality gap：

$$g
=
\frac{J-J^\star}{J^\star}\times100\%.
\tag{15}$$

这样一句：

> “在所有可精确求解的小规模实例上，我们的算法平均距最优解 1.7%。”

其说服力远远超过：

> “实验表明我们的算法效果较好。”

到了大规模问题，即使拿不到真最优，也可以和理论下界或 relaxation bound 比。

这就是研究论文的味道。

## 第二个分水岭是 ablation，而不是再塞一个“高级算法”

假如你的方法由三个东西构成：

> memory-aware priority + critical-path priority + local search

不要只展示最终结果。

你应该跑：

Baseline
→ + memory aware
→ + critical path
→ + local search

这样评委马上知道：

> 到底是谁在起作用。

如果最后 improvement 是 18%，而三个模块分别贡献 9%、5%、4%，这就形成了非常扎实的论证。

这比突然写一句：

> “因此我们创新性地提出 XX 改进遗传模拟退火算法。”

强太多。

- 可做原创算法的空间

- 与普通队的能力差

### Defense Score

- 问题是否 30 秒能讲明白

- improvement 是否一张图能看出来

- 非本领域评委能否理解

然后真正最大化：

$$S(T)
=
S_{\mathrm{paper}}(T)
\times
S_{\mathrm{defense}}(T).
\tag{18}$$

这比单纯问“哪题最容易国一”要先进得多。

前两年 C 题拿冠军，最多只能告诉我们历史样本里的

$$P(T=C\mid \text{冠军})
\tag{31}$$

比较高。

但你真正关心的是：

$$P(\text{冠军}\mid T=C,\ \text{我们的团队能力})
\tag{32}$$

这两个概率完全不是一回事。

根据贝叶斯公式，

$$P(T=C\mid \text{冠军})
=
\frac{
P(\text{冠军}\mid T=C)\,P(T=C)
}{
P(\text{冠军})
}.
\tag{33}$$

如果 C 本来就是最热门的题，$P(T=C)$ 很大，那么即使单支队伍选择 C 后夺冠的概率并不高，最后观察历届冠军时，C 仍然可能频繁出现。

这正是**base-rate neglect**：只看冠军来自哪里，却没看有多少人进入了那个赛道。

---

你说的“两阶段概率”才是正确建模方式。

设 $Q$ 表示“进入数模之星答辩”，那么对题目 $T_i$，真正的夺冠概率应该拆成

$$P(\text{冠军}\mid T_i)
=
P(Q\mid T_i)
\,
P(\text{冠军}\mid Q,T_i).
\tag{34}$$

如果进一步考虑你们自己的能力结构 $X$，真正要最大化的是

$$P(\text{冠军}\mid T_i,X)
=
P(Q\mid T_i,X)
\,
P(\text{冠军}\mid Q,T_i,X).
\tag{35}$$

而你的核心判断是：

> **第一项可能跨题差一个数量级；第二项通常只差一个有限倍数。**

这非常关键。

比如纯粹举一个假想例子。

### 热门简单题 C

假设：

$$P(Q\mid C,X)=0.4\%.
\tag{36}$$

因为强队很多，大家都能完成得很好。

但 C 非常适合展示，所以一旦入围，你的答辩夺冠概率比较高：

$$P(\text{冠军}\mid Q,C,X)=15\%.
\tag{37}$$

那么总概率：

$$P(\text{冠军}\mid C,X)
=
0.004\times0.15
=
0.0006.
\tag{38}$$

即 $0.06\%$。

---

### 高门槛题 A

假设由于你们的 AI + 工程组织优势：

$$P(Q\mid A,X)=3\%.
\tag{39}$$

已经比 C 高了 7.5 倍。

但答辩不好讲一些：

$$P(\text{冠军}\mid Q,A,X)=8\%.
\tag{40}$$

那么

$$P(\text{冠军}\mid A,X)
=
0.03\times0.08
=
0.0024.
\tag{41}$$

即 $0.24\%$。

虽然入围后夺冠能力只有 C 的一半左右，**最终夺冠概率仍然是 C 的 4 倍。**

这就是你说的那个 trade-off。

## 而且第一阶段其实比“2 / 参赛人数”还复杂

如果每题两队进入答辩，一个最粗糙的随机模型当然是

$$P(Q\mid T_i)\approx\frac{2}{N_i},
\tag{42}$$

但真实情况不能这么算，因为你的队伍不是随机抽取的。

真正影响你的是**头部竞争者数量**。

比如：

- C 有 8000 队；

- A 有 1800 队。

看起来 A 只是少了四倍。

但可能 C 有 100 支真正高水平队伍，而 A 因为专业门槛、代码规模和复杂度，只剩 15 支真正有竞争力的队伍。

那么对于你来说，真正 relevant 的 field size 更接近：

$$N_i^{\mathrm{eff}}
=
\text{能够与你竞争前两名的队伍数量}.
\tag{43}$$

甚至还应该考虑这些队伍的实力，而不是简单数人数。

可以定义一个粗略的“竞争压力”：

$$\Lambda_i
=
\sum_{j\in T_i}
P(S_j>S_{\text{you}}\mid T_i),
\tag{44}$$

意思是把每个竞争对手“超过你们”的概率加起来。

真正理想的赛题是：

$$\Lambda_i\ll 1
\tag{45}$$

或者至少比其他题小很多。

这比单纯看参赛人数高级得多。

$$S_{\text{you}}(D)
\downarrow.
\tag{47}$$

$$\Delta S(D)
=
S_{\text{you}}(D)
-
S_{\text{normal}}(D)
\tag{48}$$

不是：

> 难题人少，所以选难题。

> **题目难度增加以后，我们的相对优势变大。**

这句话比“选最难的”准确得多。

## 一、成功参赛 / 国三 → 国二：最大的变化是从“做完”变成“可信”

这是第一道真正重要的分水岭。

一篇国三水平的论文完全可以：

- 三问都做了；

- 模型也没明显错误；

- 有代码、有图；

- 结果看起来合理；

- 使用了若干常见算法。

比如一道预测题：

> 数据清洗 → 特征工程 → Random Forest / XGBoost → 给预测结果。

已经是一篇完整论文。

问题在于，评委可能不知道：

> 为什么这个模型合理？
> 结果是不是真的稳定？
> 换个模型怎么样？
> 参数为什么这样选？
> 有没有过拟合？

所以我会把国三称为：

> **completion threshold。**

核心要求是：**没有致命错误，并且把赛题完整解决。**

而国二开始进入：

> **credibility threshold。**

模型不仅要给答案，还得证明答案值得相信。

比如预测问题，至少开始出现：

$$\mathrm{RMSE}
=
\sqrt{
\frac{1}{n}
\sum_{i=1}^{n}
(\hat y_i-y_i)^2
},
\tag{74}$$

并且不是只报一个 RMSE，而是和合理 baseline 比较、做训练验证划分、讨论误差。

优化问题也是类似。

不能只说：

> “我们的算法得到目标函数 1234。”

而需要：

> greedy = 1520
> baseline heuristic = 1411
> our method = 1234

于是评委才知道 1234 到底好不好。

所以：

> **国三 → 国二最大的分水岭不是算法高级程度，而是有没有完整的证据链。**

> → greedy memory allocation

不错。

例如你发现：

于是定义一个新的 priority：

$$p(v)
=
\alpha L(v)
+
\beta M(v)
+
\gamma C(v),
\tag{76}$$

其中：

- $L(v)$ 表示 critical-path contribution；

- $M(v)$ 表示 memory-pressure contribution；

- $C(v)$ 表示释放后继节点的潜力。

> proposed：69。

$$p_{LM}(v)
=
\alpha L(v)+\beta M(v),
\tag{77}$$

评委就知道：

> **你提出的结构真的产生作用了。**

这就开始有国一的味道。

# 四、国一 → 数模之星：分水岭已经不是“有没有创新”，而是“有没有硬优势”

到了这个层次，竞争对手基本都：

- 模型合理；

- 图不错；

- 验证充分；

- 有创新点；

- 论文写得不错。

所以这些东西已经从 advantage 变成了 requirement。

数模之星候选真正需要的是：

> **你的核心 claim 可以被非常强的证据支持，并且这个 claim 比其他一等奖论文更强。**

我特别喜欢用一个词：

> **dominance。**

例如同样解决一个优化题。

普通国一：

> 我们的方法比 baseline 平均改善 12%。

数模之星候选可能进一步做到：

> 大规模实例比第二强 baseline 好 9%；

> 不同超参数下结论仍稳定。

对于可精确求解的小实例，可以直接定义 optimality gap：

$$g
=
\frac{
J_{\mathrm{ours}}-J^\star
}{
J^\star
}
\times100\%,
\tag{80}$$

其中 $J^\star$ 是精确最优解。

如果你能够说：

> “所有可精确求解实例中，我们平均距全局最优仅 1.6%。”

这句话对于评委而言信息量极高。

> 对问题一我们使用 A。
> 对问题二我们使用 B。

够用。

国二应该开始出现结果：

> 方法 A 将误差降低 XX%。

$$\text{Problem}
\rightarrow
\text{Insight}
\rightarrow
\text{Method}
\rightarrow
\text{Evidence}
\rightarrow
\text{Conclusion}.
\tag{81}$$

这五段逻辑最好非常清楚。

# 国二水平：开始证明“我的方法确实有效”

还是同一套核心算法，但队伍把验证做扎实了。

首先建立一个完全统一的 simulator。

给任意 schedule $S$，都能算：

$$J_{\mathrm{mem}}(S)
=
\max_t M_{\mathrm{live}}(t),
\tag{84}$$

即问题 1 的最大驻留缓存。

问题 2 定义：

$$J_{\mathrm{spill}}
=
\sum_{b\in\mathcal S} c_b,
\tag{85}$$

其中 $c_b$ 是对 buffer $b$ 进行 SPILL 产生的数据搬运量。

问题 3再计算：

$$J_{\mathrm{time}}
=
\max_{v\in V}t_{\mathrm{finish}}(v).
\tag{86}$$

然后开始做真正的 baseline：

- FIFO topological scheduling；

- DFS；

- BFS；

- critical-path priority；

- memory-release priority；

- 自己的方法。

| 算例 | FIFO | DFS | Critical path | 本文 |

# 国一水平：出现真正的 problem-specific insight

假设第三支队伍没有一上来就想：

> “我该用遗传算法还是模拟退火？”

而是认真研究这个题。

他们发现一个现象：

> **真正导致缓存峰值爆炸的，并不只是当前驻留量，而是某些调度选择会让大量 buffer 的生命周期同时延长。**

于是他们定义节点执行后，对未来 live-set 的影响。

例如定义：

$$\Delta L(v)
=
\sum_{b\in R(v)}\operatorname{size}(b)
-
\sum_{b\in A(v)}\operatorname{size}(b),
\tag{87}$$

其中：

- $R(v)$：执行 $v$ 后可以释放的 buffer；

- $A(v)$：执行 $v$ 后必须继续保留或新激活的 buffer。

再引入关键路径项：

$$C(v)
=
\max_{u\in\mathrm{succ}(v)}
\left[
C(u)+\operatorname{cycle}(u)
\right].
\tag{88}$$

然后构造一个真正针对这个题的 priority：

$$P(v)
=
\lambda_1\Delta L(v)
+
\lambda_2 C(v)
+
\lambda_3 U(v),
\tag{89}$$

其中 $U(v)$ 衡量执行 $v$ 后能够 unlock 多少后继节点。

这就不是“随便套一个算法”。

而是：

> **我们发现 DAG 调度中的 buffer lifetime expansion 是核心矛盾，因此针对它设计了算法。**

然后论文继续做一件非常关键的事情：

### 小规模 exact solver

从原图抽取小型子图，比如：

- 20 节点；

- 30 节点；

- 50 节点。

用 MILP / CP-SAT 求真最优。

然后比较 heuristic。

定义 optimality gap：

$$g
=
\frac{J_{\mathrm{heuristic}}-J^\star}
{J^\star}
\times100\%.
\tag{90}$$

结果：

> 小规模 50 个测试实例中，平均 gap = 1.8%，最大 gap = 4.1%。

一下子说服力就变了。

再做 ablation：

| 方法 | 最大缓存 |
| --- | --- |
| Baseline | 100 |
| + lifetime awareness | 82 |
| + critical path | 74 |
| + unlock score | **69** |

于是评委知道：

这种论文开始明显进入：

> **国一竞争区。**

因为评委已经不只是觉得：

而是：

> “你确实发现了这个问题中特有的结构，并设计了一个有效方法。”

# 一、核心思想：不要 Algorithm-first，要 Evidence-first

普通队伍经常是：

> 看到预测题 → XGBoost
> 看到优化题 → 遗传算法
> 看到时间序列 → LSTM
> 看到多目标 → NSGA-II

这叫：

> **算法匹配问题。**

但更强的方法是：

> **先问我们需要证明什么，再决定什么工具能产生这个证据。**

因此对于一道题，第一步不是列算法，而是把问题写成一个统一对象：

$$\mathcal P
=
(\mathcal X,\mathcal F,\mathcal J,\mathcal D,\mathcal E),
\tag{97}$$

其中：

- $\mathcal X$：决策变量 / 待预测对象；

- $\mathcal F$：约束和可行域；

- $\mathcal J$：我们真正希望优化的目标；

- $\mathcal D$：可利用的数据；

- $\mathcal E$：如何判断一个方案好不好。

这里最重要的其实是最后一个：

$$\mathcal E.$$

也就是 **Evaluator**。

因为只要 evaluator 建好了，后面 AI 可以帮你产生几十个方案。

如果 evaluator 都没建好，你让 20 个 Agent 并行，只是在：

> **高并发地产生不知道好不好的东西。**

---

# 二、整个方法论真正的核心：建立闭环

我会把整个比赛过程抽象成：

$$\text{Representation}
\rightarrow
\text{Hypothesis}
\rightarrow
\text{Intervention}
\rightarrow
\text{Measurement}
\rightarrow
\text{Falsification}
\rightarrow
\text{Update}.
\tag{98}$$

翻译成人话：

> 我认为问题的关键是 X。
> 所以我针对 X 改一个东西。
> 然后严格测结果。
> 如果没有改善，说明我的理解可能错了。
> 如果改善了，再进一步确认为什么。

这个循环可以重复几十次。

这比：

> “再试一下遗传算法。”

高级很多。

---

# 三、第一步永远是：把题目压缩成数学骨架

拿 2025 A 举例。

题目表面上有：

- NPU；

- Matmul；

- FlashAttention；

- Cube；

- Vector；

- MTE；

- L1；

- UB；

- SPILL。

看起来像一大堆芯片知识。

但第一轮压缩以后其实就是：

> 一个带资源约束的 DAG 调度 + 动态内存分配 + 多目标优化。

你应该立即问：

**变量是什么？**

比如调度顺序：

$$S=(v_1,v_2,\ldots,v_n).
\tag{99}$$

约束是什么？

$$u\rightarrow v
\quad\Longrightarrow\quad
\operatorname{pos}(u)<\operatorname{pos}(v).
\tag{100}$$

目标是什么？

例如缓存峰值：

$$J_1(S)
=
\max_t M_{\mathrm{live}}(t).
\tag{101}$$

总执行时间：

$$J_2(S)
=
\max_{v\in V}t_{\mathrm{finish}}(v).
\tag{102}$$

额外搬运量：

$$J_3(S)
=
\sum_{b\in \mathcal S}c_b.
\tag{103}$$

到这里，原本十几页背景已经被压缩成：

> **寻找满足偏序约束的排列，使三个目标尽可能好。**

这一步叫：

> **representation。**

非常多队伍输，其实不是不会算法，而是 representation 没找对。

---

# 四、第二步：先做最笨但完全正确的 baseline

这个原则很重要：

> **永远先追求“可验证”，再追求“聪明”。**

对于调度题：

> 普通拓扑排序。

对于预测题：

> 线性回归 / 均值预测。

对于路径规划：

> Dijkstra / greedy。

对于分类：

> logistic regression。

为什么？

不是因为你准备拿它交卷。

而是因为它提供一个：

> **零点。**

假设 baseline 的指标为

$$Q_0.
\tag{104}$$

以后任何所谓“创新”，都必须回答：

$$\Delta Q
=
Q_{\mathrm{new}}-Q_0.
\tag{105}$$

如果连 $\Delta Q$ 都不知道，你其实不知道自己有没有进步。

---

# 五、第三步：不要立刻改算法，先诊断 baseline 为什么差

这一步是普通建模论文和真正研究型论文最大的区别之一。

不要问：

> “有什么高级算法？”

问：

> **“当前方案损失在哪里产生？”**

还是 NPU 调度。

跑 baseline 后发现：

### Case A

缓存峰值特别大。

那就观察：

> 是什么让 buffer 长时间不释放？

### Case B

缓存不大，但是运行时间很长。

那就观察：

> 哪些执行单元长时间 idle？

### Case C

SPILL 很多。

那就观察：

> 是总容量真的不够，还是 fragmentation 导致？

于是你开始建立：

> **failure decomposition。**

例如：

$$J
=
J_{\mathrm{dependency}}
+
J_{\mathrm{memory}}
+
J_{\mathrm{fragmentation}}
+
J_{\mathrm{pipeline}}.
\tag{106}$$

不一定数学上真的严格可加，但认知上把问题拆开。

这一步非常重要，因为它决定你后面的创新是不是**针对真正瓶颈**。

---

# 六、第四步：从观察提出“结构性假设”

这就是比赛里最值得追求的东西。

比如你观察：

> 真正导致峰值缓存过高的原因，不是当前使用量，而是某些调度动作会同时延长很多 buffer 的生命周期。

这时候形成一个假设：

> **H₁：如果调度优先考虑未来 buffer 生命周期，而不仅考虑当前内存释放量，则峰值内存会进一步降低。**

注意：

这句话里面还没有算法。

只有一个**关于问题结构的假设**。

这才是关键。

然后才问：

> 怎么把 H₁ 数学化？

比如定义：

$$L(v)
=
\sum_{b\in B(v)}
\operatorname{size}(b)
\,
\Delta\tau_b(v),
\tag{107}$$

其中 $\Delta\tau_b(v)$ 表示选择节点 $v$ 后对 buffer $b$ 生命周期产生的影响。

然后再设计一个 priority：

$$P(v)
=
-\alpha L(v)
+
\beta C(v)
+
\gamma U(v).
\tag{108}$$

这时候式（108）不是凭空出现的。

它是：

> **观察 → 假设 → 数学化**

推出来的。

这就是好论文里的“创新来源”。

---

# 七、第五步：每加一个东西，都必须做受控实验

这是整个方法论里第二重要的原则：

> **不允许同时改五个东西然后说效果变好了。**

否则你不知道究竟是什么有效。

假设原模型是 $M_0$。

加入 lifetime：

$$M_1=M_0+H_1.
\tag{109}$$

再加入 critical path：

$$M_2=M_1+H_2.
\tag{110}$$

再加入 unlock：

$$M_3=M_2+H_3.
\tag{111}$$

然后测：

| 模型 | Score |
| --- | --- |
| $M_0$ | 100 |
| $M_1$ | 83 |
| $M_2$ | 74 |
| $M_3$ | 69 |

那么你就获得了真正的知识：

> H₁ 很重要；
> H₂ 有明显帮助；
> H₃ 有小但稳定的帮助。

这就是：

> **ablation thinking。**

不是为了最后论文补一张消融表。

而是整个开发过程从一开始就是这么工作的。

---

# 八、第六步：不断追问“69 到底好不好？”

这是很多国二论文和国一/数模之星论文的真正分水岭。

你得到：

> objective = 69

不能就满意。

必须继续问：

> **69 离理论最好还有多远？**

这里的方法不是某一个固定算法，而是一种普遍原则：

> **建立参照上限 / 下限。**

优化题：

- 小规模精确解；

- relaxation；

- lower bound；

- upper bound。

预测题：

- oracle 特征；

- noise floor；

- human/physical limit。

逆问题：

- synthetic ground truth。

这样才能计算：

$$g
=
\frac{J-J^\star}{J^\star}.
\tag{112}$$

如果 $J^\star$ 不知道，就找下界 $L$：

$$g_{\mathrm{bound}}
=
\frac{J-L}{L}.
\tag{113}$$

于是：

> “我们的结果是 69”

升级成：

> “理论下界是 66，我们是 69。”

这两个 statement 完全不是一个等级。

---

# 九、第七步：寻找 regime，而不是追求“一招通吃”

很多优秀论文的深度来自这一点。

不要只问：

> 哪个模型最好？

而要问：

> **什么情况下哪个模型最好？**

例如卷积调度可能发现：

- feature map 大、kernel 小 → DFS 型策略好；

- feature map 小、kernel 大 → BFS 型策略好。

于是模型不是：

$$S=S_{\mathrm{fixed}},
\tag{114}$$

而是：

$$S^\star
=
S^\star(z),
\tag{115}$$

其中 $z$ 是问题实例的结构特征。

这一下就从：

> heuristic

变成：

> **adaptive strategy。**

数学建模比赛特别喜欢这种结果，因为它不只是给答案，还给：

> **规律。**

---

# 十、第八步：AI 最适合干什么？

这时候 AI 的位置也会变得很清楚。

不是：

> AI 给我一个答案。

而是：

> **AI 扩大 hypothesis search space。**

比如你已经定位：

> buffer lifetime 是瓶颈。

你可以并行让多个 Agent：

- Agent A：从 scheduling theory 找相关指标；

- Agent B：从 register allocation 找类似问题；

- Agent C：构造 graph-theoretic measure；

- Agent D：寻找 MILP formulation；

- Agent E：做 local search；

- Agent F：分析失败 case；

- Agent G：跑参数实验。

但是它们全部共享：

> 同一个 evaluator。

因此：

$$M_1,M_2,\ldots,M_k
\xrightarrow{\mathcal E}
Q_1,Q_2,\ldots,Q_k.
\tag{116}$$

最后不是让 LLM 投票：

> “哪个方案看起来最有道理？”

而是：

$$M^\star
=
\arg\max_{M_i}Q_i.
\tag{117}$$

这才是 AI 真正可以产生数量级优势的地方。

# 十一、第九步：专门研究失败案例

这个习惯非常值钱。

假设你的方法平均提高 20%。

但是 Conv-1 上只提高 2%。

普通队：

> “总体效果良好。”

强队：

> **为什么 Conv-1 不行？**

然后发现：

> Conv-1 的 graph width 很大，关键路径不明显，所以 critical-path term 基本失效。

这就产生第二轮知识。

甚至可以定义问题特征：

$$z
=
(
\text{graph width},
\text{depth},
\text{memory pressure},
\text{reuse ratio}
).
\tag{118}$$

然后分析：

$$\Delta Q=f(z).
\tag{119}$$

你不只是知道：

> 方法有效。

而开始知道：

> **为什么有效、什么时候有效、什么时候失效。**

这已经非常接近科研。

# 十二、第十步：最后不是“整理所有做过的东西”，而是找一个核心 claim

四天结束以后你可能试过：

- 20 种 heuristic；

- 5 个 allocator；

- 8 个超参数组合；

- 3 种 search；

- 两个 exact solver。

**论文绝对不能把这些全写进去。**

最终需要压缩成一个主线。

比如：

> **传统调度只考虑当前局部收益，忽略 buffer lifetime 的未来传播；我们提出 lifetime-aware DAG scheduling，在保持执行并行性的同时显著降低缓存峰值，并在多种算子图上接近理论下界。**

这就是一个 claim。

然后整篇论文其实是在证明：

$$\boxed{\text{Claim}}
\tag{120}$$

你所有内容都应该服务于它：

> 理论为什么支持它？
> 实验是否支持它？
> ablation 是否支持它？
> baseline 是否支持它？
> failure analysis 是否支持它？

如果某个实验和核心 claim 没关系，删掉。

# 十三、不同题型，方法论其实完全一样

这是最重要的抽象。

| 题型 | 找什么结构 | 怎么验证 |
| --- | --- | --- |
| 优化 | 瓶颈、约束、可分解性、对称性 | exact / bound / Pareto |
| 预测 | 数据生成机制、误差来源、regime | CV / holdout / ablation |
| 物理 | 守恒、尺度、无量纲量、机制 | residual / experiment |
| 图问题 | 局部结构、拓扑、cut、path | exact small graph / scaling |
| 时间序列 | 周期、趋势、状态、突变 | rolling validation |
| 逆问题 | identifiability、noise | synthetic recovery |
| 分类 | feature structure、imbalance | ROC / calibration / robustness |

所以真正要学的不是：

> XGBoost、LSTM、GA、SA、NSGA-II……

而是：

> **什么证据能够让我知道自己的模型是对的？**

算法可以现场查。

这个问题很难现场补。

# 十四、我会把整个方法压缩成一个十步比赛协议

这是我认为你真正可以赛前背熟的东西：

- **形式化**：变量、约束、目标、数据、评价指标是什么？

- **建立 evaluator**：如何自动判断一个方案好坏？

- **建立 baseline**：最快获得一个正确可运行的方案。

- **诊断失败**：baseline 的损失到底产生在哪里？

- **寻找结构**：是否存在 bottleneck、对称性、分解、生命周期、临界路径、regime？

- **提出假设**：明确说出“如果 X，那么 Y 应该改善”。

- **最小干预**：一次只加入一个 idea，用消融验证因果。

- **寻找极限**：exact solution、bound、noise floor、oracle、理论极限。

- **压力测试**：不同数据、参数、规模、噪声、失败 case。

- **压缩 claim**：最终只留下真正被证据支持的核心贡献。

这里面第 4、5、6 步，我认为是整个体系最有价值的部分。

因为第 1、2、3 和 7、8、9，AI 可以帮很多。

但：

> **到底从结果里看见了什么结构？**

依然是最值得人类投入注意力的地方。

# 十五、还可以把团队的工作方式也抽象掉

你作为队长，不应该主要负责：

### Problem Model

### Evidence Board

哪些 claim 已经有证据？

哪些只是猜测？

### Experiment Queue

下一次实验对减少不确定性有多大价值？

可以定义一个实验价值：

$$V(e)
=
\frac{
\mathbb E[\text{information gain from }e]
}{
\text{time}(e)
}.
\tag{121}$$

然后优先跑：

$$e^\star
=
\arg\max_e V(e).
\tag{122}$$

这也是为什么我认为你之前讲的 Graph Engineering 很适合数学建模比赛。

> Problem
> → Hypothesis
> → Method
> → Experiment
> → Evidence
> → Claim

失败的 hypothesis 不是垃圾，也应该保留：

> H₄ 被实验否定。

这样另一个 Agent 就不会再浪费三个小时重新走一遍。

## 一、你们要同时搜索三个层次，而不只是“搜索算法”

考虑一道优化题。可以把技术路线的搜索抽象为：

$$\min_{r\in\mathcal R}
\ \min_{a\in\mathcal A(r)}
\ \min_{\theta\in\Theta(a,r)}
J_{\mathrm{原题}}
\!\left(
\operatorname{Decode}_{r}
\left[
a_{\theta}\bigl(r(\mathcal P)\bigr)
\right]
\right),
\tag{124}$$

并要求解码后的方案满足原题约束。

这里，$\mathcal P$ 是原问题；$r$ 是问题表示或数学重构；$a$ 是该表示下的算法；$\theta$ 是算法参数；解码操作负责把结果还原成原题要求的答案。

这三个层次分别在问：

| 搜索层次 | 核心问题 | 例子 |
| --- | --- | --- |
| **表示层** | 这件事究竟可以被看成什么数学问题？ | 调度问题能否转成带权图排序？某个子问题是否其实是网络流？ |
| **算法层** | 在这个表示下，怎样求解？ | 精确求解、分解、动态规划、启发式、混合方法。 |
| **参数层** | 怎样把这条路线调到更好？ | 搜索预算、权重、邻域大小、停止条件。 |

**你的资源应该同时覆盖这三层，而不是让所有机器都挤在第三层。**

假如问题表示存在根本缺陷，再多调参也只是把错误框架优化得更充分。反过来，找到一个漂亮的表示，却没有能力实现、检验和扩展，也不会自动形成竞争优势。

所以你说的“深度和广度并重”，我认为更准确的含义是：

> **广度覆盖不同的表示与解释；深度把有希望的表示推进到算法、证据和完整交付。**

这也与已有 AI 算法发现研究中的两条路线相呼应：AlphaEvolve 通过生成代码和评价反馈迭代算法；DeepEvolve 则明确把外部研究检索与实现、评估结合起来。不过这些研究只能提供方法上的参考，不能直接证明某套资源配置能在华为杯取得什么名次。[[图片：]arXiv+1](https://arxiv.org/abs/2506.13131?utm_source=chatgpt.com)

## 二、“高级数学降维打击”，真正应该怎样做？

我同意把它作为一条正式探索路线。但“高级”不是筛选条件，**能否改变问题的求解结构**才是。

好的数学迁移，可能让你减少必须搜索的情况，获得可证明的下界，把大问题拆成小问题，或者发现原本看起来复杂的子问题其实有精确算法。

### 例子：2025 A 题，可以检索得比“调度算法大全”深得多

你上传的 A 题第一问，要求按照合法调度顺序扫描 ALLOC/FREE 操作，计算 L1、UB 的最大驻留缓存，同时满足 L0A、L0B、L0C 各自的驻留限制。1c656697-15a3-4d87-ac3f-ed3a271…

因此，可以把 L1、UB 的申请和释放写成节点权重：

$$w(v)=
\begin{cases}
+\operatorname{Size}(v),
&v\text{ 为 L1 或 UB 的 ALLOC 节点},\\
-\operatorname{Size}(v),
&v\text{ 为 L1 或 UB 的 FREE 节点},\\
0,
&\text{其他情况}.
\end{cases}
\tag{125}$$

那么第一问的目标可以写成：

$$\min_{\pi\in\mathcal T_{\mathrm{合法}}(G)}
\ \max_{0\le k\le |V|}
\sum_{\ell=1}^{k}w(\pi_\ell),
\tag{126}$$

其中合法序列集合包含原有拓扑约束及 L0 驻留约束，空前缀的和取零。

这一步之后，检索就不必局限于：

> “NPU 调度怎么做？”

而可以转向：

> “带正负节点权的 DAG，怎样最小化拓扑序的最大前缀和？”
> “计算图峰值内存最小化有哪些结构性结果？”
> “哪些子图可以先独立优化，再用于全局调度？”

**这里确实能找到非常贴近的理论。**《New Tools for Peak Memory Scheduling》讨论了带正负权的 *node-sum* 模型、它与计算图内存模型之间的转换，以及用“主导调度”处理子图的工具；论文还给出了特定串并联图类别上的参数化算法。[[图片：]arXiv](https://arxiv.org/html/2312.13526v1)

这就比“再试一个遗传算法”多了一种可能性：

> **从已有数学理论中拿到组织搜索空间的方法，而不是只拿到一个搜索器。**

但下一步不是直接宣布“论文里的定理解决了 A 题”，而是逐项检查：原题的 L0 限制是否被覆盖？显式 ALLOC/FREE 是否与论文模型一致？图变换会不会破坏定理要求的结构？缓存地址、SPILL 和流水执行又增加了哪些约束？题目的第二、三问确实还包含这些额外要求。1c656697-15a3-4d87-ac3f-ed3a271…

即便不能整体套用，它仍可能给你一个**局部精确算法、剪枝规则、下界或更好的分解方式**。这些都是可研究的迁移方向，不需要一开始就承诺完整等价。

### 再举一个更简单、但更能说明本质的例子

假设某个子问题是：把任务分配给执行者，每项任务恰好分配一次，每个执行者恰好接一个任务，总成本可加。

$$\begin{aligned}
\min_x\quad &\sum_{i,j}c_{ij}x_{ij},\\
\text{s.t.}\quad
&\sum_jx_{ij}=1\quad\forall i,\\
&\sum_ix_{ij}=1\quad\forall j,\\
&x_{ij}\in\{0,1\}.
\end{aligned}
\tag{127}$$

一种路线是把它当组合优化，让多个 Agent 设计启发式；另一种路线是识别出这是线性指派问题，并转为最小费用流求解。OR-Tools 的官方文档就展示了这种转换，同时明确提醒：网络流适用于特定结构，不能替代能够处理更广泛约束的 MIP 或 CP-SAT。[[图片：]Google for Developers](https://developers.google.com/optimization/flow/assignment_min_cost_flow)

**真正的“降维打击”不是公式更难，而是别人还在搜索，你已经知道什么结构允许直接求解。**

当然，一旦加入复杂的成组约束、非线性成本或相互依赖，上面的转换就可能不再成立。跨领域检索的价值，恰恰包含识别这些适用边界。

## 三、因此，跨学科检索必须产出“迁移方案”，而不是算法名录

我建议给检索分支一个明确的交付要求：

> **找到一个可能有用的理论，并说明它如何对应原题、缺什么条件、能换来什么收益、怎样最快验证。**

每条候选路线只需形成一张简短的“迁移卡”：

| 内容 | 必须回答的问题 |
| --- | --- |
| **来源** | 原论文、教材或官方文档在哪里？具体依据是哪一定义、定理或算法？ |
| **对应关系** | 原题中的变量、约束、目标，分别对应理论中的什么对象？ |
| **适用缺口** | 哪些假设已经满足，哪些尚未确认，哪些明显不满足？ |
| **预期收益** | 可能减少搜索空间、得到下界、改进建模，还是只改善实现？ |
| **最小验证** | 做什么推导、反例搜索或小规模实验，能最快决定是否继续？ |

例如，不能只提交：

> “可以尝试图分解、凸优化、谱方法。”

而应该提交：

> “这部分耦合可能只通过少量边界变量发生。若能确认，便可先枚举或优化边界状态，再独立处理内部子问题。当前尚未确认缓存复用是否会引入额外跨区依赖。下一步先在两个小实例上检查分解后的解能否还原为原题合法解。”

这才是一项可调度的研究任务。

**检索的最小产物不是知识，而是一个可验证的下一步。**

同时，要保留三种不同状态：**严格等价、可证明的松弛、仅有启发性的类比。**它们都可能有价值，但不能在汇总时被合并成一句“已经证明可以这样做”。

## 四、广度与深度应该形成“双循环”，而不是先发散、再永远收敛

我会保留两条持续运行的路线。

**第一条是问题重构循环：**寻找新表示、跨领域理论、可分解结构和替代假设。

**第二条是工程验证循环：**把当前最有希望的路线做成合法实现，诊断误差，比较基线，完善证据。

它们互相反馈：

> 工程分支发现一种反复出现的失败模式，把它交给理论分支；理论分支找到一个结构性解释，再把它转成工程实验。

这样就避免两个极端：一边永远检索、没有结果；另一边只顾写代码、始终没有跳出最初框架。

### 不应平均分配资源，但也不能只奖励“马上涨分”

你的预算有限，应该让候选路线逐级获得投入：

**短探测 → 小规模验证 → 有竞争力的实现 → 全规模与严格审计。**

这与 Hyperband 等方法采用的“自适应资源分配、对部分候选提前停止”的思想相近；但它们研究的是特定的超参数优化场景，不能机械照搬成数学研究分支的淘汰规则。[[图片：]Journal of Machine Learning Research](https://jmlr.org/papers/v18/16-558.html)

尤其要给理论路线另一种里程碑。它暂时没有提高指标，也可能已经：

- 证明某个转换成立；

- 找到一个反例，排除整类错误路线；

- 给出有效下界；

- 确认某类实例具有可利用的结构。

这些都是进展。

所以我会用下面这个概念判断下一步投入，而不是只看当前分数：

$$\operatorname{VOI}(e)
=
\mathbb E\!\left[
\max_a\mathbb E[U(a)\mid E,Z_e]
\,\middle|\,E
\right]
-
\max_a\mathbb E[U(a)\mid E],
\tag{128}$$

这里，$E$ 是当前证据，$e$ 是候选研究或实验，$Z_e$ 是其可能结果，$a$ 是后续行动，$U$ 表示最终有效交付的价值。

式（128）表达的就是：**这个实验的价值，在于它能让我们后续做出多大改善的决定。**实际比赛不必计算精确概率，而是用它检查资源分配逻辑：

> 这个任务完成后，我们会改变什么决策？
> 它值得占用强模型、机器时间和人工复核注意力吗？

## 五、你的资源，应该按“任务价值与验证成本”分配

按你提供的资源，我建议采用下面的分工。**这是初始配置，不是对具体模型能力或机器速度的实测结论。**

| 资源 | 我建议优先承担的任务 |
| --- | --- |
| **Codex 20x 所提供的强模型调用预算** | 数学重构、复杂资料综合、关键实现、评价器审查，以及足以改变全局路线的判断。 |
| **CodeBuddy 中可大量调用的低成本模型** | 沿已确定线索扩展检索、提取原文条件、整理候选差异、生成测试候选、汇总实验日志。 |
| **MacBook Pro** | 交互与调度入口、研究状态与证据管理、小规模原型和分析；也可按实测能力承担计算。 |
| **几台游戏笔记本** | 分发相互独立的实验、随机种子、实例、求解分支；任务是否用 GPU，由实际算法决定。 |
| **可租赁算力** | 已确认有价值、但本地计算资源妨碍按时完成的训练、搜索或验证任务。 |

这里最重要的不是“强模型负责思考，便宜模型负责机械劳动”这种固定阶层，而是：

> **昂贵资源放在高后果决策上；低成本资源扩展候选；任何资源的输出，都要经过与其风险相称的检验。**

低成本模型当然可能提出好想法，强模型也可能犯基础错误。你们可以先拿几项真实任务校准，再调整路由，而不是根据模型品牌预设所有能力边界。

### 租算力应该有明确触发条件

例如，理论分支已经找到一条有潜力的路线，但需要更多实例验证；或者核心模型已通过小规模测试，只差完成全量实验。这时租赁算力才有清楚的用途。

一个粗略的时间判断是：

$$T_{\mathrm{部署}}
+T_{\mathrm{传输}}
+T_{\mathrm{运行}}
+T_{\mathrm{复核}}
<
\min\!\left(
T_{\mathrm{本地完成}},
T_{\mathrm{剩余}}-T_{\mathrm{收尾保留}}
\right).
\tag{129}$$

这不是充分条件，还需要考虑费用、运行风险和实验价值，但至少避免“因为可以租，就先租一堆”。

**资源充分调度，不等于资源持续满载。**有时一次关键推导能省去一整天计算；有时最有价值的动作，是停止一条已经没有信息增益的分支。

另外，多机负责搜索没有问题；论文中的算法耗时比较，最好在统一参考环境、统一预算口径下重跑，避免把硬件差异写成算法优势。

## 六、你已有的分布式协议，下一步应承载“研究状态”，而不仅是任务消息

既然你已经测试过通信与同步，那么这里没有必要重新搭一套“项目经理 Agent、程序员 Agent、测试员 Agent 开会”的组织图。

我更建议围绕**研究对象**分配任务和上下文：

> 一个问题表示、一条理论迁移、一个待检验假设、一组实验、一个结果、一个论文主张。

例如某个工作节点只需拿到：

> 当前题意版本、它需要遵守的约束、相关原始文献、这次要检验的命题、已有反例，以及验收条件。

它不需要读取所有人的聊天记录。

这与你“边界与注意力分配”的思路是一致的。一个研究任务可以抽象为：

$$W=
(
\text{输入版本},
\text{研究问题},
\text{允许改动的范围},
\text{交付物},
\text{验收条件},
\text{资源上限}
).
\tag{130}$$

比“去研究一下动态规划”更好的任务是：

> “检查这个子问题能否使用边界状态进行动态规划。交付状态定义、转移式、状态完备性的论证，以及一个可能破坏该状态表示的反例。不修改当前主线模型。”

这同时允许模型探索，又限制了错误传播范围。

**协议中的关键分界，应当是‘提出候选’与‘成为共同认可的事实’。**一次推导、一条 AI 检索总结、一组实验结果，都不应在尚未核验时自动升级为所有分支共享的前提。

## 七、广度越大，验证必须越强，而不是越相信“最佳结果”

这是你们这种资源配置特别需要注意的地方。

反复在有限验证数据上比较大量候选，也可能把验证标准本身过拟合；模型选择带来的选择偏差，是已有研究明确讨论过的问题。[[图片：]Journal of Machine Learning Research](https://jmlr.org/papers/v11/cawley10a.html)

所以我建议把评价分成三件事，而不是只有一个“统一分数”：

**搜索评价**用来快速淘汰路线；**最终验证**用来检查选中的方案是否可靠；**规范审计**用来确认模型、约束、代码、数据和论文表述一致。

具体到你们的工作流：

预测题应保留不参与日常搜索的最终验证机制；优化题除官方实例外，按题意增加结构不同的测试，并用独立可行性检查器审查结果；理论路线要检查定理假设、寻找反例，而不是让多个模型投票判断证明是否正确。

另外，我也要修正上一轮一个过于机械的表达：**不是最大化“有证据的主张数量”，而是把必要问题完整解决，并让少数重要贡献拥有足够强的证据。**证明一个关键结构、写出一个可靠求解器，都比多拼几个小创新更值得投入。

在竞赛使用上，协作范围仍需限定在参赛队内。2026 年开赛公告明确禁止与队外人员讨论赛题，并要求 AI 作为辅助工具、不能替代队伍的独立思考和主体工作；模型、公式、代码等引用也需要注明来源。因此，来源记录、人工理解与关键结论审核应直接进入你们现有协议。[[图片：]中国研究生创新实践系列大赛管理平台](https://cpipc.acge.org.cn/cw/contestNews/list/4/1)

---

**所以，你的优势不应只表述成“我们可以并行做很多实验”。**

更完整的表述是：

> **我们可以同时探索若干真正不同的数学表示，用跨学科研究提高候选路线的质量；再用分布式工程把这些路线快速变成可检验的对象；依据证据持续集中资源，而不是凭直觉一次押注。**

选题时也就应该多问一句：

> **这道题除了可并行的工程工作量，是否还存在值得探索的数学结构？而我们能否把发现结构、核验结构、利用结构这三个环节接起来？**

对于你们，最有价值的难题不是单纯代码多，也不是单纯数学深，而是：**有足够多不同的切入点，其中可能存在高价值结构，而且发现之后能够通过工程和实验兑现成同题竞争优势。**
