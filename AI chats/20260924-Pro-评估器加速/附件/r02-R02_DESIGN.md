# 三问并发算法探索：r02 静态设计 v0.1

**未执行设计。当前批准 E0/E1/E2 调用均为0。所有下述试验费用只是未来新申请的上界，不是继续执行权。**

## 1. 真正的优化对象与三层分工

离线研究的基本单位是一个完整、冻结的 SolverRun，而不是一个漂亮的单计划分数。固定内容包括算法代码、条件参数、图、问题、仿真核数、随机种子、在线候选/时间/CPU限制、后端与确认规则。

- 离线研究选择结构表示、算法机制和条件参数；积累有适用范围的结论。
- 在线 solver 从一张图构造计划；只能执行预先冻结的有限策略。当前 Q3 单候选路径不应被强制改成大批搜索。
- 作业层只负责身份、资源、调度、结果、取消和费用。不能因空闲 worker 自行创造候选。

同一图上许多内层候选不是许多独立的算法性能样本。历史强种子免费给定的实验必须标为 seed-conditioned；不能把寻找强种子的历史成本从完整 solver 收益中抹去。全矩阵逐图挑算法得到的是事后 oracle-portfolio 参照，不是一个免费可部署的选择器。

主目标在一个输入上仍是本问题官方 Makespan。跨图研究要先冻结汇总规则：可在配对块内报告相对固定基线的改善，若使用论文中的平均单核加速比，必须具备各图相应单核分母并遵照原定义。不可随结果改用“更有利”的几何均值、挑选图子集或新权重。COPY/字节 Cache 命中率为诊断和次要指标，不加成一个未经解释的万能分数。

## 2. 首选：覆盖约束的分块配对挑战

这是一个研究控制规则，不声称为新算法配置定理。

初版只有四个主要状态：ACTIVE、PARKED、GUARD_NOT_APPLICABLE、INVALID_IMPLEMENTATION。质量不佳进入 PARKED，并非证明整个机制被支配。算法历史和负结果保留。引擎出错、费用不足或超时属于实验/服务状态，不转成算法质量状态。

建议一个有限研究阶段只开最多6个活跃 spec、最多3个已审阅机制组；更大的机制登记册可以保留，但未安排的条目明确列为覆盖缺口。每个完整块给适用机制代表可比较的机会，然后才分配下一块。每轮最多加入2个审阅后的新 spec，避免结果驱动的无限代码分叉。

分配依次考虑：
1. 尚未获得适用输入的机制；
2. 已登记而未实际触发的关键交互/参数区域；
3. 当前质量—完整 solver 成本前沿与结构层专长；
4. 一个来自降级集合的预登记盲抽审计机会。

预算不能满足前两项的最低机会时，缩小声明的研究范围，或切换固定面板；不凭模型置信度补齐缺失证据。初版不在两个图后做显著性淘汰；在配对观察范围内可以降优先级，但不能把局部劣势升级成全域判决。

### 晋级、淘汰和多样性

- 当前输入的候选胜者按固定目标和原 proposal 序号决定；服务完成顺序无权参与。
- 晋级依据同输入、同预算配对结果，而非跨图直接比 cycles。
- 保留结构层内质量更好、或者同质量更低总 wall/CPU/RAM的候选。保护专长不等于宣称在目标总体中最优。
- 新颖性标签只用于探索预算，不替代 Makespan。大量相同输出不会获得更多“发现”配额。
- 只有明确的规格错误、已证不满足条件的输入、或在一个已完整穷尽的有限域内确证被支配，才允许相应范围的硬移除。
- 某图 guard 不成立，记适用性缺失；带回退的完整部署策略可在该图评估，但结果属于实际执行的回退分支。

连续两个已完成块里，族内调参没有产生新的有序计划/顺序/可行结构，或者只改变名称而排名仍完全相同，则停止继续加该类权重，转到一个未覆盖结构表示或反例机制。两个块是工程停止建议，不是统计收敛证明。

## 3. 备选：固定交互面板

预先选定基线、关键二阶/三阶组合、结构边界和有限参数区域；所有候选在相同输入块上等额比较。适用于预算太小、候选性能反转频繁、结构分层资料不足、或自适应调度无法可信校准时。

比首选少了一层研究状态，费用与执行集合更容易复现；代价是继续评价明显较差的 spec。两者都不需要代理训练，其 CPU/RAM主要取决于真实生成和局部准备，不是控制逻辑。

更复杂的方法留给下一阶段：irace 的实例 racing / restart、SMAC 的条件参数模型和实例配置都与本题存在结构联系，但部署它们之前应证明：模型/演化确实改变了有效计划；在图族隔离的影子实验中，单位总费用的最终遗憾比固定面板更低；重要机制没有被系统性压低；训练/拟合本身计费。不存在“收集100条就一定可以升级”的阈值。

## 4. 条件化语法

语法草图：

```text
AlgorithmSpec := GuardedPolicy(
  representation,
  constructor = decompose -> assign -> order -> group,
  refinement = none | finite_reviewed_transform_sequence,
  online = one_shot | strict_serial | frozen_round,
  objective, tie_break, limits,
  fallback_constructor
)
```

先决定可表达的结构，再选条件参数。修复最多一个已审阅的确定性步骤；修复后的真实 spec 和输出都入账。任意拼接两个计划的 JSON、靠反复随机修到合法，不是首版的组合算子。

### 条件变量与交互

| 场景/机制 | 可变项 | 必需前提/不开放内容 | 强交互与状态 |

| P1 初始 Task 划分 | 非分叉链、弱分量、固定块、单大Task | COPY收缩后的真实依赖；容量/完整执行另验 | 粒度×分核×整Task释放×边界COPY；已有构造 |
| P1 固定划分重排 | move/swap/合法插入/guided move | 依赖加全部核链联合无环 | 归属×顺序×跨核等待×DDR；已有构造 |

官方配置、Cache策略、Pipe槽数不是搜索变量；仿真核数是任务输入和验证维度；worker数是执行资源。不得用调整官方硬件数值制造算法收益。h、固定ID映射、数值容差不能作为任意随机基因。

### 一个精确但局部的参数压缩机会

Q3 affine 的推广若只使用正整数 lag 改变排序键，而其他构造条件固定，可按输出相同的整数区间压缩。键为：

\[
 s_{j,i}(L)=p_{j,i}+jL. \tag{R02-A1}
\]

固定一个排序后，每个相邻键对要求一个关于 L 的整数线性不等式；相同分数按固定 op ID 打破平局。所有相邻约束的交集给出产生相同完整顺序的整数区间。每区间只评分一份计划即可；跨区间的评价仍完整重编译/模拟。

这比直接扫许多 lag 值更贴近有效候选数；但区间数量仍可能很多，必须设 max_regions。未遍历区间明确未覆盖。ID平局点不能遗漏。分核/组件/前缀/图/ID顺序一旦改变，区间证据作废。不能直接迁移到根据全局遍历重新分配sgid的P2构造器。该压缩是本轮推导，未写成或运行实现。

### 本轮构造的逻辑反例，未运行官方评价

三个位分别表示分核、粒度、优先级变更。000得100；单独或两项变更得110；111得70。集合{000,011,101,110}覆盖全部二阶组合，却漏掉唯一优秀三阶组合。故低阶覆盖不是最优覆盖；对已经知道强耦合的三项，首版直接保留指定三阶bundle。

对未观察算法，构造两个世界：全部已测结果一样，只让一个未测机制在一个世界非常好、另一世界很差。当前数据不能区分。没有空间支持、分布/正则性或结构定理，不能声称高概率覆盖任意潜在好算法。

## 6. 误筛防护

初版只允许弱代理排顺序/形成解释，不允许硬剪枝。当前E2是计算型精确重放路线的有限验证实现；它与E0的区别是实现证据等级/输出/成本，不是旧近似精度层。P2不是P3低保真，改小图不是同一个实例的安全低保真。

小预算先不用反复p值淘汰。固定学习时点、配对输入块、结果汇合和盲审计。以后若需要序贯置信区间，必须先定义图族为采样单位、指标有界/尾部条件、是否随机抽样与多比较错误预算；置信序列也不会解决题型分布错配。

E0在同输入上确定，并不防止在少量图上反复选算法过拟合。独立复跑同一计划证明身份/执行一致，不增加独立图样本数。同图多seed、1–5核、标签置换和同源尺度变体应作为一个图族聚类处理，不能拆到训练/封存两边。

超时记录发生阶段与运行下界；评估尚未完成时 Makespan未知，不能把服务秒数或timeout填写成模拟cycles。在线过程若已有合法incumbent，报告该输出及未完成状态；若没有则报告没有合法输出。排队超时不是算法运行慢的直接证据。UNKNOWN不退款、不自动重试，不参与“低质量”排名。

## 7. 覆盖审计与条件概率

至少同时报告：
- 声明域覆盖：已登记机制、参数层次、必要二/三阶交互、结构守卫和核数；
- 可行域覆盖：条件真实成立，不把待实现或未测简单删除出分母；
- 实现覆盖：算子真正触发，输出变化有见证；
- 评价覆盖：不同有序计划在相同问题/配置下有可靠评分；
- 独立证据覆盖：全池真值、降级审计和未暴露图族的官方确认。

一个受约束覆盖率可用“已评分实现的义务数 / 已登记可行义务数”；同时公布未实现、未知可行和未安排数，防止通过缩小分母制造100%。这是有限登记空间覆盖，不是全部程序或全局最优覆盖。

设某次独立封存面板有一个冻结有限候选池，短名单或选择器遗憾定义为：

\[
 R=\frac{\min_{a\in S}M_a}{\min_{a\in A}M_a}-1. \tag{R02-A2}
\]

分别报告最差池、1%内好方案保留率、降级好方案数量、可避免损失、不同计划数、触发的机制组数、独立图族数、总费用与质量曲线。不可把这些计数合成为声称统计意义上的ESS。

条件性发现界：若每次在给定全部历史后，至少有 alpha 的明确探索概率，探索分布中符合目标的可完成候选至少占 q，且保证 m 次完成机会，则：

\[
 P(\text{未提议到好候选})\le (1-\alpha q)^m. \tag{R02-A3}
\]

若保留/确认失败分别另有 beta、gamma 的上界，可用联合界给出成功率下界。不需要把自适应结果假装独立，但需要上述逐历史条件下界；目前没有q/beta/gamma证据，不填实际百分比。研究语法没有表达好机制时q为0。

59个真正独立、预定标准、完整真值的面板零失败，可使“有限池保留成功率”的单侧95%二项置信下限超过95%；这不意味着全机制空间95%覆盖，也不能把59次同图计划评价当59个面板。

物理CPU/RAM/wall严格上限必须有对应主机能力。仅admission、采样和超时终止的主机不能宣称瞬时硬限；要求hard cap时须拒绝不满足的主机。超时清理/UNKNOWN保守记账、不补跑；因此可能达不到18个完整单元，届时只报告不完整，不能提高预算补齐。

固定面板 vs 挑战的同调用数比较只是一个轴。完整solver费用与三客户端真实吞吐必须在后续另批测量，不能用遮蔽矩阵回放的虚拟时间冒充真实wall。若旧图已全部暴露，第三图只能标继续开发验证，不能宣称封存。

### 何时升级

仅当当前影子审计显示：覆盖规则确实触发不同计划、晋级在不同图族可复现、盲审计漏选可接受且有区间、总生成/准备/确认费用清楚，才试更高复杂度的配置器。首个升级候选可为既有typed语法上的irace式实例racing或SMAC式条件模型，不开放任意代码变异。

LLM适合提出一个新机制假说、补一个交互组或生成最小反例；它的自评分不作晋级依据。遗传式组合只有在合法primitive可闭合组合、修复率低、后代有真实结构变化时才值得试。代理模型只有在完整隐藏面板上的风险—费用曲线优于无模型规则时才进入主路径。

## 9. 共享基础设施需要补的接口

1. `register_algorithm / register_trial`：算法、完整solver运行、计划、作业分层身份；成本scope明确，历史种子成本显式。
2. `capabilities`：固定后端支持问题/表示/native-only/native-diagnostic/official-full、每路径最大E0费用、版本与已验证域。
3. `reserve_challenge`：完整配对块费用原子预留和final圈存；资源lease按真正执行时取得，不能等待评分时占死生成器CPU。
4. `declare_epoch / decision_commit`：候选池/父版本/原序号、已完成证据集合、CAS式incumbent修订；完成即返不等于学习即更新。
5. `failure_observed`：立即停派发的错误闩与原序号确认前缀分开；精确保留strict-serial或failed-epoch策略，不静默改客户端行为。
6. `record_evidence_alias / coverage_witness`：研究层范围内精确计划别名、所有生成谱系、实际算子触发/未适用；首版不引入跨实验scorecache。
7. `stage_costs / censoring`：生成、官方局部构建、准备、native、序列化、IPC、E0、输出、启动与清理分项；保存发生阶段、已运行下界和费用未知。
8. `exposure_ledger / blind_audit`：图族分割、可见结果掩码、审计抽样概率与揭盲时间；服务保管结果不自行读取研究策略含义。

现代码的关键阻塞：P23 `evaluate_record`捕获异常后自动E0；`full=True`也是E0；`native_enabled=False`会走E0而不是禁止E0。无额度时不能调用这些可能回退的路径。新增显式 `allow_fallback=False` 或能力分离后才能安全native-only。

P1入口行为不统一：search.py评分非ok后仍继续且提前写provisional best_plan；profile_refine/prospective有停止与单独确认路径。proposed失败epoch全回滚又与部分原流程不同。协议必须由具体入口确认，不能靠“P1统一严格停止”一句话覆盖。

Fang proposals.py当前硬编码4核，官方核数推广需另一个明确版本与验证；并发薄适配不能顺便改算法语义。profile_candidates.py在生成阶段临时替换模块函数以捕获局部编译，不应未经隔离就放入多个共享线程；保持独立生成器进程或先重构显式上下文。

共享设施可以先仅实现一个协调进程、有限驻留worker、单写账本与三个薄客户端。当前不需要Redis/Ray、共享可变模拟Cache、云资源或自动跨机重投。
