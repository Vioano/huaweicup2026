## 2. 归属算法与可检查适用域

### 2.1 只压缩分析标签，不压缩执行图

先复用冻结 `_ports/_recognize` 得到有闭合守卫的 row，然后独立计算 first-row 深度和每层 raw Q/K/V key。定义锚点标签：

- `P(l,k)`：以原始 key k 为输入的投影操作；
- `A(l,k)`：该层该 key 的全部 row 内部操作。

同 key 两个 row 可共享归属标签，但**没有把它们的操作合并为一个算子**。两图标签数分别为 42、48，原始计算操作仍分别为 4113、5274 个。

对非锚点 u 定义：

`U(u) = 第一批上游锚点标签集合`，`D(u) = 第一批下游锚点标签集合`。

传播遇到 P 或 A 都停止。按拓扑序/逆拓扑序用 bitset 并集求出；`(U,D)` 只用于分类，不能据此丢边、合并浮点操作或替换原图。

### 2.2 由桥接关系识别跨层身份

DSU 的元素是 `(层, 原始 key)`，不是“第几个 row”或排好序后同号的 key。

对 `U(u) ≠ ∅` 的非锚点，把 U(u)∪D(u) 对应的所有元素并入一类。对直接锚点→锚点的非 K/V 广播边做同样合并：它们是内部节点数为零的桥。随后要求每个 DSU 类在同一层**最多一个不同 key**。

满足时，DSU 类就是持续轨道。锚点与 `U≠∅` 桥接节点归属其唯一轨道；中间层跳过的 carry 不另造 owner。若一类出现同层两个 key，保留该真实 join 的分类证据，但当前构造返回 unsupported，不能把 join 各复制一次、归属两边，或擅自选一边后继续沿用证明。

对剩余 `U=∅` 节点，反向传播第一批固定轨道的集合：只有一个轨道则归其私有辅助区；否则进入 S。要求 S 为原始计算 DAG 的祖先闭合集；将 S 的每个弱连通分量整体放一个核。这样不同 S 分量间没有 S→S 传输，同一原 op 仍只出现一次。

### 2.3 硬守卫

基础输入须满足官方图格式契约；构造还独立检查 ID 唯一/不相交、原始边无重复、原始 op DAG 无环、tensor 单生产者、只有 tensor-mediated 边，以及移除官方 COPY 的最近计算祖先收缩与直接 tensor 计算依赖一致。全部计算操作须为正整数周期的 M/V 操作、至少产生一个映射后 L1/UB 输出。

结构上还检查：row 不重叠、不重入，key 识别无歧义、不同层 key 不复用，投影与 row 标签不冲突；轨道不合并同层不同 key；S 祖先闭合；阶段不倒退；私有轨道之间所有原始边必须是**已识别的同层 P→A K/V 边**。其余跨轨道动态 join 均拒绝。本轮两图全部通过。

## 3. 为何选持续归属，而不是逐层迁移 DP

### 3.1 广播负载有一个真实不变量

005 有 84 个、086 有 96 个 K/V 广播 tensor，每个都被**该层所有轨道**消费。当前每条轨道跨三层持续存在；五核分组非空。因此任意这种五核分组中，每个广播 tensor 都在所有五核被消费，而只有一个生产核。官方按 tensor/目标核造 COPY 对，故每个恰有 4 个远端目的核，与具体分组无关。[S2,S5]

K/V 跨核 payload 不变量分别为 350208、405504 bytes。持续归属把全部非广播动态桥接、同 key join、旁路搬运压为零。因此，在该构造族内部，先优化私有 pipe 工作量有依据；不是以“row 全稠密”乘出一份虚假的通信代价。S 的放置仍单独计费，两份实际计划各有额外 4320-byte 跨核 payload。

这不证明迁移在 Makespan 上永远无益。迁移可能交换通信与不同层的释放时机、FIFO 阻塞、Cache 事件顺序；本轮不开展该搜索。

### 3.2 一个当前层状态不够的反例

有 `a0→x→j2` 旁路，同时 `b1→j2`。两段历史具有完全相同的 layer-1 placement，j2 也都在 core0，但 x 在一段历史由 core0 产生、另一段由 core1 产生。未来就至少相差一条远端传输及 500-cycle 依赖。

所以只用 `DP[layer,current_assignment]` 不能精确计算未来通信；至少还须保留未消费旁路 tensor 的 owner。若要精确官方 M3，incarnation/backing、各 pipe FIFO 前端、分配序状态及资源/Cache 历史还会相关，不能声称小状态 DP 自动包含这些。

本轮采用明确受限的压缩：**先选整个持续轨道的 owner，三层及其所有 bypass 一并固定。** 这是可解释的候选族限制，不是官方全局最优性定理。

## 4. 分组 DP 与优先序

### 4.1 精确求解私有负载代理

令每条轨道 i 的总原始 pipe 工作量为 `(m_i,v_i)`。对轨道集合 T：

`w(T)=max(Σ_{i∈T}m_i, Σ_{i∈T}v_i)`。

在 K 个非空组中最小化最大 w。固定每次取包含当前最小轨道号的子集，递推：

`F(k,T)= min_{A⊆T, min(T)∈A, |T\A|≥k−1} max(w(A),F(k−1,T\A))`。

复杂度 O(K·3^r)，状态存储 O(K·2^r)。本轮 r=7/8，K=5。先求最优阈值 W*，**第二遍**在每组 w≤W* 的约束下最小化 `Σ_c(M_c²+V_c²)`，再按 mask 确定性破平局。不能在第一遍只存一个词典序 `(max,sumsq)` 后缀：前缀较大的 max 会遮住后缀 max，导致次级目标错误。

这里对核标签的规范化只对负载代理正确，**不声明核编号置换是官方执行行为等价**；实际事件平局和 Cache 可能受遍历顺序影响。也不把同工作量的不同轨道混为相同原图节点。

实际私有工作量与结果：

- 005：轨道 0–4 为 `(9972,9306)`，5–6 为 `(6876,7200)`；分组 `[0] [1] [2] [3,5] [4,6]`，W*=16848。
- 086：轨道 0–5 为 `(10692,10338)`，6–7 为 `(7380,8016)`；分组 `[0] [1] [2,3] [4,6] [5,7]`，W*=21384。

轨道号按首层 raw key 规范命名；跨层身份由 DSU 决定，不靠号数匹配。

S 分量逐个放置，确定性最小化“其输出 tensor bytes × 远端目的核数”，再按加入该分量后的最大 pipe 工作量、核号破平局。DP 最优性不含这一步，也不含官方 Makespan。

### 4.2 每核优先序

定义阶段偏序：

`S < I < P0 < A0 < B0 < P1 < A1 < B1 < P2 < A2 < B2`。

I 为不依赖任何 P/A 的私有辅助操作；B_l 为最后一次经过层 l 锚点的非锚点桥接操作。所有原始边都要求阶段不倒退。

在每个阶段内，只从原 DAG ready 集选择节点，按以下确定性键取最小：

`(代理最早开始时刻, −原 DAG bottom-level, 原 op ID)`。

代理开始时刻同时考虑原始前驱完成、跨核 500、该核对应 pipe 空闲、该核前一个原 op 的分配开始时钟；没有模拟 COPY、DDR、Cache、实际 Step3 的内存边。把得到的全局拓扑序 τ 投影到各核，即是 singleton 优先级，提交不含任何开始/结束时间。

阶段是优先序规则，**不是提交额外的全局完成屏障**；不同核可按真实依赖继续重叠。所有原依赖、每核两条计算 pipe FIFO 都在 τ 方向向前。

现版选点扫描 ready 集，最坏 O(n²)；不是为了虚报 solver 速度而声称线性。锚点后的签名传播约 O((n+e)·⌈a/word⌉)，a=42/48；冻结 row 识别器成本另计。测得的本地脚本时间不作为冷 solver 效率验收。

## 5. 按官方语义证明桶前沿无 spill

### 5.1 先确定到底是哪一种“活跃”

这不是随意选全局执行时刻得到的 live set。令核 c 的 singleton word 为 `u_c,0,…,u_c,n−1`。对该核触及的原 tensor t，收集本核 eligible producer（若有）及本核所有 eligible consumers 所在桶位置，定义：

`f_c(t)=min positions`，`l_c(t)=max positions`。

DDR tensor 在 Task 内映射为 UB；按映射后的 pool p 定义**闭区间桶前沿**：

`F_c,p(j)=Σ size(t) · 1{f_c(t)≤j≤l_c(t), pool(t)=p}`。

每个 `(c,t)` 只计一次，包含本核输出、接收输入、原图输入及最后输出；不能只数跨层 boundary tensor。carry 的最后位置是最后真实消费者，不是“层结束”。

### 5.2 为什么端点覆盖官方 COPY 桶

冻结 Task builder 每核一 Task：[S5]

- 原图输入 COPY_IN、远端 COPY_IN 放在该核最早消费 singleton 桶；
- 原图输出 COPY_OUT、每个远端 COPY_OUT 放在生产 singleton 桶；
- `_prioritize_task_seq` 稳定按桶排序，桶内保持 Step1 拓扑序。

因此每个桶只有一个原计算 u、若干在 u 前的输入 COPY_IN、若干在 u 后的输出 COPY_OUT。所有该桶新/末次触及 tensor 都是 u 的输入或输出。**在 u 的 alloc 后、execute/free 前，闭区间 F 的张量同时参与 Step2 容量检查；其余桶内微步不超过这一集合。**

### 5.3 无 spill 定理

在上述 singleton、唯一生产者、无直接 op 边守卫下，假定此前未 spill，则 Step2 的最高占用等于上述闭区间前沿。Step2 明确是 alloc→检查→execute→last-use free，而不是先释放末次输入。[S6]

若 `max_j F_c,p(j)≤C_p` 对所有 c,p 成立，假设存在第一次 spill；在该步之前图尚未改名，此步占用不超过已核验的 F，因此没有触发 spill 的超容量，矛盾。故整个 Step2 不产生 spill。

Step2 只在 `pending_spills` 中建立新的片上 incarnation 并改接消费者；因此本条件下，每个核触及原 tensor 对应一个片上 incarnation，不会把不同重载版本错误合并。

### 5.4 不可偷换成运行时峰值或无内存边

F **不是**多 pipe 并发执行的实际瞬时峰值。官方 Step3 在产出发射前分配，等全部消费者完成才释放；COPY_OUT 也是消费者。Step3 严格按 `allocation_order` 发射所有有片上输出的 op，使用 FIFO 可拆分/合并字节 credits，复用时从旧 tensor 的所有消费者（死输出则 producer）向新 producer 添加 MEMORY_REUSE 边。[S7]

容量守卫只保证存在符合桶顺序的无 spill 串行见证。实际较早发射的操作可能尚未结束，Step3 会等待容量；不能据 F 报 runtime peak，也不能宣称没有 MEMORY_REUSE 或内存停顿。

在固定源码、正周期/正带宽和题述顺序语义下，局部不存在由该容量条件造成的资源死锁：若下一次 allocation 暂时不容纳，所有更早 allocation 已经发射，之前的非分配操作也只依赖更早操作；让这些完成后，保留的必需 live set 不超串行前沿，下一次 allocation 就可继续。这个论证不代替实现的 max_iter、事件舍入及官方完整契约检查。

### 5.5 为什么实际内存边仍可被路径证明覆盖

本构造额外检查**每个原计算操作至少产生一个片上输出**。考虑一条由旧张量释放产生的内存边 `x→y`，y 为下一次分配 producer。

若 x 是计算消费者，它必须已完成，因而它自己的 allocation 已发生；严格 allocation_order 排除了 x 位于 y 后面的桶。若 x 是 COPY_OUT，它位于旧 tensor 的 producer 桶，而该 producer 的 allocation 更早。若是死输出 WAW，源 producer 同样更早。

同桶内部也不会反向：该桶 COPY_IN 必须在唯一计算 u 前、COPY_OUT 必须在 u 后，不能先完成 u 的 COPY_OUT 再为 u 的输入分配。故这些内存边的桶投影严格向前。**证明依赖的是实际官方 FIFO credits 和 allocation_order，不是选择某个理想内存分配。**

所有真实 COPY 的 FIFO 投影则桶位置不下降。把每核 word 的相邻桶之间全部加边，便得到包含这些投影的路径包络。不同核之间 COPY_OUT→COPY_IN 又从原生产桶指向真实消费者桶，沿 τ 严格向前。因此扩展数据边、内存边、四条 pipe FIFO 和跨核边的联合图无环。

## 6. 完整路径的跨核次数：三层为 4，不是 2

构造包络 `H_seq = 原计算 DAG + 每核整个 word 的相邻边`。其新增边比仅 M/V FIFO 更强，但用于**覆盖路径/计算 crossing count**，不用于把串行工作量当官方周期下界。

第5节证明了实际 Task 的 COPY FIFO 与 MEMORY_REUSE 都能向前投影到此包络。原跨核 COPY 对则投影到其 tensor 的原 producer→目标核最早 consumer。

路径上可能跨核的边只有两类：

1. S→私有区。S 祖先闭合且每个弱连通分量单核；阶段单调使路径不能回到 S，因此至多一次。
2. 同层 P_l→A_l 的 K/V 广播。FIFO 和内存边也不允许从 A_l 回到 P_l，因此每层至多一次。

三层给出 `D≤1+3=4`。该结论覆盖所有旁路、join、FIFO 与上述内存复用边；不是把单层常数口头相加。两份候选包络的实际最大 crossing count 均等于4，完整 witness 存 metadata。

这只说明任一完整扩展依赖路径上至多有四条 500-cycle 跨核释放边。它不意味着只有四次 COPY，不意味着全系统等待总和≤2000，也不意味着 `M3≤compute_bound+2000`。COPY 服务时间、带宽竞争、容量阻塞、Cache 时序仍可能主导 Makespan。

### 6.1 最小阶段反例

六节点阶段链 `P0(a)→A0(b)→P1(b)→A1(a)→P2(a)→A2(b)` 已有三次跨核，否定多层仍≤2。再加异核 S→P0，七节点链可达到4。代码 toy 用单位操作周期与500边权得到该抽象链长2007；这不是完整 attention 原图或官方实验。

## 7. 代理量与 R8 结论的边界

`H_MV = 原计算依赖 + 每核 M/V FIFO` 上的最长路 `L_delta`，给每条原始跨核依赖加500，确实是**该固定计划**两种 mode 的周期下界。它忽略 COPY 服务、DDR/Cache 竞争及内存边，不是预测器。

两计划的 L_delta 分别为21636、27109。只有这种有效下界≥某个目标 M3 时，才能据此拒绝“会严格改善该目标”的候选；小下界不能证明可达，更不能保证 G。

反过来，`H_seq` 的 L 值不是官方下界也不是上界。本轮005的包络 L_delta=33522，高于旧30642，**不能**因此筛掉候选：包络额外串行化了整个核。分组工作量、字节代价、影子时间以及核号规范化，也都不能据此作官方无损剪枝。

## 9. 小型验证与最不确定之处

`test_toys.py` 只运行合成例：11个小分组问题的DP与全枚举双目标对照；三层4-crossing抽象链；4个1-byte张量的链，union=4、正确闭前沿=2，容量1明确拒绝；旁路非Markov反例；真正异轨道动态join拒绝；零内部节点的直接桥归属。全部通过。原图只做结构/计划/证书检查，没有执行官方语义程序。

最不确定的是**周期收益**：持久轨道的总负载平衡及广播字节不变量，不能预测官方 COPY FIFO、严格分配发射、真实 MEMORY_REUSE 和 Cache 时序下的 M3。086 的一个双重轨道组尤其可能暴露阻塞。

最应优先证伪的实现假设是“无spill后的所有实际内存边都向前投影到singleton桶”。文中已有基于冻结源码的证明，但它依赖每个计算 op 都有片上输出、输入COPY按最早消费者归桶、输出COPY按生产者归桶等硬守卫，不能推广到无输出sink、多op子图、直接op边或其他Task接口。现有代码检查了这些实际适用条件；尚未以官方prepared原件验证该lemma。

**结论**：两图的真正新覆盖来自保留投影边界后的持续轨道，而非否定真实bypass。可交付的是一个无原op变换、全路径有边界、容量有源码级证书的确定构造，以及两份可被官方一次性推翻的计划；不是全局最优性、提速承诺或新增全500成绩。
