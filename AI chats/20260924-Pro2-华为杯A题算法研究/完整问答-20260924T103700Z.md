## 2.1 用编译—仿真分解贯通三问

令公开方案为

$$p=(\pi,\kappa,\sigma),$$

其中：

$$\pi:V_{\rm eligible}\rightarrow\{\text{子图编号}\},$$

$$\kappa:\{\text{子图}\}\rightarrow\{0,\ldots,K-1\},$$

而 $\sigma_k$ 是核心 $k$ 的子图顺序。

这对应且只对应：

```
{
  "node_to_subgraph": {"原操作ID": 0},
  "core_schedules": [[0], []]
}
```

题面明确限定方案字段与覆盖关系；没有操作启动时间、预取、等待或重算决策。

通用神经网络处理器下的多核调度问题

最有用的抽象是

$$(G,p,\mathrm{cfg},q)
\xrightarrow{\Phi_q}
(H_p,\mathcal A_p)
\xrightarrow{\Psi_q}
T_q(p).$$

这里 $\Phi_q$ 是**官方固定展开**：构造 Task、COPY、Step1 顺序、spill/rename、内存复用依赖和 Pipe 顺序；$\Psi_q$ 是**官方全局资源演化**。优化者只能通过 $p$ 间接改变展开结果，不能直接编辑 $H_p$ 中的顺序边。

通用神经网络处理器下的多核调度问题

三个问题的差别，可以压缩成下面这张表：

| 问题 | 官方 Task 粒度 | 同核跨子图数据 | 跨核同步 | 全局资源 |
| --- | --- | --- | --- | --- |
| Q1 | 每子图一个 Task | 不保留，仍经 DDR 边界搬运 | 同核前序 Task $+100$；异核真实前驱 $+1000$，取约束最大值 | DDR 等分共享 |
| Q2 | 每核一个合并 Task | 可以驻留；子图顺序仍影响展开 | 目标 COPY_IN 等源 COPY_OUT 完成后 $+500$ | DDR 等分共享 |
| Q3 | 同 Q2 | 同 Q2 | 同 Q2 | 再加独立 CACHE_READ 池与只读 FIFO Cache |

这些时间和资源定义来自题面，不是代理模型选择。

**一个重要的精确压缩对象是“编译像等价类”。**

若两个方案产生完全相同的语义准备产物、初始资源状态和所有参与并列比较的 ID，那么确定性仿真结果相同。可以据此跳过重复评估。

但“切图相同”“流量相同”“图同构”都不等于这个证书。特别是子图编号可能影响生成 ID，而生成 ID 又可能影响固定排序。因此，**子图编号不能未经证明按纯粹无名标签处理**。

## 2.2 矩阵怎样建，什么信息不能丢

以下邻接矩阵统一采用“行是目的节点，列是源节点”。

设 $O$ 是全部操作，$\mathcal T$ 是张量。定义两个 $|O|\times|\mathcal T|$ 关联矩阵：

$$P_{ot}=\mathbf 1[o\text{ 生产 }t],\qquad
C_{ot}=\mathbf 1[o\text{ 消费 }t].$$

则二部图邻接矩阵和直接操作依赖矩阵为

$$\mathcal B=
\begin{pmatrix}
0&C\\
P^\top&0
\end{pmatrix},
\qquad
D=\mathbf 1[CP^\top>0].$$

跨过原 COPY 节点，可以得到 eligible 操作上的偏序关系 $D_V$。**这个消去对偏序保真，但对搬运、张量身份和内存状态不保真。**

若 $X\in\{0,1\}^{|V|\times S}$ 是子图归属矩阵，$Y\in\{0,1\}^{S\times K}$ 是核心归属矩阵，则

$$Q=\mathbf 1[X^\top D_VX>0],\quad \operatorname{diag}Q=0$$

是商图，而 $Z=XY$ 是操作到核心的归属。

再令 $W\in\mathbb R^{|V|\times4}$ 的第 $v,r$ 项是操作 $v$ 在 Pipe $r$ 上的计算工作量，则

$$Z^\top W$$

给出每核每 Pipe 的负载。**它是下界和构造特征，不是完成时间。**

这里有两个容易被“矩阵方法”带偏的地方。

**DAG 邻接矩阵的普通特征值全部为零。**因为拓扑置换后它严格三角、因而幂零。不能拿它的普通谱半径解释本题吞吐。

**无向拉普拉斯会直接抹掉边方向。**若边—点关联矩阵每行是“尾端 $-1$、头端 $+1$”，反向一条边只把该行乘 $-1$，所以

$$L=B^\top\operatorname{diag}(w)B$$

不变。

超图谱仍可用来找共享输入聚集区。Zhou 等的归一化超图拉普拉斯为

$$L_H=I-D_v^{-1/2}H W_eD_e^{-1}H^\top D_v^{-1/2}.$$

但它优化的无向归一化切割并不等于本题按目标核心、COPY 对和时间计费的目标；固定 ID、FIFO、同步和资源历史也都没有进入。**我把它保留为种子或消融基线，不作为主求解器。**[[图片：]NeurIPS Papers+1](https://papers.nips.cc/paper_files/paper/2006/file/dff8e9c2ac33381546d96deea9922999-Paper.pdf)

# 三、路线 A：偏序理想集 → 张量辅助节点 → 一次分层最小割

这是本轮数学构造最完整的一条。

## 3.1 先得到两个合法性定理

### 命题 A1：无环聚合等价于某个拓扑序上的连续分块

对 DAG 的一个分区，以下两者等价：

$$\text{商图无环}
\iff
\text{存在一个原图拓扑序，使每个分区块连续。}$$

**证明。**若商图无环，先按商图拓扑序排列块，再按各块内部拓扑序排列节点并串接。反过来，若每块在某拓扑序中连续，所有跨块边只能从前块指向后块。证毕。

它的算法意义是：**“拓扑序＋连续切线”是完整的参数化描述，但固定一个拓扑序后再切线只是受限子空间。**

此外，“每块偏序凸”不充分。两条链

$$a\to b,\qquad c\to d$$

分成 $\{a,d\}$、$\{b,c\}$，每块内部没有漏掉路径中间点，商图仍然成环。

### 命题 A2：单调核序可以保证更强的跨核无环性

给操作赋核序标签

$$\ell(v)\in\{1,\ldots,K\},
\qquad
u\to v\Rightarrow \ell(u)\le\ell(v).$$

每核一个子图，或在该核内部继续按拓扑连续段切分。

**在每核官方局部展开无环、跨核 COPY 沿原生产者→消费者方向生成的条件下，全局展开图无环。**

证明很短：局部边不改变核标签，跨核边严格增加核标签。有向环不可能含跨核边；完全在一个核内的环又被局部检查排除。

这比“商图拓扑序合法”强，但**不是无损限制**：它排除了可能有利的

$$\text{Core A}\to\text{Core B}\to\text{Core A}$$

往返布局。它适合做一个有强合法性保证的候选族，不适合宣称覆盖全局最优。

## 3.2 逻辑活跃张量边界可以精确变成图割

考虑前驱闭合的操作集合 $I$，也就是偏序理想集。令

$$x_v=\mathbf1[v\in I].$$

暂限于**唯一 eligible 生产者、至少一个 eligible 消费者**的内部张量。张量 $t$ 的生产者为 $p(t)$，消费者集合为 $C_t$，大小为 $s_t$。

定义

$$F(I)=
\sum_t s_t
\left(
x_{p(t)}-\min_{v\in C_t}x_v
\right).$$

因为 $I$ 前驱闭合，这正好表示：

> 生产者已经执行，但还有消费者未执行的内部张量字节数。

它是一个顺序前缀完成后的**逻辑活跃前沿**，不是官方乱序执行峰值。

现在构造一个源汇最小割网络，源侧表示“选入 $I$”：

- 每条依赖 $u\to v$，增加反向无限容量弧 $v\to u$，强制前驱闭合。

- 每个张量新增辅助节点 $z_t$。

- 增加 $p(t)\to z_t$，容量 $s_t$。

- 对所有消费者 $v\in C_t$，增加 $z_t\to v$，容量无限。

为什么正确？当生产者在源侧、至少一个消费者在汇侧时，$z_t$ 被迫放在汇侧，恰好付一次 $s_t$。其他情形可以不付这项。

**所以，这不是把超边粗暴展开成多条付费普通边，而是精确“一张量一次计费”的割表示。**

外部输入、最终输出、死输出、多生产者张量必须单列；不能默默套入这个公式。

## 3.3 多核标签也能在一次最小割里求解

定义分层二元变量：

$$x_{vj}=\mathbf1[\ell(v)\le j],
\qquad j=1,\ldots,K-1.$$

增加无限弧

$$x_{vj}\to x_{v,j+1}$$

保证各层嵌套；依赖 $u\to v$ 则对应

$$x_{vj}\to x_{uj}.$$

每层复制刚才的张量辅助节点，容量为 $\alpha_js_t$，要求 $\alpha_j\ge0$。

任意一元标签代价均可写为

$$U_v(\ell(v))
=
U_v(K)+
\sum_{j=1}^{K-1}
[U_v(j)-U_v(j+1)]x_{vj}.$$

正负一元项都能用源边、汇边和一个常数精确编码。因此一次最小割可以精确求解

$$\boxed{
\min_{\ell\ {\rm 单调},\ {\rm 锚点约束}}
\left[
\sum_v U_v(\ell(v))
+
\sum_{j=1}^{K-1}\alpha_jF(I_j)
\right].
}$$

**精确的是这个代理模型，不是原题 Makespan。**

当 $\alpha_j=1$ 时，张量项等于

$$\sum_t s_t
\left(
\max_{v\in C_t}\ell(v)-\ell(p(t))
\right).$$

这也暴露了它的局限：它惩罚**标签跨度**，而物理题目没有“相隔两个核心比相邻核心更远”的代价。对 $K>2$，该项甚至会对中间没有消费者的标签收费。

所以生成候选之后，要利用 $K$-bit 掩码廉价重算每个张量实际触达的目标核心，而不是继续把跨度当通信量。

## 3.4 锚点和负载约束不能被略过去

可以把关键路径位置偏好、每核各 Pipe 的负载价格放进 $U_v(k)$，通过少量价格配置生成不同候选。

二分时，若

$$c_v(\lambda)=a_v-\lambda w_v,\qquad w_v\ge0,$$

且锚点固定，就满足经典参数化最小割的单调容量条件，可以获得嵌套的规范割族并复用残量网络。Gallo–Grigoriadis–Tarjan 的原文明确依赖源侧容量单调增加、汇侧容量单调减少、其他容量不变；不能随意变更多个参数还声称保留该性质。[[图片：]ResearchGate](https://www.researchgate.net/publication/220616489_A_Fast_Parametric_Maximum_Flow_Algorithm_and_Applications)

**但不设锚点会退化。**例如只有内部边界成本时，最小割可能始终选择“全部放左边”或“全部放右边”。本轮代码已经验证了这个反例。

因此：

> 参数扫描不是严格平衡划分的免费算法；负载价格也不保证命中指定负载。

这与无环平衡划分文献中的困难性相符，但不能把该文献的割目标困难性不经归约直接改称本题的困难性定理。[[图片：]arXiv](https://arxiv.org/pdf/1704.00705)

## 3.5 实现方式、复杂度和官方输出

```
构造 A 类候选：
    读取不可变原图 CSR、张量 pins、原 ID
    提取 eligible 偏序与满足条件的内部张量
    对少量锚点 / 负载价格配置：
        建立分层网络
        求精确最小割，解码核标签
        每个非空核生成一个子图
        必要时按核内拓扑连续段继续细化
        输出原 ID 的 node_to_subgraph 和 N 个 core_schedules
        通过官方准备与各层合法性检查
        以 E0 或已验收精确引擎比较短名单
```

设 $n$ 为操作数，$m$ 为依赖数，$t$ 为内部张量数，$p$ 为消费者 pins 数，则网络规模为

$$V_H=O(K(n+t)),\qquad
E_H=O(K(n+m+p)).$$

单候选成本为

$$T_{\rm MF}(V_H,E_H)+O(n+m+p),$$

再加官方准备和评估。一般 Dinic 的保守界可写成 $O(V_H^2E_H)$，**不能包装成线性算法**。研究包中的递归 Python Dinic 只适合微验证，生产实现应使用迭代、连续内存的整数残量网络。

### 最有判别力的实验

先用菱形链、宽叉合流、长寿命 skip tensor、双链交叉共享和纯链作对照。固定配置，通过合法张量的累计驻留跨越容量阈值，保持每个操作自身输入输出满足题面容量要求。

比较同预算下的：分层最小割、固定拓扑连续切分、只按 Pipe 负载构造、无向谱种子。

最重要的消融是：

> 将张量辅助节点换成普通边计费；去掉锚点；去掉单调核序；去掉实际目标核掩码复核。

如果只是 $F(I)$ 下降，而 E0 Makespan 不降，或者求割吃掉了精确评估预算，就应否定该结构层的收益假设。

# 四、路线 B：输入乘积结构 → 矩形布局，而不是逐算子分核

这条路线的适用面更窄，但一旦结构存在，降维可能比路线 A 更直接。

## 4.1 不先找“相似操作”，先反转输入关联

考虑一组独立作业

$$o_{ij},\qquad i=1,\ldots,R,\quad j=1,\ldots,C,$$

其中 $o_{ij}$ 使用两个输入族的 $A_i,B_j$，输出私有。作业也可以是内部不共享张量的有界小模板。

一种很便宜的检测方法是：

> 把输入张量当作顶点，把一个消费两个共享输入的作业当成一条边。

检查这个输入图是否二部；若一个无重边连通分量满足

$$|E|=|A|\cdot|B|,$$

它就是完整笛卡尔积。

这是 BFS 二着色＋计数检查，复杂度 $O(n+p)$，**不是一般最大 biclique 搜索**。没有找到结构就退出，不应为了理论包装去解另一个昂贵组合问题。

多操作模板需要额外核对私有内部张量、端口和具体同构；哈希只能找候选，不能证明官方行为等价。

## 4.2 矩阵因子化直接揭示低维坐标

令输入关联矩阵 $H$ 的行是 $RC$ 个作业，列是 $R+C$ 个输入。按 $(i,j)$ 排列时，

$$H_A=I_R\otimes\mathbf1_C,\qquad
H_B=\mathbf1_R\otimes I_C,$$

因此

$$HH^\top=
I_R\otimes J_C+J_R\otimes I_C.$$

若两族输入大小分别为 $a,b$，共享权重矩阵相应是

$$aI_R\otimes J_C+bJ_R\otimes I_C.$$

这里最重要的不是去求这个巨大矩阵的谱，而是：

**不要形成 $(RC)^2$ 的操作相似度矩阵；直接恢复两个输入轴。**

超图通信建模文献已经说明，共享数据应按 net 触达分区计费，而不是按全部操作对展开计费；数组访问映射与通信下界文献则给出了从访问结构推导矩形块形状的思路。这里只借用其结构机制，不借用它们不符合本题的重排自由度。[[图片：]Bilkent University Computer Science+1](https://www.cs.bilkent.edu.tr/~aykanat/papers/99IEEETPDS.pdf)

## 4.3 一个能证明的面积—输入量关系

某个核心分到 $m$ 个作业，触达 $r$ 个 $A$ 输入、$c$ 个 $B$ 输入，则

$$m\le rc,$$

而不同输入的字节并集为

$$V=ar+bc.$$

于是

$$\boxed{V\ge2\sqrt{abm}.}$$

证明只是集合包含关系和 AM–GM。满矩形满足 $m=rc$，连续松弛中最佳形状满足

$$ar=bc,\qquad \frac rc=\frac ba.$$

这给出了可解释的构造规则：

> 输入越贵的那个方向，越应减少该核触达的不同输入数量。

**这个下界针对输入并集，不是 DDR 实际字节，也不是 Makespan。**只有在每核该输入只 ingress 一次、无 spill 等附加条件下，它才对应那部分 COPY_IN 字节；Q3 还要决定这些 ingress 实际走 DDR 还是 CACHE_READ。

## 4.4 构造与复杂度

生成少量行条带、列条带、$p\times q\le K$ 网格；对 $K=3,5$，使用递归矩形切分，不强求所有块等形。

切点由面积平衡、四 Pipe 负载平衡和输入轴字节前缀给出，只枚举附近的 floor/ceil 候选，并保留少量非矩形负载对照。

```
构造 B 类候选：
    检测并验证输入乘积分量
    建立四 Pipe 工作量二维前缀和、输入字节轴前缀
    枚举有界数量的条带 / 网格 / 递归矩形布局
    将原作业或完整模板分配到矩形与核心
    保留原 ID，只改变公开允许的分组和子图顺序
    与外部 DAG 按明确端口接合
    官方展开、验证、短名单 E0 确认
```

若枚举 $A$ 个布局，代理阶段可以做到

$$O(n+p+AK),$$

但输出全部节点映射本身仍可能需要 $O(An)$。不要把不可避免的方案物化成本藏掉。

### 重复分支什么时候才能计数化？

只有当完整准备语义允许交换分支——包括端口、时长、Pipe 顺序、资源副作用、cache key 等价关系和固定 ID 并列行为——才可以把 $m$ 个分支的分配压缩成

$$(m_1,\ldots,m_K),
\qquad
\#\text{计数组合}=\binom{m+K-1}{K-1}.$$

不能仅因原图同构，就从 $K^m$ 直接跳到计数。即使计数化成立，组合数也可能仍大；进一步只取平衡计数需要更强的同质计算条件。

## 4.5 Q3 应看 FIFO“准入顺序”，不是 LRU 重用距离

对大小为 $s$ 的 key，在它插入后、首次被淘汰之前，令 $A$ 为后来实际成功准入的条目字节累计，则其仍驻留的条件是

$$s+A\le C_{\rm cache}.$$

这里统计的是**完成后成功插入的条目**，不是访问次数。命中不晋升；同 key 的幂等插入和超大条目跳过也不增加 $A$。题面和成员报告都把插入放在 miss 完成后，而不是发起时。

这可以指导合法作业顺序的相位设计，但不能凭空插入等待或预取。

### 击穿它的反例

重计算集中在矩形对角线，可能使矩形通信很好、负载却很差；私有输出很大时，输入复用收益可能不重要；固定 ID 顺序可能使输入驻留过久而 spill。

# 五、路线 C：max-plus 端口消元——保留资源事件，只消掉真正静态的内部状态

## 5.1 哪一部分可以精确线性化？

在一个已经固定、无环的执行图里，若所有操作时长 $d_v$ 固定、同步延迟 $\delta_{uv}$ 固定，而且没有未表示的动态资源约束，则完成时间满足

$$x_v=
\max\left\{
r_v,\ 
\max_{u\to v}(x_u+d_v+\delta_{uv})
\right\}.$$

这里 $r_v$ 是**完成时刻的外部下限**，已经包含必要的本节点时长。

令

$$A_{vu}=d_v+\delta_{uv},$$

无边为 $-\infty$，则

$$x=A\otimes x\oplus r.$$

DAG 上的 max-plus 闭包是有限最长路。这是离散事件系统中可以严格使用的线性结构。[[图片：]TU Delft Repository](https://repository.tudelft.nl/file/File_681d1849-7274-4560-a103-aeb57d4d87ee)

**但整个官方评估器不是这样的常系数系统。**DDR 争用会改变服务时间，Q3 查询决定服务池，动态内存状态还可能限制发射。题面明确把实际 COPY 完成时间交给全局共享带宽模拟。

通用神经网络处理器下的多核调度问题 +1

## 5.2 精确端口消元公式

把节点分成保留端口 $B$ 和内部节点 $I$。全部乘法均为 max-plus 乘法，则

$$x_I=A_{II}^{*}(A_{IB}x_B\oplus r_I).$$

代入后得到

$$\boxed{
A'_{BB}
=
A_{BB}\oplus A_{BI}A_{II}^{*}A_{IB}
}$$

以及

$$\boxed{
r'_B=r_B\oplus A_{BI}A_{II}^{*}r_I.
}$$

这是一个 max-plus 的 Schur 补式消元。

它对**所有外部释放时间**成立，不只是对某一条已经观测到的 trace 成立。尤其不能忘记 $r'_B$：内部源节点可以影响出口，仅保存端口到端口路径是不够的。

真正需要保留的端口包括：DDR/CACHE 请求及完成、跨核释放、Task gate、跨区域 Pipe 约束，以及所有尚未完全编码进固定依赖的内存申请、释放和引用副作用。

**如果这样做后几乎每个计算 op 都成了端口，那就停用。**不能先删掉副作用，再宣布得到了很高压缩率。

若有 $b$ 个端口，预处理可通过多次 DAG 最长路做到

$$O\bigl(b(n_I+m_I)\bigr),$$

存储与一次矩阵—向量传递是 $O(b^2)$，矩阵合成是 $O(b^3)$。端口太多时，矩阵填充可能比原稀疏图还贵。

## 5.3 怎样变成窄接口动态规划？

在有窄接口的区域中，生成少量**实际可提交的局部划分、核心归属和子图顺序选项**。每个选项先经官方核内阶段固定语义，再生成端口转移和方案回指。

```
端口选项 DP：
    状态 = 已认证的初始接口状态
    对每个区域：
        对每个状态、每个接口匹配的已编译选项：
            计算端口转移并保存原方案回指
        合并完整相同的状态
        仅在纯 max-plus 条件下做分量支配删除
    还原公开 JSON
    整体官方验证，E0 确认
```

# 七、能安全减少昂贵评估次数的下界、证书和增量策略

## 7.1 下界必须由实际约束推出

对所有方案都成立的便宜下界至少有

$$LB_{\rm global}
=
\max\left\{
CP_{\rm original,compute},
\quad
\max_r\frac{\sum_{v:\operatorname{pipe}(v)=r}c_v}{K}
\right\}.$$

第一项忽略搬运和同步，只保留必需计算路径；第二项来自同 Pipe 的工作守恒。**两者取最大，不能相加。**

对一个已经准备好的固定方案，可以更强：

$$LB(p)=
\max\left\{
CP(H_p,d^{\min},\delta),
\ 
\max_{k,r}\sum_{v\in(k,r)}d_v^{\min},
\ 
\frac{B_{\rm forced\ DDR}(p)}{60}
\right\}.$$

其中 $d^{\min}$ 是每条操作在允许路径下的乐观时长，Q3 可以乐观地把 eligible COPY_IN 都当作命中；强制 DDR 项只包括必走 DDR 的字节，不能把所有 COPY_IN 都默认 miss。Q1 的 Task start/end gate 与 100/1000 延迟必须显式表示。

证明依据是：**真实执行必须满足每一条完成时间不等式。**不是“我把理想贪心调度器里的时长缩短，所以它一定给出下界”。

若 $LB(p)$ 已不优于 E0 验证的 incumbent，可以剪掉这个候选。但除非下界覆盖全部待选方案，否则不能据此宣布全局最优。

min-cut 代理值、无向谱能量、自由重排下的 pebbling 最优峰值，都不是可直接代入的原问题 Makespan 下界。

## 7.2 有一个可以直接停止扩核搜索的链式特例

限定为：一次输入搬入、线性计算链、一次最终搬出；没有旁路共享，必要缓冲始终适配容量，整图局部展开不产生 spill 或额外等待。

此时所有必要操作已被数据链强制串行。增加跨 Task/核切分不能创造并行，只会增加非负搬运或同步。因此整图单核方案达到该特例的串行下界。

这是**有条件的原问题特例结论**，不是“所有窄图都应该单核”。条件仍要由官方准备/E0 确认。

## 7.3 增量失效范围应从全局事件状态定义

一次局部方案改动可以沿三条路径传播：

$$\text{边界变化}
\to
\text{生成 ID／固定顺序变化},$$

$$\text{请求发起变化}
\to
\text{其他核在飞传输完成时间变化},$$

$$\text{完成次序变化}
\to
\text{FIFO 插入／淘汰变化}
\to
\text{远处未来 miss/hit 变化}.$$

所以不能只重算两个核心。成员材料也明确指出了生成 ID 和全局带宽重算的影响。

$$V(t)=\int_0^t\frac{\mathbf1[n(u)>0]}{n(u)}\,du,
\qquad

每个请求的剩余工作变成 $f_i-V(t)$，共同减量只更新一个 $V$。本轮已验证连续精确算术模型，但没有验证官方整数 retirement 和取整语义。因为活跃集很小，这个改写即使理论正确，也未必值得优先实现。

## 9.2 CPU 基线要足够强

我会以如下 CPU 版本作为真实竞争者，而不是用 Python 字典密集实现当稻草人：

- 原图 CSR、tensor pins、工作量与原 ID 连续存储；共享 immutable 数据。

- 每个候选一个独立 scratch arena，候选间并行，而不是在一个全局事件循环里加锁。

CUDA 官方指南也强调先定位真实热点、计入传输成本，并根据实际并行规模决定是否迁移，而不是“出现矩阵就上 GPU”。[[图片：]NVIDIA Docs](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html)

## 9.5 用盈亏点决定启用，不编造 GPU 加速倍数

成本模型可以写成

$$T_{\rm GPU}(A)=
T_{\rm init}+L_{\rm launch}
+\frac{Q}{\beta_{\rm transfer}}
+\max\left(\frac{F}{P_{\rm GPU}},\frac{M}{\beta_{\rm GPU}}\right)
+T_{\rm sync}+T_{\rm fallback}.$$

若每候选 GPU 计算与搬运成本为 $g$、优化 CPU 成本为 $c$，只有 $c>g$ 时才有大致盈亏点

$$A>
\frac{T_{\rm init}+L_{\rm launch}+T_{\rm sync}}{c-g}.$$

本轮没有这些实测常数，因此不提供伪精确阈值。

例如 $b=32$ 的端口矩阵—向量更新只有约 1024 次 max-plus 更新；单个候选很可能不足以摊销启动。应分别测 batch $1/16/64/256$、冷/热启动和完整流程，不能拿 batch=256 的吞吐替代单例 5–10 分钟收益。

**如果数学压缩把几百个候选降成几个，最终 CPU 更快，这是压缩成功，不是必须补一个 GPU 阶段。**

# 三、目前最强路线：独立分支 × 内部阶段，再进一步压成资源操作词

## 3.1 先区分“数据独立”和“资源独立”

我以 eligible 操作 DAG 的弱连通分量作为独立作业。

这里的“独立”只表示**没有计算数据依赖跨分量**。不同作业仍然可以共享输入，同时争用 DDR 和 L2；所以不能把各作业单独评估的时间相加或取最大，代替全局 E0。

但是，当每个作业整体放在一个核心时，跨核 COPY 同步边可以消失。这使我们能够把重点转向：

> 同一个核心上，多个作业的内部阶段应该怎样交错，才能兼顾共享输入驻留和 M/V 流水重叠？

---

## 3.2 一般构造：时间切块和仿射交错

时间切块有两个低维参数：每波包含多少作业，以及每个作业内部一段包含多少操作。

例如，不再按“作业 0 全做完，再做作业 1”，而是：

```text
这一波所有作业的第一个阶段
这一波所有作业的第二个阶段
……
下一波
```

相同波、相同阶段合成一个子图。每个作业内部的拓扑次序不变，跨作业没有 eligible 依赖，因此商图合法性有直接的单调阶段结构支撑。

另一种更细的构造是给作业 j 中的操作 v 一个**仅用于排序**的坐标：

\[
\theta(j,v)=P_j(v)+j\Delta,
\qquad
P_j(v)=\sum_{\substack{u\text{ 在作业内}\\\text{先于 }v}}\max(1,c_u).
\tag{R2-01}
\]

按这个坐标和原始 ID 排序，编译成公开子图优先级。**坐标随后丢弃，不作为真实时间提交。**

这把大规模排列搜索，缩成了少数阶段宽度、波次大小和相位斜率的选择。最后输出仍然需要覆盖全部操作；减少的是**搜索维度**，不是假装消除了线性大小的 JSON。

### 一个非常清楚的真实收益：case044 的 spill 消失

Q2、4 核，保持核心归属不变：

| 指标 | 整分量分核 | 阶段宽度为 4 的时间切块 |
|---|---:|---:|
| Makespan | 124268 | **68057** |
| 切图新增搬运 | 2791200 B | 2791200 B |
| spill 新增搬运 | 2887424 B | **0 B** |
| 核 0 的 Step3 L1 峰值 | 524192 B | **160000 B** |

这里不仅是“看起来复用更好”：**核心没换，切图新增搬运没变，改变同核阶段组织就消除了官方插入的 spill。**

但无 spill 不等于无 MEMORY_REUSE 边。那些依赖仍在准备产物里，不能删掉。

## 3.3 更强的特例：重入 M/V 资源操作词

实际扫描发现三个整图匹配的同质作业族：

- case008：108 个作业；
- case095：462 个作业；
- case084：1077 个作业。

每个作业的计算 Pipe 结构都是：

\[
M(a)\ \longrightarrow\ V_1,\ldots,V_s
\ \longrightarrow\ M(a),
\qquad
\sum_i c_{V_i}=b.
\tag{R2-02}
\]

这里没有真的合并 V 算子，只把它们视为一个阶段来构造顺序。

case008/095 的两次 M 各为 1158 cycles，V 阶段合计 2196；case084 则分别是 588 和 1152。它们都适合尝试一个很小的前视量：

\[
h=1+\left\lceil\frac ba\right\rceil.
\tag{R2-03}
\]

本轮三个族都得到前视 3 个作业。把作业 i 的首次和末次 M 分别记为 \(F_i,B_i\)，指定：

\[
\begin{aligned}
\mathcal W_M&=(F_0,F_1,F_2,B_0,F_3,B_1,F_4,B_2,\ldots),\\
\mathcal W_V&=(V_0,V_1,V_2,\ldots).
\end{aligned}
\tag{R2-04}
\]

尾部再排完尚未执行的 B。

**直觉是先给 V 阶段提供少量在制品，再交替执行新作业的首次 M 和旧作业的末次 M，避免 M 等待单个作业完成整个 V 阶段。**

实现不是把上述时间线交给理想调度器：程序将原 DAG 加上两个计算 Pipe 词的相邻边，检查无环，求一个拓扑优先级，随后编译为 singleton 子图。真正的运行时间继续由 E0 决定。

### 这个特例可以证明什么？

在**没有 COPY、同步、内存约束**的理想双执行器模型中，对独立、相同的作业，且 V 阶段不长于两个 M 阶段之和，上述词满足：

\[
2am
\le T^*_{\mathrm{ideal}}
\le T_{\mathrm{word,ideal}}
\le 2a(m+1).
\tag{R2-05}
\]

下界来自 M 总工作量。上界可以通过显式安排每隔两个 M 时长启动一个 V 阶段、配置有限启动和收尾段证明；备忘中给出了完整构造，包括一、两个作业的边界情况。

**这个上界不是官方模型上界。**实际 COPY、spill、内存复用和带宽争用都可能使它失效。它的价值是解释为何只需一个很小的前视词，而不是搜索所有作业排列。

|---|---:|---:|---:|

**case008 最有解释力：核心归属、全部搬运分项完全一致，spill 都为零。**每核 M 必需工作量是 62532 cycles，V 是 59292 cycles；从 123060 降到 63768，主要来自计算流水重叠，而不是少搬数据。

对这个已通过 E0 的方案，可以使用真实问题的计算工作量下界：

\[
LB=
\max\left\{
CP_{\mathrm{compute}},
\quad
\max_r\frac{\sum_{v\in r}\max(1,c_v)}K
\right\}.
\tag{R2-06}
\]

因此：

\[
0\le
\frac{T-T^*}{T^*}
\le
\frac{T}{LB}-1.
\tag{R2-07}
\]

case008 的资源词方案距离这个有效下界的相对差距上界为 **1.977%**。这比只报告“比某个弱基线快近一倍”更有说服力，但仍不是最优性证明。

# 四、耦合图不能只靠分支交错：强张量合并＋唯一最细无环闭包

当大部分工作都在一个弱连通分量内，上一条路线缺少可以交错的独立作业。这里真正有用的是一个结构性粗化方法。

先选少数张量大小阈值，把超过阈值的**内部张量**的生产者和消费者设为 must-link，使用并查集合并。然后对粗商图求强连通分量，将每个 SCC 整体合并。

关键不是“用 SCC 修一下环”这么简单，而是有一个准确结论：

> **固定初始 must-link 分区之后，商图 SCC 缩并给出的，是唯一最细的无环粗化。**

证明很短：一个 SCC 内任意两块都相互可达；若它们在最终分区中仍不同，这些路径投影到最终商图上仍构成双向可达的闭合游走，最终商图不可能无环。因此所有合法粗化都必须合并该 SCC；而 SCC condensation 本身就是 DAG。

这个结论提供了两点价值。

首先，合法修复不再是随意局部移动，而是有**最细性证书**的闭包。

其次，阈值降低时 must-link 只会增加，因此闭包形成嵌套粗化层级。当前原型只试四个固定阈值，尚未实现“只枚举层级变化断点”的增量版本；这是下一步可以进一步减少构图与评估次数的地方。

该路线在追加对照中的 case046、case048 上效果很明显，但不是普适解。**case002/Q2 中，简单 topo-64 方案为 78828，而强张量方案最好为 106130。**因此简单拓扑构造必须继续保留，不能为了理论结构整齐而移除。

我重新阅读了 Popp、Schlag、Schulz、Seemaier 的 *Multilevel Acyclic Hypergraph Partitioning*，特别是其无环收缩条件及证明。论文并不支持“同一块内任意收缩都安全”；本轮采用的是上面直接证明的 SCC 最细闭包，并没有声称实现了该论文完整的多层与模因算法。:chatgpt-content-reference{index="7"}

# 五、输入乘积路线的真正修正：先识别输入束，而不是要求每个作业只有两个 tensor

上一轮“每个作业使用两个输入”的模型，对真实数据太窄。

**真实图中，一个作业可能使用几十个输入，但其中许多输入被完全相同的一组作业消费。**先把这些输入的消费支撑合并，才会显露乘积结构。

令 H 的行为独立作业，列为核内计算部分的输入边界张量——通常是原 COPY_IN 的输出；X 是作业到核心的 one-hot 归属：

\[
H_{jt}=\mathbf1[j\text{ 使用 }t],
\qquad
X_{jk}=\mathbf1[j\text{ 位于核心 }k].
\tag{R2-08}
\]

当作业整体分核，Q2/Q3 在尚未插入 spill 的准备阶段，这部分入口 COPY_IN 字节为：

\[
D_{\mathrm{ingress}}(X)
=
\sum_t s_t
\sum_k \mathbf1[(X^\top H)_{kt}>0].
\tag{R2-09}
\]

**相同 H 列支撑可以合成一个加权输入束，对这个静态函数精确。**但不能合并真实 tensor、cache key、访问次数或取整后的服务时间。

这与 Çatalyürek、Aykanat 的超图通信建模中“按数据触达的分区，而非按操作对边数计费”的机制一致；其经典分布式 SpMV 模型还有输入所有者假设，不能把论文中的通信公式原样当成本题全局代价。:chatgpt-content-reference{index="8"}

随后，每个触达两个输入束的作业，在“输入束图”上作为一条边。通过二着色、完整二部连接和支撑闭合检查，识别真正的矩形坐标。

实际发现：

**case011：176 个输入边界张量压成 8 个输入束，显现 4×4 结构。**

**case080：279 个输入边界张量压成 9 束，显现 6×3 结构。**

100 例中，检测到 **14 个 case 含非平凡二维乘积分量，10 个覆盖全部作业**。其余不强行补成矩形。

这条路线目前有实际但有限的收益：case080/Q2 的二维分核方案从 **111314 降到 107030**，约改善 3.85%。然而，case037/Q2 的一个细切矩形方案达到 **96153**，远差于 **53320** 的分量方案。

**所以它值得作为专用构造器，但证据不支持把它作为全体图的主算法。**

## 三个勘误分别有没有造成搜索方向偏置？

### 1. F-EXEC 量词错误

对我已经交付的第二轮原型，**没有发现因此排除候选的证据**。

原因不是“这个错误无所谓”，而是我的搜索器没有把旧 F-EXEC 文句实现成快速合法性 shortcut：最终合法性由冻结 E0 决定；而主要结构构造的 core order 又恰好保持了全局拓扑顺序。第二轮还有一个真正经官方入口产生的 Task-order cycle 失败样本，所以最终研究结论没有把“商图 DAG”误写成“Q1 一定可执行”。

### 2. 24 / 44 加核对照

这个问题对我的路线选择基本没有残留影响，因为我在第一轮输出时已经主动指出它改变工作量，第二轮也没有使用“更多核可能让最优值变差”来剪枝。

更精确的长期口径仍然应该是：

> 固定核数分别优化；不同核数之间只报告各自经 E0 得到的可行方案和题面规定的加速比，不假设最优值关于核预算的单调性。

### 3. F-TASK-006 spill 通则错误

这是对**搜索方向最可能造成潜在偏置**的一项。

第二轮实际代码没有按“每次 spill = 2×size”剪候选，所以已有搜索成绩没有被这个错误规则直接污染。但我之前的定性讨论确实把“缩短生命周期、避免 spill”赋予了较高优先级。对 Q2/Q3，这个优先级有真实 E0 证据支撑；**对现在的 Q1 主线，它需要重新校准**。

所以以后不能把“活得久”直接映射为统一高惩罚。至少要区分：

> 原输入已有 backing；内部结果尚无 backing；曾首次 spill 后已有 backing；当前 incarnation 位于 L1 还是 UB；这是第几次 incarnation。

这个修正**可能重新打开一些我此前会直觉上嫌“spill 太多”而降低优先级的 Q1 分割/顺序方案**。这不等于已经证明那些方案更好，只说明不能凭旧模型先验淘汰它们。

# 当前 Q1 主线应该怎样重新排列已有思想

现在如果只看问题 1，我会把上一轮的结构路线重新解释成下面这样。

**must-link＋SCC 仍值得保留，而且是三条里受勘误最小的。**它解决“哪些节点若强制合并后，怎样得到最细的商图 DAG 闭包”。但它只解决切图层。随后每核 Task 排列还必须满足组合 DAG；最干净的安全构造是让每核 schedule 都成为同一商图拓扑序的子序列。这个约束会牺牲一部分搜索空间，但逻辑上很干净，适合 Q1 初始结构化构造。

**输入束仍值得保留，但目标必须从“减少触达核心数”改成“减少触达 Task 数”。**情况 A 中同一核心的两个子图也没有片上数据继承，题面明确同核不同 Task 一样重建 DDR 边界。:chatgpt-content-reference{index="10"} 因此，对 Q1，输入束最直接的用途是告诉我们“哪些共同消费大输入的操作应该尽量进同一个子图”，而不是仅仅分到同一个核心。

**资源词/阶段编译不应继续当 Q1 的主降维机制。**Q2/Q3 的强结果依赖“同核多个子图最终合成一个 Task，然后通过稳定优先级控制这个 Task 内 M/V FIFO”。Q1 没有这个自由：每个子图就是 Task，Task 间严格串行，还有固定等待和 DDR 状态清空。把一个 M→V→M 作业拆成许多 singleton 子图，可能恰好摧毁原本可在单 Task 内发生的 M/V 并行。

所以，第二轮的 R2-05～R2-07 **作为 Q2/Q3 的理想资源词界仍然成立**，但对 Q1 没有直接算法证书意义。

# 哪些问题值得等中间层形式化完成后再重新深想

本轮我不建议启动第三轮搜索，但有四个问题确实值得在正式中间层出来后重新推理。

第一是 **Q1 的“最小足够状态”到底是什么**。现在已有结构对象只有商图和 Task 顺序，而真实局部代价还取决于 Step1 顺序、backing 状态、incarnation 链、L1/UB 分开容量以及边界 COPY。需要一个比完整 E0 小、又不会把这些状态扔掉的中间表示。

第二是 **Q1 的生命周期边界代价能否分解**。新勘误表明 spill 边际代价具有状态性：首次内部 spill 与已有 backing reload 不同。原来那种“活跃字节越大越坏”的统一代理可能仍然有相关性，但已经不足以做结构剪枝。

第三是 **Q1 Task-order 合法空间能否比“共同拓扑序子序列”更大而仍可廉价参数化**。共同拓扑序是强而安全的充分条件，却可能错过好的交错。F-EXEC 量词修正意味着任何扩大搜索空间的方案都必须真正考虑“依赖边＋每核链边”的联合 DAG。

第四是 **Q1 对 must-link 的收益函数到底该偏通信还是偏局部流水**。合并子图减少 Task 边界、100-cycle 切换与重复 DDR，但也可能把更多操作塞进一个局部 Step1/2/3，产生更坏的 spill/FIFO。新 backing 语义又使 spill 代价不是统一常数。这个地方很适合作为下一轮真正有数学价值的核心问题，但现在还不应在形式化没齐时硬推。

## 本次审计结论

可以把影响分成三层：

**无需撤回：**商图无环相关定理、must-link SCC 的唯一最细无环闭包、第二轮所有真正由冻结 E0 输出的数值、Q2/Q3 资源词的理想界和已运行官方收益、Q2/Q3 输入束静态入口字节公式、logical_tid cache-key 稳定这一事实。

==================================================
0. 基础对象与符号
==================================================

【D00-1：研究环境 / Evaluation Environment】

定义一个冻结研究环境：

E = (G, q, k, C, H)

其中：

G：
一张具体 case JSON 所定义的原始计算图，包括 ops、tensors、edges 以及所有官方语义需要的原始字段。

q：
问题语义，q ∈ {Q1,Q2,Q3}。

k：
核数。

C：
官方配置，包括容量、DDR 带宽、Task wait、cross-core delay、Q3 Cache 参数等所有会影响官方执行语义的配置。

H：
官方 evaluator 的冻结代码身份，例如 commit/hash/源码集合 hash。因为 evaluator 实现版本发生变化时，即使 G,q,k,C 相同，也不能默认是同一个数学映射。

因此后续说“固定环境”时，默认以上五项均固定。

--------------------------------------------------

【D00-2：合法方案空间】

记

P_E

为环境 E 下所有能够通过官方方案合法性检查的提交方案集合。

方案至少由官方允许的：

node_to_subgraph
core_schedules

确定。

这里“合法”只表示属于官方允许的方案输入域。

不要把：

“plan JSON 格式合法”

“Task-order 合法”

“最终执行一定成功”

“性能良好”

混成同一个概念。

如果研究需要，可进一步定义分层合法域：

P_plan
P_task
P_exec

但必须说明具体使用哪一层。

--------------------------------------------------

【D00-3：官方完整行为】

对 P ∈ P_E，官方程序执行后产生的不仅是 Makespan，而是一整条确定性计算过程。

研究中把完整行为记为：

B_E(P).

B_E(P) 可以包含以下层级：

L0：输入方案结构
L1：Task / COPY 构造后的结构
L2：Step1 结果
L3：Step2 spill / backing / incarnation 等结果
L4：Step3 Pipe FIFO / memory dependency 等执行结构
L5：全局事件模拟轨迹
L6：最终 result

并非所有层都必须由现有 CLI 原生输出。

如果某层需要额外 instrumentation 才能观察，必须注明：

“这是对冻结官方语义的只读观测”

而不是修改官方语义。

==================================================
1. 官方映射
==================================================

【D01：Official Mapping / 官方映射】

在固定环境 E 下，定义官方映射：

F_E : P_E → B_E
                                           (CRG-01)

其中：

F_E(P) = 官方程序按冻结语义对 P 产生的完整行为。

因此，“官方映射”不是：

P → Makespan

这么一个标量函数。

Makespan 只是官方映射的一个投影：

M_E(P) = π_M(F_E(P)).
                                           (CRG-02)

其他诸如 spill bytes、COPY、Cache hit、release time、DDR contention 等也都是 F_E(P) 的不同观测投影。

除非特别说明，本项目后续说“研究官方映射”，指研究 F_E 的结构，而不是只拟合 M_E。

==================================================
2. 映射族
==================================================

【D02：Mapping Family / 映射族】

令 Θ 为一组允许变化的研究参数。

定义：

FAMILY(Θ) = { F_E : E ∈ Θ }.
                                           (CRG-03)

Θ 可以包含：

G：图结构轴
q：Q1/Q2/Q3 语义轴
k：核数轴
C：硬件/规则参数轴
H：实现版本轴

研究时必须说明当前映射族允许哪些轴变化、哪些冻结。

例如：

“固定 G,H,C，只改变 q,k”

与

“跨 100 个 G，同时改变 k”

不是同一个映射族实验。

==================================================
3. 行为观测与行为签名
==================================================

【D03：Observation Map / 行为观测映射】

定义一个显式选择的观测映射：

Φ : B_E → Z_1 × Z_2 × ... × Z_m.
                                           (CRG-04)

Φ 决定研究者实际比较哪些官方行为。

例如可以包含：

Task 数与边界
COPY 图
COPY bytes
Step1 sequence
spill victim
backing
incarnation
Step3 FIFO
memory dependencies
关键 release time
DDR busy intervals
Cache hit/miss
Makespan

不同研究问题允许使用不同 Φ。

禁止在没有指定 Φ 时说：

“两个方案行为一样”。

--------------------------------------------------

【D04：Behavior Signature / 行为签名】

定义：

σ_Φ(P) = Φ(F_E(P)).
                                           (CRG-05)

这是方案 P 在指定观测 Φ 下的行为签名。

行为签名可以是：

精确完整对象；
结构哈希；
分层特征；
压缩摘要。

如果使用压缩摘要，必须说明它是否可能发生碰撞或丢失未来行为信息。

==================================================
4. Regime 与 Guard
==================================================

【D05：Guard】

Guard 是官方映射内部或研究抽象中一个明确的离散条件：

g : state → {0,1,...}

其取值改变会导致：

控制流、
结构选择、
依赖关系、
资源处理方式、
或某种离散执行决策

发生变化。

例如：

是否 overflow
选择哪个 spill victim
是否生成某 COPY
某 Cache 请求 hit/miss
某 FIFO 队首是否可发射

都可以形成 guard。

单纯：

“某 Makespan 从 10000 变成 10001”

不是 guard crossing。

--------------------------------------------------

【D06：Regime】

首先选择一个离散决策签名：

ρ(P).

ρ(P) 由研究者明确指定的一组 guard / active-set / ordering decisions 构成。

定义一个 regime 为：

R_r = { P ∈ P_E : ρ(P)=r }.
                                           (CRG-06)

因此 regime 永远是：

“相对于某个 ρ 定义的 regime”。

不存在不说明分辨率的绝对 regime。

一个非常细的 ρ 可能导致每个方案单独成为一个 regime；
一个过粗的 ρ 又可能掩盖真正的切换。

这本身就是需要研究的问题。

--------------------------------------------------

【D07：Guard Boundary / 切换边界】

对于某个 guard g，如果方案空间中的局部编辑使：

g(P) ≠ g(P')

则称该编辑跨越了 g 的 guard boundary。

这里“边界”不要求方案空间具有连续欧氏几何。

它是离散方案图上的切换边界。

==================================================
5. Primitive Operation
==================================================

【D08：Primitive Operation / 底层操作】

Primitive operation 不是任意 heuristic。

定义一个 primitive a 为带类型的部分映射：

a : D_a ⊆ P_E → P_E
                                           (CRG-07)

其中 D_a 是它的适用域。

每个 primitive 必须定义：

1. 操作对象；
2. 前置条件；
3. D_a；
4. 确定性输入参数；
5. 输出方案；
6. 输出合法性条件；
7. 修改了哪些方案字段；
8. 是否有逆操作；
9. 构造成本；
10. provenance。

可能的候选包括：

split
merge
task/subgraph move
core reassignment
within-core insertion
adjacent swap
priority refinement

但这些只是候选，不预设为最终 primitive 集。

--------------------------------------------------

【D09：Cross-environment Operation】

改变环境本身的操作不能直接当作 D08 的同类 primitive。

例如：

k 核 → k+1 核

应记为：

c_k : P_Ek → P_E(k+1)

的跨环境 continuation operator。

后文单独定义。

==================================================
6. 编辑大小 / Operation Distance
==================================================

【D10：Edit Size】

为了定义“局部”和“敏感”，必须先定义编辑大小。

禁止只说“这是一个小改动”。

定义一个明确的编辑度量：

d(P,P')

或操作成本：

c(a;P).

它可以是多维的，例如：

改变的 op 数
改变的 subgraph 数
改变的 Task 数
改变的 core assignment 数
改变的 order relation 数
partition boundary 变化数

推荐保留多维 edit signature：

e(P,P') =
(e_partition,
 e_assignment,
 e_order,
 ...)

而不是一开始强行压成单个标量。

如果需要单标量，权重必须显式给出。

==================================================
7. 离散局部响应 / “离散雅可比”
==================================================

【D11：Local Response / 离散局部响应】

给定：

固定 E，
方案 P，
primitive a，
P ∈ D_a，
行为观测 Φ，

定义：

J_a^Φ(P)
=
Δ_Φ(
    Φ(F_E(P)),
    Φ(F_E(a(P)))
).
                                           (CRG-08)

这里 Δ_Φ 是针对每个观测对象显式定义的差异算子。

不同分量不能默认都做普通减法。

例如：

数值：
difference / ratio

集合：
symmetric difference

序列：
edit distance / changed positions

图：
edge/node delta

事件轨迹：
event alignment / causal diff

因此 J 不是普通连续 Jacobian。

“离散雅可比”只是本项目对：

一组 primitive 对一组行为观测的有限响应结构

的简称。

如果给定 primitive 集 A={a_1,...,a_n}，可以定义：

J_A^Φ(P)
=
{ J_a^Φ(P) : a ∈ A, P∈D_a }.
                                           (CRG-09)

它可以是稀疏表、张量或图，不要求是矩阵。

==================================================
8. 耦合度
==================================================

【D12：Coupling / 耦合】

耦合不允许只做语言判断。

建议至少分为三个量：

A. Layer coupling

设行为观测被分成 L 个机制层，
第 l 层变化度为 r_l。

给定阈值 τ_l，定义：

C_layer
=
[Σ_l w_l · 1(r_l > τ_l)]
/
[Σ_l w_l].
                                           (CRG-10)

B. Object coupling

衡量一次编辑影响到多少远端 Task/op/tensor/event。

例如：

C_object
=
|受显著影响且不在编辑局部邻域内的对象|
/
|可观察对象总数|.
                                           (CRG-11)

C. Propagation distance

在原始依赖图 / Task 图 / execution graph 中，

从直接编辑对象到最远显著响应对象的图距离。

因此推荐使用：

CouplingSignature =
(C_layer, C_object, C_distance, ...)

而不是一开始制造一个任意总分。

如果研究者希望定义其他 coupling metric，可以 amendment，但必须可计算。

==================================================
9. 敏感方向
==================================================

【D13：Sensitive Direction / 敏感方向】

敏感方向不是连续空间的真实向量。

定义一个操作族 A_s 在研究域 S 中是：

(ε,δ,α)-sensitive

当且仅当：

1. 编辑大小满足 c(a;P) ≤ ε；
2. 行为响应大小 R(J_a(P)) ≥ δ；
3. 上述现象在 S 中至少达到指定稳定度 α。

其中：

ε：
“小编辑”的阈值；

δ：
“显著行为变化”的阈值；

α：
稳定性要求，例如实例比例、邻域覆盖率或置信下界。

因此必须区分：

single-witness sensitivity
local sensitivity
cross-graph sensitivity
cross-core sensitivity
cross-q sensitivity

单个极端例子只能成为 sensitive-direction candidate，
不能自动称为稳定敏感方向。

==================================================
10. 行为等价
==================================================

【D14：Immediate Observational Equivalence】

给定 Φ：

P1 ≡_Φ P2

当且仅当：

Φ(F_E(P1)) = Φ(F_E(P2)).
                                           (CRG-12)

这只是“当前观测等价”。

它不保证未来经过编辑后仍然等价。

--------------------------------------------------

【D15：Behavioral Equivalence Relative to Future Operations】

给定：

观测 Φ，
允许未来操作集合 A，

定义：

P1 ~_(Φ,A) P2

要求：

对所有同时合法的有限操作序列

w = a_t ∘ ... ∘ a_1,
a_i ∈ A，

两边具有相同的可执行性结构，并满足：

Φ(F_E(w(P1)))
=
Φ(F_E(w(P2))).
                                           (CRG-13)

如果两边允许的下一步操作集合本身不同，也不能视为强行为等价。

这是一个接近 deterministic bisimulation / Nerode equivalence 的研究定义。

实际计算可能无法验证“所有有限 w”。

因此工程实验可以定义：

H-step behavioral equivalence

只检查长度 ≤ H 的 continuation，

但必须明确标为有限视野近似，不得冒充完整等价。

==================================================
11. 行为商
==================================================

【D16：Behavior Quotient】

给定等价关系 ~_(Φ,A)，定义：

Q_(Φ,A)
=
P_E / ~_(Φ,A).
                                           (CRG-14)

也就是把行为上无法由未来允许操作区分的方案归为同一类。

研究“行为商是否有价值”的关键量不是名字漂亮，而是：

compression ratio

例如：

κ =
|P_sample|
/
|Q_sample|.
                                           (CRG-15)

如果 κ≈1，则在当前观测和操作集下几乎没有压缩价值。

==================================================
12. 最小充分状态
==================================================

【D17：Sufficient State】

给定：

允许未来操作集 A，
未来观测 Φ，

状态映射：

S : P_E → Σ

称为充分状态，当：

S(P1)=S(P2)

足以推出：

P1 ~_(Φ,A) P2.
                                           (CRG-16)

也就是说，知道 S(P) 后，不需要保留完整历史方案，就足以预测所有允许 continuation 的未来可观察行为。

--------------------------------------------------

【D18：Minimal Sufficient State】

相对于固定 (Φ,A)：

最理想的抽象最小状态就是 D15 的行为等价类：

S_min(P)
=
[P]_(~_(Φ,A)).
                                           (CRG-17)

这在抽象意义上总可以定义。

但研究真正关心的是：

它是否存在一个比完整方案/完整执行历史明显更紧凑、可计算的 representation。

因此：

“抽象 quotient 存在”

绝不能被写成：

“我们已经发现了一个有用的最小充分状态”。

有用的 minimal sufficient representation 必须同时考虑：

压缩率、
构造成本、
更新成本、
未来预测能力。

==================================================
13. Local Evaluator Set
==================================================

【D19：Local Evaluator】

一个 local evaluator 不是全局黑盒 surrogate。

定义第 r 个局部评估器：

ĥ_r

附带：

适用域 detector D_r(P,a)
预测目标 T_r
误差/置信度模型 U_r

它可以预测：

ΔMakespan
候选 pair ranking
是否值得进入 E1/E0
某个局部机制量

而不必预测绝对 Makespan。

--------------------------------------------------

【D20：Local Evaluator Set】

定义：

L =
{ (D_r, ĥ_r, U_r) }_r.

必须包含 routing / abstention：

如果：

没有 detector 接受；
多个模型强烈冲突；
不确定性超过阈值；
检测到 guard crossing 风险；

则：

ABSTAIN

并回退到更精确 evaluator。

因此：

局部评估器集的正确性目标

不是“任何地方都给答案”，

而是：

在声明适用域内有高可靠性，
域外可靠拒答。

==================================================
14. 生成完备 / 可达完备
==================================================

【D21：State Graph】

给定 primitive 集 A，

构造有向方案图：

Γ_A = (P_E, E_A)

其中：

P → P'

当且仅当存在 a∈A，

a(P)=P'.

--------------------------------------------------

【D22：Pairwise Reachability Completeness】

如果任意：

P,Q ∈ P_E

都存在 Γ_A 中从 P 到 Q 的有限有向路径，

则称 A 对 P_E：

pairwise reachability complete。

这是很强的要求。

--------------------------------------------------

【D23：Rooted Generative Completeness】

如果存在一个或一组 canonical seeds S0，

使得任意 Q∈P_E 都能从某个 P0∈S0 到达，

则称 A：

root-generatively complete。

它比 D22 弱，但对 solver 可能已经足够。

--------------------------------------------------

【D24：Restricted Completeness】

如果只能覆盖：

P'_E ⊂ P_E，

必须显式写：

“A 对 P'_E 可达完备”。

禁止把受限空间的证明推广成完整官方方案空间。

--------------------------------------------------

注意：

生成完备是“表达能力”的概念。

它和：

实际搜索复杂度

完全不同。

一个生成完备 primitive 集仍然可以在线只探索极少的 macro。

==================================================
15. Macro Operation
==================================================

【D25：Macro Operation / 宏操作】

Macro 不是“把几个 heuristic 打包”。

定义 macro m 至少包括：

m =
(g_G,
 g_R,
 π,
 A_m,
 Ω_m)

其中：

g_G：
图结构适用条件；

g_R：
mapping regime / guard 条件；

π：
内部 primitive policy / composition；

A_m：
允许调用的 primitive；

Ω_m：
预期机制与可观测结果。

它仍然是 partial transformation。

Macro 必须能够回答：

为什么现在适用？
内部执行了什么？
预期改变哪个机制？
如果失败如何 rollback？

==================================================
16. 多核尺度轴
==================================================

【D26：Core-count Axis】

把：

k=1,2,3,4,5

看成映射族中的离散尺度轴。

不是五个互不相关的问题。

记：

E_k = (G,q,k,C,H).

研究目标包括：

方案结构如何随 k 变化；
敏感方向是否跨 k 稳定；
guard 在什么 k 翻转；
峰值机制是否随 k 保持。

--------------------------------------------------

【D27：Core-count Continuation】

定义一个 continuation：

C_k :
P_(E_k)
→
P_(E_(k+1)).
                                           (CRG-18)

它不是单纯重新运行 solver。

它利用已有 k 核方案结构产生 k+1 核初始方案。

一个最简单的 embedding 可以是：

保留原方案并加入空核，

前提是该问题语义和官方合法性允许。

随后再通过：

move
split
reorder
macro

释放新核的并行度。

必须区分：

“可行嵌入”

与

“性能改善”。

==================================================
17. 官方固定单核基准与 Speedup
==================================================

【D28：Official Single-core Baseline】

对于图 G，

官方 singlecore_evaluate.py 产生一个固定基准：

B(G).

其语义是：

所有 eligible 计算 op 合入一个子图 / 一个 Task，
放到 core0，
经过官方单核执行流程。

它不是：

算法能够得到的理论最优单核结果。

--------------------------------------------------

【D29：Official Speedup】

对于 q、k 和方案 P：

Speedup_q,k(G,P)
=
B(G)
/
M_(G,q,k,C,H)(P).
                                           (CRG-19)

因此出现：

Speedup > k

在数学上并不矛盾，

因为 B(G) 不是单核最优值。

多 case 平均 speedup 必须按官方题面规定：

先逐 case 算 speedup，
再做规定的汇总；

不要擅自改成 aggregate-Makespan ratio。

==================================================
18. Peak Witness
==================================================

【D30：Peak Witness / 峰值见证】

“峰值见证”和“峰值机制”必须严格区分。

定义一个峰值见证：

W =
(E, P, R_ref, y)

其中：

E：
具体环境；

P：
具体方案；

R_ref：
明确的参考集合/基线；

y：
观察到的高收益行为。

例如：

某 case，
Q3，
4 核，
resource-word plan，
Makespan=63768，
相对官方单核 baseline speedup>7

可以是一个 peak witness。

但它本身不是机制。

“高”必须相对于显式参考定义，例如：

top-p quantile
relative improvement ≥ δ
speedup ≥ threshold
相对同预算 baseline 的异常高收益

不得看到一个漂亮数字就自行叫峰值。

==================================================
19. Peak Mechanism
==================================================

【D31：Peak Mechanism / 峰值机制】

峰值机制不是某组参数，也不是某个 JSON。

它是一个条件性结构命题。

一个候选峰值机制 M 至少包含：

M =
(S_G,
 S_P,
 S_q,
 S_k,
 S_C,
 S_R,
 O,
 ΔY)

其中：

S_G：
图结构条件集合；

S_P：
方案 / 操作条件；

S_q：
问题语义适用集合；

S_k：
核数适用区间/集合；

S_C：
配置适用域；

S_R：
official-mapping regime 条件；

O：
触发的 primitive / macro；

ΔY：
稳定出现的高收益响应。

也就是说，它表达的是：

当图具有结构 S_G，
系统位于 regime S_R，
满足问题/核数/配置条件时，
执行 O 会通过某个可解释的官方映射变化产生显著收益。

--------------------------------------------------

一个单独的：

case008 + resource_word + k=4

只能支持：

“存在一个 witness”。

要升级成“mechanism”，至少应有：

1. counterfactual 邻居；
2. 可识别的行为变化；
3. 图结构条件；
4. 可证伪迁移预测；
5. 至少某种稳定性证据。

==================================================
20. 图结构特征
==================================================

【D32：Graph Feature】

图结构特征必须定义成：

x_i : G → X_i

的可计算函数。

例如：

DAG width
depth
fan-out distribution
tensor-size distribution
M/V workload ratio
repeated motif count
reuse topology
weak-component structure
critical-output structure

均必须有算法定义。

禁止把：

“这个图很规则”
“这个图很并行”
“这个图像流水线”

直接当 feature。

这些只能是提出 feature 的直觉。

==================================================
21. Structural / Local / Accidental Peak
==================================================

【D33：Structural Peak】

如果候选峰值机制在预先定义的图结构邻域、多个实例、多个核数或一片参数域中保持稳定，并达到指定迁移阈值，则称：

structural peak。

阈值必须预先给出。

--------------------------------------------------

【D34：Parameter-local Peak】

如果机制只在较窄：

k / config / regime

区域中稳定，

但在该区域内可重复，

称：

parameter-local peak。

它仍然可能很有价值。

--------------------------------------------------

【D35：Accidental Peak】

如果轻微改变：

图结构、
操作、
核数、
或局部 regime

就使收益不可重复，而且无法找到有预测力的条件变量，

则暂称：

accidental peak。

注意：

“尚未找到机制”

不等于已经证明是 accidental。

==================================================
22. Peak-to-Mechanism Distillation
==================================================

【D36：Peak-to-Mechanism Distillation】

定义研究流程：

Peak Witness
→ Counterfactual Neighborhood
→ Layer-wise Behavior Diff
→ Candidate Cause / Guard
→ Graph Structural Condition
→ Mechanism Hypothesis
→ Cross-instance / Cross-k / Cross-q Test
→ Guarded Macro Candidate.

这叫：

Peak-to-Mechanism Distillation。

最终产物不是“最优参数表”，

而是：

可识别条件
+
可执行操作
+
可证伪预测。

==================================================
23. Algorithm Distillation
==================================================

【D37：Research Solver】

Research solver 首要目标允许是：

可观测
可重放
可干预
可归因
可组合

而不一定是最快。

它可以记录：

operation provenance
intermediate signatures
behavior diff
evaluator route
rollback
counterfactuals

--------------------------------------------------

【D38：Algorithm Distillation】

Algorithm distillation 指：

把已经验证的：

primitive
guard
macro
regime detector
routing policy
缓存/索引结构

压缩成竞争版 solver。

它不是简单：

“把代码写快一点”。

一个有效 distillation 必须给出：

质量损失 ΔQ
运行时间变化 ΔT
内存变化 ΔM
失去的可解释能力

并有明确接受阈值。

==================================================
24. “少数敏感方向”假说
==================================================

【D39：Low-dimensional Sensitive Structure Hypothesis】

“官方映射存在少数敏感方向”

目前只是研究假说，不是事实。

它的可证伪版本应类似：

在指定方案邻域和 primitive 集 A 中，

只有较小比例的 operation classes

能够解释大部分显著 Makespan / behavior variance。

可以用例如：

前 r 类 operation 对响应能量/显著事件的解释比例

来测量。

如果需要接近完整 operation basis 才能解释变化，

则“少数敏感方向”假说失败。

## 2. 精确术语表

以下沿用 CRG v1，不另行改义。本轮不提出 Definition Amendment。

首先，“官方映射”研究的是整条确定性行为，而不是只研究最后一个数：

$$P
\xrightarrow{\mathrm{Task/COPY}}L_1
\xrightarrow{\mathrm{Step1}}L_2
\xrightarrow{\mathrm{Step2}}L_3
\xrightarrow{\mathrm{Step3}}L_4
\xrightarrow{\mathrm{global\ events}}L_5
\xrightarrow{\mathrm{result}}L_6 .
\tag{PB-01}$$

| 术语 | 本轮的无歧义含义 |
| --- | --- |
| **固定环境** | 按 D00，固定具体图、问题语义、核数、配置和官方代码身份。另将 Python、运行目录、文件名等作为实验控制条件记录。 |
| **合法方案空间** | 明确使用方案层、Task-order 层还是执行层。JSON 可读、商图无环、执行成功和成绩好是不同判断。 |
| **官方映射** | 冻结环境中，plan 经过式（PB-01）产生的完整行为；Makespan、spill、Cache 等只是不同投影。 |
| **映射族** | 明确允许变化的图、问题、核数、配置、实现版本轴所对应的映射集合。本轮主研究图、问题和核数，少量配置变化只作诊断。 |
| **观测映射／行为签名** | 明确选择哪些行为、如何表示及比较。完整对象、无损哈希、摘要特征不能混称同一种签名。 |
| **guard／regime／切换边界** | guard 是离散条件；regime 是指定决策签名的等值类。固定环境的一次局部编辑翻转 guard，才是 D07 意义的边界跨越；改变核数是跨环境变化。 |
| **primitive operation** | 带类型、确定参数和合法适用域的部分方案变换。一次 split、insert、move 等需要给出完整规格，不因代码短就自动成为 primitive。 |
| **编辑大小** | 保留分区、归属、顺序等多维变化数量。改变一个构造参数，不等于只改变一个次序关系。 |
| **离散雅可比／局部响应** | 在固定环境中，指定 primitive 前后的指定行为差异。数值取差或比，集合取对称差，序列与事件采用各自的对齐方式，不当作连续导数。 |
| **耦合度** | 按 D12 分别计算层覆盖、远端对象比例和传播距离。不能只说“强耦合”，也不能把数据图上不可达当成资源影响为零。 |
| **敏感方向** | 同时满足小编辑阈值、显著响应阈值和指定域稳定度。单个大 macro 的巨大收益不是稳定局部敏感性的证明。 |
| **行为等价／行为商** | 当前观测相同只是 D14；D15 还要求未来允许操作及其所有 continuation 不可区分。商的样本必须先区分真正不同的 plan。 |
| **最小充分状态** | 相对于未来方案编辑及未来观测充分，而不只是让某次仿真继续运行的 checkpoint。抽象等价类存在不等于找到了廉价表示。 |
| **局部评估器集** | 每个评估器有 detector、预测目标和不确定性；域外、冲突或 guard 风险时 ABSTAIN，回到更精确评估。 |
| **生成完备／可达完备** | root-generative、pairwise reachability、restricted completeness 分开。本轮有限候选族没有完整官方空间的完备性声明。 |
| **macro operation** | 图 guard、regime guard、primitive policy、允许操作集、预期可观察机制组成的部分变换，必须有失败回滚。 |
| **多核尺度／continuation** | 核数是映射族的离散轴；利用旧计划构造下一核数方案，不等于冷启动重跑，也不保证性能改善。 |
| **峰值见证** | 具体环境、具体计划、明确参考及高收益观察。是否“高”必须先指定门槛。 |
| **峰值机制** | **图结构 × 方案／操作 × 问题 × 核数 × 配置 × regime** 联合作用的条件性命题，具有可迁移的干预预测。 |
| **Peak-to-Mechanism Distillation** | 见证→反事实→逐层差异→guard／原因→图结构条件→跨实例／核数／问题测试→guarded macro。 |
| **算法蒸馏** | 将验证过的 primitive、guard、macro、路由和索引压成竞争版程序，并报告质量、时间、内存及可解释性损失。 |

本轮尤其保留两个区别：**仿真状态充分，不等于对未来 plan 编辑充分；构造参数去重，不等于不同 plan 的行为商压缩。**

### 3.4 “四核超过 7 倍”应怎样解释

以尚待本轮 singlecore 复跑的基准记录 487605 为条件，算术分解是：

$$\frac{487605}{63768}
=
\frac{487605}{123060}
\frac{123060}{63768}
\approx
3.96234\times1.92981
=
7.64655 .
\tag{PB-02}$$

这说明高比值包含“固定基准→普通四核方案”和“普通方案→结构顺序方案”两段改善。**它不是 Cache 带来的 7.65 倍，也不能把第一因子未经控制就全部归为纯核数收益。**

更有意思的是：

$$123060-63768
=
59292
=
27\times2196 .
\tag{PB-03}$$

运行记录中，case008 是 108 个计算时长模板相同的作业，四核每核 27 个，单作业中间 V 阶段总工作为 2196。这个精确吻合支持一个很强的候选解释：**资源词把原来暴露出来的 V 等待大部分隐藏到了 M 工作后面。**但“吻合”仍然不是全部因果贡献的证明；COPY 相位和 MEMORY_REUSE 的变化尚需完整对照。

## 4. 对峰值机制路线的总体评价

**值得继续，但应收敛到三个机制候选，而不是建立“所有问题都有少数敏感方向”的先验。**

### 4.1 优先级最高：Q2/Q3 的资源重入交错

已有证据支持它成为一个 **macro 来源候选**：固定分区与归属，改变优先级，出现很大的执行改善；Q2/Q3 成绩相同且没有 Cache 命中，排除了“这次收益来自 Cache 命中”的解释。

但当前代码的 graph guard 比“同构重复分支”弱得多。`word_descriptor` 检查的是实际串行计算链、Pipe 模式、首尾 M 工作相同、计算时长 tuple 相同，以及 V 总工作不超过两次 M 工作之和。**它没有证明完整 Op–Tensor 图同构，没有检查所有输入共享、tensor size/pos 和生命周期都相同。**

因此，待验证的机制应写成：

> 当图含重复的 M→V*→M 计算链，完整输入／内存结构落在已验证风险域内，且处于 Q2/Q3 的单核合并 Task 语义时，通过合法优先级编译形成有限前视的资源词，减少 M 队首等待 V 的时间，从而获得稳定收益。

不能写成“识别到 M→V→M 就必快”。

### 4.2 Q1 最值得保留：晚输入门控前缀分离

case051 的解释比许多更大的百分比更有价值，因为它已经把差异定位到了明确的门控与关键路径位置。

仓库记录中，旧 Task8 在 13007 开始；拆分后的前半可以在 6482 开始、9674 结束，后半仍等到 13007。旧关键节点持续 2722 cycles，新后半只有 81；其余 119 个关键路径节点持续时间不变，差额恰好是 2641。**这是一条 trace 上的精确时间账目，不是“所有 Task 工期固定”的预测模型。**

同时，前瞻实验已经给出负结果：003、008、044 三个新池中的六个待排序 split，其入口提前量全部为零，没有重排和新增收益。

这改变了下一项任务的目标：

**不是继续调整“入口提前量”的权重，而是检验候选生成器能否直接找到真正脱离晚输入门控的切点。**

### 4.3 Q3 独立候选：共享输入的 FIFO 准入相位

case080 的同计划 Q2/Q3 排名翻转，是一个明确的场景交互见证线索：affine 增加了 spill，Q2 变差，Q3 却改善。它足以要求我们保留这类候选，不能按 Q2 排名或零 spill 硬筛掉。

真正需要提炼的是：

> 共享 support 结构，在某个由完成次序、准入、淘汰和两带宽池活跃集合定义的 regime 下，怎样通过合法顺序操作改善关键 COPY 的服务路径？

“命中率更高”只能是观测，不是充分机制。case044 已经提供相反方向的对照：命中率下降，但 Makespan 改善。

### 4.4 三类峰值的操作性分类

建议下一次试验预先采用以下规则，而不是事后给 winner 起名字：

| 分类 | 建议的操作标准 |
| --- | --- |
| **Structural peak** | 在预定义 graph guard 下，至少 3 个非简单复制的匹配实例、至少 3 种核数；至少 80% 的正域单元达到事先规定的收益门槛，并报告覆盖率、成本及最差回归 |
| **Parameter-local peak** | 在预先列出的较窄核数／配置／regime 单元内达到上述重复性，但跨出该域后稳定失效；边界能被 detector 预测 |
| **Accidental peak** | 小扰动下收益反复消失，预注册条件无预测力，而且有限修正预算内仍无法归纳；只暂称“该测试域内偶然” |
| **尚未分类** | 缺少反事实或迁移证据；不能因尚未找到解释就归为 accidental |

资源词的 prospective 高收益门槛可先设为**相对同核普通方案改善至少 10%**；Q1 单次局部操作可设为**至少 0.5% 且至少 1000 cycles**。这些是研究阈值建议，不是宣称当前材料已经通过。

**第二，小 primitive 邻域没有显著响应，不一定推翻一个需要协同编辑的 macro。**它会否定相应的小编辑敏感性主张，但可能留下“较大、结构化组合操作有效”的结论。不能把 coherent 框架中的某一条箭头强行保住。

## 6. 图结构候选特征体系

**纯图特征必须只由 G 决定。**依赖当前 plan、容量或 trace 的量，应单独标为环境／方案条件化特征。

| 特征家族 | 可计算定义 | 检验方式与风险 |
| --- | --- | --- |
| **DAG depth / width** | 语义 COPY 收缩后的最长依赖路径；小图用传递闭包与匹配求偏序宽度 | 大图可先报固定 Kahn 顺序的最大前沿作为下界／代理，不能叫精确 width；最大层大小也不自动等于 width |
| **弱连通分量** | eligible DAG 无向化后的分量数、大小分布、最大分量工作占比 | 区分可整体分核的作业与大耦合图；分量之间仍可争用 DDR、共享输入 |
| **M/V 工作分布** | 分 Pipe 累加有效计算周期；分量内分别统计，不只用全图比率 | 构造“总比率相同但内部顺序不同”的负对照，检验比率是否真的有预测力 |
| **资源重入** | 对真正串行分量提取压缩 Pipe 词、首尾 M 与中间 V 阶段工作 | 将 M→V→M 与 M→M→V 等同工作量图比较；不要只匹配字符串而忽略真实依赖 |
| **重复分支** | 对有界大小的 Op–Tensor 子图比较带属性结构、端口、size/pos；哈希只用于预分桶 | 当前构造仅检查计算时长模板，尚未证明完整同构；大组件无法在预算内核实时标 unknown |
| **shared tensor support** | 每个输入 tensor 的消费 job 集合；相同集合合成统计意义的输入束 | 只能压缩统计，不能合并真实 tensor、Cache key、请求次数或整数取整 |
| **fan-in / fan-out** | Op 度数与 tensor 消费者数分别统计，并保留字节加权分布 | 度数相同但源端逐目标 COPY_OUT 不同、关键消费者不同，可能有完全不同结果 |
| **size / pos 分布** | L1、UB、DDR 分别统计大小分位数、总量及单操作输入输出并集 | 一旦除以容量就依赖 C，不再是纯 G 特征 |
| **critical outputs** | 计算依赖图中到各出口的最长尾工作、出口覆盖结构 | 这是 data-only criticality，不是官方资源关键路径；后者必须从执行观测取得 |
| **Task-boundary potential** | 对事先固定、与分数无关的规范拓扑切线，计算跨界 tensor 并集曲线 | 可作为纯图候选特征；实际边界量必须结合 P，Q1 按 Task、Q2/Q3 按 core 区分 |
| **memory pressure** | 固定规范拓扑序上的首次／末次 touch 闭区间前沿，按 pos 分开 | 不是实际驻留峰值，更不是容量证书；真实 Step1/2、backing 和 incarnation 另行观测 |
| **product / grid** | 将触达两个输入束的 job 当边，做二着色、完整二部连接、重边和 support 闭合检查 | 不把识别问题变成昂贵的最大 biclique 搜索；未匹配就退出该构造域 |
| **reuse topology 与 ID** | support 重叠、规范次序下的重用间隔、同深度／同类型并列中的原 ID 次序 | 图同构不保证固定 ID 启发式相同；重编号是新的 G，不是免费等价归一化 |

对于 case008，目前报告给出的“108 分量、864 eligible ops、统一计算时长模板”与构造代码一致，但**本轮没有读取完整 G 后独立验证这些结构计数**。对于其他特征，我没有把“看起来合理”写成“已经有效”。

下一步应先做**零 E0 的只读结构扫描**，再冻结正例、反匹配例和变量选择。即使扫描全部 100 个 G，也不等于授权跑 100 个 solver；这两种成本与实验身份必须分开。

## 7. 多核／Q1–Q3 映射族研究设计

### 7.1 先按“最早可能失效的层”分解参数轴

这是目前比笼统宣称“映射低维”更可执行的结构。

| 变化 | 通过合法性检查后，最早可能改变的计算层 | 可复用什么／不能复用什么 |
| --- | --- | --- |
| **Q1 固定分区，仅改变分核、核序或 Task wait** | 局部计算结构可保持；核心元数据、联合环和 L5 改变 | 可以研究复用官方局部编译；不能只回放两个核，更不能复用旧 Makespan |
| **同 plan 从 Q2 到 Q3，其他共有参数固定** | Task/COPY、Step1–3 使用相同构造路径；差异进入 Cache 全局事件 | 可以配对比较共同准备产物；不能把 Q2 分数直接当 Q3 排名 |
| **只改变 Q3 L2 容量／带宽** | L5 的准入、命中、两池事件 | 不应重新发明局部调度；也不能按 hit rate 线性缩放时间 |
| **改变 L1／UB 容量** | L3 spill 和 L4 内存依赖即可变化 | 必须重新检查 backing、物理化身和 MEMORY_REUSE |
| **改变 DDR 带宽** | COPY 参考工作量、局部排布／内存依赖及全局事件均可能变化 | 不能把原 Makespan 按带宽倒数缩放 |
| **改变分区或 B 场景优先级** | L1 边界／COPY 所属，或 L2 优先序 | 后续 spill、FIFO、MEMORY_REUSE、Cache 都可能失效 |

上述差别直接来自两个 Task builder、Step2/3 和全局模拟。

尤其不能把 Q1 的固定分区编译缓存直接用于 Q2 的 resource-word 顺序搜索：**Q2 优先级本身会改变 Step2/3。**

### 7.2 核数 continuation：先证明嵌入，再测改善

对冻结源码，在保留全部旧 ID、有序 mapping、旧核次序和配置的条件下，只在末尾追加一个空核，不新增请求，也不改变原有 active request 集合。对成功执行的计划，可得到指标投影上的条件性结论：

$$M_{E_{k+1}}\!\left(\iota_k(P)\right)=M_{E_k}(P).
\tag{PB-04}$$

这里的等式**不是完整结果等价**：核数、空核条目等元数据不同。它也不是“使用新核会更快”。官方共享带宽按在飞请求而非核预算等分，是这个嵌入结论的重要原因。

如果该嵌入在所声明成功域内成立，扩大可用核预算的可行域最优值就不会因为“多了一个可空置核心”而恶化；**有限预算求解器实际找到的值仍可能非单调**。两者不能再混淆。

建议每个核数同时保留三种对象：

**冷构造；旧方案追加空核；从旧结构出发的一次 guarded continuation。**

报告从一核开始的整条轨迹成本，以及“已给定父计划”条件下的边际成本。不能把前一核数的搜索当作免费预计算。

对于报告中的 108 个同质作业，若限制整 job 不拆分，均衡分核的 M 工作尺度为：

$$L_{\mathrm{whole\text{-}job}}(k)
=
2a\left\lceil\frac{108}{k}\right\rceil,
\qquad a=1158.
\tag{PB-05}$$

| k | 受限整-job 族的 M 工作尺度 |
| --- | --- |
| 1 | 250128 |
| 2 | 125064 |
| 3 | 83376 |
| 4 | 62532 |
| 5 | 50952 |

**这些不是本轮实测 Makespan，也不是不加条件的原问题最优值。**它们只是判断启动／收尾、带宽和内存代价何时开始主导的参照。

### 7.3 Q1、Q2、Q3 必须保存“同 plan 跨环境”与“各环境自己优化”两张表

同 plan 跨 q 比较，用于识别 Task barrier、复制同步和 Cache 的机制差别；各 q 自己构造的最好方案，用于实际性能比较。混在一起会把“换了语义”和“换了算法”两种干预混淆。

Q1 尤其不能把 singleton 看成零成本优先级标签：每个子图是独立 Task，同核也重新通过 DDR 交接，还有 Task 等待。Q2/Q3 才是在同一个核 Task 内利用子图顺序组织资源词。

依 CRG D29，Q3 仍记录固定单核基准比；另外保存**同 plan、同核数的 Q2/Q3 比值**作为无 Cache／有 Cache 对照。两者名称、分子分母和用途都不互换。

### 7.4 合适的数学语言

我建议使用：

> **带 guard 的参数化编译—离散事件系统，以及相对于指定决策签名的有限行为相图。**

其中可分两个签名：

**编译签名**记录 Task/COPY、Step1 序、spill victim、backing 来源、incarnation 链、Pipe FIFO、MEMORY_REUSE；**事件签名**记录关键 release 的决定者、退休／发射并列顺序、资源池 active set、Cache hit/miss 与准入／淘汰。

这比直接称为“光滑分层空间”或“分段线性映射”稳妥。官方包含整数取整、binary64 计算、固定并列顺序和数据结构状态，不能不加条件地套上连续几何。

**speedup curve 只能提出 regime transition 候选。**同一 Makespan 可以对应不同签名；非关键分支跨 guard，也可能不改变 Makespan。

### 7.5 与其余 coherent 对象的接口

峰值见证首先向 Pro A 提供完整父子计划和指定观测，用于形成真正的局部响应表；再测层耦合、远端影响和稳定敏感性。对新生成 ID，应同时保留原 ID 和生成 provenance，不能靠重新编号把差异抹掉。

行为商不是必经关卡。若观测包含完整 L0 plan，不同计划已经被输入层区分，不能期待非平凡压缩；若换一个不含全部输入标签的观测，则必须重新检查未来操作可执行性。**不能为了得到高压缩率而偷偷删掉会影响未来行为的信息。**

局部评估器也不是必需品。Q1 exact batch/native 交接已经显示复用收益强烈依赖候选数量：原生路线报告在大批固定划分候选中很快，但只有三个候选时可能更慢。不能将这类批吞吐峰值直接用作单例 macro 的成本假设。

**反证／停止条件：**换核数立即失效且须大改全计划；额外修复和评估抵消收益。**依赖：**PB00，以及对应已固定的 PB01/PB02/PB04 macro。**可并行性：**三条轨迹可并行，单轨迹内部串行。**预计资源：**每轨迹单 CPU worker，宏已齐备时工程量约半天。**成功后解锁：**多核尺度上的 macro 路由与 warm-start 策略。

### PB06-LAG-CELLS：只做值得做的仿射参数压缩

**命题：**完整排序的精确整数区间可以减少重复构造；它既不证明哪个区间最好，也不自动构成不同 plan 的行为商。

**输入／branch／commit：**Q3 `a4e7ee1…` 的 `AFFINE_LAG_EQUIVALENCE.md`、`construct.py`，以及本轮纯整数测试。

固定前缀和局部 job 位置后，相邻操作保持顺序的条件为：

$$(j_u-j_v)\ell
\le
p_v-p_u-\mathbf1[u>v].
\tag{PB-07}$$

全部相邻约束与正整数域相交，得到一个精确区间；不同核独立 lag 时是区间的笛卡尔积，不能默认为一个标量扫描。当前线上代码仍是固定 `affine_eighth`，并没有因为这个证明自动获得提速。

**允许修改范围：**独立研究参数接口与 `PB06-LAG-CELLS` 目录。**禁止修改范围：**F0，不改写旧固定 1/8 算法身份。

**实验协议：**检查区间内部和两侧边界的完整有序 plan 字节。强基线采用“参数扫描＋plan hash 去重”，两方法都不重复评价相同 plan。最多 12 个新 distinct plan 做 Q2/Q3 配对，即 **24 次 E0**。

**输出：**精确区间、构造去重率、跨边界编辑大小、同时翻转多个比较的反例和总成本。

**验收指标：**区间字节一致性零差异；至少减少一半重复构造或产生净时间收益；相同 distinct-plan 集合的最好值不损失。

**反证／停止条件：**参数几乎每变一次就换 plan；区间计算更贵；多核组合爆炸。**依赖：**PB00 的原图与身份。**可并行性：**与 PB01–PB04 独立，结果可供 PB05 使用。**预计资源：**CPU 单 worker，约半天。**成功后解锁：**参数层去重和 guard 边界见证，而不是虚假的评估吞吐或行为商成绩。

---

**最终取舍：先补齐 PB00，再优先并行验证 PB01、PB02、PB04。**PB03 是当前 Q1 生命周期风险模型的重要支撑；PB05 应消费已经固定的 macro，而不是边迁移边重新调参；PB06 只有在确实要扩展仿射参数族时才值得接入。

目前最值得追求的成果不是“找到一个 7 倍参数”，而是：**说明哪类图、哪种官方语义、哪些核数与状态条件下，一个明确的合法操作会改变哪些行为，并能在没看结果之前预测它值得尝试。**
