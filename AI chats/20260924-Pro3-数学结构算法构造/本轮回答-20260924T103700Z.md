# 3. 推荐的数学对象

## 3.1 更像“带守卫的部分变换系统”，不是一个群或环

推荐整体对象是：

> **Typed guarded partial transformation system：带类型、前后条件、合法性层级和操作见证的部分变换系统。**

方案是状态，具体编辑是箭头，编辑序列是路径。合法组合具有结合性和恒等操作，但**不要求所有操作都有逆**。

它和其他对象的关系可以这样划分：

| 数学对象 | 在本方案中的位置 |
| --- | --- |
| 部分变换系统 | 整体操作语义 |
| category-like composition | 组织可组合的编辑路径 |
| rewrite system | 简化已经证明等价的编辑程序 |
| graph grammar | 实现分裂、合并及局部结构更新 |
| groupoid-like 层 | 只适用于带完整 receipt 的具体可逆编辑记录 |
| 群／环 | 没有必要，也没有自然的全局结构支持 |

例如，**JOIN 在裸方案上是多对一的**：合并后通常无法知道原来如何分成两个块。因此不能因为工程上保存了 undo，就声称 JOIN 本身可逆。

Rollback 也只是恢复研究方案与相关缓存状态，**不是逆转官方模拟事件，更不是删除已有实验记录**。

## 3.2 必须同时保留合法性的不同层级

我建议明确维护：

- `P_plan`：字段、覆盖、商图以及官方方案层顺序检查通过；

- `P_task`：Q1 中加入全部核内 Task 顺序边后检查通过；

- `P_exec`：按官方语义实际成功完成；

- 一个用于证明的保守结构域 `P_ord`。

定义：

$$\mathcal P^{\mathrm{ord}}_E
=
\left\{
P:
\text{方案字段有效，且商图与全部核内相邻块序边的并图无环}
\right\}.
\tag{PC-301}$$

**对 Q2/Q3，这个并图域只能作为一种保守构造域，不能被说成官方执行合法性的充要条件。** 场景 B 的子图序是影响核内展开的优先级，不能被偷偷替换成 Q1 的整 Task 完成等待。

当前 Q1 `neighborhood.py` 已经正确地把自己的结论限制在 Task-order 合法性，并明确要求后续 E0/E1 判断执行与代价。

## 3.3 对上轮一句话作进一步收紧

我上轮审计曾把“Task 入口可能继承的 DDR backing”列为 Q1 摘要研究方向。**这不能理解成情况 A 存在一个供选手控制、跨 Task 任意继承的 backing 状态。**

# 4. 最小 primitive set 候选

## 4.1 推荐“三种语义编辑＋一种表示编辑”

推荐的底层模式是：

**CUT、JOIN、SPLICE、RECODE。**

其中：

- CUT/JOIN 改 partition；

- SPLICE 同时覆盖 core assignment 与 core order；

- RECODE 专门处理子图标签和 mapping 条目顺序这种可能影响官方编译的表示差异。

**不另设 Task move、adjacent swap、priority refinement、granularity refinement 为独立底层生成元。** 它们可以由这四类模式表达。

每个确定参数实例都是部分映射：

$$a_\theta:
D^\ell_{a,\theta}
\subseteq \mathcal P^\ell_E
\longrightarrow
\mathcal P^\ell_E,
\qquad
\ell\in\{\mathrm{plan},\mathrm{ord},\mathrm{exec}\}.
\tag{PC-302}$$

这里的合法层级不能省略。一次输出只有结构证书时，不能贴上 `exec-certified`。

## 4.2 四个 primitive 的契约

| Primitive | Domain、参数与前置条件 | 输出与合法性 | 受影响对象 | 逆操作 |
| --- | --- | --- | --- | --- |
| **CUT** | 当前块 B；非空真子集 I；显式 fresh 子图号。I 是块内依赖偏序的理想集，即不遗漏其块内前驱。 | 把 B 替换为 I、其补集；同核相邻；更新 mapping。检查所声明层级的合法性。 | partition、Task/COPY、后续全部编译与事件均可能变化。 | 用 JOIN 恢复，但保留原标签、成员和键序 receipt。 |
| **JOIN** | 同核相邻块 A、B；收缩后仍在所声明合法域。 | 合并成员，保留指定标签，删除一个核序项。不能只因“相邻”就认为安全。 | 边界、门控、spill、FIFO、内存依赖及全局资源。 | 裸操作无唯一逆；receipt 提供原成员划分后才能 CUT 回去。 |
| **SPLICE** | 当前块 B、目标 core、**先移除 B 后**的目标 gap。参数必须确定。 | 删除再插入。相同 core 是重排；不同 core 是重新归属。mapping 不变。 | Q1 常保持局部编译不变；Q2/Q3 可能改变核心 Task 内容与跨核 COPY，影响可传播到其他核。 | 记录旧 core/gap 后可逆。 |
| **RECODE** | 子图标签的单射重编码，以及 mapping 条目排列。**不能修改原图 op/tensor ID。** | 同步更新 mapping 与 core_schedules 中的标签，或改变 mapping 迭代顺序。重新校验。 | 抽象分区可能不变，但官方生成 ID、排序和输出可能变化。 | 单射逆与条目排列逆。 |

所有操作共享以下 provenance：

```
environment identity
parent plan hash
operation/schema version
deterministic parameters
semantic read/write sets
guard results
declared legality level
inverse patch / receipt
constructor or mechanism source
random seed and draw index, when applicable
```

新子图号不能在每次 replay 时临时重新选一个“看起来可用”的值，否则可能无法恢复字面行为。

## 4.3 “最小集”不是文字游戏

必须区分两个意思：

**有限操作模式**：上面的四种模式，参数可变。

**有限具体部分映射集合**：把所有参数实例全部展开后仍然有限。

官方子图标签可以取任意非负整数，因此不限制标签时，四种模式的全部实例并不是字面有限集合。若要严格得到有限集合，可以将研究域限制为标准十进制 op 键、子图标签取零至非 COPY 算子数减一，再展开所有合法参数。

这个受限域覆盖所有**抽象 partition／assignment／order**，但不覆盖官方允许的全部字面编码；也**不宣称换成标准编码会保持官方行为**。

至于把全部修改塞进一个 `REPLACE_PLAN`，虽然只需一个“生成元”，却不能解释局部响应、相互作用或机制，不值得采用。

## 4.4 构造成本与检查成本分开

给定已经建立的 COPY 收缩依赖图，CUT 的理想检查线性于块内点边数；JOIN、SPLICE 可以利用商图索引；RECODE 和完整方案序列化线性于方案大小。

但这不包括昂贵的下游工作。顺序执行基线应记录：

$$T_{\mathrm{edit}}
=
T_{\mathrm{construct}}
+
T_{\mathrm{legality}}
+
T_{\mathrm{compile}}
+
T_{\mathrm{simulate}}
+
T_{\mathrm{route}}
+
T_{\mathrm{record}}.
\tag{PC-303}$$

这些项必须是不重叠的计时区间；并行时另测外层墙钟，不能把 worker 时间之和冒充实际延迟。

# 5. 生成完备／可达完备分析

## 5.1 可以证明一个有用、非平凡的受限完备性

**命题 C1〔FORMAL〕：在固定有限依赖 DAG、固定至少一个核的结构域 `P_ord` 内，忽略字面编码时，CUT/JOIN/SPLICE 是任意对可达完备的；需要匹配具体标签和键序时加入 RECODE。**

证明是构造性的。

**第一步，把起点方案细化成 singleton。**

每个块内部选拓扑词，依次 CUT 理想前缀。原商图无环，不能离开一个原块后又返回；块内部又沿拓扑词细化，因此中间结构仍合法。

**第二步，把所有 singleton 汇集到 core0。**

取当前扩展结构的一个全局线性扩展。按该序扫描，将节点 SPLICE 到 core0 的已整理前缀之后。各核的剩余序列一直是这个全局序的子序列，不会制造环。

**第三步，把 core0 的词改成目标拓扑词。**

目标方案的块图拓扑序，加上每块内部拓扑词，给出目标词。依次把目标下一个节点向左 SPLICE 到匹配前缀后。被它跨过的节点必须与它不可比，否则两个词不可能同时是合法线性扩展。

**第四步，按目标方案重新分核。**

保持目标词的相对次序，把 singleton 分配到目标核。

**第五步，JOIN 成目标 partition，再恢复目标编码。**

每个中间状态都是目标无环块图的拓扑细化，因此仍合法。

如果非 COPY 算子数为 n，起终点块数分别为 mP、mQ，则可以给出线性编辑长度上界：

$$L_{\mathrm{path}}
\le
(n-m_P)+n+n+n+(n-m_Q)+2
\le 5n+2.
\tag{PC-304}$$

**这里线性的是编辑次数，不是完整运行时间。** 每次复制整份 plan 仍可能产生二次数据量；实现应存稀疏 patch 或持久序列。

这个证明也给出了 rooted generative completeness：选一个固定拓扑词、singleton、全部放在 core0，作为 canonical seed 即可。

## 5.2 这不等于执行成功域完备

不能把上述证明推广到整个 `P_exec`。

结构合法路径上可能出现：

- Step2 无法找到合法 victim；

- 新边界改变 L1/UB 压力；

- Step3 产生不同的内存依赖；

- Q2/Q3 的跨核 COPY 与 FIFO 联合阻塞；

- 官方迭代限制或其他运行错误。

本轮**既没有证明整个执行成功域连通，也没有证明它不连通**。

研究版应允许在结构合法域中构造、组合操作，并把最终候选交给相应精确验证；中间节点若没有实际执行成功证据，就保持 `exec=unknown`。

如果以后采用“同时修改多个字段、只验证最终状态”的原子事务，必须注明：它可能不是由所选执行成功域中的 primitive 路径实现。不能借此偷渡完备性。

## 5.3 缺生成元的反例很明确

在本报告的操作定义下：

| 删除的操作 | 无法保证到达的状态 |
| --- | --- |
| CUT | 更细 partition |
| JOIN | 更粗 partition |
| 跨核 SPLICE | 不同核心归属 |
| 核内 SPLICE | 不同核序 |
| RECODE | 另一种子图标签或 mapping 条目编码；单节点图已经可能暴露缺口 |

这说明了表示能力的来源，却不要求在线按这些证明路径进行搜索。**实际求解应该沿少数有机制支持的 macro，而不是先退回 singleton 再重新构造。**

# 6. Operation interaction／commutation／inverse

## 6.1 Legal insertion interval 是一个值得直接复用的结构证书

固定 partition。移除待移动块 B 的核序关联，连接原核剩余相邻块；保留数据依赖。在这个图中计算 B 的祖先集合和后继集合。

设目标核移除 B 后的序列为 v。合法插入槽位恰好是：

$$\ell
=
1+\max\{i:v_i\text{ 是 B 的祖先}\},
\qquad
u
=
\min\{i:v_i\text{ 是 B 的后继}\},
\qquad
j\in[\ell,u].
\tag{PC-305}$$

没有祖先位置时取负一，没有后继位置时取序列长度。

理由是：新环必须经过 B。插得过早会把 B 放到某个祖先之前；插得过晚会把 B 放到某个后继之后。反之，处于这个区间不会形成这种环。

当前 Q1 实现已经使用这一机制，并缓存同一 incumbent 下每个 Task 的祖先／后继关系。**缓存必须在 parent 改变后失效或更新。**

## 6.2 方案级交换，不等于响应可加

方案级交换要求两个组合都合法，且最终字面方案相同：

$$b(a(P))=a(b(P)).
\tag{PC-306}$$

足够的工程条件不仅包括写集合不相交，还包括：

- 对方不改变本操作读取的结构和 guard；

- gap 地址仍有同样含义；

- fresh ID 分配不冲突；

- 两条路径的最终 mapping 顺序也相同。

**“操作不同核”不是充分条件。**

即使式 PC-306 成立，单步 Makespan 响应也可能存在强交互：

$$I_{a,b}^{M}(P)
=
M(b(a(P)))
-
M(a(P))
-
M(b(P))
+
M(P).
\tag{PC-307}$$

四个方案必须来自同一环境与同一 parent。不合法项记为未定义，不能补成零。

这提供一个很实用的四臂实验：原方案、仅 a、仅 b、a 后 b。共享 DDR、FIFO Cache 或关键路径切换可能使交互项很大。若两种组合不交换，则该式是**有序交互**，不能称为对称 Hessian。

## 6.3 编辑大小必须避免“低参数＝小编辑”的混淆

建议使用：

$$e(P,P')
=
\left(
|\Pi(P)\triangle\Pi(P')|,
\#\{v:\operatorname{core}_P(v)\ne\operatorname{core}_{P'}(v)\},
|O(P)\triangle O(P')|,
e_{\mathrm{repr}}
\right).
\tag{PC-308}$$

其中：

- Π 是同块 op 无序对集合；

- O 是同核、不同块、由提交核序确定的有序 op 对；

- 表示分量记录子图标签和 mapping 条目顺序变化。

**resource-word 和 affine 只有少数参数，却可能改变大量顺序关系。** 它们可以是低参数的强构造，但未经编辑大小检验，不能称为 D13 的“小编辑敏感方向”。

耦合则按 CRG 分开报告。建议初版对离散结构采用零差异阈值，层权重相同；时间变化另外报告绝对 cycles 和相对变化。局部邻域预先固定为直接编辑块及原图一跳邻域。资源作用到原图不连通分量时，依赖距离应报告“不可达／无穷”，不能为得到一个小距离而临时换图。

## 6.4 最重要的修订：W 不自动构成 D15 行为商

**同一个当前编译结果，可以支持评分缓存；不代表两个方案可以永久合并为一个搜索状态。**

例如，粗方案和细方案通过 W 检查，具有相同的操作性事件签名，但：

- 细方案具有某个相邻 JOIN；

- 粗方案没有该 JOIN；

- 或者只有粗方案满足某个 CUT 参数的适用条件。

下一步启用操作集合已经不同，按 D15 就不能归为强行为等价。

$$P\equiv_\Phi Q
\quad\centernot\Longrightarrow\quad
P\sim_{(\Phi,\mathcal A)}Q.
\tag{PC-309}$$

因此必须建立两个不同的数据结构：

| 数据结构 | 可以按什么复用 | 不能做什么 |
| --- | --- | --- |
| **Score cache** | 已证明的当前编译／操作性评分签名 | 不能自动删除 future capabilities 不同的代表 |
| **Search frontier** | 完整方案、可用编辑及研究 provenance | 不能只用 Makespan 或 W key 表示搜索状态 |

真正的 quotient search 需要额外证明：等价类内启用操作相同，且操作后的结果仍落在相同类中。验证到 h 步就只叫 h-step。

这意味着：**本轮不应以发现“最小充分状态”为架构前置条件。** 先保留完整 PlanIR；有证据表明某些信息对指定未来操作确实无关，再压缩。

对应来源分别保留了方法、控制条件与限制。

## 7.2 第一批只建议三类 macro candidate

### M-A：Q1 `ReleaseIdealSplit`

**图 guard：** 当前块内部 DAG、外部真实前驱关系明确。

**Regime guard：** release 标签绑定当前 parent，且存在部分工作被另一部分的晚到前驱一并阻塞的现象。

**Primitive policy：** 计算阈值理想或受限 min-cut 理想，执行 CUT；必要时再利用合法区间 SPLICE。

**预期机制：** 减少部分工作承担的整 Task 等待；同时观测新增边界、同核切换、跨核前驱等待、spill 与 DDR 竞争。

这里不是“预测有改进就保证改进”。当前 `release_ideals.py` 已经明确：它是构造 kernel，不继承旧局部调度或 DDR backing；它求解的 cut/work 子问题不等于 Makespan 下界。

### M-BC：Q2/Q3 `ReentrantWord`

**图 guard：** 真正串行且同构的 M—V*—M 作业；两端 M 工作相等；中间 V 总工作满足已声明的理想模型范围。每核作业数必须成为显式特征。

**Regime guard：** 固定 owner、mapping 条目顺序与编号控制；候选经过真实 Step2/Step3 检查。要引用理想模型的性能结论，还必须满足它排除额外资源干扰的条件。

**Primitive policy：** 先生成目标资源词，再降低为 CUT/SPLICE 程序。生成的“最早前缀坐标”只是提交优先级的构造工具，不是硬件启动时刻。

**预期机制：** 减少关键重入 Pipe 的空闲；同步观察 COPY 位置、spill 与 Cache，不能只看 M/V 计算负载。

现有 Q3 constructor 已经包含同构、串行性和工作量守卫，并明确跳过不适用图。它适合成为这个宏的第一份可追溯来源，而不是最终定论。

### M-C：Q3 `SharedInputPhase`〔HYP〕

**图 guard：** 可计算的输入消费超边、tensor 大小、每核访问集合。

**Regime guard：** 有当前 Cache 请求序列及足够可靠的 guard 信息。

**Primitive policy：** 仅改变合法子图优先级和粒度；不提交额外等待、预取或重算。

**预期机制：** 改变同刻 miss、后续命中、FIFO 淘汰和两个带宽池的重叠。pending insert 必须包括在飞 hit 完成后的插入可能性。

这条目前只应保留为宏候选。域不明确或 guard crossing 风险高，就进入精确评价，而不是给出武断的收益判断。

## 7.3 Pro B 到算法侧的交接应是什么

Pro B 发现机制后，算法侧不应只接收“一个赢家 JSON”。

应接收以下可执行契约：

```
graph detector
q / k / C / H applicability
ρ version and regime guard
primitive program / deterministic lowering
Φ response prediction
counterfactuals and known failure cases
rollback and postcondition
evidence level
```

这样才能把“结构 S＋regime R→模式 O”转成一个真正受守卫的部分变换。

# 8. Research solver 架构

## 8.1 同意先优先可研究性，但只做最小系统

我赞成第一版优先：

**可组合＋可观测＋可干预＋可归因。**

但不建议先造完整的通用代数平台。初版结构应当很薄：

```
FrozenEnvironment + PlanIR
              ↓
PrimitiveKernel + Draft + Receipt
              ↓
ConstructorCompiler + GuardedMacroRegistry
              ↓
LegalityCertificates → EvaluatorRouter
              ↓
L0–L6 ObservationStore → TypedDiff / Coupling
              ↓
ConfirmedIncumbent + Frontier + ScoreCache
```

官方方案仍只有两个字段；其余全部是 sidecar，不改变接口。

研究状态至少要区分：

- **当前可提交赢家**：经过所要求的精确确认；

- **探索 frontier**：可能变差但值得研究的合法候选；

- **结构合法、执行未知的中间方案**；

- **正式失败、代理拒答、外部超时**。

若只允许每个 primitive 都改善 Makespan，可能在语言层面就删除了需要先退后进的路径。**单调改进策略是搜索政策，不是操作定义。**

## 8.2 Instrumentation 分三级

| 级别 | 保存内容 |
| --- | --- |
| Tier 0 | 环境／方案哈希、操作 receipt、guard、合法层级、精确指标、路由与成本 |
| Tier 1 | 与本次命题相关的 L1–L6 机制摘要 |
| Tier 2 | 峰值、反例、争议样本与抽样的完整轨迹 |

**未观测必须是 `not_observed`，不能伪装成空集合或零次事件。**

字面 diff 和 provenance 对齐后的机制 diff 要分开。生成 ID 整体平移在字面层是真实变化，但不必意味着所有远端计算机制都改变；反过来，机制对齐也不能成为忽略字面差异、宣称 E1 零差分的借口。

## 8.3 防止无限理论化的阶段门槛

以下是建议研发门槛，不是官方标准：

| 阶段 | 退出条件 |
| --- | --- |
| **S0：操作内核** | 一个有界实现窗口内完成四模式、receipt、合法层级；已有 constructor 能按原控制生成相同 plan。 |
| **S1：观测接口** | 最多48次 E0 的小面板中，打开只读观测不改变对应完整结果；三问及五种核数都有触达。 |
| **S2：机制筛选** | 最多两轮有界实验，得到一个可迁移宏，或一个明确失效域；同时测 guard 与观测开销。 |
| **S3：蒸馏比较** | 同预算质量—时间—内存比较通过才采用；否则删除无收益的 quotient/local-model 模块。 |

即使最后发现**强行为商没有压缩价值，局部模型也不划算**，薄操作 IR、宏构造与精确批评估仍然可能是成功路线。

# 9. Core-count continuation

## 9.1 首个 continuation 是末尾追加空核

$$C_k(P)
=
\left(
\operatorname{mapping}(P),
\operatorname{schedules}(P)\mathbin{+}[[]]
\right).
\tag{PC-310}$$

它改变环境中的核数，**不是固定环境 primitive**。

结构上没有新增块或依赖边，因此可保留原方案组织。执行时间是否保持，还需要对应实现确认：空核不改变非空编译、事件序列和浮点结算。

即便 Makespan 保持，`num_cores` 和空核记录也改变了，**不能复制旧 full result**。

在已经证明保值嵌入的域内，可以推出：

$$M_{E_{k+1}}(C_k(P))=M_{E_k}(P)
\ \text{对域内所有 P 成立}
\quad\Longrightarrow\quad
\inf_{\mathcal P^{exec}_{E_{k+1}}}M
\le
\inf_{\mathcal P^{exec}_{E_k}}M.
\tag{PC-311}$$

这与“某个使用更多非空核的具体分配变慢”完全兼容。

## 9.2 实际 continuation 流程

建议：

**空核嵌入作为保底 → SPLICE 一个有机制依据的块／链／分量 → 必要 CUT → 检查新 regime → 精确确认。**

三问的差别是：

| 问题 | 主要机会 | 必须重新检查 |
| --- | --- | --- |
| Q1 | 移动完整 Task 常可复用固定 partition 的局部编译 | 同核100／跨核1000等待、全局 DDR |
| Q2 | 释放计算并行、调整重入资源词 | 跨核 COPY、固定同步、源核导出顺序、spill |
| Q3 | 同上，并改变共享输入的请求相位 | 同刻 miss、FIFO 淘汰、两池竞争、在飞插入 |

word 宏在核数增大后，每核作业数可能不足以形成原来的流水重叠。因此跨核数复用的是**模式和 guard**，不是原样复制“好参数”。

同时保留一个独立 cold 结构 seed。Warm continuation 若继承了错误的 partition，必须有机会离开，而不是永远围绕旧方案移动。

官方固定单核基准仍独立生成，不能用优化后的单核方案替换。当前源码确实将全部非 COPY 算子放入一个子图、core0，再进入官方情况 A 流程。

# 10. Evaluator routing

## 10.1 首版建议 exact-first，而不是“先训练一个局部模型再说”

| 层 | 路由规则 | 禁止的推断 |
| --- | --- | --- |
| 结构检查 | 字段、覆盖、商图；确定的官方非法可拒绝 | 不支持／超时不能当 invalid |
| Q1 Task-order | 使用精确插入区间或并图校验 | 不把 Q1 条件套成 Q2/Q3 执行充要条件 |
| 局部评估器集 | 每个模型声明 detector、目标、误差；域外、冲突、guard 风险时 ABSTAIN | 精确 boundary bytes 不等于精确 ΔMakespan |
| E2 | 仅在 capability manifest 匹配时用于软排序 | 不当下界；不用 Q2 名次硬删 Q3 |
| Q1 exact batch | 每次校验新方案；固定有序 mapping 复用局部编译 | 不把局部程序缓存称为全局答案缓存 |
| Native replay | 首先 shadow；相应域独立验收后才进入实际选择 | 当前原型不是完整 JSON 或通用三问引擎 |
| E0 | 新域、争议、最终确认、抽样审计 | 内部确认成本不能从 solver 计时中消失 |

当前 exact batch 的关键结构值得直接采用：图和引擎在实例内固定，缓存键包含有序 raw mapping、带宽与容量；每次调用仍校验 Task-order，更新 core/pred 信息并重新全局模拟。**这是编译产物复用，不是 D15 的方案行为商。**

## 10.2 操作空间同时具有“质量结构”和“评价成本结构”

应给每个 primitive 标记它是否跨越编译上下文：

| 编辑 | Q1 中常见情况 | Q2/Q3 中常见情况 |
| --- | --- | --- |
| 固定 partition 的 SPLICE | 局部编译可复用，全局重放 | 同核重排可能改优先级词；跨核移动改变 Task/COPY |
| CUT/JOIN | 通常重新编译；生成 ID 可影响其他 Task | 核归属不变时 raw Task 可能保持，但优先级词可能改变 |
| RECODE | 可能改变生成 ID／遍历 | 可能改变排序与诊断，不默认无影响 |

研究版可以按相同编译上下文批处理，但应预留跨上下文候选的探索配额。否则会出现一种新的偏置：

> 评分便宜的 move 被大量探索，而可能更有价值但需重新编译的 split/merge 被系统性压制。

## 10.3 当前 native 结果不能变成无条件路由承诺

**AUTHOR-REPORT：** native 交接报告在三候选时，计准备成本相对 E1 只有约0.43～1.95倍；64候选高复用批次约33.7倍。它还明确指出，当前接口主要返回密集时刻数组与 Makespan，生产回退、错误域、多平台和长跑仍待工程化。

因此，路由要看**实际复用密度、输出需求、支持域与准备成本**，不能看名字中有没有 native。

本轮没有核验 Q2/Q3 通用 exact batch 的能力声明，所以它们的默认可靠路径仍是 E0，而不是把 Q1 evaluator 的 problem 参数换一下。

# 11. Algorithm distillation 路线

蒸馏的目标不是保留整个平台，而是保留**已经证明有用的结构**。

| 处置 | 对象 |
| --- | --- |
| **编译掉** | 通用操作解释器分派、宏参数解析、已有有效证书覆盖的重复前置检查 |
| **缓存** | 图索引、真实局部编译、经过证明的当前评分对象；全部有界、版本及类型敏感 |
| **内联** | 热路径 CUT/SPLICE、低成本 guard、固定序列更新 |
| **删除** | 无预测力 feature／局部模型、压缩率接近1且昂贵的商、每候选完整 Trace、无收益候选族 |
| **变成 macro** | 通过反事实和迁移检查的操作模式 |
| **变成静态规则** | 确定的适用域和安全变换，而不是未经证明的收益保证 |

蒸馏结果至少报告：

$$\Delta Q
=
\left\{
\frac{M_{\mathrm{dist}}-M_{\mathrm{research}}}
{\max(1,M_{\mathrm{research}})}
\right\},
\quad
\Delta T
=
\{T_{\mathrm{dist}}/T_{\mathrm{research}}\},
\quad
\Delta M
=
\{RSS_{\mathrm{dist}}/RSS_{\mathrm{research}}\}.
\tag{PC-312}$$

解释能力损失另列：少了哪些 Φ 分量、哪些反事实不能直接重放、诊断需要付出多少回退成本。不要把它们强行加成一个总分。

建议采用两步验收：

**第一步，固定候选流。** 两版生成相同候选，检查精确结果与失败分类不变，测掉纯架构开销。

**第二步，同预算搜索。** 允许蒸馏改变候选选择，比较最终 E0-confirmed 质量与全部在线成本。

候选研发门槛可以预注册为：固定候选流零语义差异；相对研究版最终 Makespan 恶化中位数不超过0.5%、最差不超过2%；不能比已确认保底方案更差；端到端几何平均至少1.5倍。**这些只是建议门槛，不是已取得成绩或官方标准。**

现有 Q1 `search.py` 明确把最终 E0／baseline 确认放在其“搜索预算”之外，这是一种如实披露的研究协议；竞争版若把 E0 确认作为内部选择流程，就必须纳入整体 solver 墙钟，不能继承局部计时口径后称为完整端到端速度。
