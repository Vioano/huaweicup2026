# 一、结论：不要再寻找一个“通信惩罚系数”，而要区分三种证据



跨核拆分应由“收益准入”决定，而不能由“存在负载不均衡”决定。


本轮得到两项可直接实现的结果。


第一，已提供的012、055失败，实际上已有很便宜的绝对 DDR 工作量拒绝证书，不必先解决所有通信隐藏细节。


第二，对没有被这一粗界拒绝的候选，我给出一个新的固定执行图因果区间证书：利用每条 DMA FIFO 上的前驱前缀、后继后缀，在线性乘以核数的复杂度内，计算每个 COPY 的安全持续时间上界。它比 r02 的“所有 COPY 一律按全局最大并发数放大”更强，而且能够把真实 FIFO、credit 门控放进证明。


两者之间必须保留“未知”状态：


$\boxed{
\begin{array}{ll}
L_{\rm cut}\ge U_{\rm whole}
&\Rightarrow \text{可安全拒绝严格时间改善；}\\[2mm]
U_{\rm cut}<L_{\rm whole}
&\Rightarrow \text{可证明切分改善；}\\[2mm]
\text{其余情况}
&\Rightarrow \text{界限不足，不能把乐观值当收益。}
\end{array}
}
\tag{R3-01}$


本轮建议的唯一新增候选是一个闭合分支的迁移，不是重新启用任意 dominant_component_dag 拆分。未知情况才对 whole/cut 这一个二元决策做完整比较。




# 二、两个失败其实已经有便宜的拒绝证书




## 2.1 必搬 DDR 服务量是绝对下界，不是“额外延迟”



对一份确定归属的候选，枚举官方必然生成的 DDR COPY。每个 COPY 的独占工作量为：


$d_e=\max\!\left(1,\left\lceil\frac{s_e}{B}\right\rceil\right),
\qquad
L_{\rm DDR}=\sum_{e\in\mathcal D_{\rm mandatory}}d_e
\le M.
\tag{R3-02}$


这里可以只枚举确定必有的 COPY，忽略尚不知道的 spill；遗漏工作只会使下界变弱。


**关键是正确去重。**应按 tensor 与实际 source-core→target-core 连接计数，不能把同一目标核上的多个消费者分别收费。输入复制按实际消费核计数，输出按官方条件计数。当前 P2 构造正是这种规则。


这个界没有声称搬运时间要全部加在计算时间之后。它只说：整个程序总时间，不能少于共享 DDR 必须完成的总服务工作。



## 2.2 用派生审计做事后核验



甚至只使用“额外 DDR 字节数”，也能得到更弱但足够的下界：



已报告失败	新方案额外 DDR	仅由这些字节得到的下界	原方案 Makespan	

012，四核	1,324,386 B	22,074 cycles	13,803 cycles	

055，五核	3,186,536 B	53,109 cycles	21,144 cycles	



两例的数据均来自本轮派生审计。


因此，这两份具体计划即使通信隐藏得再好，也不可能胜过原方案。它们不需要先发生 spill，才有理由拒绝。


这与016完全不矛盾。你报告的约40 MB新增大向量流量，对应的服务量下界约为666,283 cycles，仍低于完整方案的两百万量级 Makespan。它大于“节省的计算量”，不代表大于“允许占据的整个执行时间”。




“总通信服务量大于计算收益”不能安全拒绝；“必需总通信服务量已经大于对照方案完整时间”可以安全拒绝。




本轮没有重新生成012、055计划，也没有统计这一界还能挡住其他多少回退。上面是对已提供数字的数学审计，不是新的覆盖率实验。




# 三、选定的中间模型：迁移一个闭合分支




## 3.1 模型与直接构造



考虑一个真实 fork–join 区域：


$P\longrightarrow\{X,Y\}\longrightarrow J.
\tag{R3-03}$


要求：




- 


$X,Y$
 之间没有依赖；它们与外部的所有张量边界都已识别。



- 

先研究一个计算 Pipe 的情形。每个块可以含内部 DAG，但其核内拓扑字固定，块内无未计入的等待。



- 

whole 方案把这些计算都留在 donor；helper 先有一段既定工作 
$Q$
。



- 

切分只把 
$X$
 移到 helper，保留所有原始张量依赖；输入前沿送过去，输出前沿送回来。



- 

共享只读输入要么已在该阶段入口合法驻留，要么其读取已经包含在通信和门控分析中。





用小写字母表示相应计算时间。提交的计算字为：



方案	donor	helper	

whole	
$P,X,Y,J$
	
$Q$
	

cut	
$P,Y,J$
	
$Q,X$
	



这不是指定执行起止时刻。跨核输入、返回结果仍由官方 COPY 生成，join 仍由原始 tensor 依赖约束。


设已经有可信的通信响应上界：




- 


$D_f$
：从 
$P$
 完成到 
$X$
 所需输入全部到达的上界；



- 


$D_r$
：从 
$X$
 完成到 donor 收到其全部返回结果的上界。





它们必须包含共享 DDR、两个复制方向、释放延迟、DMA FIFO和credit门控。各边独占最短时延不能直接充当这两个上界。



## 3.2 可计算的收益充分条件




### 定理一【已证明，适用于上述闭合模型】



如果 
$P,Y,Q$
 的执行没有未计入的门控，则：


$\boxed{
U_{\rm cut}
=
\max\!\left\{
a+y,\
\max(b,a+D_f)+x+D_r
\right\}+z.
}
\tag{R3-04}$


证明：


donor 的剩余分支最晚在 
$a+y$
 完成。helper 要等其原工作和前沿输入都完成，因此 
$X$
 最晚从两者的最大值开始；再支付 
$x$
 和返回响应上界。join 等待这两条分支，故取最大值后加 
$z$
。


当 whole 的主导时间为 donor 的全部计算时：


$T_{\rm whole}=a+x+y+z\ge b,
\tag{R3-05}$


得到：


$\boxed{
T_{\rm whole}-U_{\rm cut}
=
\min\!\left\{
x,\
y-\max(b-a,D_f)-D_r
\right\}.
}
\tag{R3-06}$


所以一个明确的严格收益充分条件是：


$\boxed{
y>\max(b-a,D_f)+D_r.
}
\tag{R3-07}$


它的意义不是“搬出去的计算足够大”这么简单：


donor 留下的独立工作，必须足以覆盖 helper 原有积压和无法隐藏的往返通信。


这也提供了无需参数网格的分支选择：对同一个二分叉，分别计算“迁移左支”和“迁移右支”的这个解析余量，选择较好的一种；没有正余量就不生成该模型内的迁移候选。


但在实际 P2 中，未经门控认证的 
$D_f,D_r$
 只能用于提出候选，不能用于宣称收益。



### 范围不能扩大



如果有其他分量同时竞争 DDR，就不能让每个迁移对都独占带宽后独立计算上界。应使用下一节的同一个全局固定执行图给它们分配上界。


如果有多阶段，也不能把一个局部改善直接乘阶段数。只有原图已有的 join 确实关闭了相关阶段工作，且下一阶段的输入、未完成 COPY 和 credit 状态都受到同一条件控制时，才允许逐阶段组合上界。304个稳态阶段观察到相同周期，不自动证明任意规模都进入同一个状态。




# 四、为什么廉价聚合统计不够：一个门控边就能翻转优劣



下面给出一个五计算块的编译后门控模型反例。它使用本题的带宽与500 cycles跨核延迟；不声称已经构造了两份原始JSON，让官方恰好产生指定的两种credit历史。


参数为：


$\begin{gathered}
a=1,\quad x=1000,\quad y=1550,\quad z=1,\quad b=1000,\\
s_f=6000\ {\rm B},\quad s_r=60\ {\rm B},\quad
B=60\ {\rm B/cycle},\quad\delta=500.
\end{gathered}
\tag{R3-08}$


whole 的时间是2552 cycles。


两种切分拥有相同的原计算 DAG、计算工作量、切口尺寸、跨核次数和物理容量。不同的只是 receiver 大 COPY_IN 是否还受一个本地完成门控约束。



### 情形A：读取没有额外门控



前沿写入100 cycles，等待500，再读取100。因此输入在701到达。helper 的 
$Q$
 在1000结束，于是 
$X$
 在1000—2000执行；返回结果再需502，join 最后执行1。



### 情形B：读取复用了 
$Q$
 最后才释放的额度



prepared graph 多出本地依赖：


$Q\longrightarrow {\rm forward\ COPY\_IN}.
\tag{R3-09}$


读取只能在1000开始、1100结束；之后所有后续相应延后。



方案	模型 Makespan	相对 whole	

whole	2552	—	

cut，情形A	2503	改善49	

cut，情形B	2603	退步51	



这里的边在 receiver 内部，不是非法的跨核 memory-credit 边。


最少需要补充的信息，不是再加一个“缓存峰值”数字，而是：关键 COPY 的门控前驱来自哪里，它位于哪条计算或 DMA FIFO 的什么位置。


FIFO先后、tensor最后读者和credit来源不同，可以在零spill的情况下产生不同结果。官方 Step3确实按被复用额度的旧读者／写者添加依赖，而不只是记录当前用了多少字节。


因此，016报告的503 cycles等待是非常有价值的定位信息，但“恰逢某个V结束”仍不等于已经证明存在那条 WAR 边。真正的证据应是 prepared graph 中的前驱关系。




# 五、本轮的主要新增定理：用 DMA 因果区间构造安全上界



这一节不再假装能从原图的几项统计恢复credit。它从一份已经完成官方准备的固定计划出发。



## 5.1 需要的图



构造固定执行 DAG 
$G_P$
，节点包含全部计算和生成的 COPY/SPILL，边包含：


原本保留的执行依赖、真实 MEMORY_REUSE 边、每条 Pipe 的相邻 FIFO 边，以及跨核 COPY_OUT→COPY_IN 的500 cycles完成到开始lag。


这些分析边不是往提交里添加任意同步，而是把官方已经强制的关系显式表示出来。


源码支持这个边界：Step3输出固定 Pipe 顺序，并将额度复用关系写进执行图；最终 P2装载它们，按前驱、FIFO和跨核释放发射。



## 5.2 每条 DMA 队列上的潜在竞争者，其实是一个区间



将每条物理 DMA FIFO 中的 DDR COPY 依次编号：


$Q_p=(e_{p,1},\ldots,e_{p,m_p}).
\tag{R3-10}$


对任意操作 
$v$
，定义：


$\begin{aligned}
\alpha_p(v)
 &=\max\bigl(\{j:e_{p,j}\prec v\}\cup\{0\}\bigr),\\
\beta_p(v)
 &=\min\bigl(\{j:v\prec e_{p,j}\}\cup\{m_p+1\}\bigr).
\end{aligned}
\tag{R3-11}$


其中先后关系是固定执行 DAG 的可达关系。



### 引理【已证明】



在另一条 DMA FIFO 上，与 
$v$
 没有因果先后的 COPY，恰好为：


$\boxed{
\alpha_p(v)<j<\beta_p(v).
}
\tag{R3-12}$


**证明：**同一物理 FIFO 是一条链。若其中某个 COPY 是 
$v$
 的前驱，更早的 COPY 全是前驱；若某个 COPY 是后继，更晚的全是后继。因此前驱形成前缀，后继形成后缀，中间剩余部分恰为不可比较区间。


这意味着不需要建立所有操作之间的二次规模可达矩阵。


所有 
$\alpha$
 可沿拓扑序传播每条DMA队列的最大前驱下标；所有 
$\beta$
 可逆拓扑传播最小后继下标。每个节点只保存至多十个队列坐标。



## 5.3 一个 COPY 的安全持续时间上界



对 DDR COPY 
$e$
，令：




- 


$I_e$
 为其他 DMA FIFO 上全部因果不可比较 COPY 的工作量总和；



- 


$\kappa_e$
 为“一条自己的FIFO，加上不可比较区间非空的其他FIFO”的数量。





则：


$\boxed{
\overline d_e
=
\min\!\left\{
\kappa_e d_e,\ d_e+I_e
\right\}
}
\tag{R3-13}$


是该 COPY 运行持续时间的上界。



### 证明一：并发份额界



当 
$e$
 仍有工作时，能同时竞争带宽的 COPY，只能来自这些不可比较区间；每条FIFO又至多有一个在运行。因此其带宽份额不低于总带宽的 
$\kappa_e$
 分之一，完成独占工作 
$d_e$
 至多需要第一项。



### 证明二：干扰工作收费界



从 
$e$
 开始直到其流体工作完成，DDR始终有 
$e$
 可服务，所以不会空闲。这个区间的总时长，等于为 
$e$
 服务的工作，加上为其他 COPY 服务的工作。


后者不可能超过所有潜在竞争者各自完整工作量之和，所以得到第二项。


两个界都成立，可以取较小者。对于正整数工作量与整数周期向上取整完成的模型，这两个整数上界仍成立。


**特别注意：门控等待不是这个持续时间界的一部分。**门控等待通过固定图的前驱和lag进入开始时刻，不能把它漏掉后归入“少量DMA干扰”。



## 5.4 从操作界得到官方语义下的候选界



计算操作保持原时长，DDR COPY使用上述上界。沿固定执行图递推：


$\begin{aligned}
\overline f_v
 &=
 \max_{u\to v}\bigl(\overline f_u+\ell_{uv}\bigr)
 +\overline d_v,\\
U(P)&=\max_v\overline f_v.
\end{aligned}
\tag{R3-14}$


对成功验证、门控已完整表示、按就绪条件尽早发射的固定计划：


$\boxed{M(P)\le U(P).}
\tag{R3-15}$


**证明：**按拓扑序归纳。实际前驱完成时间不晚于各自上界；FIFO前驱、跨核lag和memory前驱均已计入。因此实际发射不会晚于递推给出的开始上界。操作自身的持续时间又受式（R3-13）约束。


这里证明的是官方固定优先序执行的支配上界，不是“存在一条我人为安排得很好的时间表”。后者不能自动证明官方会按那条时间表执行。


在上一节门控反例中，四次跨核COPY沿输入传输—
$X$
—返回传输形成因果链，因此它们不能互相争用。该证书给出的上下界恰好都是2503或2603，能够区分优劣；而统一按四个DMA队列放大每个COPY的粗上界，早门控情形会得到2810，无法证明改善。



## 5.5 伪代码与复杂度




certify_fixed_plan(prepared):
    G = 实际执行依赖 + MEMORY_REUSE + Pipe FIFO + 跨核lag
    检查完整覆盖、单槽顺序和联合无环

    按每条物理DMA FIFO给DDR COPY编号
    forward:
        传播各DMA队列的最大前驱编号 alpha
    backward:
        传播各DMA队列的最小后继编号 beta

    建立各DMA队列COPY工作量的前缀和

    for 每个DDR COPY e:
        用(alpha, beta)取得其他队列的不可比较区间
        I = 这些区间的总工作量
        kappa = 1 + 非空的其他队列数量
        upper_duration[e] = min(kappa*d[e], d[e]+I)

    lower = 独占时长最长路与必搬DDR下界
    upper = upper_duration上的最长路
    return lower, upper, COPY级证据



设操作、边、DDR COPY数量分别为 
$N,E,D$
，有 
$m$
 条包含DDR操作的物理FIFO，则核心证书的复杂度为：


$\boxed{
O\bigl(m(N+E)+mD\bigr)\ \text{时间},
\qquad
O(mN+N+E)\ \text{空间}.
}
\tag{R3-16}$


在所述P2硬件契约下，至多十条DMA FIFO。它不是一般DAG最优调度算法，而是一个低维的固定候选收益验证器。



### 不能省略的边界



没有prepared graph，也没有独立门控证明时，这个上界不能直接应用于原计算DAG。


一个非常强但可静态检查的特例是：整个相关Task中，每种内存的初始驻留加全部不同物理张量分配量都不超过容量；且无重复生产、无spill。在这种范围内，分配始终可使用virgin额度，不需要credit复用。它足以支持很小的静态证明域，但通常不适用于长达数百阶段的图。


一般情形必须取得真实准备结果。由于冷准备占主要成本，本证书的首要价值是保证和定位，不是承诺大幅减少求解秒数。上界过松时，已经准备好的计划继续精确执行，往往比另造复杂代理更合理。




# 六、活跃核松弛：优化器本身正确，但优化的量不够




## 6.1 原来的二分选择没有明显数学错误



当前代码的模型是：


$L(q)=
\max\!\left\{
\left\lceil\frac nq\right\rceil W,\
\left\lceil\frac{qS+P}{B}\right\rceil,\
H
\right\}.
\tag{R3-17}$


计算项不增，输入服务项不减，所以检查两者首次交叉两侧，再把最优平台归到更少核，确实能求这个模型的最小值。当前实现也扫描每个job的实际波次投影，而不是把job 0的私有生命周期外推给所有job。


问题在于：


求对一个松弛模型的最优核数，不等于求对实际执行的核数。


原始touch容量包络也只是充分的原始序列条件；它可能过保守地排除较少核，也可能在通过时仍未控制COPY扩展和credit时序。当前文档已经明确保留了这些边界。



## 6.2 四个计算操作就能让它误选



考虑两个相同job，每个都是：




- 

A：1 cycle，读取共享输入X，X为600 B；



- 

B：20 cycles，读取A的输出和共享输入Y，Y为180 B；



- 

每个job最终输出6000 B。





使用固定60 B/cycle带宽。所有张量分配总量都足以放进virgin容量，不依赖spill或credit制造反例。


单核波次字为A₁、A₂、B₁、B₂；两核各自执行A、B。



项目	一个活跃核	两个活跃核	

原松弛值	42	26	

完整输入—计算—输出模型时间	233	246	



时间线可以手算。


一个核：X在10结束，Y在13结束；两次A分别在10—11、11—12运行；B₁在13—33，B₂在33—53。输出DMA从33开始，连续完成两份100 cycles的输出，结束于233。


两个核：两份X共同服务到20，两份Y到26；两次B在26—46运行。两份输出再分享200 cycles服务，结束于246。


因此，原模型选择两个核，但一个核更快。


这是对活跃核子模型的反例，不是声称2794外层路由一定会进入这个小图，更不是2794的新官方回退记录。



## 6.3 只建议增加一项：输入—输出闭合的 DDR 时间窗下界



不再添加经验性输出惩罚。对固定候选中每个必需DDR操作 
$e$
，计算：




- 


$h_e$
：它开始前必需经过的时间下界；



- 


$t_e$
：它结束后到全图完成仍必需经过的时间下界。





这些值可由保留依赖和已确认FIFO的最长路得到。然后使用：


$\boxed{
L_{\rm DDR\text{-}window}
=
\max_{\alpha,\beta}
\left[
\alpha+\beta+
\sum_{\substack{e:h_e\ge\alpha\\t_e\ge\beta}}d_e
\right],
}
\tag{R3-18}$


其中只考虑选中集合非空的阈值。


**证明：**被选中的全部服务工作，都必须发生在整个调度的区间 
$[\alpha,M-\beta]$
 内。共享DDR的总服务率至多为1，因而该区间长度不能小于这些工作量之和。


它同时覆盖输入启动、输出排空、切口和已知门控造成的服务集中，而不是把所有字节平铺到整个Makespan。


按 
$h_e$
 递减扫描，将 
$t_e$
 离散化，加入一个COPY就是对一段前缀做区间加并查询最大值，能够在：


$O(D\log D)
\tag{R3-19}$


时间内精确计算这个下界。


在上面的反例中，一个核的上下界均为233；两个核的DDR时间窗下界也是233。因此已经能证明：两个核不可能严格胜过这个已认证的单核方案，尽管原松弛强烈偏好两个核。


这仍然是下界修正，不是万能核数选择器。不要把新项加入以后，继续假设它关于核数保留原来的单调交叉结构；也不要再次用“最小下界”冒充“最好可行方案”。




# 七、落地为一个固定算法：一次闭合迁移，最多两份完整计划



我建议保留2794的whole／shared-wave路线作为确定性种子，再增加一个受控准入模块，而不是打开旧的任意DAG拆分开关。


候选生成只做一个明确的结构改动：识别闭合二分叉，按式（R3-06）的解析余量决定迁移哪一支，固定一个donor/helper组合及核内顺序。所有共享输入新增复制、返回tensor和其他分量的竞争，都计入最终候选。



P0 = 当前固定whole/shared-wave构造

若没有满足闭合分支守卫的迁移:
    返回P0

P1 = 一个解析选出的闭合分支迁移
     不扫描切点、窗口、优先级参数

计算P1的必搬COPY服务量及保留依赖/FIFO下界

取得P0的有效上界或本次运行的精确结果
若 L1 >= U0:
    返回P0

准备P1一次，验证实际执行图
计算因果区间证书(L1, U1)

若 U1 < L0 或 U1 < 本次精确M0:
    返回P1，并保存证书

若 L1 >= 本次精确M0:
    返回P0

其余:
    精确评价P1
    在P0、P1之间按实际主目标选择
    同时间的搬运取舍按预先固定规则处理



这两个计划对应的是保留一个分支还是迁移它这一数学上明确的二元决策，不是一组有限次数的参数搜索。全部构造、准备、评分、失败回退都属于同一算法的在线成本。


如果接口不能复用prepared结果，重复准备必须照实计时。若墙钟预算不允许第二份冷准备，就应保留种子，并将“候选未判定”记录下来，而不是声称完成了精确取优。


当前E2的32计划验证没有覆盖这条新候选族；本轮也没有读E2实现。因此首个准入实验应使用冻结E0，不能凭旧的零差分记录赋予新族精确性。已有文档同样指出了这一范围限制。




# 八、“接受锯齿”可以，但不能把系统性错误包装成结构取舍




## 8.1 平均加速比与逐例全胜不是同一个目标



两算法平均成绩的差为：


$\boxed{
\Delta A
=
\frac1N\sum_i
B_i\left(\frac1{M_i^{\rm new}}-\frac1{M_i^{\rm old}}\right)
=
\frac1N\sum_i
\frac{B_i(M_i^{\rm old}-M_i^{\rm new})}
     {M_i^{\rm old}M_i^{\rm new}}.
}
\tag{R3-20}$


因此不能靠“改善了多少例”“总共省了多少cycles”替代真正目标。少数显著改善可以抵消其他损失；同样，少数高加速比格子的严重退步，也可能吃掉很多小改进。


本轮派生审计已经说明这一点：



路线对平均成绩的贡献变化	四核	五核	

dominant_component_dag	−0.155246	−0.223416	

shared_input_wave	+0.144557	+0.167183	



这是对已报告配对统计求和后除以100，不是新的算法成绩，也不能拼成2794预测。


所以我赞成“不要求逐例全胜”，但不赞成把这条拆分路线的整体回退解释为应当接受的锯齿：它使用的准入条件根本没有证明通信能被隐藏，且已有具体计划违反绝对DDR收益条件。



## 8.2 什么取舍应接受，什么退化应修复？



可接受的结构取舍包括：计数取整导致核数曲线不光滑；在明确结构域中用更多DDR换取更短Makespan；某个固定低成本构造在边界实例变差，但它在既定平均目标下总体有收益，且取舍机制、适用条件和墙钟成本都透明。


应修复的系统退化包括：忽略已知必搬流量；把下界当可行时间；遗漏输出或credit；结构守卫通过但所用定理条件不成立；由某个无语义的编号顺序决定是否大量拆分；未计入第二次冷准备却宣称算法高效。


“结构专用”本身也不免疫过拟合。一个识别器可以不写case ID，却通过不断增加形状例外、阈值和退出条件，逐渐把100图记下来。是否过拟合，要看它能否解释并通过预先冻结的结构反例族，不只看代码里有没有数字编号。

# 九、相对r01/r02新增了什么，以及本轮实际验证了什么



旧结论中，固定compute FIFO与保留依赖的最长路界继续成立，但仍然只是固定候选下界。r02的通信隐藏条件继续在其清洁通信模型内成立；016的成功不能扩大它的门控适用范围。


本轮新增的是：


**从“是否存在计算负载差”转为“是否存在完整收益证书”，并将固定执行图里的潜在DDR竞争者压缩成每条FIFO上的一个因果区间。**这样无需二次可达矩阵，就能同时处理两方向COPY、共享带宽和真实门控，给出操作级、计划级上界。


已完成的标准库原型测试包括：160个合成固定DAG与独立有理数公平共享事件模型对照；150个DDR时间窗界与阈值穷举对照；162个闭合分支收益边界算术检查。上述门控翻转例和活跃核反例也已核验。全部通过，但它们不是官方成绩，也不是E2与E0逐位等价证明。

## 最值得先实现的一个改动



只增加一处“拆分收益准入门”：先以必搬DDR绝对下界拒绝不可能改善的候选；只为一个闭合分支迁移保留whole/cut比较，复用同次prepared graph输出因果区间证书。暂不同时修改活跃核策略。


最小官方证伪实验用附件的一张五计算节点原图、两份合法形式的singleton计划，whole/cut各跑一次冻结E0。它只迁移一个闭合分支，没有新增任意屏障；同时导出真实COPY、FIFO和MEMORY_REUSE，检查官方Makespan是否落在证书区间内。任一上界被突破，先修证书的语义缺口；区间成立但不能分胜负，就承认“未知”，不要调一个惩罚系数把它改写成“有收益”。
