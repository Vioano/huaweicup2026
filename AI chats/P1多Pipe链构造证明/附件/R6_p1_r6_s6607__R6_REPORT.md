# R6：重复多Pipe DAG波内的分支外援

## 结论

不值得实现标量McNaughton wrap-around。值得先实现一个单一替代：**导出真正独立、前驱闭合的多Pipe分支；在原重核上把早期工作Y与汇合尾J分为不同Task；外援核先做导出分支X，再做本波原工作L。** 这是异步的局部fork/join，不添加全局第二波。

本轮仅作静态分析。新plan构造、官方Task编译、响应模拟、E0/E1/E2均为0。没有改进成绩或新统一均值。

## 为什么必须三片，而不是两片

若把X移出去但剩余Y∪J仍在同Task，X→J会变成X→(Y∪J)的Task释放约束，Y被一起推迟。三片才保留X与Y的真实独立性。

任意切法也不保商图DAG：原路径a→b→c合并{a,c}、保留{b}，即出现两向Task边。将这种切分改称“wrap-around”不能消除环。

对一次实际执行，汇合Task的启动至少由max(本核Y结束+100、外援X结束+1000、其他原外部释放约束)决定。所有结束均指完整Task（含COPY），不是最后计算op。

反例：两个独立计算X(M8)、Y(V8)汇入J(V1)，无DDR、足够内存。未切Task可以9 cycles完成；拆成X/Y/J跨核后，1000远程门控会压倒8 cycles的可外援工作。此为手算机制反例，本轮未调用编译器或评估器。

## 算法/拒绝/复杂度

见 `CONSTRUCTION_NOT_EXECUTED.md` 的确定规则及两键伪代码。核心是：有向桥上游、独立晚尾、每个donor至多一个锥、donor/helper角色互斥、外援先行、同一波联合判断全部并列重核。新Task的秩 `(旧波, micro, 本核波内序, 核号)` 严格增加；micro不是新barrier。

输入域不满足桥/前驱闭合/单sink/波向前时拒绝；整批工作向量不改善、Task预算失败时拒绝。共享DDR服务已超过当前输入已验证上界时可严格拒绝。剩下的工作向量与成本比较只是启发式，必须保留一个新候选的E1/E0守卫。新FIFO/MEM/spill及等待叠加全部未知。

在计算邻接和旧波次已形成后，桥树工作统计线性，选中少数join的闭包/边界检查增量可保守记O(K(n+m)+K²W)，排序另计；基线、二部图展开和COPY收缩另计。每波净增至多2(K−1) Tasks。
