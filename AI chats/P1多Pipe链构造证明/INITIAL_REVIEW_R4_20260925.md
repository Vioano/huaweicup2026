# R4 初审：可保留的证明与尚不能采用的结论

来源为本目录 R4 原生回答和附件，不是新的官方成绩。root 与复用的 Sol 做源码/数学只读复核；Luna 做字节归档。没有执行附件代码，没有新增 Task 编译、候选构造或 E0/E1/E2。作者报告的 CPython3.13.5 两次合成 Task 编译和69点算术检查仍属于作者实验。

## 已有证据能支持什么

固定完整 execution_graph 前驱到四条 Pipe 完成前缀的压缩成立：单槽 FIFO 的已完成集合是前缀，取各 Pipe 前驱最大 rank 足够。抽象字节信用链也能证明，在唯一 managed producer、无 spill、完整保留消费者退休到新 producer 发射依赖的域内，任意满足这些边的重调度不超过容量。它不能证明回放峰值等于 Step3 编译峰值，也不能证明 Fraction 与官方浮点/EPS 完全相同。该论证与此前本机 `docs/a/P1_MEMORY_CREDIT_LEMMA.md` 一致，并非等待本回答后才产生的结果。

旧相对 ID 键直接扩到 MEM 域不成立。作者的反例与本机独立反例机制一致，但输入和运行时不同；不称为复现作者两图。本机证据在固定提交 `4b34d043dd68b68681a38684734c0de476f69282` 的 `results/a/p1-memory-cache-counterexample-20260925/`。差异中的边可被传递依赖蕴含，不能推断 Makespan 已不同，更不能撤销旧保守域或已核 E0。

本机另一个完整 008/K5 计划已核 E0 与新 MEM 响应模型一致为114352，但劣于既有100603。它说明一个实际计划的模型值可信，不说明扩大搜索域必然获益；该计划未进入统一 solver。证据同固定提交 `results/a/p1-memory-packet-probe-20260925/008-k5/public/`。

## 新缓存键的限定

Sol 只读核对了 P1 Task 重建、Step1排序、Step2生命周期与 Step3 分配释放顺序。`reuse_prekey.py` 保留计算 op 的实际 `set(sorted(incidence))` 遍历，补上已发现的释放信用顺序缺口。当前严格有序私有链、原图 tensor 关联等于实际重建 compute 关联、无 spill，且编译源码/config/进程运行时固定时，未发现直接反例。

仍须在实现说明中补足合成 COPY 的映射：全局生成 ID 的绝对跳号不应影响排序，因为它们高于原 compute ID，Task 内保持 touched tensor 的相对顺序；需检查所有相关比较，而不是只看 COPY 队首。边界 COPY 每次仅含一个 managed 端点是本域的重要前提。`runtime_scope()` 的版本/位数/hash_info 不是跨任意 Python 二进制的完整持久缓存身份；第一版只做进程内缓存，并绑定全部冻结源码和配置。

最终计划重新编译不能证明未选边的缓存正确。在以上条件与针对性证伪完成前，继续使用实际位置编译，不直接把作者键接入生产。

## 下界与惰性控制器

R4-11 第一项需真正的完整链 M 阻塞前提，不能仅从外形 M/V/M 推得。它数的是 M 工作量加不重叠的完整链 V 阻塞间隔。另两项是 V 工作及完整边界 COPY 独占服务。R4-12 忽略将来门控和切口的额外代价，因而是同一私有链构造类的乐观后缀界；要求服务量由完整 tensor 边界计算，且切开后的必要服务不小于整链服务。

对作者 `edge_envelope.py` 做静态数学检查：两个 max-affine 函数的和在由各自等值线与盒子边界划出的每个多边形上是仿射函数。紧致非空裁剪盒子的最低值可在这些多边形顶点取得；代码枚举边界、s=q 和全部相交点。整数系数保证整数(q,s)处的值为整数，故对实数最小值取 ceil 仍是整数点域的下界。这只核对算术方案，不等于复跑69点，更不证明传入的资源系数适用于任意图。

控制器还必须明确三点，附件没有提供已实现的完整 solver：

1. 相同状态发现更小前缀代价时须重开/更新后继盒子；旧大代价下的剪枝不能永久排除该状态。不能未经一致性证明就采用“一次 closed 永不重开”的 A*。
2. 所有未展开正常转移、drain 和真实不等尾部均要被 OPEN 或已核排除证书覆盖。预算耗尽保持未知；不能把超时当不可行，也不能由一个失败包宽排除更大包宽。
3. 上界必须是同一目标模型下核过的完整计划。若基线在同步类外，明确为“同步类与该基线的并集”。官方 E0 整数结果不能未经核对当作 Fraction 模型上界。只用 cycle 下界剪枝不能宣布额外 DDR 的字典序最优。

结论：可推进有预算、按下界展开的研究原型；尚无更好官方成绩、全量可用性或全 P1 最优证明。先完成进程内缓存契约的小规模证伪，再决定是否实现控制器；既有统一 structural_refine 的全量验证与本扩域研究分开，均服从共享评测窗口。暂不向 Pro 追加另一轮长研究。
