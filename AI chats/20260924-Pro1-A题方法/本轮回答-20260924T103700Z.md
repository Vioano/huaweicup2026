## 3.1 【FORMAL】完整 result 已经暴露了逻辑方案

冻结官方成功结果中：

- Q1 的每个原计算操作携带 `task_id`，每核结果保留 Task／子图顺序；

**这条结论应尽早用于节省研究时间：不要继续寻找“完整 result 大商”。要先减少观测，再研究商。**

## 3.2 【FORMAL＋AUTHOR-REPORT】编译复用是真结构，但不是行为等价

Q1 的固定分区可以共用官方局部编译产物；不同核心归属和核序仍需刷新调度外壳、重新模拟全部共享 DDR 与事件。这就是当前 exact batch 已实现的边界。

**共享同一个编译程序，不意味着当前结果相同，更不意味着未来编辑不可区分。**

这件事很关键：

> **高全局耦合不否定编译复用；低局部响应也不推出行为商；行为商失败仍然允许 exact batch＋macro search 成功。**

原生交接报告中的收益也有这个条件：64 个不同调度摊销准备成本时约 33.7 倍，只有 3 个候选时约 0.43–1.95 倍；这仍是作者内部评分口径，不是本轮独立的完整求解器性能结论。

## 3.3 【E0】一个非平凡 D14 类，可能被两步未来编辑完全拆散

本轮固定：

**Q2、1 核、4 个互不依赖的无 tensor 计算操作、固定 singleton 映射。**

两条 M 操作时长为 2、5；两条 V 操作为 3、11。穷举 24 种核内子图排列。允许操作只有三个确定的“交换相邻槽位”动作；这个 24 状态域对它们封闭。

结果如下：

| 观测 Φ | 当前观测类 | 加入未来编辑后的结果 |
| --- | --- | --- |
| 只看 Makespan | 1 类，全部为 14 | 所有未来仍为 14，D15 也是 1 类 |
| 看每个原操作的精确起止时刻 | **4 类** | 1 步细化成 **20 类**；2 步成 **24 类**，随后稳定 |

具体区分对：

两个计划当前逐操作时刻相同；执行同一个“交换前两个槽位”动作，其中一个交换了两条 M 工作，另一个只交换 M/V 的全局排列，于是逐操作时刻不同。

## P01：完整 result 上不存在有价值的逻辑方案压缩商

**当前证据：**【FORMAL】源码恢复证明；【EMP】本轮 27 份结果恢复成功。

**最强反例边界：**文本键别名、输入编码冗余可能合并；减少 Φ 后也可能出现非平凡类。但这些不是对上述逻辑方案命题的反例。

**成功价值：**立即停止通用 full-result quotient 方向。

**失败应砍什么：**只收紧恢复命题的输入／输出域；不能反过来立即宣布找到有用大商。

## P02：Q1 的编译复用域广于 Q2/Q3

**命题：**Q1 固定有序映射、图、局部编译配置和 H 时，合法 move/reorder 不改变剥离调度元数据后的局部程序；Q2/Q3 需要更强的相同优先序条件。

**当前证据：**【FORMAL】源码数据依赖；【AUTHOR-REPORT】exact batch 和 native 的有限验证。

**最强反例：**split/merge 改变全局生成 ID；Q2/Q3 改序改变 COPY 所属桶，继而改变 Step2/3。

**最小实验：**相同父计划分别施加 move/reorder、split/merge、B 的 priority 编辑，逐层比较 L1–L4。

**成功价值：**精确降低编译次数，不需要先拟合代理。

**失败应砍什么：**“只改两 Task 就只失效两 Task”等过强缓存规则，而非所有复用。

## P03：小编辑可以具有低编译耦合、高时间耦合

**命题：**某些 Q1 move/reorder 的局部程序完全不变，但共享 DDR 可使远端原操作时刻广泛变化。

**当前证据：**【HYP】尚未完成统一耦合测量；全局带宽更新路径支持这种可能性。

**最强反例／误判风险：**把整条后缀统一平移误称为“每个 Task 的服务机制都改变”；或者只看原计算图可达节点，漏掉不连通分量之间的资源作用。

**最小实验：**固定分区，成对保存编译签名、逐操作开始差与持续时间差、DDR 在途集合差。

**成功价值：**分清哪里能省编译、哪里仍必须全局重放。

**失败应砍什么：**以局部图距离直接划定全局增量重评范围的方案。

## P04：D14 压缩经未来操作后会显著缩水

**命题：**只依据当前时刻、FIFO 投影或某个中间签名合并方案，可能被很短的未来编辑区分。

**当前证据：**【E0】本轮 24 状态实验的 4→20→24 类。

**最小实验：**同时改变 Φ 和允许操作集；记录最短区分 continuation。闭合有限域可以细化到不动点，非闭合样本只能报有限视野。

**失败应砍什么：**若压缩率接近一，停止该 Φ/A 下的商优化，保留编译复用。

## P05：低维摘要通常不是 D17 充分状态

**命题：**总负载、总剩余 COPY、缓存占用量和命中率不足以支持全部未来允许编辑；紧凑状态必须满足操作闭合。

**当前证据：**【FORMAL】完整输出恢复性；当前／未来等价分离；【HYP】更小受限状态仍可能存在。

**最强反例：**相同缓存成员与容量、不同 FIFO 次序；相同总剩余搬运、不同请求身份与剩余量分布；相同当前执行程序、不同未来操作适用性。

**最小实验：**每删除一个字段，就寻找“状态相同、某条 continuation 结果不同”的区分对。

**成功价值：**证明某个小状态确实足以更新，而不只是能回放一次。

**失败应砍什么：**通用“摘要即 Markov 状态”；不能把失败转移给官方 evaluator。

## P06：局部评估器只有赢过真实精评路径才值得存在

**命题：**计入 detector、特征、拒答、回退和最终确认后，某个局部 Δ／排序专家仍能改善同预算质量或达到同质量的时间。

**当前证据：**【AUTHOR-REPORT】入口提前量在新池无收益；P23 冷耗时主要在局部编译，原生事件重放已较快。

**最强反例：**为了判断 regime 先完整跑 Step3，随后代理又拒答；或者模型一致地漏掉真正优解。

**最小实验：**相同冻结候选池，局部专家路由与 exact-only 做同总预算对照。

**成功价值：**减少有实际成本的精评，而不只是得到好看的预测误差。

**失败应砍什么：**相应专家，不必砍掉 exact batch 或候选构造。

## P07：“少数敏感方向”跨图、跨核稳定仍是未知

**命题：**预先固定的少量操作类，可以在未用于选类的图／核数上解释大部分显著行为变化。

**当前证据：**【E0】008 是高收益见证；不是稳定敏感方向。resource-word 改变了大量优先关系，也不能未经编辑大小测量就叫“小改动”。

**最强反例：**按结果重新分组动作类制造稀疏性；响应集中仅来自一个图；换核数后收益符号翻转。

**最小实验：**操作类平衡采样，在开发组选择方向，在另一组图／核数测响应能量和显著事件覆盖。

**成功价值：**为 guarded macro 的优先级提供可迁移依据。

**失败应砍什么：**全局低维敏感假说；保留个别可解释、参数局部的机制。

## P08：空核嵌入有结构依据，但加核获益与跨 q 迁移没有保证

**命题：**末尾增加空核可保留旧活动执行投影；真正利用新核则是另一步需要验证的 continuation。

**当前证据：**【FORMAL】冻结代码的活动对象与遍历条件；【E0】同一 008 计划在 Q1/Q2/Q3 的巨大差异。

**最强反例：**任意重编号核心、强迫所有核非空、重新运行不同构造器，都可能改变时序，不能替代空核嵌入证明。

**最小实验：**从明确的单核计划逐次追加空核，再做有谱系的有限迁移；每个 q 单列。

**成功价值：**跨核 warm-start 至少能保住父解。

**失败应砍什么：**相应域的无条件 continuation，不改写固定单核基准。

# 5. 必要的数学形式化

## 5.1 行为响应向量应是“类型化记录”，不是一个混杂数值向量

建议冻结如下 Φ。这里的“向量”允许包含图、序列和事件对象。

| 机制 | 应保留的观测 | 差异定义 |
| --- | --- | --- |
| Task partition／boundary | 原成员集合、核心归属、核序、Task 依赖 | 成员关系变化、迁移数、边增删 |
| COPY | 完整 COPY 结构、原 tensor、源／目标角色、实际生成 ID、字节分项 | 节点／边差、角色对齐、字节差 |
| Step1 | 原始完整序列及 B 的优先后序列 | 相邻关系／逆序变化；另报计算投影，但不代替完整序列 |
| spill／backing／incarnation | victim、backing 来源、是否写出、from/to/version/pos、重接边 | 有序记录差，新增／删除／版本链差 |
| Step3 FIFO | 四条 Pipe 的完整 FIFO，含 COPY 和 spill | 分 Pipe 顺序差 |
| memory dependencies | WAR/WAW 来源、复用字节、被复用 tensor、位置 | 带属性边差 |
| release | Q1 Task 门控；B 跨核 COPY 释放；全部并列控制前驱 | 时刻差、控制集合差、slack 变化 |
| DDR contention | 带身份的在途请求、剩余量、更新时间、实际与投影完成时刻 | 事件对齐、区间差、远端响应 |
| Q3 Cache | key、hit/miss、插入／驱逐、有序 FIFO、在途请求、两个池 | 事件序列和状态差 |
| Makespan／result | 标量及完整正式对象 | 差值、比值、全字段差异 |

**对齐规则必须保留两层。**原计算 ID 是稳定锚；生成 COPY／spill 可按原 tensor、来源成员、端点角色、出现次数及使用锚点辅助匹配。但实际 ID 仍须保留，未匹配对象记为新增、删除或未知。

这种对齐用于解释，**不是已经证明安全的 alpha-renaming 或缓存键**。

## 5.2 编辑大小、局部响应与耦合

建议先保留多维编辑签名：

$$e(P,P')=
\bigl(
n_{\mathrm{同组关系改变}},
n_{\mathrm{操作换核}},
n_{\mathrm{共同对象顺序逆转}},
n_{\mathrm{直接编辑原操作}}
\bigr).
\tag{OMA-01}$$

同组关系改变数可以通过分区交叉计数计算，不需要真的枚举所有操作对。每项同时报告原始值和归一化值。

D11 的局部响应按上述对象分别计算。还应测量两个动作的非加性交互：

$$I_{a,b}(P)=
M_E(b(a(P)))-M_E(a(P))-M_E(b(P))+M_E(P).
\tag{OMA-02}$$

它只在四个计划都合法有定义、动作参数在组合中仍有意义时使用；**不保证对称，也不等于连续 Hessian**。

D12 的三个量应这样落地：

**层耦合：**预先固定 L1–L6 的子观测和归一化差异，采用 CRG-10。建议同时报告“严格零容差变化”和“实用显著阈值变化”，避免生成 ID 漂移把所有层一律染成高耦合。

**对象耦合：**优先以原计算操作为固定分母；直接编辑邻域在运行前定义。新 COPY／spill 在单独生成对象层统计，不能让分母随结果任意变化。

**传播距离：**同时报告原计算图／Task 图最远可达距离，以及“原依赖图不可达但明显受影响”的比例。后者在共享 DDR 中尤其重要。不可达对象不能被丢弃来制造局部性。

时间响应必须分开**开始时刻变化**和**持续时间变化**。前者可能只是统一后移，后者才直接表明服务过程发生变化；两者都重要，但含义不同。

## 5.3 guard 与敏感方向的可测版本

至少保留两种分辨率的 ρ：

**细签名**记录 COPY 是否存在、overflow/victim/backing 分支、FIFO、release 控制项、池活跃次序与 Cache 事件；**粗签名**只保留事先指定的类别，例如“发生 spill／没有 spill”“存在远端入口控制／没有”。

细签名可能让每个方案独占一个 regime；粗签名可能漏掉决定性切换。**这是要测量的折中，不应提前选择一个使压缩率漂亮的分辨率。**

真实 ρ 通常事后才知道。线上 detector 只是预测或证书，不能把运行后的 guard 真值当作免费输入。

对 D39，可先固定操作类别及每类采样分布：

$$E_c=
\mathbb E_{(P,a)\sim\mu_c}
\left[
\left(\frac{\Delta M}{M_E(P)}\right)^2
\right],
\qquad
\eta_r=
\frac{\sum_{c\in\mathcal C_r}E_c}
{\sum_{c=1}^{K}E_c}.
\tag{OMA-03}$$

操作类按类平衡，而不是谁采样多谁“解释得多”。前 r 类必须在开发组选择，再到另一组图／核数测 $\eta_r$，并同时报告改善、退化和显著事件覆盖。总能量为零时记“不适用”。

D13 的稳定性还需要明确的小编辑阈值、显著响应阈值和域内比例；**响应能量集中不能替代这三个条件**。

## 5.4 行为等价应该截断在哪里

完整 result 的恢复关系可写成：

$$D_G\!\left(\pi_{L6}F_E(P)\right)
=\operatorname{canon}(P),
\qquad P\in\mathcal P_{\mathrm{exec}}.
\tag{OMA-04}$$

这里 `canon` 只表示用于证明的整数逻辑方案，不授权生产中丢弃插入顺序。

更有希望的是**下游计算实际消费的 L4 执行程序**。但每层都要防止遗漏：

| 截断层 | 相同到什么程度才可能继续复用 | 常见错误 |
| --- | --- | --- |
| Task/COPY | 有序图、属性、ID，以及后续优先信息一致 | 同 COPY 数、同字节当同图 |
| Step1 | 局部图、tensor size/pos、完整序列和配置一致 | 同计算顺序就当 Step2 相同 |
| Step2 | 完整扩展图、序列、incarnation/backing 与数值条件一致 | 同 spill 次数或同记录总量当同执行图 |
| Step3 | 四 Pipe FIFO、内存边、COPY 工作、跨核链接一致 | 只比较 M/V 计算词 |
| 全局事件 | 相关状态、同刻顺序、余量及输出历史一致 | 同逐操作时刻就当完整 Cache/结果相同 |
| 面向未来 A | 还要保持动作适用性和状态更新闭合 | 当前相同就永久去重 |

对 Q1，可以先利用一个较弱却很有用的分解：

$$F_E(P)=
\operatorname{Render}\!\left(
\operatorname{Replay}(K_{\pi},A(P));\mu(P)
\right).
\tag{OMA-05}$$

固定分区的真实编译程序是 $K_{\pi}$，归属／核序／门控是调度外壳，$\mu$ 保存正式输出需要的标签和统计。

**这说明有重复计算可省，不说明存在 D15 大商。**

## 5.5 D17 的充分状态必须满足“操作闭合”

一个实用的充分条件是同时证明：

$$P\in D_a\iff d_a(S(P)),
\qquad
S(a(P))=\bar a(S(P)),
\qquad
\sigma_\Phi(P)=o(S(P)).
\tag{OMA-06}$$

第一项保留动作可用性，第二项允许在压缩状态上更新，第三项保留当前观察。对操作序列长度归纳，就能推出 D15，从而满足 D17。

**只证明第三项——这个状态能算当前结果——远远不够。**这正是“原生可重放程序”和“未来充分状态”的区别。

| 指定问题／A／Φ | 候选表征 | 当前判断 |
| --- | --- | --- |
| Q1 固定分区 move/reorder，Φ 为 M | 共享编译程序＋当前核序＋验证 Task 图 | 可以减少重复存储／编译；不是已证明最小状态 |
| Q2 固定归属 priority/grain，Φ 为 M | 完整桶／优先信息及可重建局部图 | Pipe 投影能解释当前执行，但未必支持未来 priority 操作 |
| Q3 同类动作，Φ 为 M＋Cache 事件 | 上述信息＋逻辑 key／size／Cache 和双池规则 | 紧凑闭合表征未证明；占用量和命中率肯定不够 |
| 任意 split/merge/move，Φ 为 full | 至少能恢复完整逻辑方案 | 不值得追求通过行为合并得到通用低维状态 |

例如两个 Cache 状态包含相同两个 key，但 FIFO 顺序相反；下一次插入第三个 key，再读取其中一个，就能区分它们。类似地，同样的总剩余搬运，按请求分配不同会导致不同完成顺序。

这些是**字段必要性的机制反例**。要把它们升级为某个 D17 反例，还必须证明两个状态来自指定方案域，以及相同未来操作能实现区分过程，不能跳过这一步。

此外，把整个 plan 编成一个大整数，不是有用的“低维表示”。应比较**信息量、共享静态数据、构造成本和更新成本**。

## 5.6 哪些正式结构适配，哪些不适配

**Partial order：Go。**计算 DAG、Task＋核链 DAG、完整执行 DAG 各有清楚含义；不能混用其合法性结论。

**Max-plus：受限 Go。**固定依赖、固定时延和给定释放的最早事件问题有成熟代数结构。本轮核对了 Baccelli 等书中 Theorem 3.17／3.20 的路径闭包解释；它不赋予动态 DDR／Cache 一个固定线性响应矩阵。[[图片：]Rocq](https://www.rocq.inria.fr/metalau/cohen/documents/BCOQ-book.pdf)

**Piecewise affine：只适用于明确定义的影子模型。**固定 E 的方案是离散对象，必须先指定数值坐标或参数轴。固定事件次序／活跃集合后，实数模型对工作量和等待可能呈仿射；对带宽有倒数，官方还有 `ceil`、EPS、binary64。不能将实数等价写成 E1 零差分。

**Finite-state／automaton：局部 Go。**固定有限 key、size、容量的 Cache 子机有有限有序状态，但状态数可能很大。加入时钟、剩余服务和动态生成身份后，不自动得到有用的小自动机。

**Bisimulation／Nerode：作为检验工具 Go。**本轮封闭 24 状态实验可以逐轮细化到不动点；正式大图的抽样邻域不能冒充封闭状态空间。Paige–Tarjan 的最粗划分思想提供方法背景，但本轮实现只是直接细化，不是其优化算法。[[图片：]CS Princeton](https://www.cs.princeton.edu/techreports/1986/038.pdf)

## 5.7 多核尺度轴

在固定 q、C、H 和参考 runtime 下，把空核加在末尾，不改变旧活动操作的发射／退休参与顺序：

$$M_{E_{k+1}}\!\left(C_k^{\mathrm{empty}}(P)\right)
=M_{E_k}(P),
\qquad
\inf_{\mathcal P_{\mathrm{exec}}(E_{k+1})}M
\le
\inf_{\mathcal P_{\mathrm{exec}}(E_k)}M.
\tag{OMA-07}$$

这是声明域内的源码级嵌入结论，不是完整 result 相等：核数、空核条目、Q2/Q3 的 Task 元数据会变。

真正利用新核后的收益，必须另测；任意核心重编号也不能默认保持同刻事件顺序。**Q1/Q2/Q3 分别沿核数轴研究，不把 q 变化合成同环境“小编辑”。**

# 6. “局部评估器集”的明确判断

## 6.1 对四种预测目标的取舍

| 目标 | 判断 | 原因 |
| --- | --- | --- |
| 跨 G/q/k 的统一绝对 Makespan 预测 | **No-Go，作为当前主线** | 尺度和机制切换混在一起；已有精确重放路径，尚无证据证明另建大代理值得 |
| 直接预测同父计划编辑的 ΔMakespan | **Conditional-Go** | 最贴近动作决策，但差分不会自动消掉误差，两个动作的 Δ 也不能直接相加 |
| 同池 pair ranking | **Conditional-Go，优先小试** | 不要求虚假的数值精度；仍需测近优候选保留和短名单遗憾 |
| 只判断是否值得精评 | **Conditional-Go** | 与预算最直接，但错杀峰值风险最高，必须有拒答和挑战槽 |
| 精确机制量：合法域、边界字节、冻结门控 | **Go，作为特征或证书** | 可验证、可解释；不能因此替代 Makespan |

## 6.2 不再按旧 E2 的性能假设设计架构

P1 exact batch 的固定分区复用已经是实际接口；native replay 是更窄输出、明确数值域的重放路线。P23 当前适配是**局部编译＋原生全局重放**，并不是此前那个误差较大的简单回归代理。

因此，局部专家的竞争对象必须是**当前实际精评路径**。尤其 P23 报告显示，冷候选主要耗在局部编译；再压缩已经很快的事件重放，未必改善端到端成本。

## 6.3 推荐的路由逻辑

先核对 q、H、输出能力与预算；再提取运行前可得的廉价特征。若当前候选本来可以便宜地精确重放，直接精评，不强行经过模型。

否则最多请求少量局部专家。出现域外、未覆盖的 guard 风险、强模型分歧或过宽不确定区间时，**ABSTAIN → E1/E0**。

**ABSTAIN 不是丢弃候选。**否则最有价值的跨 guard 操作会被系统性排除。

模型一致也可能只是共享偏差，所以需要预注册一部分精评槽给随机和机制多样挑战者。训练／校准按图和父计划整组留出，不随机拆散同一父计划的近邻来制造泛化。

成本必须算完整：

$$T_{\mathrm{routed}}
=
T_{\mathrm{features}}
+T_{\mathrm{detector}}
+T_{\mathrm{models}}
+T_{\mathrm{fallback}}
+T_{\mathrm{selected\ exact}}
+T_{\mathrm{final\ E0}}.
\tag{OMA-08}$$

P23 的 `full=True` 或回退可能实际调用一次本问题 E0；P1 对应路径可能调用完整 E1。派发前要按真实路由预留，不能把 `native_enabled=True` 当成“不会消耗完整评价”的承诺。

验收要同时看：**risk–coverage、近优集合召回、shortlist regret、拒答率及原因、真实总时间、同预算 E0-confirmed 质量**。仅有低平均误差或高相关系数，不足以接入。

# 7. 建议 Codex `/goal` 候选任务

以下是**候选卡，不是已经启动或获得预算授权的任务**。不代最终综合者分配写权。完整卡还保存在GOAL_CARDS.md。

## Goal ID：MAP-OBS-01 — 建立不改变语义的分层行为观测

**核心命题：**只读观测可以生成有 provenance 的 L0–L6 签名，并保持完整 E0 结果不变。

**branch／commit／输入：**官方 `main@f27ef37…`；Q1 `4dff90e…`、Q2 `74c4637…`、Q3 `a4e7ee1…` 的固定计划，先声明最多六个输入。

**允许修改：**新建研究目录、测试、结果、只读 hook／外层适配器。**禁止修改：**官方字节、正式输入/config、生产 E1/E2、各算法默认实现、封存结果。

**实验协议：**先冻结 schema 和对象对齐；每例无观测／有观测配对；不新增事件切点；完整对象严格比较；普通性能测量关闭观测。

**输出产物：**observer、schema、原始及对齐快照、typed diff、未匹配对象清单、成本与失败记录。
