# 交给 Codex 的 A 题研究总纲

## 目标、适用范围和上下文优先级

目标是以可验证的高质量完整成果争取进入数模之星答辩，再考虑答辩表达；不得为了演示性牺牲算法、实验和交付质量。没有依据预测排名或胜率。

用户有三台游戏本、一台 MacBook Pro，已有可用的分布式 Agent 协作协议；AI 资源包括其提供的 Codex 20×和 CodeBuddy 积分。不要假设额度无限，不把机器数量等同于独立模型配额，也不要在比赛期间另造一个复杂 Agent 调度平台。沿用已有协议。

本聊天前两轮是仅有题面或单例时的探索。遇到冲突时，用本包 `AUDIT_REPORT.md` 的代码事实与实测证据更新旧假设；不要把聊天历史中的提案和静态推断当成实验成绩。所有事实先核验当前官方材料哈希；有正式更新则重建语义对照和回归结果。

读取 `official_manifest.json`、`AUDIT_REPORT.md`、`evidence/static_all100.json`、`evidence/baseline_bound_gaps_all100.json`、`evidence/candidate_comparison_17.json` 和 `evidence/singlecore_coverage.json`。这些文件已经完成的工作尽量复用，不从零重做无差别原始 JSON 阅读。

## 主线

构建“考虑固定 Pipe 顺序、内存复用依赖与共享带宽的结构自适应联合调度器”。优化对象是合法的 node_to_subgraph 与 core_schedules，经原样官方程序展开后的 Makespan。

不是只做静态图划分；不是一套理想 NPU 模拟器；不是把各种黑箱优化算法跑一遍挑最好；也不是只针对 case_010 的 2-byte 切分规则。

候选集合保持小而机制不同：可靠保守基线、结构/阶段感知构造、通用代价感知列表构造，以及在有收益证据时启用的顺序与 L2 局部改进。采用按实例特征与预算触发的条件式组合，保留已通过官方评估的 incumbent。

## 必须落实的源码事实

1. 三问均经过 Step1/Step2/Step3。最终多核阶段执行 Step3 的固定逐 Pipe FIFO 和内存复用依赖，不是任意 ready-op 动态选择。
2. 可行性检查至少包含节点覆盖、分区商图、Task 顺序组合和全局展开执行图。通过 derive_multicore_plan 不代表最终可执行。
3. 场景 B 对每个源核—目标核对都生成 COPY_OUT/COPY_IN；不要错误采用“一次写出、所有远端读”的通用多播假设。
4. 问题 2/3 同核子图合为 Task，但分桶顺序仍影响内部 Pipe 顺序、驻留和 SPILL。必须把切分、数据归属、执行顺序分开表示。
5. L2 按 logical tensor key 查询，在途首次 miss 不自动合并；跨核源 COPY_OUT 的同步等待不会因为目标 Cache hit 而自行消失。
6. 问题 3 的官方 data_movement_bytes 不按 Cache hit 扣减。保留原官方指标，另列实际 DDR 服务字节量。内存峰值字段也要注明取自局部 Step3。
7. COPY 工作量逐操作 ceil 后再共享带宽。不要拿总字节/带宽冒充官方精确耗时。
8. 原图、cycles、张量大小、固定配置、评分代码不可修改；不可删除/重复计算、不重结合归约、不改节点 ID。局部图/辅助依赖只用于分析，输出仍只有规定两字段。

## 研究路线与替代关系

### 路线 A：结构与阶段感知的粗粒度调度

识别重复分支、共享输入、长链、归约/广播、窄接口、Cube/Vector 负载互补。统计的是拓扑和张量属性，不猜神经网络名称，不以 case 文件名分类。

优先避免在大张量连续计算链中间切开；在合法的弱接口处分阶段。场景 A 必须联合优化 Task 数、同步深度、输入重复读取和负载平衡，不把每个细块都单独变成一个 Task。允许一个子图包含互不连通的独立计算，题面没有要求子图连通。

合并后要检查商图，必要时提供 DAG-safe 合并/拆分。分阶段的前后同核复用不能通过制造子图商图环实现。

起始机制样例可使用 case_010、case_051，反例必须包含 case_002、case_044、case_094。这些编号仅用于研究选样，不能出现在生产算法分支中。

### 路线 B：固定调度器感知的分配与顺序联合优化

建立全局参考拓扑序、核心归属、局部分桶和逐 Pipe 投影的中间表示。外层以计算/通信/驻留/关键路径成本生成候选，原样官方程序决定可执行与真实收益。

先做固定核心归属的顺序消融，再做固定宏块的核心分配消融。利用执行等待环的带类型边定位必须修改的决策；用局部重排、迁移、合法合并修复，不能删掉原图依赖或篡改 validator。

研究全局参考序能否导出可证明安全的编码，但在覆盖 COPY 和 SPILL/内存复用边的证明完成前，不得声称仅有原图拓扑序即可保证最终可执行。

与路线 A 共用 IR 和评估接口；保留一个独立实现者作为挑战者，防止共享同一错误代价模型。

### 路线 C：下界、结构压缩和局部精确方法

独立审核纯计算关键路径、各 Pipe 总负载、必需冷读流量和 head/tail 窗口容量下界。下界小不证明可达到；当前解到下界的比值提供最优性差距上界。

研究重复分支的计数化/对称性压缩，但保持原节点并处理官方 id tie-break 的影响；未证明评估器不变性前，只把其视为构造启发式，不能宣称严格等价降维。

在边界较小的局部区域，尝试固定外部条件后的动态规划或精确优化。简化模型的最优不等于完整模拟器的最优。微图 oracle 可完整枚举验证，已有 4-op/2-core 基础版本。

这条路线从项目开始即并行，不能被降级为“最后给已有算法补公式”。交付可以是算法、下界证书、停止优化某族实例的依据，或明确反例。

### 路线 D：L2 时序（有条件投入）

先区分首次并发 miss、容量淘汰、SPILL 回读、共享输入复制和计算主导。用原有独立工作重排影响时序，不新增预取操作或任意等待指令。

至少做固定方案无/有 L2 对照，再把无 L2 优化方案与 L2 专用方案交叉评估。优化目标仍是 Makespan，不是命中率。若命中显著提高而关键执行时间无改善，降低该机制优先级。

## 统一工程边界

official 为只读；solver、experiments、research、paper 独立。先冻结共同输入/输出 schema，再让各路线并行实现。

每个实验记录：job_id、case、scenario、core_count、seed、算法版本、参数、输入/配置/官方代码/方案哈希、运行环境、构造时间、内部评估次数、全部求解时间、status、makespan、官方搬运字段、Cache 字段、错误与等待环。每项产物只由一个 job 写入；使用临时文件及完成后的原子发布。

不要把不同 N/场景的结果写回官方 data 默认文件名，避免覆盖。不要让多个 Agent 直接写同一个工作区；各自工作树/分支，接口与公共模块指定维护者。

内部可做缓存和经过差分验证的快速成本估计；官方 code、config 与数据字节保持不变。最终数值由原样 CLI 或原样函数重评，不以内部代理替代。

## 预算与机器

MacBook Pro 作为用户主控、理论/接口审核和结果汇总节点；两台游戏本承担主线与挑战线；另一台维持干净复现环境并执行验证和回归。角色不是永久绑定，实验可进入共享队列。

四台电脑用于研发并行，仿真目标 N=2—5 是另一层概念。优先测 CPU/内存/序列化和评估热点；不要预先把显卡当作本题主要资源。

强模型用于问题建模、源码合同、理论/算法、反例与集成判断；低成本模型用于明确接口后的实现、测试和记录。不要机械规定“95%交给便宜模型”；也不要让强模型反复吞入 250 MB 原始 JSON。先由确定性程序提取任务相关视图。

把约四分之一强模型可用预算留给后半程作为初始安排，再据实际额度调整。LLM 不能成为最终求解器运行依赖。

最终求解器采用显式墙钟预算，先得到可靠合法方案，再尝试可中断改进；将所有内部评估和选择成本计入求解时间。题面建议单例 5—10 分钟并避免暴力迭代，不可把四机离线穷搜最佳结果冒充快速构造。

## 实验与论文验收

- 最终覆盖全部 100 个用例、三问、N=2—5；已存在 1,200 组多核基本组合，另加单核与对照。
- 固定 singlecore_evaluate 的 100 个基准完成后才能报全体平均加速比；Q1/Q2 的单核点按题面定义。问题 3 的一核有 L2 点也应实测，不能因为只有一核就假定无 Cache 收益。
- 开发、冻结验证按结构族/规模管理；最终全部报告。不要按连续 case 编号简单切分，不要在看完全部结果后声称有未见的测试集。
- 同预算强基线，完整逐用例结果，分结构结果，构造耗时和失败情况；负向案例必须保留。
- 核心消融：张量共享 vs 普通边；有无同步阶段；固定归属下顺序；有无生命周期/内存依赖；结构路由 vs 单一构造；固定方案下 L2。
- 每个摘要数字和论文结论链接到唯一可复现产物。冻结后由独立节点从干净 checkout 重建主要表格与曲线。
- 正式竞赛对 AI 的许可和披露规则不在此附件中完整说明；队长核验相关正式规定。不要引用聊天中的“都允许”作为参赛依据。

## 建议工作节奏

前 15%：共同合同、基线和数据索引，同时启动理论与结构探测。接下来 25%：不同机制路线的小规模可证伪实验。中间 35%：选主线、整合、同族迁移和预算内求解器。最后 25%：冻结、全量实验、消融、写作与独立复现。

所有路线用同样的最小验收卡：假设；适用结构；最小实现；支持证据；反例；成本；下一步；停止条件。连续两轮不能在预先选定的代表性/验证用例中产生可复现改进，或只提高次要指标不改善 Makespan，则合并、缩小适用范围或停止。可有独立明确的理论交付，不强迫所有理论线都立即改善分数。

## 启动指令

先复用证据包建立事实/假设索引和任务依赖图，完成接口与唯一写入者分配；随后启动结构路线、通用分配/顺序挑战路线、理论线三个独立研究过程。L2 先用已有微图与全部固定方案对照作为诊断，不抢占主线。第一轮交付必须是可运行方案、官方结果、失败样例和结论，不是只有长文方案。不得宣称已经达到数模之星水平；用结果和证据逐步提高竞争力。
