# Scientific Figures

根据数据与表达目标选择绘图工具，交付可重新生成、能追溯到结果的论文图件。

## 选择工具

- **数值、统计、残差、敏感性图**：优先使用项目已有的 Python / Matplotlib 环境。绘图代码放 `src/`，读取 `results/<run>/` 的实际结果，图件放 `figures/<run>/`。沿用已有脚本和锁文件，勿为绘图单独制造一套实验数字。
- **技术路线、算法流程、依赖关系**：使用随附的 ELK → Draw.io 脚本，见 [Draw.io 用法与边界](references/drawio.md)。小型图也可以直接写可编辑 XML；已有 `.drawio` 应按原结构修改。
- **MATLAB / Wolfram / Julia**：用户已有这类求解代码时，保留该语言与环境，读取相同的结果表，保存绘图源文件及版本记录。不要仅为统一外观迁移求解器或安装大型运行时。
- **System Atlas**：继续承担系统模型和协作视图；本 Skill 承担论文交付图，不能把图中节点自动当作已实现或已验证模块。
- **概念插画**：按宿主提供的图像生成能力制作；生成图不能充当观测数据、精确统计图或可编辑流程图的验证证据。

## 项目约定

1. 从任务卡、结果表和已有论文段落确定本图要回答的问题。常规字号、间距和配色可自主选择；只有来源、单位、连线语义或结论存在实质歧义时询问用户，并继续可独立完成的部分。
2. 保留数据、预处理和单位含义。误差棒注明 SD、SE、CI 等定义及样本量；缺失值不当作零，不隐藏失败样本，不为美观改变数值或截断到误导结论的范围。合成示例明确标注。
3. 优先 PDF / SVG 矢量图，PNG 供预览。保留 `.py` / `.m` / `.wl` / `.jl` / `.drawio` 和语义 JSON 等可编辑来源。位图分辨率、最终纸面宽度和模板要求以当届公告为准；不要把默认 300 dpi 当作合规证明。
4. 比较图使用一致的单位、颜色含义和轴范围。颜色搭配线型/标记/文字，确保黑白打印仍可区分。中文字体按本机已安装字体选择并检查缺字；不硬编码某个人的字体路径。
5. 在最终论文宽度查看导出图，检查文字、图例、公式、箭头端点、遮挡和多面板关系。布局检查通过不代表视觉或科学结论验收。发现具体缺陷后修复并复查相关范围；无新证据时不重复扩大测试。
6. 记录输入哈希、代码版本、环境、命令、参数与输出。图注引用实际结果表，并说明假设和局限。语义 JSON 驱动的新图应修改 JSON 后重生成到新文件；手工修改 `.drawio` 后将其作为当前编辑源，避免被旧 JSON 覆盖。

## Astra 使用约定

本工具通过 Node.js 确定性排版，无模型 API 或 API Key。Astra 负责理解内容、选择图形、写代码与检查导出图；不锁定团队成员的模型设置。

遵从用户已授权的任务范围。旧绘图 Skill 中的泛化暂停门槛、反复“95% 接受概率”自评分不作为本项目验收标准；使用可查证缺陷和实际产物。复杂且确实获益的图可安排独立审查，但常规小改动无需额外代理。模型适配依据与研究来源见项目 `docs/FIGURE_SKILLS_RESEARCH.md`。
