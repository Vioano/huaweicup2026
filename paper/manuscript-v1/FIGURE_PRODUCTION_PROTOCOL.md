# 论文图件制作与验收规范

更新：2026-09-26。适用范围：本论文正文、附录、机制动画及配套图件。

**这是本项目制图的统一入口，汇总用户在本任务中的连续要求。后续制图先读本文件，再读具体图稿说明与数据来源。** 用户的新要求优先于本文件；更新本文件后同步术语表和题纲，不能只把更正留在聊天里。本文档记录已明确的要求，不把助手提出但尚未验证的工具方案写成成功事实。

关联文件：[详细题纲与写作对齐](DETAILED_OUTLINE_AND_ALIGNMENT.md)、[中英文术语约定](TERMINOLOGY.md)、[数据与理论来源](SOURCES.md)。

## 1. 图服务于什么

1. 首先符合原题执行语义，说明算法为什么有效，而不只展示漂亮的分组框和结果数字。
2. 三题构成同一条可理解的研究主线：共同的图、方案、合法性与评价接口，随 Task 屏障、核内驻留、共享只读 Cache 的变化逐步扩展。读者能看出哪里保持不变、哪里新增、为何需要新增。
3. 使用统一的配色语义、节点形状、方向、术语和比较方式；优先让同一真实片段贯穿三问。
4. 达到计算机／AI 顶会论文配图的清晰度和审美。用户认可的生图风格是视觉依据，不再退回拥挤的矩形、巨大字体、文字压箭头的初稿。
5. “3Blue1Brown 级别”指原理可见、变化可追踪、推导有直觉；不照搬其深色背景和配色，也不以动画炫技替代论文论证。
6. 讨论中的 **coherent 只是对三题理论连贯、统一、论证完整的要求**。不得在论文里写成官方术语、自创算法名或“Coherent 框架”。正文写“本文研究框架”，并落实其具体内容。

## 2. 默认采用两阶段，按图决定是否增加第三阶段

### 2.1 机制图的默认路线

**结构正确的骨架 → 生图模型完成最终美术与中英文排版 → 核验后直接入稿。**

- 第一阶段从已核对的 JSON、方案、证明或执行规则生成简单结构稿；可以不好看，但节点、边、方向、分组、数值和边界条件必须正确。
- 第二阶段把结构稿与明确的内容清单交给生图模型，生成最终机制图。模型同时负责布局、字体、字号、文字位置、框大小、留白、箭头曲线及中文排版。
- 科学内容、文字和最终纸面可读性通过检查后，**允许直接使用生成的 PNG**。不能为了“必须有代码”再把正确且好看的图重画一遍。
- 生图稿存在错误时，只修复有证据的错误；优先让生图模型作有明确不变量的局部修订。不能把未经检查的生图输出直接视为正确。

### 2.2 第三阶段只在确有需要时启用

适用原因：交付明确要求真实矢量；内容需要经常确定性更新；图中包含必须精确控制的几何；局部内容不能在生成稿中可靠修正。

- 优先验证自动轮廓矢量化：沿现有成图提取字形、框线、箭头曲线，不重新决定布局。
- 矢量描摹后的文字一般是轮廓，不能冒称为可直接编辑的文本；节点也不自动成为带语义的可编辑对象。
- SVG 或 PDF 后缀不代表矢量。检查其中是否嵌入整张位图；不得用位图外包 SVG，或把每个像素换成小方块，冒充符合本任务意图的矢量复刻。
- 矢量化是近似过程，原图抗锯齿、渐变和未知字体不能靠一句“像素级”保证恢复。必须回渲染到原图相同尺寸，记录真实偏差；不宣称未经测量的逐像素一致。
- **停用凭目测重新设置全部坐标、字体和贝塞尔曲线的默认做法。** 风格相似不等于忠实复刻；重叠的手工重排稿不得标为 final。
- 自动转换质量不够时，保留合格原图用于允许位图的图件。确需矢量的单图单独解决，不让整个论文被无止境重绘拖住。

### 2.3 数据图直接由代码生成

真实 Task/Pipe 时间线、overlap、性能曲线、散点图、统计分布、敏感性和数值坐标图，始终读取冻结数据作图。生图模型可提供视觉样式参考，但不能重画实测时间色块、改变坐标位置或猜测数字。无须为每张数据图机械执行一次生图。

## 3. 生图前一次说清楚中英文边界

**中文说明直接在生图阶段生成。** 不先做整张英文图，再默认用代码替换中文、改变字形和字号。

| 内容 | 约定 |
|---|---|
| 通行短术语 | Core、Task、Cache、Pipe、DDR、DAG、FIFO、JSON 等保留英文 |
| Core | 用户明确要求写 Core、Core 0；不改成“核心0” |
| 题面英文及源码标识 | 保持原拼写、大小写：COPY_IN、COPY_OUT、ADD、sg0、node_to_subgraph、core_schedules |
| 指标、符号和单位 | Makespan、cycle、B、B/cycle、K、h−r 及数学符号保持规范写法 |
| 解释、动作和自定义机制 | 中文，例如原始划分、分叉援助细化、联合迁移、完成后填充、命中？ |
| 有必要连接已有理论的概念 | 首次可写“中文（通行英文术语）”；英文必须确为该概念的既有术语 |
| 作者自创或组合的概念 | 优先中文，不通过自造英文名称制造权威感 |

每条生图提示词包含：**保留英文清单、中文标签逐字清单、数字／符号不可变清单、图形不变量**。短词可由模型合理安排排版；确切标签、对象编号、公式和数值不得自由发挥。

检查中文是否正确、自然、清晰、风格协调、无缺字或伪字。用户允许直接采用排版合适的模型中文字，不要求为了替换成本机字体而再次重绘。最终仍核对实际投稿格式与纸面大小；不能声称生成字形已认证为某字体或某个精确字号。

## 4. 统一风格的具体要求

- 采用已认可的浅色论文风格，低饱和蓝／青绿／紫／琥珀色；柔和分组底色、清晰深色文字和适度留白。避免模糊的深色渐变页脚和无信息装饰。
- 同一对象跨图保持颜色和形状含义。例如操作节点、分组边界、跨子图依赖和图外端口不能随意换身份。
- 同一比较图尽量固定节点位置，仅改变分组、归属或边的语义。相同时间比较使用同一单位和可比较的横轴。
- 保留生图稿恰当的文字基线、内边距、圆角、线宽、箭头端点和曲率，不以“近似位置”替代。
- 标签不能压住箭头或其他文字；连接线不能穿过无关节点；文字不能贴框或越界。检查全图，也检查被改动的局部。
- 美观服从内容：不能为简洁删掉重要外部依赖，不能为对称改变真实拓扑，不能用渐变颜色伪装实际强度。
- Manim 只在连续变化明显帮助理解时使用，沿用论文配色；先有纸面可用关键帧，不先制作耗时长片。

## 5. 真实切图与 overlap 必须形成证据链

固定链条：**原始图 JSON → 合法切分和调度方案 → 执行事件 → Task／Pipe 时间线 → 结果解释**。

1. 切图示例来自真实输入片段，保留真实 node/tensor ID；记录裁剪范围和图外输入、输出。不能把裁剪图冒充完整执行图。
2. 不同拆法展示同一原始片段，明确各子图、Core 归属与执行顺序。各图使用一致的对象映射。
3. 对应时间线必须来自同一份方案的真实执行记录：上层显示各 Core 上 Task 的时间跨度；下层显示各 Core 的四条 Pipe 忙碌区间。
4. 数值精度由源数据决定，明确时间单位和 Makespan 终点。不得把求解程序秒数与模拟 cycle 混用。
5. 通过图说明空隙、等待、同步、搬运、负载偏斜和重叠的变化；只说明证据确实支持的机制。
6. 允许同一图的全览加局部放大；明确放大范围，保留整体上下文。不得通过不同横轴夸大优劣。
7. 图上的全图成绩与局部片段分开说明。例如 case_026 的 5→7 Tasks、44,114→42,014 cycles 是完整方案成绩，不是八节点片段单独跑出的成绩。

## 6. 数学深度的可视化

- 定义先行：图上首次出现的操作、张量、Task、子图、Core、状态、动作、前沿量与费用要与正文符号表一致。
- 显示“对象—约束—变换—结果”的因果关系；优先用小而真实或明确标注的构造例子，解释为什么一个条件必要。
- 区分构造代理、合法性证书、必要下界、受限域局部最优性和官方执行结果。不同保证不能画成同一个“已证明最优”标志。
- h−r 等证明图标清适用域；构造示例不能冒充实际运行曲线。理论上的步序不自动等于 cycle 时间轴。
- 反例和失效边界保留：搬运变少但 Makespan 变差、Cache 命中但整图没有受益等，均用于说明统一模型为何必要。
- 研究主线的统一性体现在共同定义、逐问扩展的语义和相同的证据逻辑，不要求三问机械使用同一种算法。

## 8. 自动化、成本与验收边界

目标是批量处理，避免每张图靠助手反复看图、重新摆框和长上下文试错。

### 可自动完成

- 从冻结 JSON／CSV 提取语义清单、图输入、统计量、时间区间和哈希。
- 将统一术语与逐图标签清单写入提示词，复用已经认可的样式参考。
- 检查文件存在、尺寸、输入身份、数值一致性、节点／边清单和是否引用旧数据。
- 可选矢量转换后：检查 SVG 是否真正包含路径、PDF 是否嵌位图、同尺寸回渲染差异、边缘距离与局部异常。大面积白底不能掩盖一处丢字或错箭头。
- OCR 可辅助查错字、漏标签和编号，**不能单独证明图的拓扑和全部数学内容正确**。

### 必须保持的科学验收

生成模型有可能改边、改方向、漏节点或改数。结构源正确并不自动证明生成稿正确。依照逐图清单集中检查一次；发现异常只回到相关区域，不进行没有新证据的整图循环。最终论文实际大小再集中检查可读性。

自动化的目标是减少机械工作，不是承诺零审查、零误差。未实现或未验证的自动检查明确标为计划，不能记作已经运行。

### 成本边界

- 复用一个确认过的风格样张和短清单，不为每张图重新研究设计风格。
- 不为常规制图开最强模型子任务，不按每个样本派 Agent；工具转换与数据检查由脚本批处理。
- 出现连续失败先检查路线：直接使用合格生图是否足够，是否根本无需矢量。停止反复手工重排。
- 不因制图追加 solver、E0/E1/E2 或 Pro 理论咨询调用。数据缺口须明确说明。

## 9. 文件与状态管理

每组图至少保留结构来源、逐字标签清单、最终提示词、原始生图、采用版本、核验记录；数据图保留脚本、输入清单与结果哈希。

区分：结构已核对、视觉样张、生成稿已核对、纸面检查、论文采用。风格获认可不等于科学结论获验收；工具导出成功不等于图已经合格。弃用稿移入设计记录，不能与正式文件同名或继续标作 final。

- 手工重排的 `draw_camera_ready.py` 原型在字号、边界留白和标签位置上偏离生图稿，用户明确否定；停止将其作为默认机制图生成器。

- 主线按用户最新决定推进：机制图优先两阶段，生图前明确中英文；数据图由真实数据代码生成；第三阶段按需。
