# 中英文边界与术语契约

依据用户2026-09-26连续更正，适用于正文、图内文字、图注、符号表及动画。中文竞赛论文以中文承载解释，不把整张图翻成英文论文配图。

## 判断顺序

1. 原题使用的英文对象、提交字段、代码标识与单位原样保留，不改变大小写或用另一个中文词掩盖源码对应。
2. 计算机领域长期通行、一眼可辨的简短术语可保留英文，如Core、Task、Cache、Pipe、DDR、DAG、FIFO、JSON。
3. 作者自定义的方法名、机制组合和解释性句子优先中文；必要时首次写“中文（通行英文术语）”，此后用统一中文简称。
4. 括号中的英文必须确有其义；作者自己的组合名不能因为写了英文就被说成公认术语。“coherent”是讨论中的连贯性要求，不是论文术语或自创算法名；论文统一写“本文研究框架”或直接陈述具体模型。
5. 单个标签必须考虑图的局部语境和长度，不机械地“全中”或“全英”。生图前列明中文与英文清单，直接生成中文排版；合格成图直接入稿，不默认用代码重新换字、字号或布局。详细流程见[图件制作规范](FIGURE_PRODUCTION_PROTOCOL.md)。

## 当前统一用语

| 对象或含义 | 采用的写法 | 说明 |
|---|---|---|
| 官方执行对象与资源 | Core、Task、Cache、Pipe、DDR、L1、UB | 首次在正文定义；图中保持原词 |
| 官方操作和字段 | ADD、COPY_IN、COPY_OUT、node_to_subgraph、core_schedules | 原样、原大小写 |
| 数学与短通行缩写 | DAG、FIFO、JSON、h−r、sg0、K | 保留；不改数学符号含义 |
| Core、Core 0 | Core、Core 0 | 用户明确要求保留英文，不译作“核心” |
| Parent partition / Branch-aid refinement | 原始划分／分叉援助细化 | 作者机制名中文优先 |
| Joint relocation / In-core retention | 联合迁移／核内驻留 | 中文表达机制 |
| Complete plan / Confirmed incumbent | 完整计划／最佳已确认方案 | 不保留长英文解释标签 |
| Fill after completion / Hit? | 完成后填充／命中？ | 判定和动作说明用中文 |
| hyperedge | 超边（hyperedge） | 首次可给通行英文，后文“超边” |
| 讨论中的 coherent | 本文研究框架／统一研究框架 | 不将讨论黑话写成正式术语；落实三问统一的定义、递进语义和论证链 |
| Forest | 归约森林策略（Forest） | 作者策略名；代码入口和固定版本索引可保留英文 |
| future-sufficient state | 未来充分状态 | 本文声明动作域与观测后定义的研究对象；不是未经限定的标准定理 |
| Makespan、cycle、B、B/cycle | 保留原指标名和单位 | 中文解释其含义；不把cycle与秒混用 |

图中避免长英文标题和整句说明。直接生成的中文须正确、清晰、风格协调；按论文实际尺寸检查可读性和投稿格式，不把生成字形冒称为已认证的字体或精确字号。代码图与公式混排时分别处理字体，不能让数学排版器把汉字替换为方框。

图内中文仅指必要的内部标签；图号、图名、图注、分图标题与解释段落由 Markdown／LaTeX 管理，不进入生图文字清单。透明背景及内容分层见制图规范第4节。
