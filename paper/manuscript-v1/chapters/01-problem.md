# 问题重述与分析

## 问题背景

神经网络计算图通常同时含有矩阵计算、向量运算和数据搬运。一个 NPU 核心内的 Cube、Vector、搬入和搬出单元可在满足依赖时并行工作；多个核心又共享核外 DDR。因此，计算图上的一条边不仅表示逻辑先后关系，还可能在切分后转化为存储分配、数据复制与跨核同步。图切分的效果需要在最终执行过程中判断。

传统多处理器调度中的工作量平衡和关键路径分析提供了基础工具，但资源增加或局部次序变化可能引起调度反常现象[2]。本题进一步包含有限的 L1／UB、固定核内调度规则、共享 DDR 和只读 FIFO Cache。一个子图的执行时间会随其所处计划和其他核心的活动改变，因而不能简单地给每个子图赋一个固定标量权重，再把问题化为普通的独立任务装箱。

本文遵循赛题规定[1]，以未修改评价程序在固定配置下计算的总完成时间 Makespan 为主要质量指标，同时报告额外 DDR 搬运量，问题三另报告按字节统计的 Cache 命中率。生成方案的程序墙钟是另一类指标。模拟周期衡量方案，墙钟衡量求解程序，两者分别评价。

## 输入、输出及三问的关系

输入是 Op–Tensor 二部有向无环图。张量结点携带位置及字节数，操作结点携带类型、所属 Pipe 及周期数；依赖边连接张量和操作。输出由两个字段构成：`node_to_subgraph` 将全部非 COPY 操作映射到子图编号；`core_schedules` 为每个 Core列出子图的执行顺序。算法可以决定切分、分核及子图顺序，不能直接修改官方核内调度程序、原始计算量、缓存容量或带宽。

三问共享这个输出接口，但对方案的解释不同。

| 比较对象 | 问题一 | 问题二 | 问题三 |
|---|---|---|---|
| 执行 Task | 一个子图一个 Task | 同核全部子图合并为一个 Task | 同问题二 |
| 同核跨子图数据 | 经过 DDR，Task 间不保留 | 可在核内驻留复用 | 同问题二 |
| 跨核同步 | 前驱 Task 完成后等待 | 对应 COPY_OUT 完成后等待 | 同问题二，命中也不取消依赖 |
| 核外只读 Cache | 无 | 无 | 所有核心共享，FIFO 淘汰 |
| 主要新增决策影响 | 切分粒度与屏障 | 复用、容量和发射次序 | 查询次序、命中与双带宽池竞争 |

问题一要求降低切分造成的启动、切换和边界复制代价，同时保持足够并行度。问题二放开同核驻留能力，原来每个子图独立的容量压力转变为跨子图的存活区间压力，分核与排序必须联合考虑。问题三进一步允许跨核读共享，其收益取决于请求是否在正确时间到达、数据是否仍在 Cache 以及其他请求的竞争状态。本文将这一递进关系贯穿模型、算法和图解，而不是分别构建三个互不关联的评分公式。

## 难点分解与研究路径

**第一，逻辑图合法不等于分核次序合法。** 把操作收缩为子图后，需要重新检查子图间有向环；加入各核的执行顺序后，还可能形成新的等待环。合法性必须在完整提交方案上判定，不能只看每一块内部连通或每一条原始依赖。

**第二，边界代价具有复用和时序效应。** 同一个输入被多个操作消费时，数据搬运次数与消费者触及的Core 集合有关，并不总是与切断的操作依赖边数成正比。与此同时，保留数据占用缓存，消除一次复制也可能延长存活区间，挤出其他数据。

**第三，真实流水重叠由动态资源共同决定。** 计算单元空闲可能源于数据尚未到达、跨核释放未到、存储申请次序未轮到或其他执行前驱。仅凭时间线上的白色间隙不能断言其原因；需要把图、编译事件和 trace 关联起来。

**第四，复杂模型必须与求解成本相匹配。** 题面建议避免暴力迭代搜索，以单个用例 5～10 min 给出结果为佳。本文采用结构识别、局部精确子问题与有界候选组合，使每一次评价都有明确用途；不把“限定搜索次数”本身作为方法合理性的论据。

由此形成全文的研究路径：先明确可提交自由度与执行语义；再提取适合构造候选的结构量；用合法性和有适用域的必要下界排除无效候选；最后在完整方案上评价、选择并保留可复核结果。三问共用该逻辑，分别引入屏障、复用和缓存次序三个层次的机制。
