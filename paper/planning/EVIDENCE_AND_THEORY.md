# 从材料堆到论文论证：证据、理论与创新主张

盘点日期：2026-09-26。范围：题面、既有草稿/图件/脚本、研发任务回复与固定报告的只读核对；没有重跑求解器、官方评价或全套数学审计。下文数字来自列明的固定报告，不冒充本次独立实验。

## 1. 先按职责找资料

| 需要确认的事 | 首选来源 | 不足以替代它的材料 |
|---|---|---|
| 原题要求、可提交自由度与评分口径 | 原题、冻结附件、[官方目标核验][objectives] | 2025 参考论文、Pro 建议、团队口头目标 |
| 一个算法实际上做什么 | 完整源码 SHA、统一入口与冻结选择规则 | 流程图、算法昵称、最新单例成绩 |
| 主成绩是否全量 | 同一固定算法的 100 图×5 核逐格记录及审计 | 成绩台历史最优、部分样本均值、混合版本 |
| 图是否可发表 | 固定输入、脚本/可编辑源、实际导出与视觉检查 | 绘图任务书、截图、SVG 文件存在 |
| 理论何时成立 | 明确命题、假设、证明/反例与源码语义核对 | Web Clip 归档完整、Pro 输出很长或很肯定 |
| 理论原文在哪里 | 稳定聊天目录、追加快照、消息 ID 与附件清单 | 根索引的一行摘要、失效下载链接 |
| 本次怎样组织写作 | [章节框架](../chapters/00-outline.md)、本文件 | 研发时间线或所有历史笔记的平铺 |

本次材料分散主要有三种原因：共享主分支、未合并作者 PR、研发分支的最新实验各自更新；同一方法的原理、成绩与图并不总绑定同一版本；理论原件与审计后的可用结论混在多个入口。解决方式是固定来源和建立对应关系，暂不搬迁大型历史目录。

## 3. Coherent 的归位：研究纲领、条件结果、已用机制

Coherent 的 A/B/C 是研究主题：A 讨论官方映射、局部响应与行为压缩；B 讨论瓶颈见证到构造机制；C 讨论切分/合并/重排等操作与可达性。**它们不是问题 1/2/3 的一一对应。** [研究目录][coherent-index]列出的卡片也是建议，不表示每项已实现或已有计算预算。

| 理论线索 | 可保留的精确含义 | 目前适合放哪里 | 需防止的外推 |
|---|---|---|---|
| 官方映射与行为签名 | 计划通过官方编译形成 Task/COPY/Pipe/依赖，再产生时序；压缩必须绑定执行域与守卫 | 第 3 章主线；P1 响应机制 | 当前一次输出相同 ≠ 任意未来上下文下等价 |
| 局部响应 / 离散敏感方向 | 固定签名、固定服务或相应守卫内，描述释放/切点变化如何作用于出口 | 对应局部定理和少量机制图 | 多流 DDR 活跃集变化后沿用原线性/max-plus 模型 |
| 瓶颈见证与结构构造 | 从关键路径、COPY 队首、容量峰值等具体事件解释为什么提出候选 | 各问“为什么这样设计” | 把观察关联当唯一因果解释，或把代理分值当官方目标 |
| 变换与可达性 | CUT/JOIN/SPLICE/RECODE 等在明确结构域内的操作关系 | 附录或方法设计说明 | $P_{ord}$ 的结构可达性直接提升为 $P_{exec}$ 的执行合法性 |
| 容量闭区间 | 在物理张量身份、单一生产者、无别名及模块其他守卫下，核对 L1/UB 驻留 | P2 局部命题，P3 容量分析 | 零 spill 推出 Step3 完成、全局最优或 Makespan 改善 |
| 共享必要下界 | 保留计算依赖的投影、工作量、头尾窗口、原子装箱及合规组合 | 第 3 章概念、附录证明、各问差距图 | 固定 owner/FIFO 界称全域界；重复计资源后相加 |
| 固定服务出口包络 | 条件成立时 $F(r)=\max(\theta,\max_j(r_j+\lambda_j))$ | P3 局部响应分析 | 用它宣称解决内生 DDR 反馈或所有流水结构 |
| 树形峰值排序 | 指定私有、非交错树模型中的峰值排序规则 | P3 归约森林子机制 | 无条件推广到共享 DAG、多核交错执行 |
| 单调接受 / 嵌套证书 | 同一实例/配置、正确比较和保留已确认方案时，可维持非劣 incumbent；合法界可收紧证书 | 各算法接受规则和适用范围 | 每个候选改进、有限步全局收敛或三问成绩单调 |
| 通用 Coherent 控制契约 | incumbent 与 exploration 分离等是设计草案 | 未来工作/附录一段；[契约][control-contract] | 写成三问已共用的上线控制器 |

整稿优先读审计后的 [三问统一理论札记][theory-final]、对应审阅和本题章节证据，再按需回到长 Web Clip。札记中最关键的限制包括：保留计算投影不是删除 DDR 后重跑贪心；必要 I/O 退休间隙不等于未经证明的浮点字节守恒精确界；独立窗口相加需证明不重叠；强化公式未生成新 500 格证书时继续使用旧证书。本文盘点读取了这些边界，没有重新完成其全套证明与代码审计。

P1 路径闭合只是必要条件，加入核上顺序后的 Task 图仍需无环；分叉辅助构造还有波次、无回边、辅助核互斥等守卫。P2 超图最小割只精确解决固定区域与锚定下的基础通信目标。P3 正文若保留多释放模型和共享服务推导，应把模型演算、保存结构核查和官方成绩分栏。

## 4. 创新点先写成可辩护的贡献

建议最多保留三条主贡献，再用证据决定措辞强度，不先包装“高维”“最优”“首次”。

1. **官方语义约束下的结构化求解框架**：以切图/分核/顺序为合法控制量，将三问放到统一的“方案—执行结构—瓶颈—验证”链条。贡献在于解释和连接实际机制；是否构成文献意义的新颖性还需原始文献检索。
2. **针对瓶颈的具体构造与条件分析**：P1 分叉/前沿与合法 Task 结构，P2 张量触核集合的通信构造与容量/时序反例，P3 共享输入流水与归约森林。分别绑定正式进入主版本的代码，未接入理论只作扩展。
3. **质量、效率和机制相互印证的完整评价**：每题一个固定算法全量100×5，区分周期与求解秒数，报告 DDR/Cache 与尾部延迟，保留负结果并用同计划配对和必要界说明边界。这是实验贡献与可信度，不把复现设施本身列成数学定理。

若某项要称“精确”“最优”，句子必须同时给出适用子问题、条件和证明入口；若称“更好/更快”，必须有同条件对照。当前 100 图都参与过研发，称开发验证，不能改称独立封存测试或泛化保证。Fang 的 fork-rank 前沿、理论札记和各成员贡献应在对应机制注明来源，不能在汇总时变成单一作者原创。

## 5. 交给整稿者的更新闸门

- 每题主算法：完整 SHA、入口、参数/结构选择规则、候选和调用预算、500 格有效/失败/超时/未运行状态齐全。
- 每个理论主张：条件、证明或反例、实施情况、验证范围、勘误影响明确。未证明项缩成假设/设计，不能靠归档状态升级。
- 每张主图：从当前版本表生成，脚本/源文件、实际命令、单位、样本数、图注及论文插入宽度可读性齐全。
- 每项比较：固定分母与相同配置；无 L2 对照与独立 P2 算法分开；不拼历史赢家，不掩盖 DDR 或尾延迟退化。
- 全文完成后再统一正式参考文献；理论草稿中的外部文献目前未做专项真实性/新颖性检索。
