这是给用户随后指定的负责人的交接单，**本任务没有认领或完成网页全量核验，也没有新开 Pro 咨询**。以下缺口来自本地索引、归档说明和研发作者回复；网页当前状态仍须逐项确认。

## 2. 每个聊天应交付什么

建议交付一张逐聊天清单、一张逐消息/附件清单，以及简短结论：

| 字段 | 记录方式 |
|---|---|
| chat/branch 身份 | 原URL、负责人、项目归属、分支/编辑/重新生成关系；共享前缀去重但不丢分支 |
| 消息覆盖 | 独立可见消息清单的ID、角色、次序；与导出逐ID对照；首尾和超长回答专项检查 |
| 原文真实性 | 完整网页clip/原生复制/DOM提取/预览重建分别标记；保留公式、代码和表格；不得用摘要补造缺失原文 |
| 快照 | UTC时间、上一快照、新增/更正范围、文件大小和SHA-256；追加而不覆盖旧原件 |
| 附件 | 来源回答ID、原文件名、获取方式/时间、字节大小/哈希、是否成功打开；过期/未取得/重建件分开 |
| 完整性结论 | 完整、限定范围完整、存在缺口、无法判断；说明依据，不以滚动停止或一次clip成功替代 |
| 理论依赖 | 哪个命题被后续收紧/推翻、影响哪段代码/章节/图表；让作者确认，不自行追认科学正确 |

优先核对与正文主贡献、定理和关键反例直接相关的消息，再补外围历史。大段文字读取可能截断，页面也可能卸载旧消息，必须保留实际覆盖范围。只归档可见问答与相关附件，不导出隐藏推理、凭据或无关私人内容。

## 4. 与论文任务的边界和交接

专项负责人写 `AI chats/` 的归档说明与原件时，先遵循项目会话登记及单写范围约定；本论文任务仅维护 `paper/` 写作索引。不要为补归档重新发送已在途问题、执行下载代码或重跑算法，也不启动新理论研究。当前P2明确停止后续Pro咨询。
