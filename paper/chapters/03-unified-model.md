# 3 统一建模与求解框架

> 状态：连接稿 v0.1，面向三问合稿。下文区分原题语义、拟采用的论文组织方式与尚未实现的理论设计。具体局部定理沿用作者固定来源并保留适用条件；本稿没有新增实验或宣布全局最优。

## 3.1 决策空间与官方执行语义

设输入计算图为 $G=(V,E)$，其中 $V_c\subseteq V$ 为排除 COPY_IN/COPY_OUT 后需要分配的操作集合，给定核数为 $k$。提交方案 $P=(\pi,\sigma)$ 由 $V_c$ 到子图的映射 $\pi$，以及各核上的子图有序列表 $\sigma$ 组成。列表同时确定子图归核和每核先后次序，对应官方文件中的 `node_to_subgraph` 与 `core_schedules`。因此，求解器能决定划分、分配及列表顺序；官方后续生成的 COPY、核内 Pipe 次序、等待与 Cache 替换行为不能当作额外提交变量。

记第 $q$ 问的官方编译及执行过程为 $\mathcal E_q(G,P;k,\theta_q)$，其中 $\theta_q$ 表示题设固定硬件配置。本文把该过程分成“计划生成执行结构”和“执行结构产生时序”两层用于解释，但不改写官方评价程序。最终提取 Makespan $M_q$、额外 DDR 搬运字节 $D_q$，以及问题 3 的命中字节与未命中字节。

| 比较项 | 问题 1 | 问题 2 | 问题 3 |
|---|---|---|---|
| Task 组织 | 每个子图构成 Task | 同核子图合并到该核 Task | 沿用问题 2 的组织，增加只读 L2 |
| 子图间数据 | 跨子图数据经 DDR | 同核可复用 L1/UB；跨核有 COPY 与同步 | 读取还受共享只读 Cache 与服务竞争影响 |
| 方法核心问题 | 并行收益与切分搬运代价 | 通信、驻留容量与流水时序耦合 | 访问复用、冷读竞争与计算重叠 |

三问都必须满足各自官方合法性与容量检查。问题 2 的复用条件和问题 3 的 Cache 改变执行行为，不意味着此前没有容量约束，也不意味着任意同一方案跨配置都能直接比较而无需检查身份与合法性。

## 3.2 目标、比较与两个时间尺度

首要优化目标是在合法集合 $\mathcal P_q(G,k)$ 中减小模拟执行周期：

$$\min_{P\in\mathcal P_q(G,k)} M_q(P).$$

额外 DDR 搬运量同时报告。若实现用 $(M,D)$ 字典序选择，应写明这是该算法的接受规则，并核对 $D$ 实际使用的是官方额外 DDR 还是内部 scheduled COPY 字节；两者不能因单位相同就互换。

求解程序端到端墙钟 $T_{\mathrm{solve}}$ 从启动、读入、构造、在线评分/回退到合法方案落盘计量，单位为秒。它与 $M_q$ 的 cycles 分开，外部最终官方复评另列。原题对问题 1 的“5～10 分钟为佳”是效率建议，不是 600 秒硬淘汰线；有限调用预算本身也不能说明方法避免了暴力搜索。算法需要解释结构依据、复杂度和停止条件。

问题 1、2 的主曲线在 $k=1$ 使用题设基点 1，其余核数采用逐用例比值的算术平均：

$$\bar S_q(k)=\frac1{100}\sum_{i=1}^{100}\frac{B_i}{M_q(P_{i,k})},\quad k=2,\ldots,5.$$

$B_i$ 为固定单核基线。优化后的单核结果另列，不改写基线。问题 3 展示无 L2 与 Cache 两配置的完整比较；为了识别 Cache 本身的作用，再对同一计划定义

$$G_{i,k}=\frac{M_{\mathrm{noL2}}(P_{i,k})}{M_{\mathrm{cache}}(P_{i,k})}.$$

上述同计划比较是团队采用的控制实验，不与独立优化的 P2 算法成绩混为一谈。命中率使用命中字节除以命中与未命中字节之和；跨用例汇总时须注明是逐例均值还是字节总量加权比，二者回答不同问题。

## 3.3 从执行行为寻找结构化构造

本文拟按 Coherent 思路组织模型与算法之间的关系：先准确描述计划如何影响执行，再用可检验的瓶颈推导构造。P1 关注跨 Task 边界及分叉汇合结构；P2 关注张量触达核心集合、容量与就绪顺序；P3 关注共享输入、树形归约、冷读服务与 Cache 访问时机。三者共有“结构识别—有边界的变换—官方语义复核—保留可行方案”的逻辑，但不要求三份实现已经共享同一个控制器。

理论压缩必须保持所讨论的行为。固定执行签名下的局部响应式，可以解释某类输入释放对出口时间的影响；一旦 COPY 队列、活动服务集合或后继状态改变，就必须重新验证守卫。当前出口相同不等于所有未来动作下等价，固定服务模型的 max-plus 表达也不能直接替代内生 DDR 竞争。

因此，每个核心机制用同一种证据结构呈现：**发现的瓶颈 → 条件命题或反例 → 可执行构造 → 官方结果 → 失效范围**。例如“字节减少但 Makespan 上升”的 P2 反例说明时序模型不可被静态通信目标替代；P3 的 Cache 负收益格说明命中与完成时间需要分开解释。

## 3.4 必要下界、局部性质与结果的职责

跨三问可共享的理论放在保留计算依赖的投影上：计算关键路径、同类 Pipe 工作量、具有释放与收尾条件的执行窗口以及原子作业装箱，给出必要下界。使用时保留固定配置、非抢占性、时间单位与投影规则。彼此重复计算同一资源或时间段的界只能取最大，不能随意相加；固定分核或 FIFO 下的诊断界也不自动成为全决策域的全局界。

若对同一实例已有合法方案上界 $U$ 与适用的下界 $L$，可报告 $U/L-1$ 作为可证差距指标；它不是未知真实最优值下的实际相对误差。强化定理没有重新计算对应证书时，不能替换旧表中的 $L$。

固定候选选择可以在评分准确、守卫成立且始终保留已确认方案时保证被接受序列不劣化；这不证明找到全局最优，也不证明每次提出的候选都改进。全文采用的命题、实现与实验范围详见[证据与理论索引](../planning/EVIDENCE_AND_THEORY.md)。具体证明与伪代码由第 4～6 章及附录承接。
