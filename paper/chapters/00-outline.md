# 论文框架与 Markdown 写作顺序

状态：整稿方案，供作者沿此继续写作；不是用户已确认的最终目录。保留第 4、5、6 章与现有图号，减少交叉引用返工。题名候选：**面向通信与存储约束的结构化计算图划分与多核调度**。待实证贡献收敛后再定题名，不先承诺全局最优。

## 一条贯穿全文的论证线

原始计算图 → 合法的切图、分核与每核顺序 → 官方编译及调度形成的执行结构 → 通信、容量与流水瓶颈 → 有适用条件的结构构造 → 固定算法全量结果与反例。

Coherent 用于组织这条因果链：把决策、真实执行行为、局部机制和验证互相接上。它不是给三个不同算法套一个名字，也不表示已实现通用的精确商空间搜索或全局最优控制器。

## 拟定目录与每章必须回答的问题

| 章节 | 必须回答的问题 | 主要材料与图表 | 写作控制 |

| 8 模型评价与结论 | 哪些优势被证实？哪些依赖结构？尚未覆盖什么？ | 失败/退化、条件界、开发集局限 | 不将模拟收益写成真机收益，不宣称无条件收敛 |
| 参考文献 | 理论、方法和背景依据能否追溯到原始来源？ | 原始论文/官方材料；待后续专项检索核验 | Pro 提出的名词和文献先核实，不能直接抄引 |
| 附录 | 哪些复现细节必要但会打断正文？ | 长证明、伪代码、符号补表、固定入口、哈希与案例审计 | Web Clip、聊天流水和所有研发分支不塞进正文 |

各问统一使用“问题分析 → 模型建立 → 算法求解 → 结果分析 → 适用范围”。模型写变量、目标、约束；算法写结构识别、候选构造、接受规则、伪代码、复杂度与停止条件。正文保留能解释方法和结果的数学，长技术证明放附录。

## 从现成草稿到整稿的顺序

1. **先定事实口径**：依据 [证据索引](../planning/EVIDENCE_AND_THEORY.md) 指定每题一个主算法，明确基线、500 格覆盖与最终评价来源。P3 保留Forest主表，R9F固定全量负结果单列；讨论联合接受政策与首要Makespan目标的取舍。
2. **补共同前置章节**：先写第 1～3 章，统一符号与三问语义。第 3 章已有连接稿，第 1、2 章尚待正式成文；不以空文件冒充完成。
3. **改三问工作稿**：先对版本和论证作实质修订，再压缩研发枝节。保留作者贡献与负结果；不要只换表中最后一行数字。
4. **补最必要图件**：优先完整主曲线和 P3 同计划 Cache 对照，再做质量—时间/DDR 取舍与典型机制图。已有 18 组任务按 [图件盘点](../planning/FIGURES.md) 收敛，允许合图或移附录，不自动追加绘图任务。
5. **交叉复核**：逐条检查“正文主张—条件/证明—实现—版本—表图”。真正只在局部结构成立的结论明确限定，不借 Coherent 名称外推。
6. **写摘要与结论，再做 LaTeX 检查点**：只采用此时已冻结的结论；检查页宽字号、匿名、图表编号与正式格式。
