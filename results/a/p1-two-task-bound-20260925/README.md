# 两 Task 构造的条件资源下界

固定源码：`ef1bd773a78cba37c3930c9b0a9c5b8a9ba0a0ab`。原图、配置、作者识别器、公式实现及相关官方源码的 SHA-256 见 `structural-audit.json`。

这是一份静态结构检查和整数资源模型结果，不是新方案成绩。没有调用求解器、Task 编译、响应模拟、E0、E1 或 E2。无 spill 仍是条件，本检查没有证明这些大 Task 的容量可行性。

| 图 / 5 核 | 较宽松的返程切口资源值 | 加入两 Task FIFO / 门控后的条件值 | 最少切链数 |
| --- | ---: | ---: | --- |

| 084 | 335819 | 382408 | 206,206,203,203,203 |

三图均通过同型私人链识别器，每条链的最后 V 和末 M 之间均有一个张量，因此满足文档中 W 先 P 的结构充分条件。固定配置同核 Task 门控为 100 周期。整数阈值可行而前一周期不可行，只认证这个资源放松问题，既不保证阈值可达，也不限制其他分组方式或一般 P1 的最优值。

用途：解释为什么单凭较宽松下界选择切链比例，再合成两个大 Task，可能浪费收益。结构假设、DDR/MEM 等待、真实容量和最终官方时间仍须分别验证；不能由这份表格修改成绩台、提升已验证均值或剪除其他构造。

复现静态审计（Python 3.12.13；输出路径须不存在）：

```sh
python -B -m src.review.p1_two_task_condition_audit --cases 008,084,095 --cores 5 --output output/two-task-audit.json
python -B -m unittest tests.q1.test_p1_two_task_resource_bound tests.q1.test_p1_return_cut_resource_bound
```

本机 5 项纯数学测试通过。新公式对 4096 组小整数参数与独立枚举切链数的目标值相符，覆盖空核、零增量 DDR 和正门控导致的 x=0/1 不连续。穷举是测试参考，只用于小参数；公式实现是单调二分，不用枚举运行真实调度。
