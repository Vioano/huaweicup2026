单看总资源或某 Pipe 工作量会严重低估有序约束。例如 A 首轮的最大 Pipe 工作量仅 48636，加入 FIFO 与已完成前缀 `need` 依赖后路径达到 96297。该路径主要来回经过 M→V、V→M，含 44 条跨 Pipe need 边。B 三轮分别有 11、13、13 条这样的边。完整逐指令路径、每个尾 Task 的下界均见 [paths.json](paths.json)。

这支持优先研究真实 FIFO/need 链和切分后的等待。**两下界相减不能解释实际 7576 周期退化**；B 仍有 10015 周期未由本下界覆盖，具体来自 DDR 竞争、整数退休、多个路径汇合等何种机制，需事件证据。没有把 MEM 边数量当成因果证明。

## 模型内证明

只讨论冻结 `src/q1/response_oracle.py` 的 Fraction 服务与整数退休模型，不外推官方 binary64/EPS，也不把已编译指令的结论视为一般原图 P1 定理。

1. 对每个 Task，以 `(pipe, rank)` 为结点，添加同 Pipe FIFO 前驱及每个非零 need 前缀的最后指令到本指令的边。FIFO 已传递包含整个前缀，最长加权路径因此为必要时长。
2. 从所有核同时启动开始，对实际保存的 ports 逐元素核对五核同步轮完全相同。Fraction 模型每个事件先退休，再激活/发射，确定性规则保持镜像状态。每个 DDR 指令总有五份镜像同时接受服务，服务率至多 1/5，所以历时至少为原 work 的五倍。若两条 DDR Pipe 同时活跃，只会更慢；整数退休也不会缩短历时。
3. 同步轮结束时五核仍同时完成，经过相同 gate 进入下一同型轮，故各轮下界和 gate 可相加。首个异构尾段以后不再作五倍假设：各 DDR 指令只用独享服务 work 作为下界，按每核真实 Task 次序加 gate，最后取核间最大值。

脚本检查五核、Task 唯一覆盖、核归属、同步前缀、need 范围和 DAG 无环，固定输入 SHA，并保存路径总权重证据。单独的符号最长路没有调用响应模拟。

若存在不同释放时刻、跨核异质前置条件、前缀签名不等或其他模型变化，上述五倍服务和同步轮累计须重新论证。这里的模型本身不包含额外跨核依赖。

## 对算法研发的影响

这是两个**固定编译方案**的下界。A 的 618 周期剩余间隙说明固定 FIFO 下的模型值已靠近这条必要路径；不表示所有整链重排、其他拆分或 P1 全局已接近最优。此前 [整链构造类区间](../p1-period7-colab-20260925/run-0534Z/ZERO_CUT_MODEL_BOUND.md) 是另一个条件更宽、数值更松的论证，不能互相替代。
