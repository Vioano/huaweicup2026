## 独立复核与数学判断

本地 Sol/medium 用[独立标准库复核器](../../../src/review/p1_r6_static_verify.py)读原图、旧计划和作者成员列表；没有调用作者脚本或官方 helper。[实际输出](static-verification.json)核对五处见证的覆盖、依赖、旧 Task 高度和所有变化 tensor 的完整输入/输出 COPY 谓词。root 审核了复核器、官方 `multicore_cut_evaluate_problem_1.py` 的边界生成和 DDR 服务更新，以及 `heavy_suffix` 的波次构造。

| 见证 | 新成员 X/Y/J | 精确局部边界增量 | 官方模型的新增独占 DDR 服务工作 |
| --- | --- | ---: | ---: |
| 085 Task12/13/14，各一次 | 106/347/25 个非 COPY op | 95876 B | 1626 cycles |
| 005 Task14/15，各一次 | 82/275/25 个非 COPY op | 26500 B | 457 cycles |

表中的字节量只包括切分导致的边界 COPY 差，不含未来 spill。服务量逐 COPY 取 `max(1, ceil(size/60))` 后求差；冻结 E0 把该整数 duration 作为共享 DDR 工作注入，所有活跃 COPY 均分单位服务速率，因此不能把它直接换成裸字节除60，也不能把服务差当作 Makespan 差。085 的 95876 B 中，16896 B 来自新内部界面，**78980 B 来自重复读取**。只数导出分支的4096B出口会严重低估成本。

以下证明成立须显式落实前提：

1. 从本次输入的真实基线计划重建完整 COPY 收缩依赖，给旧 Task 按数据 DAG 最长路高度分波；每核旧 Task 高度必须严格增加。这样同波旧 Task 互无数据边，每核每波至多一个旧 Task。不能从 `heavy-or-sink` 名称推定这些前提，因为它有 fallback。本地已核对两份保存计划的高度条件，不能代替运行时检查新计划。
2. 每次把旧 Task 精确分为非空、不交的 X/Y/J；X 与 Y 互无边，J 无返回早期部分的边。无向桥上游、唯一 sink 和前驱/后继闭包提供识别方法，但最终仍逐边核对。仅称 X“前驱闭合”并不能排除 X→Y。
3. donor/helper 每波互斥。donor 排 Y 后 J；helper 排各独立 X 后原 L。跨波边增加波号；波内数据边只有 X/Y→J，核序边只有早期 X 队列→L 或 Y→J。因此秩 `(旧波号, 早期/汇合微层, 本核位置, 核号)` 沿每条边严格增加，联合 Task 数据/核序图无环。微层只是证明标签，无需提交等待屏障。仍须对最终增广图做 Kahn 检查。
4. 一个 donor 净增2个 Task，至少留一个 helper，故每波净增至多 `2(K−1)`。这不是内存可行性或性能保证。新 FIFO、MEM、spill、共享 DDR 和 helper 原 L 的迟发都仍要验证。

“只把 X 拿走，保留 Y∪J”为两片会把 X→J 升格为 X→整个余下 Task，导致 Y 也等 X；三片的意义是移除这一额外串行约束。原路径 a→b→c 任意合并{a,c}的商图有环，故不继承标量 McNaughton 的性能保证。R6 的9/1009例子是忽略边界搬运的手算机制示意，不是冻结官方输入的实测。
