# P1 次要指标：最新完整 v4 批次的 DDR 复核

来源是已保存的未修改官方 E0 结果，不是新运行。固定输入、算法、两个完整批次及 feed SHA 见 `audit.json`；全部 500 个同图同核数单元的 graph/config/baseline 身份匹配。主代理另从固定 Git blob 独立复核 v4 五核汇总和 028 的两版指标。未增加求解器或评价器调用。

P1 官方次要指标是总额外 DDR 搬运字节：`added_copy_bytes = scheduled_copy_bytes - original_graph_copy_bytes = partition_added_copy_bytes + spill_added_copy_bytes`。Cache 字节命中率是 P3 指标。下列均为 100 例字节总量比较，不是逐例百分比的平均，也不是官方加权总分。

| 五核完整批次 | 总额外 DDR 字节 |
| --- | ---: |
| 固定官方单核基线 | 1,241,686,120 |
| 统一算法 v1 | 996,664,150 |
| 统一算法 v4 | 1,049,599,886 |

v4 相对单核基线低 15.47%，相对 v1 高 5.31%。v1→v4 五核：7 例增加、4 例减少、89 例相同；全 500 格：32 增加、17 减少、451 相同。v4 五核 6 例额外 DDR 为零，74 例 spill 为零。额外字节中的 908,128,542 B（86.52%）属于 partition-added，141,471,344 B 属于 spill；分拆不是独立因果证明或可全部消除的优化空间。

028/K5 是需审视的权衡：Makespan 8,331,062→8,279,736（减少 0.616%），extra DDR 27,380,736→80,845,824 B（增加 195.27%）。不能由更低周期数宣称搬运也改善。

固定 v4 在 `src/q1/unified.py:choose` 以 `(makespan, scheduled_copy_bytes)` 字典序选优；只有相同 Makespan 时第二项才能改变选择。对同一图，scheduled 与 extra 的排序相同。该规则服务首要目标，但不等于已充分优化次要目标。

研发结论：继续保留最低 Makespan 方案，明确记录周期与搬运的取舍；优先寻找不增加 Makespan 的边界合并、复用和 spill 减少。若存在少量周期换大量搬运的替代方案，保留为可比较方案，不能未经说明改变默认选择或编造官方权重。当前研究模型下界/代理和局部实验不改变这里的完整批次成绩。
