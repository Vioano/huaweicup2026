# 044 整组件分核域的计算/输入服务联合下界

仅适用于每个原非COPY计算组件全部位于同一个核的方案。允许同核拆成多个Task，允许不同合法核序，不允许把一个组件分到多个核。按原图结构分组，11个组件各有6764个PIPE_M周期；共同外部输入50个tensor、930400 B，逐tensor ceil(size/60)的归一化DDR服务总量15530。剩余外部输入为各组件私有，总22528 B、服务385。确切原图SHA和解析数据在result.json；本轮没有构造、Task编译或评分。

若r个核承担这些完整组件：

1. 鸽巢原理保证某核至少有ceil(11/r)个组件。官方Step3的PIPE_SLOTS=1，非COPY M操作时长不小于原cycles，故T >= 6764*ceil(11/r)。
2. 每个活跃核至少承接一个完整组件，因此至少使用一次每个共同外部tensor。P1按Task的input_boundary谓词，为有本地消费者、无本地生产者的外部tensor生成COPY_IN。即便旧原图含COPY生产者，这些COPY不属于提交mapping中的计算op，仍是Task输入边界。没有跨Task持久输入缓存，所以同核拆Task只能维持或增加这一最低输入量。
3. P1新COPY的DDR端点使其进入全局DDR服务池，独占工作量为逐tensor max(1,ceil(size/60))。同时存在n份未完成DDR工作时每份服务率1/n，总服务率至多1，因此T >= 15530*r+385。COPY与计算重叠不能减少必要DDR服务总时间。
4. 两种资源可以重叠，不能把两个下界相加；T >= max(6764*ceil(11/r),15530*r+385)。输出、切口、spill、Task门控、FIFO/MEM空闲等只会进一步限制可行时长，界未计入这些项，也没有声称可达到。

旧完整044/K5方案实际64624周期、使用两核。因此1核及整组件全5核域均不可能优于这一旧方案；4核即使达到这里的乐观界，时长降幅也不超过(64624-62505)/64624≈3.28%。该域跨r的联合下界为40584，而非全P1全局界。此结果不排除更好的2/3/4核方案、组件内部跨核切分或按共享输入重组。
