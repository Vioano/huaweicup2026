# P1 统一算法检查点：结构构造与单次桥分支修正

本检查点用于下一轮统一算法 benchmark，尚未运行完整矩阵，不能继承局部实验的分数为本版本成绩。2026-09-25 用户明确：有实质改善即可更新一轮 benchmark，不必等累计达到 5%。

## 固定入口与规则

算法标识 `q1-branch-refine-research-v1`，入口：

```sh
python -B -m src.q1.branch_refine INPUT.json --cores K --output PLAN.json --diagnostics DIAGNOSTICS.json
```

只读取原图、1～5 核请求和官方固定配置，不读取 case ID、历史赢家、旧计划或评分表。

1. 沿用 `unified.solve` 的结构候选集、字节去重和在线评分守卫，最多 6 个不同候选。
2. 在实际胜者属于严格 capacity-return 域且有匹配评分时，按 `response_refine` 的 variable 规则做一次有界分包修正，至多新增 1 次 E1；构造子进程 120 秒，代表/最终 Task 编译上限 512/2048。
3. `structural_refine` 对符合严格 intact 结构的输入依次考虑 paced、root-heavy-fused 两个确定构造，至多新增 2 次 E1。
4. 新增 `branch_refine`：以当前父方案为输入尝试一次 R6 bridge-aid；父方案原字节哈希须匹配其评分，候选须有两键、正确核数、通过 Task/DAG 校验。相同字节、域外或构造失败不评分；不同有效候选至多新增 1 次 E1。

所有新增选择按 `(Makespan, scheduled COPY bytes)` 字典序，只保留严格改善；对同一原图，scheduled COPY 与额外 DDR 差一个固定基数，平局次序等价。未成功评分就保留父方案。E1 决策不等于官方验收，也不证明未知输入上绝无退化。

总上限为 6+1+2+1=10 次在线 E1 评分尝试，单评分 60 秒、worker 1。结构条件、去重和单核路径通常减少实际调用。DP Task 编译与方案构造另计，不冒充 E1 次数；这些上限不代表实际时延，也不是总墙钟硬界。完整端到端求解、子进程启动和清理均须另实测，外部最终 E0 另列。失败/不确定派发保留 null 与可确认下界，不伪报零调用。
