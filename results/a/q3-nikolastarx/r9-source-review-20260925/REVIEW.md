## Changes before a repository solver entry

1. **Use the official graph validator or reproduce its full contract before construction.** `RawIndex.build` (`:79–122`) checks several properties but does not call `validate_graph`; `main` parses JSON and passes it directly to `construct` (`:529–530`). The official validator also checks item types, edge endpoints and full input acyclicity (`data/raw/a/official/code/evaluation_validation.py:171–215`). A malformed graph with an edge to an unknown ID may raise a generic `KeyError` in `RawIndex.build:97–101` instead of a controlled unsupported-input result. For frozen official inputs this is an interface hardening gap, not evidence that 005/086 are wrong.
2. **Separate pure construction from packet loading and import auditing.** `main:498–520` hashes the recognizer file, then inserts `root` into `sys.path` and imports `src.q3.attention_rows`; that module also imports `construct.py`, which imports official helper modules. The profiler at `:509–517` only rejects selected function names under `/data/raw/a/official/code/`, and a file SHA does not prove the imported object came from that file if `sys.modules` already contains another `src` package. A fresh CLI process with the frozen packet limits this risk, but the profiler alone is not a general zero-side-effect proof. Integrate via explicitly injected, version-checked `_ports/_recognize` callables and keep file/manifest validation outside the pure constructor.
3. **Keep the narrow edge and flow guards visible.** `RawIndex.build:95–96` rejects direct op→op edges although the official validator and Task builder support them (`evaluation_validation.py:209–215`; `multicore_cut_evaluate_problem_3.py:217–236`). The DSU at `:197–212` rejects a node that connects two keys of one depth, even when a more general scheduler might place that join as a shared operation. Minimal structural probe: two distinct same-depth key anchors feed one non-anchor op that later feeds another anchor. The current union must form a same-depth collision and reject; do not relax this by dropping an edge or copying the op. These are applicability boundaries, not failures of the accepted cases.
4. **Retain the official acceptance gate.** `interval_certificate:368–402` and `path_stats:404–428` are static assertions over selected singleton words; `traffic_counts:430–453` is explicitly a source-rule prediction. `construct:465,469` rejects a capacity or whole-path guard failure; neither success establishes official P3 Makespan, P2/P3 ratio or Step execution. The report correctly leaves `M3/M2/G` null. The first official validation, if later authorized, must use the unmodified evaluator on an exact emitted plan and keep the static and measured results separate.
5. **Document cost and resource ceilings.** Subset DP is O(K·3^r) time and O(K·2^r) memo states for r≤10 (`:259–314`). The within-phase ready scan enumerates all ready nodes on each choice (`:346–358`), worst-case O(n²); `main:497,541–542` times packet/hash/import and construction together, not a cold production solver. No fixed-case or unlimited search was found.

Suggested pure interface for adaptation: `construct_layered(graph: dict, cores: int, *, capacity: dict[str, int], cross_delay_cycles: int, ports_builder, row_recognizer) -> (plan, metadata, evidence)`. The wrapper should validate the graph/config and record source identity; the pure function should either return the two-field singleton plan with static evidence or raise a typed `UnsupportedStructure`. Keep the existing rejected-structure guards, original edges, and no-spill claim conditional on the exact official semantics check. Do not replace the current R8 entry automatically or mix R9's unscored plans into full-500 results.
