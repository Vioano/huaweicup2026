# Root review: what the convex cut does and does not certify

2026-09-25. Reviewed the frozen `pilot.py`, its five toy definitions, the recorded full original-op quotient check, and the R9 `priority_words` implementation. No new graph analysis or official call was executed for this note.

The single-set contraction lemma is valid. For a core word that respects **all original reachability**, an outside excursion leaving at index i and returning at j has i<j. For a fixed right endpoint r, let b be the largest such exit with j<=r. Every proposed start L<=b includes the witnessed exit and return, so is nonconvex; L>b excludes all such excursions. A path cannot escape through an earlier/later same-core word vertex and return without violating reachability order. This establishes the cutoff, including the default b=-1 case.

The pilot's direct same-core-arc check alone does not establish that premise: a two-edge path through another core can reverse the word while leaving no direct same-core arc. For this particular base plan, `src/q3/layered_query_flow.py:334` appends nodes only after every original compute predecessor is finished, appends each chosen node to both tau and its core word, and checks full coverage. Thus its words are projections of a global compute topological order. `layered-port-static-20260925/run_summary.json` records the constructed plan's exact byte match to the frozen base plan. The source's RawIndex validates the original COPY contraction. This source/record argument supports this instance; a general utility should explicitly validate the reachability-order premise, for example by checking that original DAG plus the core-word adjacency edges is acyclic.

The explicit all-original-op quotient result is independently useful even without the cutoff's minimality claim: the one reported merge is acyclic in that graph. It does **not** establish that all generated four-pipe FIFOs and new memory dependencies remain acyclic. In particular, stable rebucketing within a 201-compute bucket can change several pipe orders. The saved singleton frontier certificate cannot be reused unchanged.

The next discriminator is the actual official Step1 raw word, then official stable rebucketing under the old and new bucket maps. It is necessary to verify exact reconstruction of the saved old sequence before interpreting a new sequence. A COPY's ordinal movement is not an issue-time prediction or a Cache-hit guarantee.

One source trap was found during preparation: the saved prepared Task `graph` is Step3's `execution_graph`, with MEMORY_REUSE edges already appended. It is not the original Task graph. The saved zero-spill Step2 `ext_edges`, together with the unchanged op/tensor records and empty additions/removals, are the appropriate recovery source; the preparation must check that the difference is exactly the recorded Step3 memory additions. Old Step3 `op_preds` must not be reused as original dependencies.

For a recovered graph with every on-chip tensor's actual producer/consumer uses, the closed interval from first to last use in the **complete** sequence is a sufficient no-spill check for Step2's allocate/check/execute/free scan. This is distinct from the singleton-bucket theorem, and is not a Step3 runtime peak. New Step3 allocation dependencies and the full multi-core execution still need their own validation before a new score can be claimed.
