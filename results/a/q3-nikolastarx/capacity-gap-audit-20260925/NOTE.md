# 044/5 容量分段后的剩余时差：只读 trace 审计

证据仅来自 `pipeline-capacity-two-shot-20260925/{run.json,case_044_multicore_res.json,evaluation/044/result.json.gz}` 和原图 `data/raw/a/official/data/case_044.json`。固定构造源码 `78d82a99…`，计划 SHA `e959272c…`；本笔记没有重新构建 Task/Step3、运行 solver 或评价器。当前分支上的后续统一实现不由这一个样本代表。

计划把 11 条同构作业的 124 个位置切成 `[0,24,51,68,96,124]`，五段每作业的纯计算量为 `[1680,1717,1120,1571,1584]` cycles。`run.json.jobs[case_id=044].static_plan_lower_bound=26842`，即 7672 的五段首批计算、4×500 跨核延迟和后续十批至少 10×1717；这是**该固定计划的松弛界**。官方 `result.json.gz.makespan=38390`，余差 11548 cycles。结果还有 `cross_core_transfers` 121 条、`spill_added_copy_bytes=0`，`scheduled_copy_bytes=1116256`，其中 `partition_added_copy_bytes=140800`；零 spill 不等于零 COPY。

下界 26842 来自 `src/q3/pipe_bound.py` 对计算 DAG、同核同 pipe FIFO 边及跨核延迟边的最长路证明；上段串行 flowshop 算式只是**本样本代数相等**，不是任意多 pipe 计划的通用已证下界。

`reproduce.py` 从原图的计算依赖连通分量定位首批作业，再经计划映射到各核；与跨核 COPY_OUT/IN 的 `cross_core_transfers[].{copy_out_end,copy_in_release}` 对照：

| core | 首批计算跨度 | 对应纯计算 | 超出 | 完全落在窗内的 COPY_IN reported duration |
|---:|---:|---:|---:|---:|
| 0 | 79–1759 = 1680 | 1680 | 0 | 460 |
| 1 | 2295–6177 = 3882 | 1717 | 2165 | 3768 |
| 2 | 6683–16085 = 9402 | 1120 | **8282** | **9276** |
| 3 | 16591–20406 = 3815 | 1571 | 2244 | 3408 |
| 4 | 20924–22515 = 1591 | 1584 | 7 | 215 |

表中 COPY_IN 是完整落窗操作的原报告 `duration` 之和；`summary.json` 另给每个 COPY_IN 时间区间与首批窗口的交集之和。core4 有跨窗口操作，交集为 235 cycles，完整落窗操作为 215 cycles。两种统计都不是独占关键路径时间。

首批在 core4 的正式 COPY_OUT 于 22565 完成，比松弛首批 7672+2000=9672 晚 **12893**。分解为初始 COPY_IN 等待 79、各段跨度超额 12698、四次交接相对 4×500 多 66、最终 COPY_OUT 50，合计 12893。之后十批到最终 38390 用 15825，比松弛界的 10×1717=17170 **少 1345**；故总差精确为 12893−1345=11548。core4 最后十批输出近似每 1584 cycles 一次。剩余空间集中在**首批加载/流水填充**，不是尾部稳态计算。这里的时间分解是观察值，并未证明各类 COPY 时长可直接相加为 Makespan 因果贡献。

具体瓶颈可在 trace 验证：core2 的 `per_core_timeline[core_id=2].ops[]` 共 9333 cycles 的 DDR COPY_IN 占用、11550 cycles 的 PIPE_M 占用；其中 9276 COPY_IN cycles 落在首批 6683–16085 的计算窗内。其阶段共享输入并集 516096 B，仅比固定 L1=524288 B 少 8192 B，但官方 Step2 实测无 spill。core1 和 core3 首批窗内也分别有 3768、3408 COPY_IN cycles；四段跨核首批交接只多出 66 cycles，不能把 11548 主要归因于 500-cycle 释放延迟。全局 DDR 竞争、COPY/计算重叠及 COPY 能否提前发生仍不能从现有时间线单独识别；本结果也没有“无首批加载”的反事实分数。

**结构化改进命题。** 当前 DP 只约束段内共享输入容量、再最小化最大段计算量。对每个连续段 `s`，从原图计算该段每批 PIPE 工作 `C(s)` 与去重共享输入 `B(s)`。研究以下 *代理目标*（不是官方下界）：

`F(cuts) = Σ_s max(C(s), B(s)/60) + 4×500 + 10×max_s C(s)`，约束 `B(s) ≤ 524288`；交叉 COPY 字节用次级排序或已证下界守卫。现有切点的 `B=[6624,214272,516096,186368,7040]`，代入得约 **37713** cycles，距真实 38390 为 677。这个接近仅来自一格，可能偶然；首批 COPY 可预取且多个核共享 DDR，因此 `F` 不能宣称为严格界，也不能以它替代官方 Makespan。

最小证伪实验：先在原图上离线求 `F` 的确定性最小连续切点（固定并列规则），比较与现计划的首批加载估计、稳态最大计算段和跨核字节；若没有实质差异即停止。若有不同，先以现有计划和新计划各一份在**另行确认的固定预算**中做官方配对评价，逐格记录首次 COPY_OUT、随后十批完成间隔、M、DDR/Cache/spill、端到端求解墙钟。若 `F` 降而首批输出不降或 M 上升，命题即被反例否定；保留该反例，不离线挑选赢家拼接全量成绩。
