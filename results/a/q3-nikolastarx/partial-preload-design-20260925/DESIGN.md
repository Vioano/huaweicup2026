## 可提交机制

P3 方案仅有 `node_to_subgraph`、`core_schedules`。官方构造每核一个 Task：图输入 COPY_IN 归到该核最早消费者子图，跨核激活 COPY_IN 也归到目标消费者子图；Step1 原始拓扑字按子图顺序稳定分桶。每核 MTE2 按生成的队列顺序发射，队首未得到跨核释放时后面的冷读不能越过。因此不能在答案 JSON 中直接指定 DMA 队列或开始时刻。

主构造保留现有归核与作业优先次序，只把首作业在某一阶段的连续计算链分成 head `[left,h)` 与 tail `[h,right)` 两个子图，顺序为 head、tail、其他作业。head 第一次使用的输入冷读随 head 放在激活前；只有 tail 才首次使用的输入随 tail 放在激活后。若官方生成的 MTE2 子序列恰是 `head 冷读、唯一激活、tail 冷读`，tail 冷读可与 head 的计算重叠。**是否真的更快取决于激活释放时间和共享 DDR；静态分桶不保证这一点。**备选是原全前缀，不修改其他归核或搬运集合。

## 单阶段固定服务定理

先把多核共享带宽冻结成一个明确的数学子问题。设 stage 有串行计算链，总服务量 `C`；激活在固定时刻 `R` 释放，在 MTE2 上固定服务 `d`；按首次使用顺序的 `m` 个不同冷读有固定服务 `w₁…wₘ`，前缀和 `Uᵣ=Σᵢ≤ᵣ wᵢ`。读 `r` 首次被计算使用之前，链上需执行 `Pᵣ` 计算服务。对某个可提交断点 `q`，MTE2 顺序是前 `q` 冷读、激活、剩余冷读，尾读与计算可并行；无其他传输、缓存状态变化、容量限制、额外激活或跨核反馈。在这些条件下精确完成时刻为

`T(q)=max(R,Uq)+d+C+max(0, max_{r>q}(Ur−Uq−Pr))`。

证明：head 开始时刻为 `t₀=max(R,Uq)+d`。尾读 `r` 在 `t₀+Ur−Uq` 完成。若不等待，计算在 `t₀+Pr` 首次用它；该读造成的累计最小延迟约束为 `Ur−Uq−Pr`。串行链的完成时刻满足所有这些约束，且按顺序执行并在需要时等待即可达到最大约束，所以等待总量为右式的非负最大值。这个定理不声称官方多 Pipe/共享带宽事件模拟遵守固定 `wᵢ`。

令 `M_q=max_{r>q}(Ur−Pr)`，`M_m=−∞`。一个后缀最大值扫描加前缀和即可在 `O(m)` 时间、`O(m)` 空间算出所有可提交 `q`；相同模型时间选较大 `q`，减少激活前的队首等待。`Uq≤R` 时 `T(q)` 随 `q` 不增；`Uq≥R` 时 `T(q)=d+C+max(Uq,M_q)`，是递增前缀与递减后缀的交点问题。候选是由真实首次消费者位置形成的断点，不是随机参数网格或 E0 搜索。纯函数见 [fixed_service.py](fixed_service.py)，只求这个子问题。

微例：两笔冷读服务量为 `1,8`，首次使用前计算量为 `0,2`，`d=1,C=3`。在首笔后拆分 (`q=1`) 时，若上游释放 `R=1`，`T(1)=11`，全前缀 `T(2)=13`；若保持局部 stage 不变而上游释放为 `R=10`，`T(1)=20`，全前缀 `T(2)=14`。后者的 MTE2 在时刻 1–10 等待激活，8 周期尾读被挡在队首之后。故“越早启动 head 一定越好”是错误的；只按冷读总量选 q 也不充分。

## 从模型到原图的守卫与未证处

1. 只在已有同构 Hamiltonian 作业链、同一阶段切点、无跨作业计算依赖且唯一首作业激活门的范围考虑。按原图输入张量的**首次消费者位置**聚合字节；共享输入只计一次。允许的 `q` 是非空 head/tail 边界产生的累积读数；同位置的多笔读不能分拆。若 Step1 的冷读队列次序与首次使用次序不一致，定理的 `q` 不适用于该顺序，直接跳过。
2. 使用官方原始大小及固定配置带宽得到独占 `wᵢ=ceil(bytesᵢ/B)` 只作结构代理；跨核激活释放 `R` 不能沿用已测 044 trace。若没有事前证明或可审计的结构性上界/预测，选择 q 的真实收益仍是**未证假设**。尤其官方按同时活跃传输共享带宽、按整数退休重新发射，改变 q 会反过来改变每个 `wᵢ` 和 `R`。
3. 真正生成候选时，必须先核对官方 Task 图/COPY ID 与基线同一归核；候选 MTE2 子序列恰为所建模顺序、局部和跨核数据依赖拓扑合法；逐位置 L1/UB 生命期峰值不过容量、Step2 无意外 spill、Step3 内存复用边和 Pipe FIFO 加跨核释放无环。任一守卫失败则舍弃候选，保留全前缀。单靠 `_prioritize_task_seq` 的局部拓扑检查不能证明全局可完成。
4. 即使全部静态守卫通过，固定服务定理仍不能预测官方 Makespan；须在新预算明确后用冻结 E0 比较同一完整方案。当前 044 的重复 key 已全部 hit；此构造旨在减少启动阻塞，不假设再增加命中。求解墙钟与官方模拟 Makespan 分别记录。
