# 已有 attention 成绩的计划下界审计

读取当前 fixed forest500 的 071、069、005 五核原计划、结果与构造记录，逐件匹配快照哈希，再对原图和原每核 M/V FIFO 运行已有 `pipe_bound.analyze`。它仅计算原 compute 依赖、pipe 顺序及真实跨核 500 周期延迟的最长路，不运行 Task、Step3、solver 或 E0。

| 005 | 30,642 | 20,257 | 19,207 | 11 |

071/069 当前选择 attention gap 词，005 选择 placement witness 词。进一步改进不应只看纯计算的全局松弛上界：每个现有计划已经带有不可省掉的 FIFO 和跨核约束。更换分核/优先词可能降低这些约束，因此表中下界只约束当前计划，不能用于证明全题无改进空间。零延迟与含延迟最长路可能不同，二者之差也不能等同于官方 Makespan 的通信损失。

本次用来选择下一研究方向：对连续流水线处理容量压力，对 attention 检查割边及闭合子图归核；没有新增成绩或全量版本。完整路径、边原因、原件引用、输入 SHA 与已有候选结果见 `summary.json`。复跑 `reproduce.py --forest-root <已有 forest500 工作树>`；三个已见图不是独立隐藏集。
