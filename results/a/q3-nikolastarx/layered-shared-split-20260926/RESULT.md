# One-prefix shared-component split: static result

The frozen baseline reproduced the sole 068/K5 violation: core 0 UB 221,208 B at bucket 145/op 4551, 90,136 B over the 131,072 B capacity. Of 81 live intervals there, 65,536 B were not attributable to a core-0 shared-component producer. The fixed descending-contribution order selected the shortest threshold-reaching prefix: components with minimum op IDs **4510, 4444, 4473** (component indices 21, 19, 20). Their baseline live-byte contributions were 40,960, 32,768, and 24,576 B, totaling **98,304 B**, within the frozen 131,072 B move cap. The move transferred 116 shared compute ops and 15,605 V cycles to core 4; private ownership stayed fixed.

After one recomputation, core 0 UB falls to **114,716 B** and passes. Core 4 UB rises to **212,992 B** at bucket 71/op 4540, exceeding capacity by **81,920 B**. The moved-producer attribution at the old bucket did not predict the new core's full interval frontier; the fixed prefix therefore fails the static no-spill guard. No alternate prefix or subset was tried.

The before/after peaks for all five cores, exact component ranking, selected IDs, work and word lengths are in [result.json](result.json). Per the freeze, path `Ldelta`, remote links, traffic, plan construction and official derivation were not run after this capacity failure. This says only that this one static placement fails; it is not an official legality or Makespan result. There were zero `construct_layered`, `derive_multicore_plan`, Task, Step, solver, or evaluator calls, and zero retries. Production source was unchanged.
