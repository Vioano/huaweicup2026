# R8 的三指标接受条件审计（建议，未实施）

本文件只审阅当前代码与既有说明，没有调用 solver、Task、Step 或官方评价器，没有新成绩，也不修改冻结算法、候选或预算。`query_flow_probe.py` 当前只在 071/K5 的候选 P3 Makespan 严格小于 7782 且物理 guard 存在时调用同计划 P2，并记录 `candidate_G`；它不决定统一求解器是否接受候选。`NEXT_IF_POSITIVE.md` 的草案则仍以严格降低 Cache 场景 Makespan 接受候选。下述规则需要另行决定、实现和冻结。

## 同一输入上的可执行条件

令旧计划在无 L2、有只读 Cache 下分别为正的官方周期数 `(m20,m30)`，新计划为 `(m21,m31)`。四个数必须在同一原始图、核数、配置、官方评价语义下获得；每一对 P2/P3 必须使用**同一计划字节**。旧值须对应当前算法当次运行的新鲜 incumbent，不能从历史逐格最优表拼接。合法性、Task/物理 guard、FIFO/复制检查及既有预算约束先独立通过。

建议把以下三个条件同时作为一次计划替换的门槛：

1. 无 Cache 非劣：`m21 <= m20`。这直接阻止通过恶化分子抬高 G。
2. 有 Cache 严格改善：`m31 < m30`。这守住官方实际周期的首要目标。
3. 同计划 Cache 相对收益非劣：`G1 >= G0`，即 `m21/m31 >= m20/m30`，对正周期用交叉乘积 `m21*m30 >= m20*m31` 比较。

三个量回答不同问题，不能用其中一个代替另两个。反例（纯算术，非官方计划）：旧 `(m20,m30)=(100,80)`，新 `(m21,m31)=(90,75)`；Cache 周期降了 5，无 Cache 也降了 10，但 G 从 `1.25` 降到 `1.20`。反过来，只要求 G 增长可能接受 `(200,100)` 替换 `(100,80)`，实际 Cache 周期恶化且分子翻倍。

逻辑上三条并非完全独立：若 1 和 3 成立，且任一周期严格变化，则 Cache 周期必严格下降；但 1、3 允许两个周期都持平，因此仍要明确第 2 条作为本次替换需进步的要求。第 2 条本身不保证第 1 或第 3 条；第 2 与第 3 条也不阻止无 Cache 变慢。对固定旧计划，以 `(M3 越小、G 越大)` 的 Pareto 前沿保存研发候选有价值，但单靠 Pareto 不能保证每次替换同时守住 M2，也不能保证 G 单调。三条件是保守的单次替换规则，可能拒绝 M3 大幅改善而 G 小幅下降的有效权衡；应保留被拒候选及其完整配对作为研究证据，由团队明确取舍，不能悄悄改变主成绩定义。

全量目标是**同一个预先冻结的算法**覆盖 100 图×1–5 核，并使五核逐图算术平均 `mean(B/M3)>5`、`mean(G=M2/M3)` 继续提高，同时报告求解端到端时间及失败/超时。单格接受门槛不证明全量均值达标，也不要求每个单例 G **严格**增加：持平的 G 可配合更小 M3 接受。全量与单例均须保留真实负结果；不要用对固定旧成绩的逐格离线选择冒充统一算法。

## 不评分的安全筛选界

若对合法候选的有 Cache 官方周期有**已证明、适用当前图/配置/计划结构**的下界 `L <= m31`，而接受要求 `m31 < m30`，则 `L >= m30` 时可直接跳过候选评分。加入 `m21 <= m20` 和 G 非劣后，候选还须满足 `m31 <= m21*m30/m20 <= m30`；仅知道上限 `m21 <= m20` 时，不能推出比 `L >= m30` 更强的通用剪枝。若另有经过证明的候选无 Cache 上界 `U` 且 `m21 <= U <= m20`，则 `L > U*m30/m20` 也排除 G 非劣；严格 M3 改善仍单独检查。未知或不适用的界不能用来跳过评分，代理估计不能冒充下界。

官方周期若为整数，应以原始整数严格比较 M3，并用任意精度整数交叉乘积比较 G；不先四舍五入或给比值加容差。若源值确为浮点数，先核对官方输出精度与重复性，预先写明判定精度并把边界案例标为未定、另作已授权复核；不能临时设 epsilon 把退化说成非劣。数值容差只处理表示误差，不保证未来图、真实硬件或统计显著性。
