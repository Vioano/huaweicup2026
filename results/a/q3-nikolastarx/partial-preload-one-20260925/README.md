# 部分预加载：单候选事前冻结

这是机制实验，不是新算法全 500 格成绩。旧固定311322b全量成绩保持原样。

## 假设与构造

保留已发布044/K5 full-prefix方案的归核和计算次序。在可拆分串行pilot中，选首批冷读名义DDR工作量最大的下游核（并列选小核号）；取能把最后一笔冷读留到tail的最早计算断点。此规则没有case-ID分支或成绩查询。本输入自动选core2/h15：17个计算操作分15+2，7笔73728B冷读分6+1。前缀名义服务为8603周期，按官方固定60B/周期逐笔向上取整。重新分桶后的首个激活位于第7笔MTE2操作，最后冷读可能与头部计算重叠。

假设：少一笔启动预加载可缩短启动等待，余下读取由计算覆盖，最终降低全图M。反证条件包括实际Task/COPY身份改变、Step2产生spill、Step3复用边进入预读或造成环，以及官方M不优于38024。共享带宽会改变上游释放时间，不能把旧时间线的释放/服务时长代入新顺序当成绩。R7单预读核/串行供给者定理不覆盖本图多流/多激活，只作启发。

`build.py`只使用保存快照，0官方调用。保存唯一候选、五核预测字、预读前缀、事实及manifest；纯静态守卫已验证1678操作/3825去重边的联合图无环、原计算顺序不变、L1峰值516480B不高于旧证书、UB为0。此时尚不包含实际Step3内存边。

## 固定执行与停止规则

1. 一次新官方prepare，恰好5核Step1/Step2/prepareStep3，观察原函数返回，不改官方实现。完整原件先保存，再核实际字、原Task/COPY身份、无spill、全部含内存复用边的联合DAG以及前缀释放条件。
2. 守卫通过才调用一次P3。旧full-prefix P3=38024直接复用固定原件，不重跑。未严格改善便结束；未消费的两个P2槽保留未用，不换候选。
3. 仅在M严格下降时，分别对新候选和旧full-prefix计划各做一次P2，形成两组同计划G。同时比较extra/spill、按字节命中率和完整Cache统计。M改善不等于全指标支配。

总上限：1prepare+3新E0（1P3、2条件P2）；每次最多5个Task核，Step1/2/prepareStep3累计各20，评分中的step3_simulation累计最多15。1worker、每阶段90秒、全批600秒上限、512MiB进程组RSS采样门槛、首异常停止、0自动重试。旧实验预算不被重置。Linux独立CPU槽须经总调度准入和新鲜冲突核验；本机05:17Z压力级别2、空闲615MiB，不启动评分。

新入口为`src.q3.partial_preload_prepare`与`src.q3.partial_preload_probe`。完整源码先提交，以`--source <该固定SHA>`核对；manifest SHA也须事前固定。监督沿用已测试的Linux父死亡、进程组和独立watchdog机制，使用新输出目录和一次性领取文件。准备/观察/官方评分耗时是机制诊断开销，不能当冷求解器墙钟。
