# 两个释放变量的相关性：条件推导

这是固定独占服务数学模型的进一步收缩，不是E2或官方浮点评分剪枝证书。模型原件见相邻`release-envelope-model-20260925/saved-family.json`。

将两个输入的释放时刻记作H、R（含相同500周期跨核等待），模型已有：

```
q1: T1 = max(9565, H+8336, R+959)
q6: T6 = max(8759, H+1385, R+1382)
```

若已知`R-H <= 6954`，则T6的三个分量逐一不超过T1：8759≤9565，H+1385≤H+8336，R+1382≤H+8336。因此T6≤T1对该限制下所有非负释放成立。仅知道H≤R不足：H=0、R=10000时T1=10959而T6=11382。不能把释放顺序偷换为释放间隔上界。

已保存的官方044/K5旧prepare显示：供给核1的MTE3首两笔正是COPY_OUT 1000001655、1000001652；各名义工作3周期，直接计算前驱分别是227、226，而227依赖226。核1没有Step3内存复用边。因此在相同供给核图和队列下，第一笔结束时第二笔数据已就绪，两个释放的差只剩第二笔写出服务和整数退休。

理想精确算术的公平共享模型若同时最多n条DDR流，第二笔名义工作3的完成等待可保守界为3n+1；若每核MTE2/MTE3各仅一槽且共5核，则取n=10得到31，远小于6954。**这里没有把这个值认证为官方浮点事件推进的严格界**，也没有重新运行官方程序验证新候选供给图；不能用它跳过已冻结的prepare/P3。新候选只改核2优先桶，实际核1图、队列与容量依赖须按保存原件和新prepare核对。

此推导说明为什么释放相关性可能进一步缩小模型候选集，也明确需要什么条件。即使它成立，q6与full仍可能各有优势，共享竞争和后续作业仍可能使局部模型与全图M方向不同。单候选选择仍是README中事前冻结的结构启发式，未改成事后模型挑分。
