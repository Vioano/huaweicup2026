# 精确 row 前沿签名的凸性与调度使用边界

本说明来自对原图 DAG 和已保存分区脚本的推导，不是 Pro 回答、评分结果或容量证明。分析对象保留全部原始 op，包括 COPY；签名仅用于识别结构，不给这些路径擅自附加计算或跨核时长。原始工作量表中 COPY 的 cycles=0 也不表示其实际搬运免费。

## 可证明的结构性质

设原始 op DAG 为 H，已识别且互不重叠的 row 内部集合为 R_i。对 row 外节点 v，U(v) 是逆向遍历首次遇到的全部 row ID，D(v) 是正向遍历首次遇到的全部 row ID；遇到任一 row 即停止该分支。这正是 partition.py 的前后向集合传播，不是“最近拓扑距离”的一个单独 row。

**命题。** 对一条内部不经过 row 的路径 x→…→y，有 U(x)⊆U(y)、D(y)⊆D(x)。若两端完整签名 (U,D) 相等，则沿途节点的签名全相等。如果另行核验了“仅收缩各 row、其余节点保持单例”的商图无环，则任何连接同签名非 row 节点的原图路径也都不会经过 row。

证明：x 的每条首次上游 row 路径都能接上 x→y，且途中没有 row，故其上游 row 属于 U(y)；下游同理。对路径中任一点 z，两侧包含关系夹住 U(z) 和 D(z)，得到相等。对于加强结论，若路径曾进入 row，令 r 为第一个 row，则 r∈D(x)=D(y)，因此存在 y→某个r内节点的路径；与另一个r内节点→…→y 在row收缩商图中组成闭游走，违背另行核验的商图无环条件。不能仅用原图DAG推出此矛盾，因为同一row内的两个端点未必相同。空前沿集合也不改变证明。

所以按**完整 row ID 集合对**相同的节点分组，再取组内弱连通分量，得到在删除row后的诱导子图中路径凸的非 row 片段。加上上述仅收缩row的无环守卫后，凸性才推广到原图的全部路径：片段内两点之间的路径不会离开该片段。这提供一个可检查的精确识别原语；前沿集合用 R 位bitset，时间上界 O((|V|+|E|) ceil(R/w))、存储 O(|V| ceil(R/w))，不把 bitset 合并当无条件 O(1)。

缺少 row 收缩无环条件的最小链式反例：原图只有 a→x→b→y→c，声明 R={a,b,c} 为同一 row、x/y 为 row 外节点。原图无环，x 与 y 却都满足 U=D={R}，而 x 到 y 的路径穿过 b∈R。此例不声称是 attention 识别器会接受的输入，只说明“任意互不重叠 row 集合”不够。

## 不能从该命题推出什么

- 现有报告的205/224个 inventory 组件使用的是较粗的 role/band/relation 标签，**不是完整(U,D)签名**。上述凸性不能直接套给这些组件。每个节点的完整签名已留在JSON中，可供下一版构造使用。
- 单个集合路径凸不普遍保证任意分区收缩的商图无环。尤其 row 本身可能包含非凸形状；联合 row/bridge 分区仍必须显式核对商图无环，不能靠名字断言。
- 同签名节点不等于只能或应该同核，不能融合、复制或重算原操作；输出仍须按原题仅提交分核和顺序。可以保留为调度时的关联标签，而让每个计算 op 为单例子图。
- Reachability 不能推出同时驻留。把 U(v) 的全部张量字节相加当活跃内存，或把跨层全部tensor支持并集当必要容量，都会高估必需驻留。后者仅在官方物理ID条件满足时可作充分证书。
- row层级、前沿集合及两Pipe总工作量不构成官方模拟器的充分状态。实际FIFO、COPY释放、incarnation/backing、共享带宽、cache顺序和浮点端点均可能改变代价，不据这些摘要做无证明的精确DP支配剪枝。

## 直接构造的下一接口

1. row/key识别只为每层 query 片段给唯一锚点，跨层共享片段保留完整U/D，而不截断0→2旁路。
2. 在完整原边上为每个计算 op 建唯一owner，所有未知/歧义情形显式拒绝。现有分区只保证唯一归属账本，不是该owner函数。
3. 保留真实依赖，按计算Pipe增加实际提交顺序对应的FIFO边；显式检查整个依赖/FIFO图无环。计划特定的下界只在其语义充分条件核对后使用。
4. 用完整路径计算通信必要等待，不能将R8单层两条remote边上限推广到三层。若无法证明新生命周期容量，允许保守证书拒绝并保留原因；不能把一次评分无spill提升成全域定理。
5. 先用官方同计划P2/P3验证有限候选。统一入口整体的全量成绩及完整墙钟须另测，单格正例不拼接到主均值。
