## 不能直接把共享流体公式当作官方下界

一个诱人的公式是：各核从 t=0 连续读取前缀，前缀独占工作量为 W_c，则完成时刻 F_c 不早于 `sum_j min(W_c,W_j)`。Sol medium 独立复核发现：官方在分数时刻处理完一笔传输后，到向上取整的整数退休时刻才发出下一笔，短间隙会让别的核多拿到服务。这个朴素公式作为一般定理是错的。

`test_math.py` 保留一个有理数精确算术反例：四个前缀工作量序列 `[4,1]`、`[1,1,3,2]`、`[2]`、`[1,1,4]`，周期1再到达一笔工作量1的额外传输。第一条前缀实际在16完成，朴素公式却给17。该脚本是合成数学机制验证，不是修改过的官方用例、E0 或 E2。

对数学上的处理器共享模型，可以保守扣除取整间隙：令 b_j 为竞争前缀 j 的内部传输边界数，每个间隙不足1周期；目标 c 结束前，j 至少已服务 `min(W_j,max(0,W_c-b_j))`。因此

`F_c >= W_c + sum_{j!=c} min(W_j,max(0,W_c-b_j))`。

证明：j 未完成且不处于内部退休间隙时，与 c 同时活跃就得到相等服务；c 从 j 的间隙中累计多得到的服务至多 b_j。若 j 已完成，则其已服务 W_j。把所有前缀实际获得的服务相加，用总服务率至多1得出结论。目标自身的间隙与额外流量只会增大所需时间。前提是所有前缀开始即就绪、无外部依赖等待、均为同一 DDR 池的冷读、每核单一串行传输；否则不使用此式。

当前保存的四条前缀满足这些结构条件，其 W 为 3577、8603、3112、123。修正后的前缀完成时刻界为 10383、15415、9442、465；将**完成时刻下限**接入后继约束（不是伪造操作开始时间），得到数学模型下的整体界 **36,592**。与实测差1,432，说明29,780所暗示的巨大空间主要来自漏掉共享服务竞争。

36,592 目前只作为有理数处理器共享与向上取整模型的研究界。官方实现使用浮点数与1e-9容差，其数值健壮性尚未独立证明，**不把此数直接注册成机器实现的严格剪枝证书**。该界也只针对已核四条前缀、固定归核/Task；改变加载与计算的交错结构后不能沿用，不是全部合法方案的全局界。

## 对下一构造的约束

继续在同样的全量预加载前缀内调顺序，可能主要挪动共享带宽竞争。要获得明显突破，应优先研究把部分冷读放在计算期间、让首批激活通过，但同时避免 MTE2 队首被尚未释放的跨核激活阻塞。候选必须由输入结构自动决定，不特判044或套用旧官方时长；仍保留容量与全局依赖检查。切换归核以改变可复用读取集合是另一方向，不能通过增加重复搬运来刷 CacheGain。

下一步的具体数学难点：从 stage 的冷读量、首批激活释放约束和每作业计算量，直接构造有限个部分预加载顺序，并给出何时能打破“全核先预加载再计算”瓶颈的条件。先解这个结构问题，再冻结新的候选与评价预算；本轮没有追加任何官方调用。
