# 当前两个固定 R8 候选是否足以达到五核均值 5

这是已有原件上的精确分数运算，不生成计划、不重新运行下界或评分。
输入为同一固定算法 311322b 的完整 500 格快照、已核单核基线与现有两份 R8 计划下界。
只执行 analyze.py 一次，1 worker、总计 10 秒、错误即停、0 重试；所有官方和构造调用为零。

若只更换集合 T 中的计划，其他计划保持原字节，则

`new_mean <= old_mean + sum(max(0, B_i/L_i - B_i/U_i), i in T)/100`。

证明：对每个合法新计划，归核和 M/V FIFO 不变时 `M_i >= L_i > 0`，故 `B_i/M_i <= B_i/L_i`；未更换计划的贡献不变。允许保留旧计划只需对增量取 max(0, ·)。相加即得上界。此处 T 仅为 071/K5、069/K5，L 分别4538、5846；新的调度或分核不能沿用这两个固定计划界。

完整均值用 Fraction 从已核原始 B、U 周期重算，基线结果哈希、原图、配置、官方源码身份以及候选计划字节逐项匹配。这里只信任既有下界证明，不再次执行或独立重证全部路径。失败候选不贡献改善。结果不是新算法成绩，也不约束扩大结构覆盖后的通用 query-flow 算法。

研发决策：两份候选仍值得按既有预算做官方机制验证；但不能把这两个点的研究当作已经足够实现 >5 的路线。若机制有效，应分析全图结构覆盖和容量限制，再冻结能覆盖更多图的统一算法。禁止从历史成绩库离线拼点过线。
