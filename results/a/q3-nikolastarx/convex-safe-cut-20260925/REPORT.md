# H-envelope convex pilot, case 005/core 0

The fixed full-core envelope H is the original 4209-op DAG plus adjacency edges between consecutive compute words on **all five** cores. Its 10319 deduplicated arcs match the prior frozen guard, and it is acyclic. Applying the previously stated max-last-exit cutoff directly to H gives **L=9** for consumer 1289 at core-0 rank 202: the largest external-path exit before a reentry through rank 202 is rank 8. This is a new closed-form safe-cut rule on a stronger graph, not a parameter search. The output [candidate](CANDIDATE_UNVALIDATED.json) merges one contiguous 194-op segment, first op 44 through 1289, into the first segment SG. It preserves the raw compute-op coverage, owners and remaining five-core word order. The independent explicit full H quotient check passed with 4016 vertices and 9877 arcs. The earlier 201-op rank-2 candidate made H's quotient cyclic, so it is outside this stronger sufficient certificate family.

For one contracted subset S in an acyclic H, the quotient is acyclic exactly when no directed H path leaves S and later reenters S. H explicitly contains every same-core adjacency, so its core-0 word is topologically ordered by construction; the max-last-exit propagation applies with the needed whole-path premise. Taking `b=max{i: an H path exits word i, visits a vertex outside core-0 compute word (including other-core compute or a raw COPY), and reenters at j≤202}` yields earliest safe start `b+1=9`. The script also checks the actual quotient rather than relying solely on that derivation. Time and memory are O(V+E) for H construction, topological propagation and quotient check. This certificate concerns only this **single** merge; it cannot justify a second simultaneous contraction.

A separate monotonicity statement is valid under explicit hypotheses: hold the Task op graph, owner, raw Step1 order, and COPY set/IDs fixed; derive COPY SG labels by the unchanged official min-consumer/max-producer rule; merge only one interval `[L,R]` ending at the target's first-consumer bucket R. If an earlier L is also H-safe, every newly included COPY_IN was in a bucket before the target COPY. Stable `_prioritize_task_seq` moves those copies into the target bucket in their raw Step1 order: they either remain before the target or move after it. Copies outside the enlarged interval retain their relative bucket position, and the old target bucket retains its internal raw order. Thus the target COPY's **MTE2 ordinal cannot increase** as L moves earlier, and the earliest H-safe L maximizes ordinal advancement *within this fixed-raw-sequence family*. The premise that the target COPY follows that first-consumer bucket and the unchanged-copy-label inference still require the separately prepared Step1-only audit. Ordinal is not an issue timestamp; earlier ordinal alone does not prove earlier issue, lower Makespan, capacity safety, or cache gain. We did not run Step1 here.
