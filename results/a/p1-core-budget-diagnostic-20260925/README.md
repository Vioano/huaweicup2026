## 空闲核嵌入的源码论证

给合法方案的 `core_schedules` **末尾**追加空列表，保持节点分组、旧 Task/core ID、原列表顺序和官方配置不变：

1. `stub_multicore_cut_and_schedule.py:156–185,222–239` 要求外层列表非空、每个子图恰好覆盖一次，允许内层空列表。末尾追加空列表不改变已有映射和依赖次序。
2. `multicore_cut_evaluate_problem_1.py:107–195` 的原 Task 编译输入不变；`:333–341` 跳过无 Task 的核。
3. `:383–445` 新核不发射指令、不产生下一事件，旧核与 executor 的访问相对顺序保留。`:238–278,404–418` 的 DDR 共享由活跃请求决定，不按声明总核数除带宽。

归纳每次 retire/activate/issue，旧指令状态、浮点计算次序和事件时刻均保持不变。因此在相同输入、冻结源码、配置和迭代上限下，原 Makespan 与搬运量保持。输出核数、空核时间线/零峰值可变。这一论证只覆盖**尾部追加空核**；不顺带允许移动或重编号核，也不声称任意不同核数构造具有单调性。根与独立 Sol 均只读核查源码，未执行补核 E0。
