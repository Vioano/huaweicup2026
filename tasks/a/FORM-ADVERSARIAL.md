# a-r1-form-adversarial：形式化与语义对抗样本

负责人：@farmeruncle123
分支建议：`codex/a-r1-form-adversarial`
沟通 Issue：见同目录 `DISPATCH.json` 中本 task ID 的 issue_url。
公共约定：[ROUND1](../../docs/a/ROUND1.md)，完整标准：[契约 v1 第 3、6 节](../../docs/a/contract-v1.md)。

1. **任务目标**：将官方评估过程写成能指导实现与测试的规范，同时构造揭露 E1 不等效、E2 筛选失效的语义对抗生成器。规则、夹具、生成器和反例形成对应关系；不只重述题面，不另写整个官方评估器。
2. **输入文件**：`data/raw/a/problem.pdf`、`data/raw/a/official/`、`docs/a/source-manifest.json`、公共契约与导入审计。输入单位和字段以冻结官方材料为准。优先读方案校验、A/B Task 构造、Step1/2/3、三个全局评估器；未知和题面/实现差异单列。
3. **输出要求**：`formal/SPEC.md` 的八模块骨架；`rules.jsonl`、`coverage.json`、`ambiguities.md`、`change_impact.md`；`src/adversarial/` 可复跑生成器、`tests/adversarial/` 小图与元数据；`results/a/form/<run-id>/` 规则覆盖与 E0 观察；`paper/sections/a-formal.md` 方法/假设/局限。首批先交 F-PLAN/F-TASK/F-EXEC 和影响所选热点的 F-LOCAL/F-TIME/F-RESOURCE/F-METRIC 规则，其他模块标出待补状态。生成器包含可解释种子图、参数扫描或变异、固定 seed、预期类别和哈希。交付对抗样本清单及复现命令；已发现差异保存原样本与缩减样本。
4. **限制条件**：官方原件只读。不得修改 E0、公共 schema、独立比较器、封存集或验收门槛。生成器不能借 E1/E2 的内部代价模型充当真值；允许在公开开发集上用差异引导寻找反例。正式合法域、故意非法输入、底层函数边界分开标注。重编号、交换核心、加核、增 Cache 等变换不得未经证明断言指标不变或改善。不租付费算力，不安装新 Skill。各生成器语言/数据结构自主选择。
5. **验收标准**：首轮至少交一套从规则到样本再到 E0 观察的可复跑链路，覆盖以下机制组的代表性正例与边界/反例：合法性/组合环；Step3 固定 FIFO 与内存复用；spill/容量临界；取整/同刻事件；L2 同时 miss/FIFO；搬运统计。无法在首轮覆盖的组有明确缺口及影响，不能填成通过。整数期望有源码或手算来源，E0 超时/异常原样保留。对 E2 除数值差异外，能生成同图同问题同核数的候选组，寻找预测排序与官方优劣相反的案例。生成成功不代表生成器宣称的合法性已获证实；E0 分类/独立验收另计。规范交付覆盖情况按规则计，不按页数验收。
6. **截止时间**：实际接手后约 1 小时首批规则/样本，约 3 小时首轮交接为建议节奏。首次回复实际 T0、预计交付时刻（Asia/Taipei）与阻塞；无另行确认的硬截止。首轮不要求完整八模块和所有发布覆盖全部完成。
