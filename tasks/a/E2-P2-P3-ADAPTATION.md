2026-09-24，用户明确授权评估器专项开始 P2、P3 适配；Q2/B 开发方的具体需求见 [Issue15 原文](https://github.com/huaweibei123/huaweicup2026/issues/15#issuecomment-5803222553)。开发和共享核心唯一写入者沿用 `nikolastarx/s-55b66a31d7bd49019122a179563dc1d2`，通信在 Issue15，Q2 接口使用方为 `yuanzhifang30-sudo/s-25ac3f7459f94fabb940724245a20ade`，其本人协调会话仍负责 Q2 状态。队长调度负责本任务 Atlas 汇总。

1. **目标**：先交可供 Q2/B 候选搜索调用的 P2 E2，再在已验证的 P2 固定基线上扩展 P3。共享可复用的事件/进程/资源框架由同一专项维护，不要求三套无必要的重写；P2/P3 各自记录支持范围、正确性、速度和剩余风险。
2. **输入**：冻结官方 P2/P3 源码、图/计划/config、当前契约及补充门槛；P1 首版基线 `f4ee4756fc15c65ddc4256f3c73ff4efc89accfc` / PR42；已有 FORM、Q1/P1 反例只作线索，各问题以自身官方 E0 为真值。P2 每核合并、跨核 COPY、Step1/2/3、等待、Pipe 和共享 DDR；P3 再含只读 FIFO Cache。开发者须从冻结源码核对命中、驱逐、完成/退休重插等完整事件，不能仅根据简述实现，不能只换问题编号。
3. **输出**：从上述基线另建独立分支/worktree，在专项独立研究目录与新结果目录工作；第一回执给实际路径/分支/HEAD/T0。交 P2 与 P3 分开的固定提交、官方格式入口/搜索接口、可运行最小例、支持与回退表、源码/输入/环境哈希、完整命令和预算/失败证据、差分与性能报告、Draft PR、算法方接入说明。P1 `f4ee475` 与原 PR42 分支保持供现有独立测试使用。
4. **限制**：不改冻结 E0/raw/config/公共真值，不接管 E1、Q1/Q2 生成器或尚未交接的旧 E2 生产目录。各问题的官方 I/O/CLI 兼容要求保持；P2/P3 不得错误回退 P1。合法、非法、未支持、超时、崩溃与缓存失败分列，精确回退和最终 E0 确认保留。划分/配置/容量/带宽与映射顺序变化按真实依赖失效。Q2 已完成的阶段 B 证据和预算不重置；新 E2 只能在固定交付和后续接入检查后用于新的实验批次。
5. **验收**：P2、P3 分别用自身 E0 对完整候选池标注；覆盖正常/非法联合环/空核/长链/跨核 COPY/FIFO/DDR，P3 加 Cache 命中、未命中、驱逐、在飞命中退休重插及容量边界。各自报告误差、最差例、短名单损失、准备/重建/回退/复核/最终确认的总成本、固定 CPU 下吞吐/P95/父子峰值与限制。既有 ≥10×E1、中位误差≤1%、P95≤3%等门槛不放宽；必须与该问题上支持等价语义和输出的固定 E1 版本比较，缺少对应 E1 时标记不可验，不借用 P1 比值或把 E0 比值改名。开发自测、独立复测与终验分开；P2/P3 独立测试接收者在首交付后另行确认，不能默认把 Windows P1 或 LYX 当前任务扩成 P2/P3 已验。
6. **检查点**：开发者先登记首批微例/正式例、E0/E1/代理调用总数（含失败/重试）、墙钟/进程/RSS 控制、实际 T0 与 ETA，再运行有界实验。首交付优先 P2 最小合法/非法与事件语义差分、明确可用接口及缺口；先形成经开发核对的 P2 固定提交，再进入 P3 增量，不为等待最终极致优化而拖延有限可用交付。原生/回退性能分开，未测跨平台/Rust如实列出；不自动启动云资源、扩全100图或无限追求加速。无新实质证据不循环催问/重跑。
