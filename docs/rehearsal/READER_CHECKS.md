# 每人必测：本地网页、Agent 读取与成本

本轮验收分三件事：**人能操作网页、接口返回正确事实、Agent 能用这些事实回答问题**。分别记录结果；脚本 PASS 不能替代后两者，也不能由队长替所有队员宣布通过。这是小型合成图上的开卷操作验收，不是模型通用能力或大规模性能基准。

## U1：每个人打开自己的本地网址（A1 连接后，约 2 分钟）

队长和每位队员都运行自己的 `team serve`，本人打开自己终端打印的 URL。队长的 localhost 链接在队友电脑上不会指向队长；不要互相复制地址代替启动服务。使用实时 serve 页面，不能用上游示例或旧导出 HTML 代替。

Windows 队友在 WSL2 的 Linux 环境运行 Atlas 后，用本机浏览器打开该服务地址。若 localhost 转发不可达，单独记录网络/浏览器阻塞并检查本人环境；不要改成监听公网来绕过问题。原生 Windows 的已知状态写入限制仍见入口。

| 检查 | 本人需要确认的实际现象 |
| --- | --- |
| 页面来源 | 项目标题为本轮合成预演；自己的角色正确；与本人 `team manifest` 对应的已确认版本相符 |
| 可见性 | 页面正常加载，文字、中文与图形没有缺失；当前窗口下没有遮挡到无法操作 |
| 基础导航 | 缩放、平移、重置可用；进入/返回后仍能定位刚才的节点 |
| 选择与详情 | 点节点主体为选中；信息按钮能显示 purpose、IO、问题、成熟度，不把选中当成展开 |
| 层级展开 | `analysis` 可原位展开三个子模块，也能进入 `analysis-inside` 再返回；不会误认为多了第二个 analysis |
| 初始看板 | A2 创建任务之前应为空，看见上游演示的 A/B/C 完成进度是打开错模型 |

记录账号、OS、浏览器、窗口大小（无法读取则记未知）、cursor、具体操作和截图或本人文字确认。未亲自打开就写“未测”；只有 HTTP 200 不能通过 U1。若有控制台错误，保存错误摘要，不上传包含会话信息的 URL。

## U2：任务与网页/Agent 对照（A3 后，约 3 分钟）

先完成现有 A2/A3，使每位队员确实有 `fit-<login>` 和独立的 `protocol-<login>` 任务。暂停写入，等待各端同步到同一个 cursor C；不必要求所有人毫秒级同时看到更新。

1. 在 Board 过滤本人任务（队长可选一名已报到队员）。打开任务详情，核对负责人、状态、验收条件、交付链接、blocked；独立 protocol 任务不应凭空生成 Canvas 模块。
2. 从 fit 任务定位到 `analysis`，再回 Board，核对过滤条件与上下文。把窗口缩窄一次，确认详情不会遮住唯一可用的关闭/返回操作。
3. 在 Canvas 原位展开 analysis，检查 baseline → residuals → revision → baseline 的箭头端点和标签，特别是绕下方返回的反馈边；文字和连线无相互遮挡。
4. Agent 用 `team query --mode view --view overview --expanded analysis --cursor C` 核对相同展开范围的规范 ID；用过滤后的 `board` 核对任务字段。页面“图数据”是视图查询入口，不能只凭截图颜色判断版本。
5. 刷新页面后核对当前任务与节点仍可读取；尚未保存的草稿如需检查，只在本人有权编辑的 protocol 任务中输入，取消并确认没有提交。未实际检查草稿保留就单列未测。

UI 的保存/拖动能力与签名请求成功分别验收。U1/U2 以读取操作为主，真实状态变更沿用 A2/F 阶段的授权和回执检查，避免多人随意拖卡干扰固定版本比较。可记录不影响任务的小问题，不把一次打开正常写成“所有界面完全无问题”。

## R1：Agent 自主选择读取策略（约 10 分钟）

每个人的 Agent 都参加，包括队长。先读 `.agents/skills/system-atlas/references/agent-interface.md`；以一次 `team manifest --state "PRIVATE_DIR"` 获取已确认 cursor、规模、策略、默认预算。无需读取完整 JSON 源文件或安装额外 MCP。

先把链接中的**问题卡**交给 Agent，让它自行选择查询、解释依据并回答。作答前暂不打开单独的命令对照和评分文件，也不要先运行自动探针再把探针答案当自主作答。若已看过，记录“参考答案可见”，只评估操作/复述准确性，不声称无提示策略选择能力。其他 Agent 不自动发现 Skill 时显式读文件，记录多花的步骤。

先读取 [问题卡](READING_QUESTIONS.md) 作答，完成后再打开 [命令与评分对照](READING_REFERENCE.md) 核验。每题按策略选择、事实准确、范围完整性和局限分别记录；不把 Agent 自报“理解了”作为证据。此分步读取也避免每次提问都加载全部协议和评分说明。

## R2：发生一次变更后能否只读增量（约 3 分钟）

记录已同步 C0；队长只更新一名成员的 protocol 任务 blocked 为本轮短码，然后暂缓其他写入，待全员同步 C1。每个人读取自己服务的 `GET /api/diff?after=C0&cursor=C1&limit=100&maxBytes=8192`，说明只改变了哪个任务字段、哪些模块没有改变，再只查那个 taskId 回读。若分页，固定 from/to 游标继续，不把首屏当全部。

注意 Atlas 0.5 没有 `team diff` 或 `team watch` 子命令。团队成员可通过**自己的 loopback HTTP 只读接口**读取增量。标准 CLI 的 diff/watch 可以连接明确的服务，但不能对成员重新启动一个本地权威 preview 或直接读取队长私有源。探针的 `--url` 方式覆盖最简单的 HTTP 路径。

需要检查订阅时，每人在自己的服务对 `/api/events?after=C0` 建立一次**最多 30 秒**的 SSE 连接（可用 curl 的 `--no-buffer --max-time 30`，超时结束单独记录，未收到事件不能判通过），在此窗口内由队长做上述变更；收到新 cursor 后执行 diff。记录连接、通知、回读各自结果。SSE 是事件流，不是整图，也不会唤醒已结束的 Agent。客户端不能维持流时标注“订阅未测/不支持”，用一次状态检查后 diff 的方式恢复；不要无限重连。无历史 cursor 则读取 manifest 重建范围，不能宣称连续增量。

## 成本和易用性怎么记

同一人、同一模型、同一 cursor、同一个问题比较“已经读过 manifest 后的窄查询”与“一次 full 全量基线”；首次使用的 manifest/Skill 阅读成本单列，不能摊掉后声称首次就更省。6 节点小图可能因为固定信封或多次调用而使冷启动更贵，这是结果，不应调指标隐藏。

- 记录每题工具调用数（含失败/重试）、实际返回 UTF-8 字节数、recordBytes、命令耗时、Agent 到回答的总耗时、是否需要本人纠正或手工换命令。
- 宿主能提供用量时记录 input/output/cached/reasoning tokens、模型 ID 与实际计费；不能提供就填未知。**字节数、字符数和 `recordBytes` 都不是计费 token。**命令耗时也不是模型思考耗时；本地分页元数据可能增加开销。
- 初始日常读取预算：单次普通查询的 records 最多 8 KiB；允许信封额外开销。Q1–Q7 通常每题不超过 3 次有效读取（共享的一次 manifest 单列）；分页审计和故障诊断单列。达到预算仍不足以正确回答时报告原因并针对性扩大，不能静默截断来“达标”。这些是本轮可调整目标，不是上游保证。
- 全量基线允许显式一次 32 KiB records 预算；探针总计最多 32 次 CLI 调用防止无限循环。若实际模型超出本轮小图，应停止使用此固定答案探针并另定预算。
- “好读”需要 Agent 提供具体证据：是否从 manifest 找到正确策略，是否需要自写遍历器，是否误解字段，修正后是否还能用 3–6 句回答。分别记录各客户端，不以平均值掩盖某个 Agent 完全失败。

先完成自主作答，再运行一次机制/测量探针（不把原始全量文件全喂给 Agent）：

```sh
uv run python scripts/rehearsal_read_probe.py --state "PRIVATE_DIR" --actor LOGIN --url "OWN_LOCAL_ORIGIN" --out "NEW_OUTPUT_DIR"
```

`--actor` 选已有 fit/protocol 任务的真实队员，队长也可选择同一个队员用于比较；`--url` 是本人的 serve origin（例如 `http://127.0.0.1:实际端口`，不能带 token/query）。新输出目录可以放 `results/rehearsal/<run-id>/<login>/reader-probe`；存在时改用新的 attempt 子目录，不覆盖旧测量。R2 后若同时测增量，加 `--after C0`，该区间须只有预定任务字段变更。

脚本调用实际 team CLI，记录原始查询文件和 `metrics.json`，检查八种策略、空路径、分页、错 token 拒绝，以及同 C 的 HTTP/CLI 视图。可选 diff 检查任务级增量。它不运行另一个 Agent，不开浏览器、不发消息、不导出私钥、session 材料或完整 team state、不自动同步、不判定语义理解。仅输出摘要；结果 PR 提交筛选后的指标和必要证据，不要把输出中可能含个人路径/本轮私有任务信息的原始文件未经检查整包上传。

最后在 RESULT_TEMPLATE 的 U/R 表填各人实际结果。通过需要“本人操作记录 + Agent 实际问答 + 查询证据”，花费仍未知就如实保留未知，不写“低成本已经证明”。
