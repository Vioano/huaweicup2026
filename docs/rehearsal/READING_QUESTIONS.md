# Agent 读取问题卡

每题保留：原问题、选择的策略及理由、命令或 HTTP 参数、cursor/范围/完整性、回答、局限。一般回答 3–6 句即可，不要求抄回整个 JSON。

| 编号 | 发给 Agent 的问题 |
| --- | --- |
| Q1 | 当前系统顶层如何组织？哪些细节被折叠了？只读足以回答的范围。 |
| Q2 | analysis 包含哪些直接子模块，与外部有哪些连接？再只看 analysis 自身的完整 IO、问题与成熟度。 |
| Q3 | 只沿 dataflow 从 data 出发能到哪些节点？能否据此说数据已经实际进入 baseline？ |
| Q4 | data 到 delivery 的最短结构路径是什么？data 到 baseline 有没有显式路径？这能否说明所有运行路线？ |
| Q5 | 图中有哪些成环区域？仅看 dataflow 时结论是否相同？这些边能否证明反馈已经在真机上完成？ |
| Q6 | 我网页在 overview 中展开了 analysis；请读与这个显示范围相同的节点和关系，而非整图截图猜测。 |
| Q7 | 指定一名已报到成员，他的任务、交付物和阻塞是什么？独立 protocol 任务与系统模块有什么关系？ |
| Q8 | 用分页完成一次明确的全量审计，并证明没有漏项/重复；解释 selectionComplete、complete、page.hasMore 的区别。 |

Q1–Q7 优先小范围查询；Q8 是**唯一主动要求全量审计**的题。不能为了省输出漏掉问题涉及的边界、任务或证据。若读取时版本改变，继续使用原 C 完成本组，或明确丢弃旧组并从新版本重做，不拼接两个版本。
