# 团队同步、分支与 worktree 规范

2026-09-23，队长授权 NikolaStarx 统一管理共享仓库的同步时机、整合分支和 worktree 协调。本规范适用于本轮 A 题，不增加成员的算法任务范围。

## 权威位置

- `main` 保存已经检查、合入的共享资料与代码。每次补发资料必须通知固定 commit；不能只说“拉一下最新”。
- 任务卡保存范围与验收，GitHub Issue 传递行动通知和阻塞，PR 交付代码，Atlas 保存已接受的图谱和任务状态。四者各有用途，不能互相代替。
- `AI chats/` 是讨论原件。历史用户问答、AI 建议和未验证研究假设不是当前执行命令；冲突时按当前任务卡、契约、题面与冻结代码区分并报告，不静默改变真值。
- `atlas/a-2026` 由 Atlas 协议同步签名数据，不用于源码开发、人工合并图谱或存放私钥。Windows Atlas runtime 是另一个固定版本工作区，不能与 A 题代码分支混用。
- 2026-09-23 新增 `Vioano/huaweicup2026` 私有研究副本，由队长从组织仓库单向同步已发布提交；成员 origin、邮箱与 Atlas 权威通道不变。执行与回读规范见 [多端同步](a/MULTI_REPO_SYNC.md)。

## 分支与工作区

用户责任与实际执行会话分开，按 [session-v1](SESSION_PROTOCOL.md) 登记会话地址、任务与修改范围，具体分工直接引用 Issue 评论。每个账号可有协调和多个专项会话；同范围仅一个执行者，交接查清在途请求后切换。独立 worktree 解决文件写入隔离，不自动隔离上下文或同 actor 的 Atlas 权限。

1. 每项任务一个工作分支、一个独立 worktree；开始前确认仓库、分支、HEAD 和未提交改动。新分支用 `codex/<task>-<login>`。farmer 已存在的 `a-r1-farmeruncle123` 沿用，避免为命名重建历史。
2. 成员只向自己的分支推送；公共源码、Schema、配置、依赖、协作约定的变更通过 PR 提给队长整合。禁止直接推 `main`、force-push 共享分支、覆盖他人分支或复用他人 worktree。
3. 接收资料时先 `git fetch origin`。有未提交改动时，先保存到本人的工作分支，或用新的 detached worktree 阅读指定提交；不得用 `reset --hard`、`clean -fd`、强制 checkout 清场，也不把别人的改动擅自 stash。
4. 代码分支需要新公共接口时，由本人检查差异后合入通知指定的提交；出现冲突先报告文件、双方意图与影响。不要为消除冲突整体选 ours/theirs，更不能覆盖官方只读文件。
5. 同一分支不同时挂两个可写 worktree。runtime、实验、阅读和实现分开；实验输出按任务/种子/运行编号分目录。
6. `.worktrees/`、依赖、构建缓存、凭据、Atlas 私有状态不提交。清理 worktree 前，必须确认没有未提交/未推送成果、没有运行进程、没有未交接产物；缺证据就保留。本规范不授权自动删除成员电脑上的工作区。

## 同步时机与补读回执

- 队长新增/修正规则、公共接口、冻结材料、会影响结论的勘误：检查后尽快提交推送，不等算法完成；先发固定提交和阅读顺序，完成合入后再发 `main` 固定提交。
- 成员形成可复现的小增量或即将离开电脑时：提交并推送本人的工作分支；未完成用 Draft PR，说明已做/未做/复现命令，不能以 push 代表验收。
- 进入新实验批次或准备交付前：查收任务 Issue，核对队长最近一次公共版本通知。收到“立即补读”时优先补齐上下文，再继续可能受影响的实验；不必丢弃已运行的有用结果。
- 补读回信包含：资料 commit、实现分支/HEAD、实际已读与未读文件、对当前方案的影响、需要队长决定的冲突。fetch 成功、网址可达或收到通知都不能写成“已完整读完”。长文件分批读到末尾；摘要不能代替原文读取。
- 没有新信息不发送空确认循环。不假定 GitHub 评论会自动唤醒所有 Agent；各成员在本人已授权的工作流程中查收。

## PR 整合

队长检查范围、来源与哈希、凭据/异常大文件、相关 diff 和必要验证，并按当前[免费协作规范](GITHUB_FREE_COLLABORATION.md)核对本机/队友实测证据后决定合入（GitHub Actions 已停用）。共享资料可在检查后先合入；算法代码保持独立 PR，以任务卡验收，未验收的研究成果不混入“已通过”结论。

队长当前监控会话主责持续收信、任务路由、跟进、同步与阻塞处理；通常把专项复核交给队长指定的其他会话。2026-09-23 用户随后明确授权该会话在 Pro 等待期间亲自试跑成员实现和构造针对性对抗样本；本轮已发布的有限复核按具体范围记录，不自动成为最终验收。路由时附任务/提交/复现与待决问题，收回具体结论后再协调成员；未指定会话或未收到验收结论时保持待路由/待复核，不凭协调记录提升成果状态。

有父子依赖的 PR 先明确 base。公共任务包合入 `main` 后，队长协调后续 PR 改为 `main`，确认 diff 只含本人改动；不因父分支已合入就立刻删除仍被引用的分支。既有 Atlas 兼容 PR 和历史预演 PR 单独处理，不随本轮资料同步自动合并。

Atlas 的 doing/review/done 只表达任务进度。Draft PR 可挂为交付引用；只有确有可独立验收的产物时进入 review，队长验收后才 done。两位成员的限定写权限不因本规范扩大。

## 队友上线接入与调度

队长当前 Codex heartbeat 默认每 30 分钟检查会话登记与原任务 Issue 的上线信号；新成员上线或紧急交接可临时改为 10 分钟，双向确认并完成分配后恢复 30 分钟，最长 2 小时无新信号也恢复。使用同一自动化，不新增同类服务；这不是 GitHub Actions，也不代表能自动唤醒队友 Agent。无实质变化不通知、不产生空确认循环。

上线先取得本人 session、实际 AI/客户端能力、资料/代码版本、未提交及在途工作、可用时段与阻塞。按实际小样交付判断能力，不只凭品牌；CodeBuddy 优先承接边界清楚、可复现、输入输出与验收明确的小增量。高难理论和跨模块问题先由合适的专项突破，再交可执行的步骤。分配附固定提交、最小必读包、写范围、预算与停止/升级条件，确认对方已读并理解后才记为接手。等待关键理论或资源时保存成果，等待具体触发，不做无目标循环。
