## 新稿与人工批注的固定流程

Antigravity写稿并生成新PDF → 原写作任务在Codex内置预览打开 → 用户选择典型错误批注 → 监督任务把原话和共性要求回填项目规则并交Antigravity全文修改 → 监督任务审核并将记录交验收台展示。两个Codex任务均不替Antigravity改正文。原写作任务维护`paper/WRITING_HANDOFF_AGY.md`与`paper/AGENTS.md`作为交接入口；验收台读取固定交付，不覆盖这些文件。

## 用户在验收台任务提出标准时

1. 验收台记录用户原意、适用范围和可检查要求；将确实新增或改变的要求写入 `catalogue.json`、`LANGUAGE_STANDARD.md` 和 `STANDARD_HISTORY.md`，发布固定完整提交及标准版本。
2. 验收台在本次工作回合内主动发给整稿任务，说明新增条目、替代了哪些旧要求、影响哪些稿件或图件，并给固定链接。影响队友时在同一共享Issue同步，不等用户再次转述。
3. 整稿任务实际读取后，回复所读提交、对规则的理解、受影响范围及下一步交付。只收到消息但尚未读文件时明确写“待补读”，不能写成已执行。
4. 无歧义的新用户要求立即约束后续修改。未同步完的事项不能被标成已验收；不受影响的工作继续，不用同步等待阻止整篇推进。

## 用户在整稿任务直接做批注时

1. 整稿任务在下一次对外消息中、且不晚于交付相关改稿时，将批注主动发给验收台，不等验收台询问。截图批注或PDF标注先保留原件；用文字说明其准确位置和含义。
2. 每组批注提供：批注ID、源稿提交、PDF哈希及页码或源文件行号、原句、用户原话或明确标注为转述的内容、作者理解、拟修改范围，以及是否影响已有标准。原话、作者解释和AI建议分别列出。
3. 验收台回报实际读到的批注范围，将人工问题关联到已有验收项；只有用户确实提出通用规则时才升级标准。缺少原句或位置的转述先登记来源缺口，不冒称已看过原始截图。
4. 验收台把新通用规则的固定版本发回整稿任务；整稿任务回读。修改结果逐条引用原批注ID和新位置，不能只回复“全文已改”。

## 共同记录的最少字段

用户通常用一处批注指出一整类问题。接收方必须记录具体实例，并提炼它背后的共性要求、说明适用边界，再同步另一方；不能只改被圈的一句。两方按“收到实例→提炼共性要求→同步双方→全文检查同类问题→回报修改范围与剩余问题”执行。相同问题可能采用不同词语，不以搜索原词代替语义检查。

例如：“硬件语义”对应概括词代替具体规则；“同核子图”对应省略对象关系的压缩表达；“执行子图”对应把表示方式误当执行对象；未交代循环等待就开始无环证明，对应缺少问题、风险和论证动机的铺垫。归类不是添加未经用户要求的新标准，应指出与原批注的共同缺陷，保留科学上必要且已解释的简洁表达。

作者回交时同时列出原实例怎样修改、全文同类位置怎样处理、实际检查范围和未解决项；不以一处改好关闭整类问题。

用户进一步明确要求由AI把单个人工发现扩展为全文专项检查。例如“执行子图”的检查对象是谓语与宾语是否匹配：硬件执行的是子图代表的计算任务，句子却可能把表示对象写成了动作对象。应逐句还原谁对什么做什么，查找词语不同但语法或语义关系相同的错误，必要时包含主谓搭配、抽象对象与实际动作的混淆。一次实例可能关联很多位置，但实际数量由逐句检查决定，不预设一百处、不凑数；必须交完整位置、具体理由和未审范围。

每个问题保留稳定ID、来源类型（用户原始批注／写作任务转述／AI提议）、原稿身份、原文位置、原文、问题、适用标准、责任人、改文身份及位置、待核事项、消息链接和当前状态。

状态分别为：已发送、接收者已读、作者已提交改文、验收者已回读、仍需修改／已接受。接收者亲自提供的回执才能记录为已读；HTTP成功、push、通知投递和作者自评均不代替回读。双向同步是否完成，应按具体标准版本和批注组核对，而非一次“收到”永久有效。

并发新消息按其用户要求的先后和明确替代关系处理。发现冲突先明确列出两条来源；只对真正不能确定的用户意图作澄清。已明确替代的旧规则及时标记失效，但不改写历史原句。双方每次交付前检查最新标准、未回执批注与待处理ID。

## AI初审与作者修改

用户最新分工下，验收台停止主动派新论文标注，已完成的初审与核对结果保留。原写作任务负责监督Antigravity整改、组织全文同类检查及必要复核，并将具体记录交给网站维护者。网站接收和展示记录，不把收到改文等同于审核通过。若监督方使用子Agent，子Agent只提出意见，须由负责审阅者核对原句、上下文与理由；误报保留为不采用，科学含义不明时要求依据，不能把模型输出或没有命中关键词当成通过。

作者保有科学含义和修改的解释责任。遇到标注误解原意，按ID给定义、原题或源码依据，由验收台处理争议，不能静默忽略。涉及新的证明或实验需求应另列，不因语言整改擅自启动实验或扩大预算。
