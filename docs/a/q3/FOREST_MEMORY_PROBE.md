# 归约树前沿顺序：有限机制验证

本轮由完整500份Cache事件诊断触发，目标是在真实P3中减少不必要的中间量同时驻留、spill和FIFO淘汰，最终以Makespan改善为准。不能把Cache命中率或标量内存代理作为成功替代品。

1. **目标**：检验确定性树后序是否改善058/079的P3绝对M，并用同计划P2/P3区分L2贡献。现有c2全500成绩不变；本轮不是新的完整算法成绩。
2. **输入**：冻结官方case_058/079、config及未修改P2/P3；两图均为已见开发图，选择依据为事件诊断、树形结构及原affine策略，不代表封存泛化集。5核。
3. **输出**：`src/q3/forest_memory_order.py`、测试、精确计划/构造元数据、P2/P3原件、哈希/命令/耗时/实际调用账，结果目录`results/a/q3-nikolastarx/forest-memory-probe-20260925/`。源提交先于正式评估固定。
4. **限制**：只一个结构化候选，保留原树运算、singleton映射和Index.assignment归核；每棵树用标量中间量前沿排序子树，ID解平手。只有结构守卫接受才构造。2次完整冷进程直接构造，至多4次外部E0（每图P3、P2各一次），0在线评分选优、0随机参数、0重试；任何失败停止余下调用。1worker、每进程90s、全批300s。先核对同机其他任务资源，本批与s59现有计划无L2500配对不同输入plan、独立账本；不混入它的500预算。
5. **验收**：哈希绑定固定输入、两字段计划、覆盖/合法性/归核不变；官方P3 M低于已有同图同核c2者记局部改善；无改善照实保留。P2/P3同计划CacheGain仅为本候选的局部值，等基线配对到齐才比较两算法CacheGain。构造耗时单列，外部评估不隐藏；标量峰值是顺序代理，不能称官方L1/UB零spill证书。未计外部评估的构造器不称带在线验收的完整solver。
6. **下一步**：仅当机制与官方结果支持，才决定统一在线算法的有界候选接入及重新冻结全500；不把两格提升拼接进历史榜单。
