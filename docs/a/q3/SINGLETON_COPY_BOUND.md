# Singleton 计划的 COPY 顺序松弛下界

目标：减少 `pipe_bound` 完全忽略 COPY 所留下的假性空间，约束**同一固定计划**
还能提前多少。此模块不生成新方案，不复刻事件模拟器，不调用 Task/Step2/Step3，
暂不进入在线剪枝。原始图、两字段计划与官方配置已足够构造这个松弛 DAG。

## 适用边界

继承 `pipe_bound.analyze` 的全部检查：singleton 原 M/V 算子、整数周期、原始
tensor/直接计算边明确、没有额外 COPY 收缩造成的未证依赖、原图和方案校验通过。
另拒绝跨核直接 op 边、多计算 producer tensor、原 tensor 除 `id/size/pos` 外的
所有字段。最后一项在**整个原图**实施，防止别的 tensor 用 `logical_tid` 别名
提前填充当前 input key。带宽和延迟必须与评估配置一致，缓存初始为空。
不支持不等于非法或无收益；调用方不得将拒绝视作剪枝证据。

## 松弛与证明

1. 保留原计算依赖及同核同 pipe FIFO。跨核计算边只收费固定释放延迟。
2. 原外部输入在每个消费核有一条必需的首次 COPY_IN，归属最早消费 singleton
   桶。建立虚节点，并连向所有本核消费者。其时长至少是
   `max(1, ceil(size / max(DDR, Cache)))`。若该 key 只在一个核消费且全图无别名，
   此首次装入前没有其他 Task 能将 key 插入全局 Cache；故可加强为 DDR 时长。
   后续 spill/reload 不会越过首次 COPY 在 MTE2 的原顺序。这里不是断言后来无 hit。
3. 唯一计算 producer 的跨核 tensor 在目标核有一条必需 activation COPY_IN。
   由 producer 完成加跨核延迟连向它，服务时长用最快带宽下界；完全省去源
   COPY_OUT 服务及内存等待。即使跨核 key 因其他读取已命中，此时长仍乐观。
4. 不同子图桶的 COPY 顺序由官方稳定排序确定。Step2 只插入额外操作，保留
   原操作顺序；Step3 和 P3 使用固定 MTE2 投影、单槽 FIFO。为每个有虚 COPY
   的桶建立零时长结束屏障，使前桶全部虚 COPY 完成后，后桶虚 COPY 才能开始。
   **同桶 COPY 允许并行**。不得把该桶总 COPY 服务加在最大释放时刻后面：
   这会错误禁止“先读外部输入，再等 activation”的合法顺序。
5. 删除了 spill、内存复用、带宽竞争、同桶串行和部分输出工作，只降低时长或
   去掉实际约束。任何成功官方执行的时间赋值均满足松弛约束，因此该 DAG 的
   最长路不超过官方 Makespan。松弛图成环时返回 `UnsupportedBound`，不输出数值。

源码依据：P3 `51–67,111–123,166–174,189–208,253–275,398–434,436–474`；
Step2 扩展序列保序；Step3 `281–296` 固定 pipe 投影。全过程最慢 O(N²+E+C log C)
（当前 rank 查询使用列表查找），辅助空间 O(N+E+C)，其中 C 为必需 COPY 数；
可优化 rank 表但当前没有必要为此改变验证过的实现。

这不是所有合法方案的最优下界，也不证明当前计划可执行。跨计划改变分核或
桶顺序之后须重算。它也不是判断 CacheGain 的公式。
