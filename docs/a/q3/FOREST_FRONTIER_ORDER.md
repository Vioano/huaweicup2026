# 树内标量前沿顺序及适用范围

目标不是改变归约代数或原树，而是在官方可提交的优先顺序里更早完成、释放局部子树。该代理辅助减少内存压力，是否改善实际P3由固定官方评估检验。

设一个子树完整计算的标量内部张量峰值为 `p_i`，完成后为父节点保留的输出字节为 `r_i`，且 `p_i >= r_i >= 0`。限定每次完整执行一个孩子子树，兄弟子树不交错；其输入外部张量、workspace、不同内存池、COPY以及并行Pipe不计入这个代理。父节点分配输出时仍保留全部孩子结果，其峰值下限项是 `sum(r_i) + output_bytes(parent)`。

在以上限定模型内，孩子按 `p_i-r_i` 降序排列可以最小化峰值。证明只需相邻交换：若 `p_i-r_i >= p_j-r_j`，则 `r_i+p_j <= r_j+p_i`，且 `p_i <= r_j+p_i`，所以

`max(p_i, r_i+p_j) <= max(p_j, r_j+p_i)`。

此前已保留量在两边同加；两孩子完成后的总保留量相同，不影响之后的任何峰值项，父节点输出分配项也与顺序无关。反复交换逆序对得到该顺序，再对树自底向上递推。因此这是**不交错DFS子树模型**内的顺序最优结论，不是允许任意交错时的最优性结论。

实现以原张量边确定内部单输出与唯一父consumer，guard排除额外消费者、多producer、无法绑定大小的直接compute边和非树结构。原始边界COPY输入输出作为外部边界保留；方案只含compute节点，遵循官方接口。每树根输出的保留字节计入该树代理，组件之间仍按固定顺序，归核沿用Index.assignment。没有改运算、结合律、张量、跨核拥有者或Cache算法。

官方执行有L1/UB两池、输入驻留、spill、核内重排、跨Pipe并行和只读共享FIFO Cache。以上交换论证没有涵盖它们；故 `predicted_frontier` 仅用于生成候选，不能作为官方零spill、合法执行或Makespan上界证明。官方同plan P2/P3控制对照负责区分Cache增益与一般顺序优化。
