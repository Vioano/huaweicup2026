# 归约森林：共享输入组归核

本轮不改变正在排队的统一算法固定源码311322b；新模块先做独立机制测试。当前森林DFS解决了部分中间量前沿压力，058/5剩余13.24%计算负载松弛差距，079/5约3.14%；这些只是可改进比例的宽松上限，不保证可达。

## 结构与候选

从原图中外部tensor的compute-component读者集合分组；每个component必须正好位于两个输入组，组交叠图必须为完整二分图、每对异侧组恰好交一个component。各component每Pipe工作量相同，且原compute结构通过已有归约树守卫。识别基于真实张量边，不以节点数量因式分解、文件名或历史成绩识别。

058的重输入轴有17组、每组270336B，轻输入轴15组、每组135168B；079为18组202752B与16组135168B。此前只根据fanout口头把058重轴称15行是不准确的，以本次实际读者集合和每组字节为准；轴名无数学含义。

任一归核方案必须向每个使用输入组g的core提供该组所有tensor，故每核输入COPY字节至少为其所覆盖输入组字节之和。它**不是物理DDR流量下界**：L2命中会改变实际路径；也未包含reload、输出或spill。比较两个轴优先的遍历，将序列切成大小相差至多1的core区块，以总输入COPY下界最小、最大单核下界次之、轴序最后解平手，生成一个候选。两种代数方案不调用E0，不扫描参数。所有原树完整留在单core、沿用DFS内部顺序，原运算与结合关系不变。

058/5的该下界从旧归核25006080B降至15814656B；079/5从29061120B降至15273984B。每core树数量分别51/51/51/51/51与58/58/58/57/57，与原负载均衡同级。这只说明最低必需副本减少，不证明实际M或spill下降。

## 事前实验约定

1. **目标**：判断输入组归核相对固定311版森林DFS，在官方P3中是否改善M/搬运；同plan P2/P3拆分Cache影响。
2. **输入**：原始058/079、5核、固定配置、未改P2/P3；都是已见开发图。对照为上一轮同图5核DFS原件和原c2记录。
3. **输出**：原计划、元数据、P2/P3压缩无损JSON、输入/源码/计划/result SHA、每次调用与墙钟，独立目录 `results/a/q3-nikolastarx/forest-reuse-grid-probe-20260925/`。
4. **限制**：2个完整进程直接构造、最多4次外部E0、0retry/0其他候选；每进程90s，全批300s，1worker，与s59/P1/P2评分排队。代码和本约定先提交后运行；入口`python -m src.q3.forest_memory_probe <new-output> --method reuse-grid`。
5. **验收**：计划覆盖/合法性、每棵原树不拆、固定同plan无L2配对；任何失败停止余下调用。不用命中率或字节代理替代M，也不将局部成绩拼入已有统一500。程序计时区分直接构造与外部E0，既有全算法耗时不被改写。
6. **后续**：只有官方机制结果支持才决定新统一入口/全量验证；代理近似最优或某两图计算下界很紧，都不能证明完整P3算法全局最优。
