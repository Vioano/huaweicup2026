# 连续流水线首批加载代理：Pareto DP 静态构造

`src/q3/pipeline_startup.py` 只生成一个原图 singleton 方案，不调用求解
入口、Task、Step3 或官方评价器。它复用 `shared_pipeline._stage_structure` 的
同构作业识别和 `shared_pipeline_capacity` 的逐段共有输入去重计数。守卫要求
非空共同外部输入、真实相邻依赖、完全相同的作业签名、位置数 ≤512、作业数
≥请求核数，且所有共有原输入的原始 `pos=L1`。每个作业使用同一组连续
位置切点，核内仍按作业顺序写入；不按 case 编号、历史成绩或固定切点分支。

给正整数位置计算量 `w_i`、一个段的 `C=Σw_i`、原始共有输入 tensor ID
并集字节 `B`、作业数 `J`、官方 DDR 带宽 `b`，DP 在 `B≤L1` 的恰好
`k=min(cores, positions)` 个非空连续段中最小化整数目标：

```text
F_scaled(cuts) = Σ段 max(b*C, B) + b*(J-1)*max段 C
F_cycles = F_scaled / b
```

L1 容量从冻结官方 `config.txt` 读取；`b` 经官方
`read_bandwidth_config` 读取（本轮为 60 B/cycle），算法没有硬编码带宽。
`F_scaled` 全程使用整数。它把首批加载和后续批次的计算瓶颈合为**构造
代理**，没有计入跨核 COPY、DDR 竞争、预取、Pipe 重叠或 Step3 缓存，
因此既不是 E0 Makespan 的下界也不是上界。容量约束只覆盖各段共有原始
L1 输入；其他输入、激活和传输仍可能带来 COPY 或 spill。

DP 在 `(stage,end)` 保留二维状态 `(A=Σmax(b*C,B), h=max C)` 的完整
Pareto 前沿。若另一状态 `A'≤A` 且 `h'≤h`，两者追加相同未来段后仍满足
`A'_new≤A_new`、`h'_new≤h_new`；最终目标分别对 A、h 单调，故删去
被支配状态不会改变最优目标值。`A,h` 相同时保留最小 cuts；最终在最小
目标状态间按 `(A,h,cuts)` 固定选择。因此输出可重复、目标值精确，
**不保证所有同分切法中 cuts 的全局字典序最小**。例如 `J=1`、没有输入
字节、`w=[1,1,3]`、`k=2` 时所有切点同分，DP 可选择 `[0,2,3]`。
不存在容量可行切分则抛 `UnsupportedStructure`，不伪造近似前沿。

设 `n` 为位置数、`d` 为每位置平均共有输入引用数。区间并集预计算
`O(n²d)` 时间、`O(n²)` 空间。`h` 只可能是某个连续区间的权重和，
至多 `n(n+1)/2` 个值；同一 `h` 最多保留一个最小 A 状态，故每格前沿
`O(n²)`。未触发资源守卫时，候选生成最坏 `O(kn⁴)`，各格排序合计
`O(kn⁴ log n)`，DP 状态空间 `O(kn³)`，单格暂存候选 `O(n³)`。
超过 250,000 个累积状态或 5,000,000 次候选扩展时整项构造显式拒绝，
绝不截断前沿后假称精确。`n≤512` 是额外规模守卫。

静态测试命令：

```sh
uv run --locked --no-sync python -m unittest tests.q3.test_pipeline_startup -v
```

`J=1` 平局的确定输出、显式资源拒绝，以及原始 044/046 各一次五核构造的
原图不变与合法覆盖。两图最终前沿分别为 61、18，实际累积状态分别为
