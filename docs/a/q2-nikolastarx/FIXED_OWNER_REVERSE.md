# Fixed-owner reverse retime: bounded implementation handoff

`src/q2_nikolastarx/fixed_owner_reverse.py` exposes `retime(graph, plan, config) -> (plan, detail)`. It accepts a structurally valid singleton P2 plan within the existing `_chain_dag` physical guard. It keeps the exact `node_to_subgraph` mapping, every operation's core, and the number of cores. It changes only each core's operation order. There is no wrapper or evaluator call.

The constructor splits maximal serial chains at owner boundaries, reverses the resulting segment DAG virtually, and uses one deterministic sink-first rank/Kahn pass with a per-core, per-pipe free-interval calendar. Every segment cross-edge, including a split inside one original chain, receives `_chain_dag`'s static physical/direct-edge estimate `cross_delay + 2 * sum(max(1, ceil(size / bandwidth)))` when owners differ. It reverses each core's virtual chronological order to obtain original-direction priorities. Before returning, it checks complete operation coverage, acyclicity of the original dependency DAG plus every per-core order, and `derive_multicore_plan`. Failure raises `UnsupportedStructure`; a future wrapper must retain the incumbent if that occurs. The official parser accepts both integer and decimal-string operation keys, and the output retains whichever form the input used.

For `V` eligible operations, `E` contracted dependencies, and fixed at most five cores, the DAG work is `O(V + E)` and calendar/order work is approximately `O(V log V)` using the existing AVL interval calendar. Memory is `O(V + E)` for the retained graph, segments, and calendar state. The modeled reverse finish is diagnostic only.

Validation: `python3 -m unittest tests.test_q2_fixed_owner_reverse -v` passed seven synthetic tests. They cover owner/partition preservation, original data plus core-order legality, deterministic output, a changed order on an asymmetric fork/join, split-chain static lag entering reverse release, integer mapping-key preservation, and rejection of invalid singleton/physical/cyclic inputs. No real graph, official constructor, prepare, solver, E0, E1, or E2 was run.

Limits: This static calendar omits COPY contention, dynamic DDR, capacity, spill, and official Makespan. Owner/partition preservation alone does not guarantee equal extra DDR bytes; such an equality claim requires evidence that **both** compared plans actually have zero spill under the relevant evaluator. A model-sorted order can form a global cycle, so the explicit acyclicity check is required. No official quality or latency gain is claimed.
