# P2 r03：收益证据与下一步构造

本记录审查 [第三轮公开答复](../../../AI%20chats/20260924-P2-异构流水与最优性界/r03-final-dom.txt)，消息 `adfe3f2a-77d8-4bdd-be48-fbb052d87a8d`。答复是公开 DOM 转换，数学式保留页面源式；完整归档清单记录读取范围和未取得的附件。Pro 自报没有运行官方 Step2、Step3、E0、E1、E2，其合成测试数字不属于本机复现。以下区分作者建议、源码核对与尚待验证的结论。

## 已核对的关键条件

1. 冻结 P2 `_build_scene_b_tasks` 按 tensor 的实际生产核、消费核去重；同一目标核多个消费者只生成一份该源核到目标核的传输。原图输入按消费核生成 COPY_IN，输出按官方条件生成 COPY_OUT，跨核直接算子边另生成一对 COPY。图输入/输出搬运与跨核转发不能任意合并。
2. `_op_duration` 对每个 COPY 先计算 `max(1, ceil(size / bandwidth))`；P2 事件模拟再把这个整数 duration 赋给 `ddr_remaining_work`。所以这里共享的是已取整的服务工作，不是先汇总字节再统一取整。零字节 COPY 也可能贡献一个周期。
3. Step2 扩展图保留原任务 COPY，spill 增加新操作。因此只计原始任务中必需的 DDR COPY 是遗漏非负工作的松弛。其总服务量是理想整数服务模型中的 Makespan 下界，不能再把这个量直接加到全部计算时间上。
4. 官方事件循环含浮点工作扣减与 `1e-9` 容差。本次还没有证明任意数量级输入下该实现与精确服务模型完全等价。新静态计数模块应说明数值域，并用已有 E0 原件核对；不能凭数学式直接宣布官方实现全输入域证书。

## 建议的适用范围

| 建议 | 可用于什么 | 必须保留的限制 |
| --- | --- | --- |
| 必搬 DDR 服务量下界 | 当候选下界严格大于已知合法方案 Makespan 时，拒绝必败候选；同值仍保留少搬运的可能性 | 正确去重、计入输入输出、配置与数值域已核；下界低不表示候选好 |
| 闭合分支迁移 | 对 `P → {X,Y} → J`，将一支迁到 helper，保留原依赖；只比较 whole/cut | 单计算 Pipe、边界闭合、块内等待已计、共享输入合法驻留或已计其读取；通信量不能冒充响应时间上界 |
| DMA 因果区间上界 | 分析一份固定 prepared 图的潜在共享带宽竞争，定位候选是否可能获益 | 必须包含真实 COPY/SPILL、MEMORY_REUSE、每 Pipe FIFO、跨核完成到开始的 lag；不直接套原始计算图 |
| 输入—输出 DDR 时间窗下界 | 解释仅优化活跃核计算松弛为何可能误选核数 | 下界最小不等于实际最优；作者小例未在官方 lowering 下复现 |

闭合模型令 donor 为 `P,X,Y,J`、helper 为 `Q`，计算时长为 `a,x,y,z,b`。若输入与返回响应分别有可信上界 `Df,Dr`，则作者给出

```
Ucut = max(a+y, max(b,a+Df)+x+Dr) + z
```

在 whole 由 donor 控制、`Twhole=a+x+y+z >= b` 时，`y > max(b-a,Df)+Dr` 是该模型中的严格改善充分条件。代数展开成立；一般异构多 Pipe 图和真实内存门控是否满足假设，要另核。当前 `guarded_component.py` 仍构造既有 DAG 候选，并没有实现这次的闭合迁移，不应借用其定理标签。

DMA 区间建议对其他物理队列取最大祖先下标 `alpha`、最小后继下标 `beta`，中间严格开区间恰为不可比较 COPY。FIFO 的链结构支持此前缀/后缀论证。若不可比较队列数加自身为 `kappa`、全部不可比较服务工作为 `I`，则流体共享模型中的运行时长上界是 `min(kappa*d, d+I)`。它约束运行期间，门控等待必须通过前驱图另计。将该上界沿完整执行 DAG 递推才是固定计划上界；尚未取得并验收实际 E2 prepared 导出契约，不宣称已落地或带来求解提速。冷准备仍可能支配成本。

E2 单写者随后只读确认：[接口审查回执](https://github.com/huaweibei123/huaweicup2026/pull/46#issuecomment-5821147398)。公开 `SceneBEvaluator` 没有稳定取得或复用 prepared 图的 API；full 官方结果也不含完整 MEMORY_REUSE 边。内部压缩缓存不保留全部 COPY/SPILL 来源身份，不能用评分 record 或私有 debug 接口冒充该证书输入。本轮不修改共享 E2，也不把证明建立在一个尚不存在的公开接口上。

## 与已测成绩的关系

第三轮发送时固定的 `2794ceba93acc1f7fc119154f61082511843d4b3` 算法在答复之前已经实现并冻结。这轮 Pro 不能获得其全 500 成绩提升的因果归功。它更直接的帮助是解释旧 `ee1b8fd` 任意 DAG 拆分退化，并提出更可靠的筛选与更窄的构造。

作者用已报告的额外搬运量说明 012/k4、055/k5 的候选绝对服务下界已高于 whole Makespan。这是对既有数字的事后机制解释。我们将从原图与固定计划重建必需计数，比较已有官方结果；不把作者除法核对当作新 E0 实验。016 的约 40 MB 新搬运虽大，仍可能被百万周期计算隐藏，因此“通信服务量大于计算节省”不是安全拒绝条件。

## 锯齿、泛化与研发优先级

正式比较始终是一套冻结算法覆盖全部 100 图 × 1–5 核，逐例采用相同官方单核基线，报告算术平均。平均变化为 `sum(B_i * (1/Mnew_i - 1/Mold_i))/100`；胜出例数、总节省周期都不能替代它。DDR 与端到端求解墙钟另列。

接受由图结构、有限并行度、取整与通信重叠产生的差异；修复遗漏必需工作、漏掉门控、把下界当收益等系统性错误。锯齿本身没有防过拟合能力，反复叠加形状特判也可能依赖公开用例。按结构做已知边界两侧的合成验证：改变 job/阶段数量、共享输入分组、可整除性、时长与搬运比、内存容量与 credit 来源；这些都是证伪实验，不估计未知官方测试分布。

ID 重标号须分两步：先把同一计划经双射迁移，核对官方 lowering 是否也受 ID 排序影响；再运行求解器检查其稳定性。不能直接将重标号后的所有差异归咎于算法，也不能因无 case-ID 查表就断言不可能过拟合。

## 当前落实顺序

1. 静态必需 COPY 计数已完成六项小例对照、六份计划原件对照，并追加旧四/五核 59 个 component-DAG 提案的筛选覆盖审计。42 个退化提案中排除 32 个，17 个获益提案均未排除；尚余 10 个退化无法识别。随后接入实验 guarded 入口，未知计数仍走完整比较。此为静态事后机制核对，不是新算法成绩。
2. 已固定的三对六份计划 E2 域校验等待资源负责人释放窗口；首次 fallback、错误或与已有 E0 不一致即停。不占 P1 正在使用的窗口。
3. 在验证域成立后，将 cheap lower bound 与完整 whole/cut 比较接入固定入口；新源版本单独冻结。最终成绩必须重新覆盖同一算法全 500，不能跨历史批次选格。
4. 用保留的困难图和结构证伪实验研发闭合迁移；真实 prepared 图证书可作为后续定位工具。暂不再发笼统 Pro 综述，先产出具体反例、无法收紧的界或构造难点。

旧 component-DAG 提案已知全部正收益在四/五核均值中分别只贡献约 `0.05414 / 0.05912`。这个事后候选能力分析不构成可提交算法成绩，也没有实施历史逐格拼接；它说明继续给同一候选精雕评分不足以填平到目标的缺口，研发需增加有效的新结构构造。
