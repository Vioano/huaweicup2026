# 返程切口构造类：先核对资源下界，再扩大搜索

2026-09-25。根代理推导；Sol 独立核对代数和限定语义。实现见 `src/review/p1_return_cut_resource_bound.py`。这是不运行编译器、响应模拟或评分器的元数据分析，用来判断研究空间，尚未接入生产剪枝。

## 适用范围与计时模型

考虑同型、私人 `M(a) -> V*(b) -> M(c)` 链，`b` 是整段 V 的正整数工作量。每条链始终属于一个核；核 k 固定含 N_k 条。每条链只能完整 W 留在一个 Task，或在最后一个 M 前切成 P、R 两个 Task 片段。不同链可以组合进同一 Task。要求无 spill、保持官方的计算顺序，并满足每条未切 W 的两个 M 在其 Task 的 M FIFO 中相邻。

官方 Step1 从 sink 反向 DFS，私人分量之间没有边。完整 spine 的终点（或它的边界 COPY_OUT）比同分量的中间 COPY_OUT 更深；终点自身若是 sink 则具有非 COPY_OUT 优先级。首次进入该分量时会完成整条 compute spine，期间不访问其他分量。Step2 无 spill 时保持 compute 序；Step3 从该序过滤出 Pipe FIFO，新增 MEM 前驱不改变 FIFO。故上述相邻性可由这些限定前提导出；任意非私人图、其他内部切口、跨核拆链不在本论证内。

这里的 T 是**精确共享 DDR 服务、完整 FIFO 依赖**模型中的周期时间；每个 COPY 的独占工作量逐项取 `max(1, ceil(size / bandwidth))`。尚未证明官方 E0 的 binary64/EPS 事件舍入在所有输入上绝不低于此界，不能直接以本结果剪掉官方候选、声称官方最优或全 P1 最优。题目实际成绩仍由冻结 E0 产生。

## 从构造降到一个小资源问题

设核 k 有 x_k 条切开的链，0 <= x_k <= N_k。未切 W 的两个 M 之间至少经历其自身 b 个 V 周期，并且其他 M 不能插入这一 FIFO 间隙。各完整链的 M 间隙与其他链的 M 工作互不重叠，所以：

`T >= N_k(a+b+c) - b*x_k`，且 `T >= N_k*b`。

设 d_P、d_R、d_W 为相应片段的全部边界 COPY 独占服务。按官方边界谓词包含旁路输入、死输出及显式 COPY_OUT；不能只数主干切口。令 `Delta=d_P+d_R-d_W >= 0`，`C=sum(N_k)*d_W`，则共享 DDR 有：

`T >= C + Delta*sum(x_k)`。

舍去容量、MEM 等待、Task 门控及其他时序约束，只会使这个问题更乐观。资源问题的可行解不是合法方案，不应把它给出的 x_k 当作已验证构造比例。

## 连续闭式解与整数强化

写 A=a+b+c。给定 T，连续切链数至少为 `max(0,(N_k*A-T)/b)`，还须 T >= max(N_k)*(a+c)。DDR 条件中的正部和等于对所有子集取最大；给定子集大小 m，最大的 N_k 构成最强条件。因此连续资源最优值精确等于以下各项的最大值：

- `max(N_k)*b`；
- `max(N_k)*(a+c)`；
- 对 m=0..K，`[b*C + Delta*A*sum(largest m N_k)] / [b + Delta*m]`。

原构造的 x_k 必须为整数。给定整数 T，必要的最小切链数为 `x_k(T)=max(0,ceil((N_k*A-T)/b))`。当且仅当每项不超过 N_k、V 工作不超过 T 且 `C+Delta*sum(x_k(T)) <= T`，整数资源问题可行。这个谓词随 T 单调，故在 `[max(max(N_k)*b,max(N_k)*(a+c),C), max(max(N_k)*A,C)]` 内二分求最小可行整数。

这是小资源放松问题的精确解，不是对实际调度进行暴力迭代。时间 `O(K log K + K log U)`、额外空间 `O(K)`；读取和识别原图的成本另计。最小 T 可行、T-1 不可行是资源问题的证据，不能替代完整调度证明。

## 两 Task 候选的额外次序条件（2026-09-25 补记）

资源最优切链数不决定 Task 内的 FIFO，不能直接当作最优构造比例。一个候选将未切 W 与切开链的 P 放入第一个 Task，将 R 放入第二个 Task。若**实际编译后的计算 FIFO 确为所有 W 在所有 P 之前**，V 顺序一致，且 b >= a，那么忽略 DDR/MEM 后，x >= 1 的单核完成时间为

`(N-x)(a+b+c) + a + x*b + x*c + g = N(a+b+c) - a(x-1) + g`。

这里 g 是两个非空 Task 间门控，x=0 则只有一个 Task，时间为 N(a+b+c)。这个模型比前述资源放松多保留了指定 Task 分组的启动和收尾约束，仍不是官方 E0 数值证书。

**不能只凭“私人同型链”推出 W 先 P。** 冻结 `schedule_step1.py` 的 sink 排序首先比较 `not is_copy_out`，深度只是第二项，升序压栈后从栈顶处理。如果 P 的最后 V 因直接 op 依赖跨 Task 而没有边界张量 COPY_OUT，它可优先于以 COPY_OUT 结束的 W。手工计算例：a=c=1、b=10、N=2、x=1，P 在前时两个 Task 的无 DDR/MEM 总时长为 23+g，而上述 W 先 P 式给 24+g。因此该式只在已核 FIFO 前提下使用；这是源码和手工时序审查，尚未执行这个合成图的官方编译或 E0。该限制不推翻前节不要求 W/P 相对次序的资源放松。

## 足以推出 W 先 P 的可检查条件

在作者 `recognize` 已接受的私人同型链中，另要求**最后一个 V 至少输出一个被末 M 消费的张量**。继续要求无 spill、无内部原始 COPY_OUT 输出 tap、所有完整 W 和切开链的 P 同属首个 Task，所有 R 同属第二个 Task，且没有其他 Task。此条件比只检查 compute 直接依赖更强；直接 V→M 边不能替代张量边。

切口使该张量在 P 中生成 COPY_OUT，所以 P 的末 V 不是非 COPY_OUT sink；P 的所有 sink 都是 COPY_OUT。W 的末 M 若没有输出，则是优先级更高的非 COPY_OUT sink；若有输出，则其终点 COPY_OUT 比同型 P 的最深 COPY_OUT 多经过末 M 一层。私人分量之间没有边，反向 DFS 访问一个终点时先走完其完整 compute spine。因此每条 W 的计算先于任何 P。Step2 无 spill 保持计算顺序，Step3 的 MEM 边可以增加等待，但不改变这个计算 FIFO。此论证允许同一条链内的跳边和旁路输入；不允许把不满足识别器或张量条件的图强行代入。

设 A=a+b+c、b≥a、每 Pipe 单槽，忽略所有 DDR/MEM 等待。x=0 时只有一个非空 Task，完成时间为 NA；x≥1 时，两 Task 至少需要

`C(N,x) = (N-x)A + a + xb + xc + g = NA - a(x-1) + g`。

其中首项是串行完整链，a+xb 是切开前缀在 M/V 两 Pipe 中的填充与处理时间，xc 是第二 Task 的串行末 M。g 只在存在第二个非空 Task 时计入；不能对 x=0 加门控，也不能将 x=1 当作自然收益。公式描述删除搬运和 MEM 约束后的计算模型，实际任务完成还可能更慢。

固定整数 T 时，最少切链数为：若 T≥NA，则 x=0；否则 `x=ceil((NA+a+g-T)/a)`。若 x>N，则该核不可行。再与 `sum(N)*d_W + Delta*sum(x) ≤ T` 联立，得到关于 T 的单调整数判据，可以二分求这个**两 Task 构造类的资源放松**的最优值。最小 T 可行且 T−1 不可行，仅证明这个小资源问题的最优；不证明其能达到，也不证明其他 Task 分组不能更好。实现 `src/review/p1_two_task_resource_bound.py` 的复杂度为 O(K log U)，其中 U 是零切口资源值。

该更紧的界用于检验“照资源比例只做两大 Task”的方向是否合理，并解释大 Task 的填充、排空和 FIFO 损失。它不是 E0 浮点舍入证书，不用于生产剪枝；也不排除多阶段 packet 构造或跨核方案的进一步提升。纯整数测试与真实编译、模型响应、正式 E0 成绩分别记录。

## 推广到 packet 转移的盒下界

上述末 V→末 M 张量条件也可以加强 Pro R4 的边资源界。考虑状态 (n,r) 的一个 Task：r 个旧 R、q−s 个新 W、s 个新 P。所有原件 ID 保留，各核是同型私人分量，且本次编译无 spill。R 只有末 M；边界搬运加入后，其 sink 深度至多是 COPY_IN→M→COPY_OUT 的 2。若末 M 没有输出，则 W 和 R 的 sink 都是非 COPY_OUT，但 W 至少经过三层计算 spine、比 R 深；若有输出，则 W 的终点 COPY_OUT 深度至少为 3。故同型终点属性与前节条件共同保证所有 W 的计算先于 P/R。P 与 R 之间不要求固定相对顺序。

令 w=q−s。先处理的完整 W 至少用时 wA；它们的 M FIFO 阻塞使这段 compute 时间不能被 P/R 填补。随后有两条独立必要条件：P/R 的 M 工作至少为 sa+rc；若 s>0，任一 P 的 V 开始前至少执行其入口 M 的 a 周期，全部 P 还需 sb 个 V 周期。因此转移时间至少为：

`max(qA − s(b+c) + rc, qA − s(a+c) + a·1[s>0], K[q*d_W + s(d_P−d_W) + r*d_R])`。

这只是下界；不要求 b≥a，也不假装删除 DDR/MEM 后的贪心响应一定是下界。相比 R4 的 V 项 qb，新的第二项在每个整数点都不小，因为差为 `(q−s)(a+c)+a·1[s>0] ≥ 0`。

剩余时间仍取 R4 的三种必要资源：各核剩余 M 工作、V 工作、全局必要 DDR 服务的最大值，并忽略未来门控。固定 (n,r) 后，转移界及尾部界都是 (q,s) 的 max-affine 函数。一个盒若 s 下界≥1，可保留填充项 a；跨过 s=0 的盒去掉该项，仅使界更松。`src/review/p1_packet_edge_bound.py` 用 Fraction 枚举裁剪盒和线性分区的全部可行交点，精确求两组 max-affine 之和的实数最小值，再向上取整。孤立的可行最小点本身不是证明；验证须包含完整交点枚举。

`tests/q1/test_p1_packet_edge_bound.py` 独立计算所有小规模 P/R 交错的两 Pipe 最早完成时间，验证新计算界不会过高，另检查 s=0、退化盒、分数交点及新界不弱于旧界。它不调用官方编译器，不证明 E0 数值等价。

## 惰性展开控制器的边界

`src/review/p1_lazy_packet_search.py` 首次把 R4 控制器伪码变成可执行的**纯抽象代价**算法。未处理 normal 转移由整数盒覆盖，盒仅做完整、不相交的二分；单点才查询精确边代价。drain 与两种 terminal 单列，前缀改善时重开状态。旧 revision 的盒可丢弃，因为相同 (n,r) 的更小前缀会重新覆盖所有未来转移；这依赖后续成员及代价只由状态决定的前提。

None 表示已证不支持；未知/超时有独立标记并保留其界。调用和展开预算分别限制，避免“只限制编译次数、却先拆出巨大盒网格”。同一冻结抽象边的查询结果会缓存，未知边不会因状态重开而隐性重试。输出的 OPEN/未知明细保留未解决路径覆盖；`lower=min(upper,所有活跃未决界)`，只有同一抽象模型的已知完整路径 upper 存在且等于 lower 才标记该模型的标量最优。

当前尚未把这个控制器接到真实 Task 编译与求解器；不能把 E0 的 upper 填入 Fraction 模型，也不能把抽象图上的最优标志解释为真实方案验收。实际接入还须统一首个/后续 Task 的门控口径，使用已审缓存契约，逐 Task 重编译最终原图计划并核对完整响应及字节数；任何未验证候选都不能替换生产基线。此实现用于准备有数学依据的候选展开，不是新官方成绩或已测端到端提速。
