# A 题图谱：一份事实，多种读取视角

用户已确认：研究路线与成员工作两种视角都要有，它们是同一模型的投影，不是两套分别维护的状态。

- **研究路线**：官方语义/E0、形式化与对抗、E1、E2、独立验收，以及尚未启动的调度搜索。模块可下钻为具体工作与候选探索。
- **成员视角**：通过任务的 `assignees` 和 `entities` 关联选择相同节点。成员没有独立复制的模块；节点 ID、细节、成熟度、证据仍唯一。成员总览与个人聚焦视图使用相同实体集合的不同位置/选择。
- **Board**：任务的 todo/doing/review/done、阻塞与交付；负责人只以任务记录为准。Canvas 的设计/实现/验证/集成四轴不等价于任务进度。

图中“队友报告”“待复核”“计划”“候选”按文字明确区分。已有实现或实验报告尚未绑定并独立复核时，不把整个模块升级为通过。当前 FORM 首批来源为 Issue #14 / PR #17，E1/E2 阶段来源为 Issue #15；候选探索不增加本轮已指派任务的交付范围。

候选分支可以先作为末端节点保留。验证失败时保留该节点及失败原因；确认采用之后才向后增加真实后续关系。未来调度搜索保留为未分配节点，尚未把任何 E1/E2 候选画成已采用方案。

`parent` 只表示子模块归属。连线 `from -> to` 在本图表示输入/依据流向使用方；`dataflow` 是数据交接，`dependency` 是设计依赖，`feedback` 是验证反馈。连线表示结构或约定，不证明已实际执行。虚线仅是显示样式，查询不会据此排除假设分支；不得把 reach/path 查询结果当作执行轨迹。

读取策略：`overview` 看组织；`local` 看一个方向与子图；`view` 获取与 Human 同一投影；`board --assignee` 看某人的任务；`board --target` 看节点关联任务；`reach/path` 只分析已明确定义的结构关系。多次读取固定同一 cursor，后续用 diff；不要混用不同版本。

队长私有 `model.json` 是权威源；Git 的 `atlas/a-2026` 分支为签名发布副本。成员/研究视图都从该权威模型读取。新增或改变任务关联时一并更新成员投影，不另造“成员版状态”。
