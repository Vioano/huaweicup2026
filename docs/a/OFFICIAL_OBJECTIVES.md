## 2. 从输入到最终成绩

附录 B.5–B.6（第 10 页）和 [官方 README](../../data/raw/a/official/README.md) 的“最常用的四条命令”“从输入到 makespan 的完整流程”共同明确：

1. 求解器接收原始计算图、核心数和固定场景/配置，输出 `<case>_multicore_res.json`。
2. 方案顶层必须且只能有 `node_to_subgraph`、`core_schedules`。前者恰好覆盖全部非 COPY_IN/COPY_OUT 操作；后者同时表示分核和每核执行顺序，每个子图恰好出现一次。需满足子图依赖和实际执行合法性。
3. 官方评估器读取图、方案和配置，重建 Task/边界搬运，运行固定核内调度和事件模拟，产生结果 JSON、Trace 和日志。**方案文件与评估结果文件是两个不同产物**。格式示例 stub 明确不是参考优化算法。
4. §1.4 和附录 B.1 要求以官方脚本和固定配置产生论文成绩。队内 E1/E2 可帮助研发和筛选，最终提交方案仍以未修改 E0 复评。

## 3. 两种时间和三个层次的“加速比”

| 量 | 单位/比较方式 | 用途与限制 |
| --- | --- | --- |
| 方案 Makespan | 模拟 cycles | 优化切图与调度结果；并非运行评估脚本的秒数。 |
| 求解端到端耗时 | 实际 wall-clock 秒/分钟 | 从图输入生成最终方案是否高效；不能只取一个内核或一次评分时间。 |
| 官方方案加速比 | 固定单核基线 Makespan / 当前多核 Makespan；P3 用同核数无 L2 / 有 L2 | 官方论文的方案质量对照。 |
| E1/E2 工程加速比 | 同资源、同范围、同口径的评估耗时或批吞吐之比 | 队内提效指标；与官方方案加速比不同。 |
| 求解器端到端提速 | 同图/配置/预算及明确方案质量条件下，完整求解耗时之比 | 必须包含构造、评价、选优等全部在线步骤；没有完整测量就不得以评分循环代称。 |

**团队计时约定（不是宣称官方给出了这些细节）**：每次图/场景/核数运行，从求解程序启动、输入读取到合法方案持久化以及返回所必需的收尾，使用外层墙钟。计入在线图分析、构造、搜索评分、内部 E0 确认、回退、加载/初始化、IPC 和同步。给定场景/核数是团队实验单元；脚注没有明确把每种核数/配置各分配一份官方 10 分钟额度，不得如此宣传。

纯粹在求解器结束后运行的独立官方最终评估可另报，其时间不能拿来冒充求解时间；若在线调用同一个官方脚本选方案，其调用及等待必须计入求解时间。预安装环境、一次性编译、离线训练与共享预计算另外记录成本、身份及摊销范围，首次冷启动需要的编译/加载则计入冷启动耗时；针对当前用例的调参和预计算不能藏在计时起点之前。网络/GPU/多进程资源与排队范围写清，不假定硬件越多就可无限增加搜索。

记录 CPU/GPU、内存、线程/worker 数、版本、输入/输出哈希、随机种子、停止条件、失败/超时率及逐例用时。实际 5～10 分钟级目标的硬件条件须由实验报告说明；官方上述脚注未给参考机规格。开发阶段可采用更小且明确的预算，原有限次数/墙钟预算不因本规范增加。

## 4. 搜索方法与研发取舍

优先寻找图依赖、通信、Pipe、容量和同步结构能够解释的构造/分解方法，并用官方成绩证明收益。局部改进、数学规划、动态规划或学习模型不是仅凭名称就好或坏；需说明有效候选来自何种结构、复杂度/候选数、停止机制及相对简单基线的增益。

**“只暴力枚举 32 次”不自动符合题意；“用了高级数学/神经网络”也不自动比简单构造好。** 若方案主要靠扩大枚举、随机重启和评估器调用次数换取偶然好值，应检查是否违背“避免暴力迭代搜索”的设计要求。报告有限局部搜索时，不把“原文未全面禁搜”当成暴力迭代的通行证；优先解释结构化缩小空间和质量—成本证据。

E1/E2 优化服务于在合理时间内构造更好的官方方案；已经授权的 [E1/E2 工程标准](EVALUATOR_AMENDMENT_20260923.md) 不被取消，也不是官方提出的标准。不能只因某评分器更快，就扩大已有实验预算、把全队工作变成无限调评估器，或宣称最终求解目标已完成。精确规则、反例、快速评价各自价值要回到这一目标解释。

### 队长进一步明确：同时追求更好的方案和极快的求解

队长于本次核验中进一步要求：**两方面都尽量优化到极致**，尝试远快于分钟级的构造速度，而非把落在 5～10 分钟内当作停止提效的充分条件。这是本队研发追求，不伪装成官方新增门槛，也不预先承诺所有规模都达到毫秒/秒级。

按每个场景、核数与图规模保存质量—耗时曲线和 Pareto 前沿：若另一方法既不更慢、官方 Makespan 也不更差，且至少一项严格更好，前者就是可被取代的方案。分别比较同等质量所需时间、同等时间达到的质量，报告改进与失败用例、冷启动、P50/P95/最慢用时、内存与并发资源。次要官方指标仍按前述口径交付，不以自行加权总分掩盖取舍。阶段可优先形成极快且合法的结构化构造，再验证有限改进的边际收益；这是一种候选路线，不限制发现更优数学或工程方法。

“双向极致”要求持续判断每项优化对完整任务的实际价值，不能用更快评分却更慢的整个求解流程替代，也不能用更差的最终方案换取未声明的速度成绩。合理的预算控制与停止无收益实验依旧生效，不意味着每项尝试无限投入。潜在部署价值来自快速从新图构造方案；官方模拟器的 Makespan 和本机求解时间只能证明各自范围，真实硬件调度收益、运行时适配和规模扩展仍需独立实验，不因这一动机自动授权部署。
