# 按容量约束的共享作业窗口

R5A揭示全组按位置推进的结构缺陷：007每核约139个、025每核约667个七操作作业同期开工。实测spill分别为11727360和95195136字节；是否为全部退化的因果仍需对照，不能仅凭相关性宣称解释完整。

新增独立入口 `python -m src.q2.feedback.capacity_window GRAPH --cores K -o PLAN`，导入冻结 e64723b 的 tensor_packet，不修改仍在验证的源。保留分核及每操作一子图映射，仅当原结构路由为shared_stages/shared_cohorts、原tensor没有logical_tid别名时尝试重排；资源词与一般DAG块路线完全保留。算法不看case ID、旧成绩、赢家表，不运行E0/Step2或多计划评分。

对每核把共同图输入全部按真实大小预留为S(L1/UB)；原DDR tensor按冻结P2重建为UB。对于该核的每个完整弱连通作业，沿其既有拓扑顺序，按每个私有tensor首次触及到最后触及的闭区间统计驻留。每个操作的输入和输出先同时计入，再释放，因此包含执行前分配峰值，得到每个内存池的私有峰值P_j。取P=max_j P_j。一个原tensor的eligible生产者/消费者若跨两个作业，它们不会是不同弱连通分量，因此这些路线没有跨作业计算依赖或跨核中间tensor。

窗口W由现有计算pipe饱和启发式（最多8）进一步限制，使每个池都满足S+W*P≤capacity。无W≥1可获此保守证书则保留原优先顺序，不把拒绝视作图不合法。随后只允许最多W个完整作业开启，按计算时钟坐标生成拓扑优先序，一个作业全部写入顺序后才开放下一个。还独立计算整个新序列的tensor闭区间峰值，核对≤capacity；此检查为线性区间统计，不是官方模拟器。

证明范围：每操作一个子图，完整弱分量保持在同核，tensor无原始logical别名且唯一原始producer。图输入COPY_IN附在首消费操作的子图桶；图输出和跨核COPY_OUT附在生产桶。这两条共享路线没有跨核中间COPY，桶内COPY不会将原tensor生命周期移动到计算触及桶区间之外。闭区间同时包含桶内全部输入输出，故上界可以覆盖COPY内部顺序。共享tensor全程预留，私有tensor只属于当前最多W个未结束作业，故任一桶上界≤S+W*P。冻结Step2按alloc→容量检查→execute→free工作，并不要求内存地址连续；在这些条件成立时该顺序的Step2无溢出可以归纳得到。该论证仍需独立源码审计和小例/官方对照；Step3生成内存假依赖、DDR竞争和最终Makespan不能由这个字节上界推出。不能宣称真实硬件缓存无溢出或时间最优。

本新增工作O(n+tensor incidence+Wn)，W≤8，加基础构造与官方计划结构校验开销；基础方法的COPY收缩成本边界保持不变。保守预留可能拒绝本可行的好顺序，窗口过小也可能损失并行度；最终E0必须保留这些负例。当前只有5项小例测试通过（0.006秒），包括闭区间输入输出峰值、全组溢出而双作业窗口可容纳、DDR→UB归属、无法认证时原样回退、覆盖/拓扑/活跃作业数。没有新官方成绩。
