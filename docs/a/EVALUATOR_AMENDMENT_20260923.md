# E1/E2 补充规范：官方接口、联合门槛与并行探索

版本：2026-09-23 / revision 1。适用任务：`a-r1-fast-eval`，关联 FORM、TEST。

队长本次明确要求：E1 改写后零差分；E2 显著快于 E1，同时控制数值误差；安排并行探索，可比较 C++ 与 Rust；输入输出沿用官方原版格式。本文据此补充可执行的任务标准。百分比与倍数是队内研发/发布标准，不是官方要求，也不是已经达到的结果。

`contract-v1.md` 与 `AI chats/` 的导入原件保持不变。本文明确覆盖 v1 §2.2–2.4 的公开接口优先级、§5.4 的校准 Makespan 门槛，并细化 §5.5 的计时口径；其他一致性、来源、封存和失败处理约定继续生效。

## 1. 公开输入输出以冻结官方接口为准

权威来源是 `data/raw/a/official/README.md`、`code/contest_io.py` 的 `run_problem_cli` / `_common_paths`，以及三个问题评估器的结果组装代码；文件身份按 `docs/a/source-manifest.json` 固定。这里的 `code/` 相对于 `data/raw/a/official/`。实现者提交逐字段兼容表，由队长指定的独立验收会话核对。

- 原图 JSON、方案 JSON、配置文件直接读取官方格式。方案仍只有 `node_to_subgraph`、`core_schedules`；不要求用户另写一套请求 JSON。
- 三个问题各提供官方风格入口：`multicore_cut_evaluate_problem_1.py`、`_2.py`、`_3.py`。允许薄 Python 包装器调用 C++/Rust 内核，分别放在 E1/E2 实现目录，不覆盖原件。
- 保留位置参数 `graph [plan]`、`--config`、`-o/--output`、`--trace-output`、`--log-output` 的含义。省略方案时读取同图名 `_multicore_res.json`，省略配置时读取图目录的 `config.txt`。保持官方默认结果/Trace/日志命名规则。
- 结果 JSON 的字段名、类型、嵌套、单位和列表含义按对应问题原版；不包一层新的 `metrics`/`status` 对象，不自行重命名 `makespan`，也不把题三字段补到题一。JSON 缩进和对象键顺序不作为相等要求，列表顺序有语义。
- 官方的拒绝行为、非零退出码和 stderr 错误出口须保留可对应的含义。超时、崩溃、未支持不得冒充“官方认定非法”；不产生新的貌似成功的结果/Trace。每次运行使用独立输出目录，避免误读上次成功文件。
- 实验必须显式指定三个输出路径到 `results/` 独立运行目录；并发任务不写同一路径，更不在只读原始图目录生成默认输出。

引擎版本、哈希、近似范围、检查深度、耗时、回退次数、误差报告放在独立 `run.json` / 报告，不往官方方案或结果 JSON 塞字段。E2 产物必须连同注明 `estimate` 的运行记录交接，不能把单独的官方形状 JSON 当作官方成绩。

E1 的完整输出必须与 E0 逐项比较。E2 的字段格式兼容不等于数值精确：只有实际估计/计算的字段才可输出；配置、身份、核数等结构字段不能近似。尚未生成完整时间线、Cache 事件等内容时，不能用空列表、零或复制旧记录补齐，也不能把伪造的 Trace 称为官方诊断。

因此分开记录两项能力：**官方完整接口兼容**与**搜索用高速数值评估**。E2 首批可以只交内部指标原型，明确“尚未完整兼容”；完整诊断请求可以明确不支持，或透明调用 E1/E0 生成整份一致结果并计入回退成本，不拼接 E2 Makespan 与另一引擎的时间线。只有逐字段与命令行检查通过，才宣称对应范围的完整接口兼容。完整输出速度另测，不能用内部只算一个数的倍数冒充完整 CLI 倍数。

v1 的 `team_eval`、JSONL 批量、常驻 `prepare_graph/evaluate/evaluate_batch` 可作为队内适配层，不能成为提交官方图/方案前的新格式转换前提；不等待该适配层开发才能开始。适配层的请求 ID、状态、检查深度等元数据仍有用，但不改变公开官方文件格式。

## 2. E1：零差分优先，至少 3 倍

- 声明并冻结的必需测试矩阵内，成功/失败语义、整数指标、full JSON 值均零未解决差异。不能用浮点容差、忽略 Cache/时间线或只比较 Makespan 代替；仅预先冻结的非语义路径白名单可归一化。
- 相同资源、相同工作口径的中大图热路径配对加速比，几何平均 **≥3× E0**；至少 90% 配对 **≥0.8× E0**。小图、冷启动、批量和完整 CLI 单列。
- 正确但未到性能门槛，交付为“正确候选/局部热点增量”；有限测试零差分不写成全输入域证明。

## 3. E2：速度和低误差同时验收

同一提交、同一近似配置、同一资源预算、同一封存评估范围，必须同时满足以下发布门槛，不能从两个版本分别选速度和精度最好的数字。

| 指标 | 本次标准 |
| --- | --- |
| 候选批评估吞吐 | **≥10× 已通过相应范围一致性检查的 E1**；预冻结批量/线程设置，不拿单线程 E1 对多线程 E2 充当同资源比较 |
| 进一步加速探索 | **≥30× E1** 为探索目标；保留 **≥50× E0** 研发目标，均须实测，不作为首批交付承诺 |
| 校准 Makespan 绝对相对误差 | **中位数 ≤1%，P95 ≤3%**；替换 v1 的 3% / 10% 数值门槛 |
| 短名单质量 | 至少 **95%** 测试池保留距该池 E0 最好值 **≤1%** 的候选 |
| 短名单遗憾 | 中位数 **≤1%**、P95 **≤3%**，最差池单列 |

数值误差为 `abs(E2_makespan - E0_makespan) / max(1, E0_makespan)`；它不是相对未知全局最优的误差，也不是官方误差容许值。P95 ≤3% 不表示每个样本都 ≤3%。报告最大误差、超过 3% 的比例、最差样本和风险处置，按问题/规模/核数/争用与 spill 风险分层，不能靠总体中位数掩盖失败子域；未通过的范围标为未验收或回退。

以上数值门槛针对 Makespan；流量、Cache 命中率、内存峰值的近似必须逐字段声明、另报误差，不能由 Makespan 通过推断全部字段通过。正式成绩与论文正式结果仍经 E0 复算。

候选池、保留数、图级开发/校准/封存分离和 E0 全池标注沿用 v1：每池至少 64 候选，保留 `min(n, max(8, ceil(0.1*n)))`。首批至少一个开发池是原型证据，不能代替独立封存验收。`rank_only` 可保留作研究基线，但不满足这次“低数值误差”的最终交付。

速度用逐池配对的 `E1_time / E2_time` 报告，预冻结范围的几何平均至少 10；同时列出每池速度、P50/P95 延迟、吞吐和最慢池，不能事后挑池。E1 尚未成熟时先对 E0 报告，标明 E2/E1 待测，不用 `E2/E0` 除以别处的 `E1/E0` 推算成绩。

## 4. 并行探索与收敛

1. **E1 独立推进**：保留当前热点改写线，不等待 E2 或两种语言全部完成。
2. **E2 C++ / Rust 对照**：先选同一小型代表性内核、相同输入/数值设置各做可运行原型，比较总耗时、内存、构建/跨语言调用成本及误差。语言只是一个变量，不预判胜者，不要求长期维护两份全实现。
3. **E2 至少两个算法候选方向**：在负载/通信估计之外，自选另一种有不同省时机制的近似、粗粒度事件或批量/局部代价路线。报告近似点与失败机制；仅换语言不算两种算法路线。不要求机械跑完所有语言×算法组合。
4. 能实际并行的 Agent/进程使用不同分支、worktree、输出目录；回报真实 Agent/进程标识与归属。不共写公共接口或同一工作区。资源/本人授权不足时报告具体约束，采用隔离小原型交错推进；不能把计划分叉写成已经并行运行，不擅自开付费资源或扩权。
5. 首个有可比证据的里程碑交“速度—误差—成本”对照表，选择满足联合门槛的候选继续；失败路线保留失败原因和引用，可以成为 Canvas 盲端，不因已经投入而继续全量实现。

## 5. 公平计时、交接与独立验收

新方案评估必须计入所有 plan 相关构图/特征、外部调用、传输、同步、风险检测及实际回退；相同图可共享的准备成本另列并说明摊销次数。编译/加载、冷启动、热路径、批量 1/16/64/256 和完整 CLI 分开；固定机器、线程/进程、编译参数和重复次数。禁止重复同一 plan 的缓存命中代替新候选吞吐。

离线同时运行不同路线可以节省研究时间；正式速度测量要隔离其他竞争负载。算法多线程收益与语言/算法收益分别报告，GPU 对 CPU 的资源差异明确列出。最终还要测 `E2 全池 + E1 短名单 + E0 确认/审计 + 调度开销` 是否降低整条搜索流程成本。

下一次实质交接补充：实现分支/HEAD、官方接口支持表、各路线的实际运行状态、固定基准版本、速度/误差/筛选损失表、最差例、回退、尚未覆盖项与更新后的 ETA。新规范不追溯把此前如实披露的原型算作违约，也不把原有约 3 小时协调目标改成新的硬截止。

队长本会话负责监控、规范发布、任务路由和阻塞处理。代码/数学细节复核、E0 适配及独立封存验收由队长另行指定的本地会话承担；未指定前如实登记待路由，不把本会话的检查、CI 或文档合入当作算法验收。
