“官方映射”不是单指 Makespan 标量。

2. 映射族：
由问题类型 Q1/Q2/Q3、核数 1–5、容量、DDR 带宽、100/1000/500 等等待、Q3 L2 参数等索引的一族官方映射。

3. guard / 切换边界：
会使官方执行机制发生离散变化的条件，例如 Task/COPY 边界改变、spill 触发、victim 集改变、FIFO 变化、Cache hit/miss 翻转、关键 release 约束变化。

4. primitive operation：
作用于合法方案的局部部分变换，如 split、merge、Task move、core reassignment、same-core reorder、priority/grain 调整等。

5. 生成完备 / 可达完备：
primitive 集合作为生成元，在明确目标方案域中原则上能够通过有限组合到达任意目标方案或其某个明确连通分量。它不意味着实际搜索时穷举。

6. macro operation：
由 primitive 组成，具有明确图结构条件 / guard / 机制解释的高价值复合操作。

7. 离散雅可比 / 局部响应：
给定 P 和 primitive a，比较 P 与 a(P) 在冻结行为观测向量上的变化。它是离散响应对象，不是连续微分。

8. 耦合度：
请你给出真正可计算的定义，用于衡量一个局部编辑会使多少官方映射层、多少远端对象和多少最终行为共同变化。

9. 敏感方向：
某类很小的方案编辑，在一定结构条件下会稳定引起显著行为变化。必须定义“小编辑”“显著响应”和稳定范围。

10. 行为等价 / 行为商：
必须先指定观测层与未来允许操作集合。不能把“同 Makespan”直接叫行为等价。

11. 最小充分状态：
相对于某类未来操作和输出，预测后续官方映射行为所必须保留的最小状态表征。不要只类比统计学 sufficient statistic。

12. 局部评估器集：

(graph G, plan/operation P, problem q, core count k, config C, official-mapping regime)

# 3. 总体判断：应保留“分解与机制”，砍掉“完整输出上的大行为商”

我的总体判断是：

> **Go：分层可观察性、官方编译分解、guarded macro。**
>
> **Conditional-Go：有适用域和真实成本验收的局部评估器。**
>
> **No-Go：保留完整 result，同时期待大量不同逻辑方案归入同一个行为商。**
>
> **仍属 HYP：存在跨图、跨核稳定的少数敏感方向，以及有用的紧凑 D17 状态。**

这里最重要的不是支持或反对整套框架，而是**切断几个不成立的逻辑箭头**。

## 3.1 【FORMAL】完整 result 已经暴露了逻辑方案

冻结官方成功结果中：

- Q1 的每个原计算操作携带 `task_id`，每核结果保留 Task／子图顺序；

- Q2/Q3 的每个原计算操作携带 `subgraph_id`，每核 `subgraphs` 保留输入方案的子图顺序。

给定原图，便能恢复整数意义上的 `node_to_subgraph` 和 `core_schedules`。Q2 源码对 `subgraph_ids` 的保存和结果输出可以直接核对。

因此，**若 Φ 保留完整 result，不同的逻辑切分、核心归属或核序已经能被零步观察区分**。D15 不可能再把它们合并。

可能被合并的，只剩某些输入编码冗余，例如键的文本表示；这不是你希望找到的结构性降维，而且 mapping 插入顺序是否可省仍须另证。

本轮从 3 份正式多核结果及 24 份合成结果恢复逻辑方案，**27/27 相符**。这项恢复检查没有新增 E0，也没有恢复或归一化原始 JSON 插入顺序。

**这条结论应尽早用于节省研究时间：不要继续寻找“完整 result 大商”。要先减少观测，再研究商。**

## 3.2 【FORMAL＋AUTHOR-REPORT】编译复用是真结构，但不是行为等价

Q1 的固定分区可以共用官方局部编译产物；不同核心归属和核序仍需刷新调度外壳、重新模拟全部共享 DDR 与事件。这就是当前 exact batch 已实现的边界。

**共享同一个编译程序，不意味着当前结果相同，更不意味着未来编辑不可区分。**

这件事很关键：

> **高全局耦合不否定编译复用；低局部响应也不推出行为商；行为商失败仍然允许 exact batch＋macro search 成功。**

原生交接报告中的收益也有这个条件：64 个不同调度摊销准备成本时约 33.7 倍，只有 3 个候选时约 0.43–1.95 倍；这仍是作者内部评分口径，不是本轮独立的完整求解器性能结论。

## 3.3 【E0】一个非平凡 D14 类，可能被两步未来编辑完全拆散

本轮固定：

**Q2、1 核、4 个互不依赖的无 tensor 计算操作、固定 singleton 映射。**

两条 M 操作时长为 2、5；两条 V 操作为 3、11。穷举 24 种核内子图排列。允许操作只有三个确定的“交换相邻槽位”动作；这个 24 状态域对它们封闭。

结果如下：

| 观测 Φ | 当前观测类 | 加入未来编辑后的结果 |
| --- | --- | --- |
| 只看 Makespan | 1 类，全部为 14 | 所有未来仍为 14，D15 也是 1 类 |
| 看每个原操作的精确起止时刻 | **4 类** | 1 步细化成 **20 类**；2 步成 **24 类**，随后稳定 |
| 保留完整 result | **24 类** | 无进一步压缩 |

第二行的当前压缩率为 6，但完整 D15 在这个**封闭有限域**上变成单例。

具体区分对：

两个计划当前逐操作时刻相同；执行同一个“交换前两个槽位”动作，其中一个交换了两条 M 工作，另一个只交换 M/V 的全局排列，于是逐操作时刻不同。

这说明 **“当前执行相同”不能直接成为搜索状态去重依据**。

第一行还提供了另一种提醒：**压缩率很大也不一定有优化价值。**当整个受限域的 Makespan 都相同时，常量状态确实充分，但它没有告诉我们怎样改进时间。

| 问题 | 优先利用的可复用部分 | 不能忽略的可变部分 |

# 4. 八条最重要的可证伪命题

以下“成功／失败”是研究判据，不是全部已经达成。

## P01：完整 result 上不存在有价值的逻辑方案压缩商

**命题：**在成功执行域、固定原图及参考 runtime 下，完整 result 可以恢复逻辑方案，因此不同逻辑方案不能处于同一个完整观察等价类。

**当前证据：**【FORMAL】源码恢复证明；【EMP】本轮 27 份结果恢复成功。

**最强反例边界：**文本键别名、输入编码冗余可能合并；减少 Φ 后也可能出现非平凡类。但这些不是对上述逻辑方案命题的反例。

**最小实验：**从 Q1/Q2/Q3 结果恢复两字段，与输入逐项比较；失败时保留具体缺失字段。

**成功价值：**立即停止通用 full-result quotient 方向。

**失败应砍什么：**只收紧恢复命题的输入／输出域；不能反过来立即宣布找到有用大商。

## P02：Q1 的编译复用域广于 Q2/Q3

**命题：**Q1 固定有序映射、图、局部编译配置和 H 时，合法 move/reorder 不改变剥离调度元数据后的局部程序；Q2/Q3 需要更强的相同优先序条件。

**当前证据：**【FORMAL】源码数据依赖；【AUTHOR-REPORT】exact batch 和 native 的有限验证。

**最强反例：**split/merge 改变全局生成 ID；Q2/Q3 改序改变 COPY 所属桶，继而改变 Step2/3。

**最小实验：**相同父计划分别施加 move/reorder、split/merge、B 的 priority 编辑，逐层比较 L1–L4。

**成功价值：**精确降低编译次数，不需要先拟合代理。

**失败应砍什么：**“只改两 Task 就只失效两 Task”等过强缓存规则，而非所有复用。

## P03：小编辑可以具有低编译耦合、高时间耦合

**命题：**某些 Q1 move/reorder 的局部程序完全不变，但共享 DDR 可使远端原操作时刻广泛变化。

**当前证据：**【HYP】尚未完成统一耦合测量；全局带宽更新路径支持这种可能性。

**最强反例／误判风险：**把整条后缀统一平移误称为“每个 Task 的服务机制都改变”；或者只看原计算图可达节点，漏掉不连通分量之间的资源作用。

**最小实验：**固定分区，成对保存编译签名、逐操作开始差与持续时间差、DDR 在途集合差。

**成功价值：**分清哪里能省编译、哪里仍必须全局重放。

**失败应砍什么：**以局部图距离直接划定全局增量重评范围的方案。

## P04：D14 压缩经未来操作后会显著缩水

**命题：**只依据当前时刻、FIFO 投影或某个中间签名合并方案，可能被很短的未来编辑区分。

**当前证据：**【E0】本轮 24 状态实验的 4→20→24 类。

**最强反例边界：**更受限的动作集可能保留大类，所以该结果不能否定全部 restricted quotient。

**最小实验：**同时改变 Φ 和允许操作集；记录最短区分 continuation。闭合有限域可以细化到不动点，非闭合样本只能报有限视野。

**成功价值：**得到真正安全的受限去重边界。

**失败应砍什么：**若压缩率接近一，停止该 Φ/A 下的商优化，保留编译复用。

## P05：低维摘要通常不是 D17 充分状态

**命题：**总负载、总剩余 COPY、缓存占用量和命中率不足以支持全部未来允许编辑；紧凑状态必须满足操作闭合。

**当前证据：**【FORMAL】完整输出恢复性；当前／未来等价分离；【HYP】更小受限状态仍可能存在。

**最强反例：**相同缓存成员与容量、不同 FIFO 次序；相同总剩余搬运、不同请求身份与剩余量分布；相同当前执行程序、不同未来操作适用性。

**最小实验：**每删除一个字段，就寻找“状态相同、某条 continuation 结果不同”的区分对。

**成功价值：**证明某个小状态确实足以更新，而不只是能回放一次。

**失败应砍什么：**通用“摘要即 Markov 状态”；不能把失败转移给官方 evaluator。

## P06：局部评估器只有赢过真实精评路径才值得存在

**命题：**计入 detector、特征、拒答、回退和最终确认后，某个局部 Δ／排序专家仍能改善同预算质量或达到同质量的时间。

**当前证据：**【AUTHOR-REPORT】入口提前量在新池无收益；P23 冷耗时主要在局部编译，原生事件重放已较快。

**最强反例：**为了判断 regime 先完整跑 Step3，随后代理又拒答；或者模型一致地漏掉真正优解。

**最小实验：**相同冻结候选池，局部专家路由与 exact-only 做同总预算对照。

**成功价值：**减少有实际成本的精评，而不只是得到好看的预测误差。

**失败应砍什么：**相应专家，不必砍掉 exact batch 或候选构造。

## P07：“少数敏感方向”跨图、跨核稳定仍是未知

**命题：**预先固定的少量操作类，可以在未用于选类的图／核数上解释大部分显著行为变化。

**当前证据：**【E0】008 是高收益见证；不是稳定敏感方向。resource-word 改变了大量优先关系，也不能未经编辑大小测量就叫“小改动”。

**最强反例：**按结果重新分组动作类制造稀疏性；响应集中仅来自一个图；换核数后收益符号翻转。

**最小实验：**操作类平衡采样，在开发组选择方向，在另一组图／核数测响应能量和显著事件覆盖。

**成功价值：**为 guarded macro 的优先级提供可迁移依据。

**失败应砍什么：**全局低维敏感假说；保留个别可解释、参数局部的机制。

## P08：空核嵌入有结构依据，但加核获益与跨 q 迁移没有保证

**命题：**末尾增加空核可保留旧活动执行投影；真正利用新核则是另一步需要验证的 continuation。

**当前证据：**【FORMAL】冻结代码的活动对象与遍历条件；【E0】同一 008 计划在 Q1/Q2/Q3 的巨大差异。

**最强反例：**任意重编号核心、强迫所有核非空、重新运行不同构造器，都可能改变时序，不能替代空核嵌入证明。

**最小实验：**从明确的单核计划逐次追加空核，再做有谱系的有限迁移；每个 q 单列。

**成功价值：**跨核 warm-start 至少能保住父解。

**失败应砍什么：**相应域的无条件 continuation，不改写固定单核基准。

# 5. 必要的数学形式化

## 5.1 行为响应向量应是“类型化记录”，不是一个混杂数值向量

建议冻结如下 Φ。这里的“向量”允许包含图、序列和事件对象。

| 机制 | 应保留的观测 | 差异定义 |
| --- | --- | --- |
| Task partition／boundary | 原成员集合、核心归属、核序、Task 依赖 | 成员关系变化、迁移数、边增删 |
| COPY | 完整 COPY 结构、原 tensor、源／目标角色、实际生成 ID、字节分项 | 节点／边差、角色对齐、字节差 |
| Step1 | 原始完整序列及 B 的优先后序列 | 相邻关系／逆序变化；另报计算投影，但不代替完整序列 |
| spill／backing／incarnation | victim、backing 来源、是否写出、from/to/version/pos、重接边 | 有序记录差，新增／删除／版本链差 |
| Step3 FIFO | 四条 Pipe 的完整 FIFO，含 COPY 和 spill | 分 Pipe 顺序差 |
| memory dependencies | WAR/WAW 来源、复用字节、被复用 tensor、位置 | 带属性边差 |
| release | Q1 Task 门控；B 跨核 COPY 释放；全部并列控制前驱 | 时刻差、控制集合差、slack 变化 |
| DDR contention | 带身份的在途请求、剩余量、更新时间、实际与投影完成时刻 | 事件对齐、区间差、远端响应 |
| Q3 Cache | key、hit/miss、插入／驱逐、有序 FIFO、在途请求、两个池 | 事件序列和状态差 |
| Makespan／result | 标量及完整正式对象 | 差值、比值、全字段差异 |

**对齐规则必须保留两层。**原计算 ID 是稳定锚；生成 COPY／spill 可按原 tensor、来源成员、端点角色、出现次数及使用锚点辅助匹配。但实际 ID 仍须保留，未匹配对象记为新增、删除或未知。

这种对齐用于解释，**不是已经证明安全的 alpha-renaming 或缓存键**。

## 5.2 编辑大小、局部响应与耦合

建议先保留多维编辑签名：

$$e(P,P')=
\bigl(
n_{\mathrm{同组关系改变}},
n_{\mathrm{操作换核}},
n_{\mathrm{共同对象顺序逆转}},
n_{\mathrm{直接编辑原操作}}
\bigr).
\tag{OMA-01}$$

同组关系改变数可以通过分区交叉计数计算，不需要真的枚举所有操作对。每项同时报告原始值和归一化值。

D11 的局部响应按上述对象分别计算。还应测量两个动作的非加性交互：

$$I_{a,b}(P)=
M_E(b(a(P)))-M_E(a(P))-M_E(b(P))+M_E(P).
\tag{OMA-02}$$

它只在四个计划都合法有定义、动作参数在组合中仍有意义时使用；**不保证对称，也不等于连续 Hessian**。

D12 的三个量应这样落地：

**层耦合：**预先固定 L1–L6 的子观测和归一化差异，采用 CRG-10。建议同时报告“严格零容差变化”和“实用显著阈值变化”，避免生成 ID 漂移把所有层一律染成高耦合。

**对象耦合：**优先以原计算操作为固定分母；直接编辑邻域在运行前定义。新 COPY／spill 在单独生成对象层统计，不能让分母随结果任意变化。

**传播距离：**同时报告原计算图／Task 图最远可达距离，以及“原依赖图不可达但明显受影响”的比例。后者在共享 DDR 中尤其重要。不可达对象不能被丢弃来制造局部性。

时间响应必须分开**开始时刻变化**和**持续时间变化**。前者可能只是统一后移，后者才直接表明服务过程发生变化；两者都重要，但含义不同。

## 5.3 guard 与敏感方向的可测版本

至少保留两种分辨率的 ρ：

**细签名**记录 COPY 是否存在、overflow/victim/backing 分支、FIFO、release 控制项、池活跃次序与 Cache 事件；**粗签名**只保留事先指定的类别，例如“发生 spill／没有 spill”“存在远端入口控制／没有”。

细签名可能让每个方案独占一个 regime；粗签名可能漏掉决定性切换。**这是要测量的折中，不应提前选择一个使压缩率漂亮的分辨率。**

真实 ρ 通常事后才知道。线上 detector 只是预测或证书，不能把运行后的 guard 真值当作免费输入。

对 D39，可先固定操作类别及每类采样分布：

$$E_c=
\mathbb E_{(P,a)\sim\mu_c}
\left[
\left(\frac{\Delta M}{M_E(P)}\right)^2
\right],
\qquad
\eta_r=
\frac{\sum_{c\in\mathcal C_r}E_c}
{\sum_{c=1}^{K}E_c}.
\tag{OMA-03}$$

操作类按类平衡，而不是谁采样多谁“解释得多”。前 r 类必须在开发组选择，再到另一组图／核数测 $\eta_r$，并同时报告改善、退化和显著事件覆盖。总能量为零时记“不适用”。

D13 的稳定性还需要明确的小编辑阈值、显著响应阈值和域内比例；**响应能量集中不能替代这三个条件**。

## 5.4 行为等价应该截断在哪里

完整 result 的恢复关系可写成：

$$D_G\!\left(\pi_{L6}F_E(P)\right)
=\operatorname{canon}(P),
\qquad P\in\mathcal P_{\mathrm{exec}}.
\tag{OMA-04}$$

这里 `canon` 只表示用于证明的整数逻辑方案，不授权生产中丢弃插入顺序。

更有希望的是**下游计算实际消费的 L4 执行程序**。但每层都要防止遗漏：

| 截断层 | 相同到什么程度才可能继续复用 | 常见错误 |
| --- | --- | --- |
| Task/COPY | 有序图、属性、ID，以及后续优先信息一致 | 同 COPY 数、同字节当同图 |
| Step1 | 局部图、tensor size/pos、完整序列和配置一致 | 同计算顺序就当 Step2 相同 |
| Step2 | 完整扩展图、序列、incarnation/backing 与数值条件一致 | 同 spill 次数或同记录总量当同执行图 |
| Step3 | 四 Pipe FIFO、内存边、COPY 工作、跨核链接一致 | 只比较 M/V 计算词 |
| 全局事件 | 相关状态、同刻顺序、余量及输出历史一致 | 同逐操作时刻就当完整 Cache/结果相同 |
| 面向未来 A | 还要保持动作适用性和状态更新闭合 | 当前相同就永久去重 |

对 Q1，可以先利用一个较弱却很有用的分解：

$$F_E(P)=
\operatorname{Render}\!\left(
\operatorname{Replay}(K_{\pi},A(P));\mu(P)
\right).
\tag{OMA-05}$$

固定分区的真实编译程序是 $K_{\pi}$，归属／核序／门控是调度外壳，$\mu$ 保存正式输出需要的标签和统计。

**这说明有重复计算可省，不说明存在 D15 大商。**

## 5.5 D17 的充分状态必须满足“操作闭合”

一个实用的充分条件是同时证明：

$$P\in D_a\iff d_a(S(P)),
\qquad
S(a(P))=\bar a(S(P)),
\qquad
\sigma_\Phi(P)=o(S(P)).
\tag{OMA-06}$$

第一项保留动作可用性，第二项允许在压缩状态上更新，第三项保留当前观察。对操作序列长度归纳，就能推出 D15，从而满足 D17。

**只证明第三项——这个状态能算当前结果——远远不够。**这正是“原生可重放程序”和“未来充分状态”的区别。

| 指定问题／A／Φ | 候选表征 | 当前判断 |
| --- | --- | --- |
| Q1 固定分区 move/reorder，Φ 为 M | 共享编译程序＋当前核序＋验证 Task 图 | 可以减少重复存储／编译；不是已证明最小状态 |
| Q2 固定归属 priority/grain，Φ 为 M | 完整桶／优先信息及可重建局部图 | Pipe 投影能解释当前执行，但未必支持未来 priority 操作 |
| Q3 同类动作，Φ 为 M＋Cache 事件 | 上述信息＋逻辑 key／size／Cache 和双池规则 | 紧凑闭合表征未证明；占用量和命中率肯定不够 |
| 任意 split/merge/move，Φ 为 full | 至少能恢复完整逻辑方案 | 不值得追求通过行为合并得到通用低维状态 |

例如两个 Cache 状态包含相同两个 key，但 FIFO 顺序相反；下一次插入第三个 key，再读取其中一个，就能区分它们。类似地，同样的总剩余搬运，按请求分配不同会导致不同完成顺序。

这些是**字段必要性的机制反例**。要把它们升级为某个 D17 反例，还必须证明两个状态来自指定方案域，以及相同未来操作能实现区分过程，不能跳过这一步。

此外，把整个 plan 编成一个大整数，不是有用的“低维表示”。应比较**信息量、共享静态数据、构造成本和更新成本**。

## 5.6 哪些正式结构适配，哪些不适配

**Partial order：Go。**计算 DAG、Task＋核链 DAG、完整执行 DAG 各有清楚含义；不能混用其合法性结论。

**Max-plus：受限 Go。**固定依赖、固定时延和给定释放的最早事件问题有成熟代数结构。本轮核对了 Baccelli 等书中 Theorem 3.17／3.20 的路径闭包解释；它不赋予动态 DDR／Cache 一个固定线性响应矩阵。[[图片：]Rocq](https://www.rocq.inria.fr/metalau/cohen/documents/BCOQ-book.pdf)

**Piecewise affine：只适用于明确定义的影子模型。**固定 E 的方案是离散对象，必须先指定数值坐标或参数轴。固定事件次序／活跃集合后，实数模型对工作量和等待可能呈仿射；对带宽有倒数，官方还有 `ceil`、EPS、binary64。不能将实数等价写成 E1 零差分。

**Finite-state／automaton：局部 Go。**固定有限 key、size、容量的 Cache 子机有有限有序状态，但状态数可能很大。加入时钟、剩余服务和动态生成身份后，不自动得到有用的小自动机。

**Bisimulation／Nerode：作为检验工具 Go。**本轮封闭 24 状态实验可以逐轮细化到不动点；正式大图的抽样邻域不能冒充封闭状态空间。Paige–Tarjan 的最粗划分思想提供方法背景，但本轮实现只是直接细化，不是其优化算法。[[图片：]CS Princeton](https://www.cs.princeton.edu/techreports/1986/038.pdf)

## 5.7 多核尺度轴

在固定 q、C、H 和参考 runtime 下，把空核加在末尾，不改变旧活动操作的发射／退休参与顺序：

$$M_{E_{k+1}}\!\left(C_k^{\mathrm{empty}}(P)\right)
=M_{E_k}(P),
\qquad
\inf_{\mathcal P_{\mathrm{exec}}(E_{k+1})}M
\le
\inf_{\mathcal P_{\mathrm{exec}}(E_k)}M.
\tag{OMA-07}$$

这是声明域内的源码级嵌入结论，不是完整 result 相等：核数、空核条目、Q2/Q3 的 Task 元数据会变。

真正利用新核后的收益，必须另测；任意核心重编号也不能默认保持同刻事件顺序。**Q1/Q2/Q3 分别沿核数轴研究，不把 q 变化合成同环境“小编辑”。**

# 6. “局部评估器集”的明确判断

## 6.1 对四种预测目标的取舍

| 目标 | 判断 | 原因 |
| --- | --- | --- |
| 跨 G/q/k 的统一绝对 Makespan 预测 | **No-Go，作为当前主线** | 尺度和机制切换混在一起；已有精确重放路径，尚无证据证明另建大代理值得 |
| 直接预测同父计划编辑的 ΔMakespan | **Conditional-Go** | 最贴近动作决策，但差分不会自动消掉误差，两个动作的 Δ 也不能直接相加 |
| 同池 pair ranking | **Conditional-Go，优先小试** | 不要求虚假的数值精度；仍需测近优候选保留和短名单遗憾 |
| 只判断是否值得精评 | **Conditional-Go** | 与预算最直接，但错杀峰值风险最高，必须有拒答和挑战槽 |
| 精确机制量：合法域、边界字节、冻结门控 | **Go，作为特征或证书** | 可验证、可解释；不能因此替代 Makespan |

## 6.2 不再按旧 E2 的性能假设设计架构

P1 exact batch 的固定分区复用已经是实际接口；native replay 是更窄输出、明确数值域的重放路线。P23 当前适配是**局部编译＋原生全局重放**，并不是此前那个误差较大的简单回归代理。

因此，局部专家的竞争对象必须是**当前实际精评路径**。尤其 P23 报告显示，冷候选主要耗在局部编译；再压缩已经很快的事件重放，未必改善端到端成本。

## 6.3 推荐的路由逻辑

先核对 q、H、输出能力与预算；再提取运行前可得的廉价特征。若当前候选本来可以便宜地精确重放，直接精评，不强行经过模型。

否则最多请求少量局部专家。出现域外、未覆盖的 guard 风险、强模型分歧或过宽不确定区间时，**ABSTAIN → E1/E0**。

**ABSTAIN 不是丢弃候选。**否则最有价值的跨 guard 操作会被系统性排除。

模型一致也可能只是共享偏差，所以需要预注册一部分精评槽给随机和机制多样挑战者。训练／校准按图和父计划整组留出，不随机拆散同一父计划的近邻来制造泛化。

成本必须算完整：

$$T_{\mathrm{routed}}
=
T_{\mathrm{features}}
+T_{\mathrm{detector}}
+T_{\mathrm{models}}
+T_{\mathrm{fallback}}
+T_{\mathrm{selected\ exact}}
+T_{\mathrm{final\ E0}}.
\tag{OMA-08}$$

P23 的 `full=True` 或回退可能实际调用一次本问题 E0；P1 对应路径可能调用完整 E1。派发前要按真实路由预留，不能把 `native_enabled=True` 当成“不会消耗完整评价”的承诺。

验收要同时看：**risk–coverage、近优集合召回、shortlist regret、拒答率及原因、真实总时间、同预算 E0-confirmed 质量**。仅有低平均误差或高相关系数，不足以接入。

### 3.4 “四核超过 7 倍”应怎样解释

以尚待本轮 singlecore 复跑的基准记录 487605 为条件，算术分解是：

$$\frac{487605}{63768}
=
\frac{487605}{123060}
\frac{123060}{63768}
\approx
3.96234\times1.92981
=
7.64655 .
\tag{PB-02}$$

这说明高比值包含“固定基准→普通四核方案”和“普通方案→结构顺序方案”两段改善。**它不是 Cache 带来的 7.65 倍，也不能把第一因子未经控制就全部归为纯核数收益。**

更有意思的是：

$$123060-63768
=
59292
=
27\times2196 .
\tag{PB-03}$$

运行记录中，case008 是 108 个计算时长模板相同的作业，四核每核 27 个，单作业中间 V 阶段总工作为 2196。这个精确吻合支持一个很强的候选解释：**资源词把原来暴露出来的 V 等待大部分隐藏到了 M 工作后面。**但“吻合”仍然不是全部因果贡献的证明；COPY 相位和 MEMORY_REUSE 的变化尚需完整对照。

## 4. 对峰值机制路线的总体评价

**值得继续，但应收敛到三个机制候选，而不是建立“所有问题都有少数敏感方向”的先验。**

### 4.1 优先级最高：Q2/Q3 的资源重入交错

已有证据支持它成为一个 **macro 来源候选**：固定分区与归属，改变优先级，出现很大的执行改善；Q2/Q3 成绩相同且没有 Cache 命中，排除了“这次收益来自 Cache 命中”的解释。

但当前代码的 graph guard 比“同构重复分支”弱得多。`word_descriptor` 检查的是实际串行计算链、Pipe 模式、首尾 M 工作相同、计算时长 tuple 相同，以及 V 总工作不超过两次 M 工作之和。**它没有证明完整 Op–Tensor 图同构，没有检查所有输入共享、tensor size/pos 和生命周期都相同。**

因此，待验证的机制应写成：

> 当图含重复的 M→V*→M 计算链，完整输入／内存结构落在已验证风险域内，且处于 Q2/Q3 的单核合并 Task 语义时，通过合法优先级编译形成有限前视的资源词，减少 M 队首等待 V 的时间，从而获得稳定收益。

不能写成“识别到 M→V→M 就必快”。

### 4.2 Q1 最值得保留：晚输入门控前缀分离

case051 的解释比许多更大的百分比更有价值，因为它已经把差异定位到了明确的门控与关键路径位置。

仓库记录中，旧 Task8 在 13007 开始；拆分后的前半可以在 6482 开始、9674 结束，后半仍等到 13007。旧关键节点持续 2722 cycles，新后半只有 81；其余 119 个关键路径节点持续时间不变，差额恰好是 2641。**这是一条 trace 上的精确时间账目，不是“所有 Task 工期固定”的预测模型。**

同时，前瞻实验已经给出负结果：003、008、044 三个新池中的六个待排序 split，其入口提前量全部为零，没有重排和新增收益。

这改变了下一项任务的目标：

**不是继续调整“入口提前量”的权重，而是检验候选生成器能否直接找到真正脱离晚输入门控的切点。**

### 4.3 Q3 独立候选：共享输入的 FIFO 准入相位

case080 的同计划 Q2/Q3 排名翻转，是一个明确的场景交互见证线索：affine 增加了 spill，Q2 变差，Q3 却改善。它足以要求我们保留这类候选，不能按 Q2 排名或零 spill 硬筛掉。

真正需要提炼的是：

> 共享 support 结构，在某个由完成次序、准入、淘汰和两带宽池活跃集合定义的 regime 下，怎样通过合法顺序操作改善关键 COPY 的服务路径？

“命中率更高”只能是观测，不是充分机制。case044 已经提供相反方向的对照：命中率下降，但 Makespan 改善。

### 4.4 三类峰值的操作性分类

建议下一次试验预先采用以下规则，而不是事后给 winner 起名字：

| 分类 | 建议的操作标准 |
| --- | --- |
| **Structural peak** | 在预定义 graph guard 下，至少 3 个非简单复制的匹配实例、至少 3 种核数；至少 80% 的正域单元达到事先规定的收益门槛，并报告覆盖率、成本及最差回归 |
| **Parameter-local peak** | 在预先列出的较窄核数／配置／regime 单元内达到上述重复性，但跨出该域后稳定失效；边界能被 detector 预测 |
| **Accidental peak** | 小扰动下收益反复消失，预注册条件无预测力，而且有限修正预算内仍无法归纳；只暂称“该测试域内偶然” |
| **尚未分类** | 缺少反事实或迁移证据；不能因尚未找到解释就归为 accidental |

资源词的 prospective 高收益门槛可先设为**相对同核普通方案改善至少 10%**；Q1 单次局部操作可设为**至少 0.5% 且至少 1000 cycles**。这些是研究阈值建议，不是宣称当前材料已经通过。

## 6. 图结构候选特征体系

**纯图特征必须只由 G 决定。**依赖当前 plan、容量或 trace 的量，应单独标为环境／方案条件化特征。

| 特征家族 | 可计算定义 | 检验方式与风险 |
| --- | --- | --- |
| **DAG depth / width** | 语义 COPY 收缩后的最长依赖路径；小图用传递闭包与匹配求偏序宽度 | 大图可先报固定 Kahn 顺序的最大前沿作为下界／代理，不能叫精确 width；最大层大小也不自动等于 width |
| **弱连通分量** | eligible DAG 无向化后的分量数、大小分布、最大分量工作占比 | 区分可整体分核的作业与大耦合图；分量之间仍可争用 DDR、共享输入 |
| **M/V 工作分布** | 分 Pipe 累加有效计算周期；分量内分别统计，不只用全图比率 | 构造“总比率相同但内部顺序不同”的负对照，检验比率是否真的有预测力 |
| **资源重入** | 对真正串行分量提取压缩 Pipe 词、首尾 M 与中间 V 阶段工作 | 将 M→V→M 与 M→M→V 等同工作量图比较；不要只匹配字符串而忽略真实依赖 |
| **重复分支** | 对有界大小的 Op–Tensor 子图比较带属性结构、端口、size/pos；哈希只用于预分桶 | 当前构造仅检查计算时长模板，尚未证明完整同构；大组件无法在预算内核实时标 unknown |
| **shared tensor support** | 每个输入 tensor 的消费 job 集合；相同集合合成统计意义的输入束 | 只能压缩统计，不能合并真实 tensor、Cache key、请求次数或整数取整 |
| **fan-in / fan-out** | Op 度数与 tensor 消费者数分别统计，并保留字节加权分布 | 度数相同但源端逐目标 COPY_OUT 不同、关键消费者不同，可能有完全不同结果 |
| **size / pos 分布** | L1、UB、DDR 分别统计大小分位数、总量及单操作输入输出并集 | 一旦除以容量就依赖 C，不再是纯 G 特征 |
| **critical outputs** | 计算依赖图中到各出口的最长尾工作、出口覆盖结构 | 这是 data-only criticality，不是官方资源关键路径；后者必须从执行观测取得 |
| **Task-boundary potential** | 对事先固定、与分数无关的规范拓扑切线，计算跨界 tensor 并集曲线 | 可作为纯图候选特征；实际边界量必须结合 P，Q1 按 Task、Q2/Q3 按 core 区分 |
| **memory pressure** | 固定规范拓扑序上的首次／末次 touch 闭区间前沿，按 pos 分开 | 不是实际驻留峰值，更不是容量证书；真实 Step1/2、backing 和 incarnation 另行观测 |
| **product / grid** | 将触达两个输入束的 job 当边，做二着色、完整二部连接、重边和 support 闭合检查 | 不把识别问题变成昂贵的最大 biclique 搜索；未匹配就退出该构造域 |
| **reuse topology 与 ID** | support 重叠、规范次序下的重用间隔、同深度／同类型并列中的原 ID 次序 | 图同构不保证固定 ID 启发式相同；重编号是新的 G，不是免费等价归一化 |

对于 case008，目前报告给出的“108 分量、864 eligible ops、统一计算时长模板”与构造代码一致，但**本轮没有读取完整 G 后独立验证这些结构计数**。对于其他特征，我没有把“看起来合理”写成“已经有效”。

下一步应先做**零 E0 的只读结构扫描**，再冻结正例、反匹配例和变量选择。即使扫描全部 100 个 G，也不等于授权跑 100 个 solver；这两种成本与实验身份必须分开。

## 7. 多核／Q1–Q3 映射族研究设计

### 7.1 先按“最早可能失效的层”分解参数轴

这是目前比笼统宣称“映射低维”更可执行的结构。

| 变化 | 通过合法性检查后，最早可能改变的计算层 | 可复用什么／不能复用什么 |
| --- | --- | --- |
| **Q1 固定分区，仅改变分核、核序或 Task wait** | 局部计算结构可保持；核心元数据、联合环和 L5 改变 | 可以研究复用官方局部编译；不能只回放两个核，更不能复用旧 Makespan |
| **同 plan 从 Q2 到 Q3，其他共有参数固定** | Task/COPY、Step1–3 使用相同构造路径；差异进入 Cache 全局事件 | 可以配对比较共同准备产物；不能把 Q2 分数直接当 Q3 排名 |
| **只改变 Q3 L2 容量／带宽** | L5 的准入、命中、两池事件 | 不应重新发明局部调度；也不能按 hit rate 线性缩放时间 |
| **改变 L1／UB 容量** | L3 spill 和 L4 内存依赖即可变化 | 必须重新检查 backing、物理化身和 MEMORY_REUSE |
| **改变 DDR 带宽** | COPY 参考工作量、局部排布／内存依赖及全局事件均可能变化 | 不能把原 Makespan 按带宽倒数缩放 |
| **改变分区或 B 场景优先级** | L1 边界／COPY 所属，或 L2 优先序 | 后续 spill、FIFO、MEMORY_REUSE、Cache 都可能失效 |

上述差别直接来自两个 Task builder、Step2/3 和全局模拟。

尤其不能把 Q1 的固定分区编译缓存直接用于 Q2 的 resource-word 顺序搜索：**Q2 优先级本身会改变 Step2/3。**

### 7.2 核数 continuation：先证明嵌入，再测改善

对冻结源码，在保留全部旧 ID、有序 mapping、旧核次序和配置的条件下，只在末尾追加一个空核，不新增请求，也不改变原有 active request 集合。对成功执行的计划，可得到指标投影上的条件性结论：

$$M_{E_{k+1}}\!\left(\iota_k(P)\right)=M_{E_k}(P).
\tag{PB-04}$$

这里的等式**不是完整结果等价**：核数、空核条目等元数据不同。它也不是“使用新核会更快”。官方共享带宽按在飞请求而非核预算等分，是这个嵌入结论的重要原因。

如果该嵌入在所声明成功域内成立，扩大可用核预算的可行域最优值就不会因为“多了一个可空置核心”而恶化；**有限预算求解器实际找到的值仍可能非单调**。两者不能再混淆。

建议每个核数同时保留三种对象：

**冷构造；旧方案追加空核；从旧结构出发的一次 guarded continuation。**

报告从一核开始的整条轨迹成本，以及“已给定父计划”条件下的边际成本。不能把前一核数的搜索当作免费预计算。

对于报告中的 108 个同质作业，若限制整 job 不拆分，均衡分核的 M 工作尺度为：

$$L_{\mathrm{whole\text{-}job}}(k)
=
2a\left\lceil\frac{108}{k}\right\rceil,
\qquad a=1158.
\tag{PB-05}$$

| k | 受限整-job 族的 M 工作尺度 |
| --- | --- |
| 1 | 250128 |
| 2 | 125064 |
| 3 | 83376 |
| 4 | 62532 |
| 5 | 50952 |

**这些不是本轮实测 Makespan，也不是不加条件的原问题最优值。**它们只是判断启动／收尾、带宽和内存代价何时开始主导的参照。

### 7.3 Q1、Q2、Q3 必须保存“同 plan 跨环境”与“各环境自己优化”两张表

同 plan 跨 q 比较，用于识别 Task barrier、复制同步和 Cache 的机制差别；各 q 自己构造的最好方案，用于实际性能比较。混在一起会把“换了语义”和“换了算法”两种干预混淆。

Q1 尤其不能把 singleton 看成零成本优先级标签：每个子图是独立 Task，同核也重新通过 DDR 交接，还有 Task 等待。Q2/Q3 才是在同一个核 Task 内利用子图顺序组织资源词。

依 CRG D29，Q3 仍记录固定单核基准比；另外保存**同 plan、同核数的 Q2/Q3 比值**作为无 Cache／有 Cache 对照。两者名称、分子分母和用途都不互换。

### 7.4 合适的数学语言

我建议使用：

> **带 guard 的参数化编译—离散事件系统，以及相对于指定决策签名的有限行为相图。**

其中可分两个签名：

**编译签名**记录 Task/COPY、Step1 序、spill victim、backing 来源、incarnation 链、Pipe FIFO、MEMORY_REUSE；**事件签名**记录关键 release 的决定者、退休／发射并列顺序、资源池 active set、Cache hit/miss 与准入／淘汰。

这比直接称为“光滑分层空间”或“分段线性映射”稳妥。官方包含整数取整、binary64 计算、固定并列顺序和数据结构状态，不能不加条件地套上连续几何。

**speedup curve 只能提出 regime transition 候选。**同一 Makespan 可以对应不同签名；非关键分支跨 guard，也可能不改变 Makespan。

### 7.5 与其余 coherent 对象的接口

峰值见证首先向 Pro A 提供完整父子计划和指定观测，用于形成真正的局部响应表；再测层耦合、远端影响和稳定敏感性。对新生成 ID，应同时保留原 ID 和生成 provenance，不能靠重新编号把差异抹掉。

行为商不是必经关卡。若观测包含完整 L0 plan，不同计划已经被输入层区分，不能期待非平凡压缩；若换一个不含全部输入标签的观测，则必须重新检查未来操作可执行性。**不能为了得到高压缩率而偷偷删掉会影响未来行为的信息。**

局部评估器也不是必需品。Q1 exact batch/native 交接已经显示复用收益强烈依赖候选数量：原生路线报告在大批固定划分候选中很快，但只有三个候选时可能更慢。不能将这类批吞吐峰值直接用作单例 macro 的成本假设。

### PB06-LAG-CELLS：只做值得做的仿射参数压缩

**命题：**完整排序的精确整数区间可以减少重复构造；它既不证明哪个区间最好，也不自动构成不同 plan 的行为商。

**输入／branch／commit：**Q3 `a4e7ee1…` 的 `AFFINE_LAG_EQUIVALENCE.md`、`construct.py`，以及本轮纯整数测试。

固定前缀和局部 job 位置后，相邻操作保持顺序的条件为：

$$(j_u-j_v)\ell
\le
p_v-p_u-\mathbf1[u>v].
\tag{PB-07}$$

全部相邻约束与正整数域相交，得到一个精确区间；不同核独立 lag 时是区间的笛卡尔积，不能默认为一个标量扫描。当前线上代码仍是固定 `affine_eighth`，并没有因为这个证明自动获得提速。

# 3. 推荐的数学对象

## 3.1 更像“带守卫的部分变换系统”，不是一个群或环

推荐整体对象是：

> **Typed guarded partial transformation system：带类型、前后条件、合法性层级和操作见证的部分变换系统。**

方案是状态，具体编辑是箭头，编辑序列是路径。合法组合具有结合性和恒等操作，但**不要求所有操作都有逆**。

它和其他对象的关系可以这样划分：

| 数学对象 | 在本方案中的位置 |
| --- | --- |
| 部分变换系统 | 整体操作语义 |
| category-like composition | 组织可组合的编辑路径 |
| rewrite system | 简化已经证明等价的编辑程序 |
| graph grammar | 实现分裂、合并及局部结构更新 |
| groupoid-like 层 | 只适用于带完整 receipt 的具体可逆编辑记录 |
| 群／环 | 没有必要，也没有自然的全局结构支持 |

例如，**JOIN 在裸方案上是多对一的**：合并后通常无法知道原来如何分成两个块。因此不能因为工程上保存了 undo，就声称 JOIN 本身可逆。

Rollback 也只是恢复研究方案与相关缓存状态，**不是逆转官方模拟事件，更不是删除已有实验记录**。

## 3.2 必须同时保留合法性的不同层级

我建议明确维护：

- `P_plan`：字段、覆盖、商图以及官方方案层顺序检查通过；

- `P_task`：Q1 中加入全部核内 Task 顺序边后检查通过；

- `P_exec`：按官方语义实际成功完成；

- 一个用于证明的保守结构域 `P_ord`。

定义：

$$\mathcal P^{\mathrm{ord}}_E
=
\left\{

\text{方案字段有效，且商图与全部核内相邻块序边的并图无环}
\right\}.
\tag{PC-301}$$

# 4. 最小 primitive set 候选

## 4.1 推荐“三种语义编辑＋一种表示编辑”

推荐的底层模式是：

**CUT、JOIN、SPLICE、RECODE。**

其中：

- CUT/JOIN 改 partition；

- SPLICE 同时覆盖 core assignment 与 core order；

- RECODE 专门处理子图标签和 mapping 条目顺序这种可能影响官方编译的表示差异。

**不另设 Task move、adjacent swap、priority refinement、granularity refinement 为独立底层生成元。** 它们可以由这四类模式表达。

每个确定参数实例都是部分映射：

$$a_\theta:
D^\ell_{a,\theta}
\subseteq \mathcal P^\ell_E
\longrightarrow
\mathcal P^\ell_E,
\qquad
\ell\in\{\mathrm{plan},\mathrm{ord},\mathrm{exec}\}.
\tag{PC-302}$$

这里的合法层级不能省略。一次输出只有结构证书时，不能贴上 `exec-certified`。

## 4.2 四个 primitive 的契约

| Primitive | Domain、参数与前置条件 | 输出与合法性 | 受影响对象 | 逆操作 |
| --- | --- | --- | --- | --- |
| **CUT** | 当前块 B；非空真子集 I；显式 fresh 子图号。I 是块内依赖偏序的理想集，即不遗漏其块内前驱。 | 把 B 替换为 I、其补集；同核相邻；更新 mapping。检查所声明层级的合法性。 | partition、Task/COPY、后续全部编译与事件均可能变化。 | 用 JOIN 恢复，但保留原标签、成员和键序 receipt。 |
| **JOIN** | 同核相邻块 A、B；收缩后仍在所声明合法域。 | 合并成员，保留指定标签，删除一个核序项。不能只因“相邻”就认为安全。 | 边界、门控、spill、FIFO、内存依赖及全局资源。 | 裸操作无唯一逆；receipt 提供原成员划分后才能 CUT 回去。 |
| **SPLICE** | 当前块 B、目标 core、**先移除 B 后**的目标 gap。参数必须确定。 | 删除再插入。相同 core 是重排；不同 core 是重新归属。mapping 不变。 | Q1 常保持局部编译不变；Q2/Q3 可能改变核心 Task 内容与跨核 COPY，影响可传播到其他核。 | 记录旧 core/gap 后可逆。 |
| **RECODE** | 子图标签的单射重编码，以及 mapping 条目排列。**不能修改原图 op/tensor ID。** | 同步更新 mapping 与 core_schedules 中的标签，或改变 mapping 迭代顺序。重新校验。 | 抽象分区可能不变，但官方生成 ID、排序和输出可能变化。 | 单射逆与条目排列逆。 |

所有操作共享以下 provenance：

```
environment identity
parent plan hash
operation/schema version
deterministic parameters
semantic read/write sets
guard results
declared legality level
inverse patch / receipt
constructor or mechanism source
random seed and draw index, when applicable
```

新子图号不能在每次 replay 时临时重新选一个“看起来可用”的值，否则可能无法恢复字面行为。

## 4.3 “最小集”不是文字游戏

必须区分两个意思：

**有限操作模式**：上面的四种模式，参数可变。

**有限具体部分映射集合**：把所有参数实例全部展开后仍然有限。

官方子图标签可以取任意非负整数，因此不限制标签时，四种模式的全部实例并不是字面有限集合。若要严格得到有限集合，可以将研究域限制为标准十进制 op 键、子图标签取零至非 COPY 算子数减一，再展开所有合法参数。

这个受限域覆盖所有**抽象 partition／assignment／order**，但不覆盖官方允许的全部字面编码；也**不宣称换成标准编码会保持官方行为**。

至于把全部修改塞进一个 `REPLACE_PLAN`，虽然只需一个“生成元”，却不能解释局部响应、相互作用或机制，不值得采用。

## 4.4 构造成本与检查成本分开

给定已经建立的 COPY 收缩依赖图，CUT 的理想检查线性于块内点边数；JOIN、SPLICE 可以利用商图索引；RECODE 和完整方案序列化线性于方案大小。

但这不包括昂贵的下游工作。顺序执行基线应记录：

$$T_{\mathrm{edit}}
=
T_{\mathrm{construct}}
+
T_{\mathrm{legality}}
+
T_{\mathrm{compile}}
+
T_{\mathrm{simulate}}
+
T_{\mathrm{route}}
+
T_{\mathrm{record}}.
\tag{PC-303}$$

这些项必须是不重叠的计时区间；并行时另测外层墙钟，不能把 worker 时间之和冒充实际延迟。

# 5. 生成完备／可达完备分析

## 5.1 可以证明一个有用、非平凡的受限完备性

**命题 C1〔FORMAL〕：在固定有限依赖 DAG、固定至少一个核的结构域 `P_ord` 内，忽略字面编码时，CUT/JOIN/SPLICE 是任意对可达完备的；需要匹配具体标签和键序时加入 RECODE。**

证明是构造性的。

**第一步，把起点方案细化成 singleton。**

每个块内部选拓扑词，依次 CUT 理想前缀。原商图无环，不能离开一个原块后又返回；块内部又沿拓扑词细化，因此中间结构仍合法。

**第二步，把所有 singleton 汇集到 core0。**

取当前扩展结构的一个全局线性扩展。按该序扫描，将节点 SPLICE 到 core0 的已整理前缀之后。各核的剩余序列一直是这个全局序的子序列，不会制造环。

**第三步，把 core0 的词改成目标拓扑词。**

目标方案的块图拓扑序，加上每块内部拓扑词，给出目标词。依次把目标下一个节点向左 SPLICE 到匹配前缀后。被它跨过的节点必须与它不可比，否则两个词不可能同时是合法线性扩展。

**第四步，按目标方案重新分核。**

保持目标词的相对次序，把 singleton 分配到目标核。

**第五步，JOIN 成目标 partition，再恢复目标编码。**

每个中间状态都是目标无环块图的拓扑细化，因此仍合法。

如果非 COPY 算子数为 n，起终点块数分别为 mP、mQ，则可以给出线性编辑长度上界：

$$L_{\mathrm{path}}
\le
(n-m_P)+n+n+n+(n-m_Q)+2
\le 5n+2.
\tag{PC-304}$$

**这里线性的是编辑次数，不是完整运行时间。** 每次复制整份 plan 仍可能产生二次数据量；实现应存稀疏 patch 或持久序列。

这个证明也给出了 rooted generative completeness：选一个固定拓扑词、singleton、全部放在 core0，作为 canonical seed 即可。

## 5.2 这不等于执行成功域完备

不能把上述证明推广到整个 `P_exec`。

结构合法路径上可能出现：

- Step2 无法找到合法 victim；

- 新边界改变 L1/UB 压力；

- Step3 产生不同的内存依赖；

- Q2/Q3 的跨核 COPY 与 FIFO 联合阻塞；

- 官方迭代限制或其他运行错误。

本轮**既没有证明整个执行成功域连通，也没有证明它不连通**。

研究版应允许在结构合法域中构造、组合操作，并把最终候选交给相应精确验证；中间节点若没有实际执行成功证据，就保持 `exec=unknown`。

如果以后采用“同时修改多个字段、只验证最终状态”的原子事务，必须注明：它可能不是由所选执行成功域中的 primitive 路径实现。不能借此偷渡完备性。

## 5.3 缺生成元的反例很明确

在本报告的操作定义下：

| 删除的操作 | 无法保证到达的状态 |
| --- | --- |
| CUT | 更细 partition |
| JOIN | 更粗 partition |
| 跨核 SPLICE | 不同核心归属 |
| 核内 SPLICE | 不同核序 |
| RECODE | 另一种子图标签或 mapping 条目编码；单节点图已经可能暴露缺口 |

这说明了表示能力的来源，却不要求在线按这些证明路径进行搜索。**实际求解应该沿少数有机制支持的 macro，而不是先退回 singleton 再重新构造。**

# 6. Operation interaction／commutation／inverse

## 6.1 Legal insertion interval 是一个值得直接复用的结构证书

固定 partition。移除待移动块 B 的核序关联，连接原核剩余相邻块；保留数据依赖。在这个图中计算 B 的祖先集合和后继集合。

设目标核移除 B 后的序列为 v。合法插入槽位恰好是：

$$\ell
=
1+\max\{i:v_i\text{ 是 B 的祖先}\},
\qquad
u
=
\min\{i:v_i\text{ 是 B 的后继}\},
\qquad
j\in[\ell,u].
\tag{PC-305}$$

没有祖先位置时取负一，没有后继位置时取序列长度。

理由是：新环必须经过 B。插得过早会把 B 放到某个祖先之前；插得过晚会把 B 放到某个后继之后。反之，处于这个区间不会形成这种环。

当前 Q1 实现已经使用这一机制，并缓存同一 incumbent 下每个 Task 的祖先／后继关系。**缓存必须在 parent 改变后失效或更新。**

## 6.2 方案级交换，不等于响应可加

方案级交换要求两个组合都合法，且最终字面方案相同：

$$b(a(P))=a(b(P)).
\tag{PC-306}$$

足够的工程条件不仅包括写集合不相交，还包括：

- 对方不改变本操作读取的结构和 guard；

- gap 地址仍有同样含义；

- fresh ID 分配不冲突；

- 两条路径的最终 mapping 顺序也相同。

**“操作不同核”不是充分条件。**

即使式 PC-306 成立，单步 Makespan 响应也可能存在强交互：

$$I_{a,b}^{M}(P)
=
M(b(a(P)))
-
M(a(P))
-
M(b(P))
+
M(P).
\tag{PC-307}$$

四个方案必须来自同一环境与同一 parent。不合法项记为未定义，不能补成零。

这提供一个很实用的四臂实验：原方案、仅 a、仅 b、a 后 b。共享 DDR、FIFO Cache 或关键路径切换可能使交互项很大。若两种组合不交换，则该式是**有序交互**，不能称为对称 Hessian。

## 6.3 编辑大小必须避免“低参数＝小编辑”的混淆

建议使用：

$$e(P,P')
=
\left(
|\Pi(P)\triangle\Pi(P')|,
\#\{v:\operatorname{core}_P(v)\ne\operatorname{core}_{P'}(v)\},
|O(P)\triangle O(P')|,
e_{\mathrm{repr}}
\right).
\tag{PC-308}$$

其中：

- Π 是同块 op 无序对集合；

- O 是同核、不同块、由提交核序确定的有序 op 对；

- 表示分量记录子图标签和 mapping 条目顺序变化。

**resource-word 和 affine 只有少数参数，却可能改变大量顺序关系。** 它们可以是低参数的强构造，但未经编辑大小检验，不能称为 D13 的“小编辑敏感方向”。

耦合则按 CRG 分开报告。建议初版对离散结构采用零差异阈值，层权重相同；时间变化另外报告绝对 cycles 和相对变化。局部邻域预先固定为直接编辑块及原图一跳邻域。资源作用到原图不连通分量时，依赖距离应报告“不可达／无穷”，不能为得到一个小距离而临时换图。

## 6.4 最重要的修订：W 不自动构成 D15 行为商

**同一个当前编译结果，可以支持评分缓存；不代表两个方案可以永久合并为一个搜索状态。**

例如，粗方案和细方案通过 W 检查，具有相同的操作性事件签名，但：

- 细方案具有某个相邻 JOIN；

- 粗方案没有该 JOIN；

- 或者只有粗方案满足某个 CUT 参数的适用条件。

下一步启用操作集合已经不同，按 D15 就不能归为强行为等价。

$$P\equiv_\Phi Q
\quad\centernot\Longrightarrow\quad
P\sim_{(\Phi,\mathcal A)}Q.
\tag{PC-309}$$

因此必须建立两个不同的数据结构：

| 数据结构 | 可以按什么复用 | 不能做什么 |
| --- | --- | --- |
| **Score cache** | 已证明的当前编译／操作性评分签名 | 不能自动删除 future capabilities 不同的代表 |
| **Search frontier** | 完整方案、可用编辑及研究 provenance | 不能只用 Makespan 或 W key 表示搜索状态 |

真正的 quotient search 需要额外证明：等价类内启用操作相同，且操作后的结果仍落在相同类中。验证到 h 步就只叫 h-step。

这意味着：**本轮不应以发现“最小充分状态”为架构前置条件。** 先保留完整 PlanIR；有证据表明某些信息对指定未来操作确实无关，再压缩。

# 7. Macro 层设计：从峰值机制进入算法，而不是包一层 heuristic

## 7.1 当前见证告诉我们什么

以下均为 **AUTHOR-REPORT：本轮读到的仓库记录，不是本轮新复跑**。

| 见证 | 读到的结果 | 算法侧应吸取的结论 |
| --- | --- | --- |
| Q2/Q3 case008 | component 123060；affine 64686；resource-word 63768。三者均无 Cache hit、无 spill，COPY 字节相同。 | 相对该报告的 component 基线，resource-word 有 48.18% 降低。这是明确峰值见证，不能归功于 Cache，也还不能只凭总量排除 COPY 时序的影响。 |
| Q2 stage-B case008 | M1/M2 都没有优于 123060；最坏探索候选为 375521、220442。 | 旧有限候选池未覆盖好行为，不说明图无优化空间，更不说明需要继续扩大同一参数枚举。 |
| Q2 joint case002 | 父方案 72415；full-ready critical 72056；earliest-start 92004。 | 计算代理最早开始不是通用有效方向。 |
| Q3 case080 | affine 在 P2 从111466变112445，在 P3从90736变83124，并增加 spill。 | P2 排名、零 spill 都不能作为 P3 硬淘汰条件。 |
| Q1 case044 | 某 split 清零 spill 却从116227变123363；merge(8,10)为126094；merge(6,8)为114443。 | “消除 spill”“减少边界”都不是质量证书。 |
| Q1 case051 | 两个 split 得到337672、336057，优于338698；一个更少搬运的 merge 为339356。 | 应跟踪 release／Task 门控变化，而不是只按流量解释。 |

对应来源分别保留了方法、控制条件与限制。

## 7.2 第一批只建议三类 macro candidate

### M-A：Q1 `ReleaseIdealSplit`

**图 guard：** 当前块内部 DAG、外部真实前驱关系明确。

**Regime guard：** release 标签绑定当前 parent，且存在部分工作被另一部分的晚到前驱一并阻塞的现象。

**Primitive policy：** 计算阈值理想或受限 min-cut 理想，执行 CUT；必要时再利用合法区间 SPLICE。

**预期机制：** 减少部分工作承担的整 Task 等待；同时观测新增边界、同核切换、跨核前驱等待、spill 与 DDR 竞争。

这里不是“预测有改进就保证改进”。当前 `release_ideals.py` 已经明确：它是构造 kernel，不继承旧局部调度或 DDR backing；它求解的 cut/work 子问题不等于 Makespan 下界。

### M-BC：Q2/Q3 `ReentrantWord`

**图 guard：** 真正串行且同构的 M—V*—M 作业；两端 M 工作相等；中间 V 总工作满足已声明的理想模型范围。每核作业数必须成为显式特征。

**Regime guard：** 固定 owner、mapping 条目顺序与编号控制；候选经过真实 Step2/Step3 检查。要引用理想模型的性能结论，还必须满足它排除额外资源干扰的条件。

**Primitive policy：** 先生成目标资源词，再降低为 CUT/SPLICE 程序。生成的“最早前缀坐标”只是提交优先级的构造工具，不是硬件启动时刻。

**预期机制：** 减少关键重入 Pipe 的空闲；同步观察 COPY 位置、spill 与 Cache，不能只看 M/V 计算负载。

现有 Q3 constructor 已经包含同构、串行性和工作量守卫，并明确跳过不适用图。它适合成为这个宏的第一份可追溯来源，而不是最终定论。

### M-C：Q3 `SharedInputPhase`〔HYP〕

**图 guard：** 可计算的输入消费超边、tensor 大小、每核访问集合。

**Regime guard：** 有当前 Cache 请求序列及足够可靠的 guard 信息。

**Primitive policy：** 仅改变合法子图优先级和粒度；不提交额外等待、预取或重算。

**预期机制：** 改变同刻 miss、后续命中、FIFO 淘汰和两个带宽池的重叠。pending insert 必须包括在飞 hit 完成后的插入可能性。

这条目前只应保留为宏候选。域不明确或 guard crossing 风险高，就进入精确评价，而不是给出武断的收益判断。

## 7.3 Pro B 到算法侧的交接应是什么

Pro B 发现机制后，算法侧不应只接收“一个赢家 JSON”。

应接收以下可执行契约：

```
graph detector
q / k / C / H applicability
ρ version and regime guard
primitive program / deterministic lowering
Φ response prediction
counterfactuals and known failure cases
rollback and postcondition
evidence level
```

这样才能把“结构 S＋regime R→模式 O”转成一个真正受守卫的部分变换。

# 8. Research solver 架构

## 8.1 同意先优先可研究性，但只做最小系统

我赞成第一版优先：

**可组合＋可观测＋可干预＋可归因。**

但不建议先造完整的通用代数平台。初版结构应当很薄：

```
FrozenEnvironment + PlanIR
              ↓
PrimitiveKernel + Draft + Receipt
              ↓
ConstructorCompiler + GuardedMacroRegistry
              ↓
LegalityCertificates → EvaluatorRouter
              ↓
L0–L6 ObservationStore → TypedDiff / Coupling
              ↓
ConfirmedIncumbent + Frontier + ScoreCache
```

官方方案仍只有两个字段；其余全部是 sidecar，不改变接口。

研究状态至少要区分：

- **当前可提交赢家**：经过所要求的精确确认；

- **探索 frontier**：可能变差但值得研究的合法候选；

- **结构合法、执行未知的中间方案**；

- **正式失败、代理拒答、外部超时**。

若只允许每个 primitive 都改善 Makespan，可能在语言层面就删除了需要先退后进的路径。**单调改进策略是搜索政策，不是操作定义。**

## 8.2 Instrumentation 分三级

| 级别 | 保存内容 |
| --- | --- |
| Tier 0 | 环境／方案哈希、操作 receipt、guard、合法层级、精确指标、路由与成本 |
| Tier 1 | 与本次命题相关的 L1–L6 机制摘要 |
| Tier 2 | 峰值、反例、争议样本与抽样的完整轨迹 |

**未观测必须是 `not_observed`，不能伪装成空集合或零次事件。**

字面 diff 和 provenance 对齐后的机制 diff 要分开。生成 ID 整体平移在字面层是真实变化，但不必意味着所有远端计算机制都改变；反过来，机制对齐也不能成为忽略字面差异、宣称 E1 零差分的借口。

## 8.3 防止无限理论化的阶段门槛

以下是建议研发门槛，不是官方标准：

| 阶段 | 退出条件 |
| --- | --- |
| **S0：操作内核** | 一个有界实现窗口内完成四模式、receipt、合法层级；已有 constructor 能按原控制生成相同 plan。 |
| **S1：观测接口** | 最多48次 E0 的小面板中，打开只读观测不改变对应完整结果；三问及五种核数都有触达。 |
| **S2：机制筛选** | 最多两轮有界实验，得到一个可迁移宏，或一个明确失效域；同时测 guard 与观测开销。 |
| **S3：蒸馏比较** | 同预算质量—时间—内存比较通过才采用；否则删除无收益的 quotient/local-model 模块。 |

即使最后发现**强行为商没有压缩价值，局部模型也不划算**，薄操作 IR、宏构造与精确批评估仍然可能是成功路线。

# 9. Core-count continuation

## 9.1 首个 continuation 是末尾追加空核

$$C_k(P)
=
\left(
\operatorname{mapping}(P),
\operatorname{schedules}(P)\mathbin{+}[[]]
\right).
\tag{PC-310}$$

它改变环境中的核数，**不是固定环境 primitive**。

结构上没有新增块或依赖边，因此可保留原方案组织。执行时间是否保持，还需要对应实现确认：空核不改变非空编译、事件序列和浮点结算。

即便 Makespan 保持，`num_cores` 和空核记录也改变了，**不能复制旧 full result**。

在已经证明保值嵌入的域内，可以推出：

$$M_{E_{k+1}}(C_k(P))=M_{E_k}(P)
\ \text{对域内所有 P 成立}
\quad\Longrightarrow\quad
\inf_{\mathcal P^{exec}_{E_{k+1}}}M
\le
\inf_{\mathcal P^{exec}_{E_k}}M.
\tag{PC-311}$$

这与“某个使用更多非空核的具体分配变慢”完全兼容。

## 9.2 实际 continuation 流程

建议：

**空核嵌入作为保底 → SPLICE 一个有机制依据的块／链／分量 → 必要 CUT → 检查新 regime → 精确确认。**

三问的差别是：

| 问题 | 主要机会 | 必须重新检查 |
| --- | --- | --- |
| Q1 | 移动完整 Task 常可复用固定 partition 的局部编译 | 同核100／跨核1000等待、全局 DDR |
| Q2 | 释放计算并行、调整重入资源词 | 跨核 COPY、固定同步、源核导出顺序、spill |
| Q3 | 同上，并改变共享输入的请求相位 | 同刻 miss、FIFO 淘汰、两池竞争、在飞插入 |

word 宏在核数增大后，每核作业数可能不足以形成原来的流水重叠。因此跨核数复用的是**模式和 guard**，不是原样复制“好参数”。

同时保留一个独立 cold 结构 seed。Warm continuation 若继承了错误的 partition，必须有机会离开，而不是永远围绕旧方案移动。

官方固定单核基准仍独立生成，不能用优化后的单核方案替换。当前源码确实将全部非 COPY 算子放入一个子图、core0，再进入官方情况 A 流程。

# 10. Evaluator routing

## 10.1 首版建议 exact-first，而不是“先训练一个局部模型再说”

| 层 | 路由规则 | 禁止的推断 |
| --- | --- | --- |
| 结构检查 | 字段、覆盖、商图；确定的官方非法可拒绝 | 不支持／超时不能当 invalid |
| Q1 Task-order | 使用精确插入区间或并图校验 | 不把 Q1 条件套成 Q2/Q3 执行充要条件 |
| 局部评估器集 | 每个模型声明 detector、目标、误差；域外、冲突、guard 风险时 ABSTAIN | 精确 boundary bytes 不等于精确 ΔMakespan |
| E2 | 仅在 capability manifest 匹配时用于软排序 | 不当下界；不用 Q2 名次硬删 Q3 |
| Q1 exact batch | 每次校验新方案；固定有序 mapping 复用局部编译 | 不把局部程序缓存称为全局答案缓存 |
| Native replay | 首先 shadow；相应域独立验收后才进入实际选择 | 当前原型不是完整 JSON 或通用三问引擎 |
| E0 | 新域、争议、最终确认、抽样审计 | 内部确认成本不能从 solver 计时中消失 |

当前 exact batch 的关键结构值得直接采用：图和引擎在实例内固定，缓存键包含有序 raw mapping、带宽与容量；每次调用仍校验 Task-order，更新 core/pred 信息并重新全局模拟。**这是编译产物复用，不是 D15 的方案行为商。**

## 10.2 操作空间同时具有“质量结构”和“评价成本结构”

应给每个 primitive 标记它是否跨越编译上下文：

| 编辑 | Q1 中常见情况 | Q2/Q3 中常见情况 |
| --- | --- | --- |
| 固定 partition 的 SPLICE | 局部编译可复用，全局重放 | 同核重排可能改优先级词；跨核移动改变 Task/COPY |
| CUT/JOIN | 通常重新编译；生成 ID 可影响其他 Task | 核归属不变时 raw Task 可能保持，但优先级词可能改变 |
| RECODE | 可能改变生成 ID／遍历 | 可能改变排序与诊断，不默认无影响 |

研究版可以按相同编译上下文批处理，但应预留跨上下文候选的探索配额。否则会出现一种新的偏置：

> 评分便宜的 move 被大量探索，而可能更有价值但需重新编译的 split/merge 被系统性压制。

## 10.3 当前 native 结果不能变成无条件路由承诺

**AUTHOR-REPORT：** native 交接报告在三候选时，计准备成本相对 E1 只有约0.43～1.95倍；64候选高复用批次约33.7倍。它还明确指出，当前接口主要返回密集时刻数组与 Makespan，生产回退、错误域、多平台和长跑仍待工程化。

因此，路由要看**实际复用密度、输出需求、支持域与准备成本**，不能看名字中有没有 native。

本轮没有核验 Q2/Q3 通用 exact batch 的能力声明，所以它们的默认可靠路径仍是 E0，而不是把 Q1 evaluator 的 problem 参数换一下。

# 11. Algorithm distillation 路线

蒸馏的目标不是保留整个平台，而是保留**已经证明有用的结构**。

| 处置 | 对象 |
| --- | --- |
| **编译掉** | 通用操作解释器分派、宏参数解析、已有有效证书覆盖的重复前置检查 |
| **缓存** | 图索引、真实局部编译、经过证明的当前评分对象；全部有界、版本及类型敏感 |
| **内联** | 热路径 CUT/SPLICE、低成本 guard、固定序列更新 |
| **删除** | 无预测力 feature／局部模型、压缩率接近1且昂贵的商、每候选完整 Trace、无收益候选族 |
| **变成 macro** | 通过反事实和迁移检查的操作模式 |
| **变成静态规则** | 确定的适用域和安全变换，而不是未经证明的收益保证 |

蒸馏结果至少报告：

$$\Delta Q
=
\left\{
\frac{M_{\mathrm{dist}}-M_{\mathrm{research}}}
{\max(1,M_{\mathrm{research}})}
\right\},
\quad
\Delta T
=
\{T_{\mathrm{dist}}/T_{\mathrm{research}}\},
\quad
\Delta M
=
\{RSS_{\mathrm{dist}}/RSS_{\mathrm{research}}\}.
\tag{PC-312}$$

解释能力损失另列：少了哪些 Φ 分量、哪些反事实不能直接重放、诊断需要付出多少回退成本。不要把它们强行加成一个总分。

建议采用两步验收：

**第一步，固定候选流。** 两版生成相同候选，检查精确结果与失败分类不变，测掉纯架构开销。

**第二步，同预算搜索。** 允许蒸馏改变候选选择，比较最终 E0-confirmed 质量与全部在线成本。

候选研发门槛可以预注册为：固定候选流零语义差异；相对研究版最终 Makespan 恶化中位数不超过0.5%、最差不超过2%；不能比已确认保底方案更差；端到端几何平均至少1.5倍。**这些只是建议门槛，不是已取得成绩或官方标准。**

现有 Q1 `search.py` 明确把最终 E0／baseline 确认放在其“搜索预算”之外，这是一种如实披露的研究协议；竞争版若把 E0 确认作为内部选择流程，就必须纳入整体 solver 墙钟，不能继承局部计时口径后称为完整端到端速度。

**验收：** q/k/H/输出级别全部匹配；错误回退可靠；没有净收益时允许选择 exact-first。

**失败／停止条件：** 准备／检测吞掉收益、系统性漏好方案或精确差异，即停相应路线；600秒／64次上限。

**依赖／并行：** C01、C03、C04约束；可与 C05 开发并行，计时串行。

**预计资源：** 单 worker CPU 基线，至多双 worker 另列；父子总内存4 GiB停止阈值。

**成功后解锁：** 不牺牲覆盖的低成本评价层。

## C07 — 1–5核 continuation

**命题／Goal：** 追加末尾空核，保留旧方案结构，再用固定小预算释放并行；比较 warm/cold，不替换 B(G)。

**Branch／commit／输入：** `main@f27ef37b` → `codex/crg-c07-continuation`；C01/C06；008、044、080；固定 singlecore 入口与已有合法种子。

**修改范围：** 新 continuation 模块、测试与报告。

**禁止修改：** 不在中间插核后假定时序不变；不复制旧 full result；不用优化单核值替代官方基准。

**实验协议：** 预冻结精简面板，使每个 q 覆盖四个核数转换；最多60次新增 E0、600秒；warm/cold 同预算，分别计嵌入、编辑、确认。

**输出：** 父子环境与方案、非空事件投影、guard 翻转、质量—时间、B-normalized 指标及另列 Q3 Cache 对照。

**验收：** k 变化不冒充同环境 primitive；保值域保持旧值；新增改善必须 E0 确认。

**失败／停止条件：** 空核导致非空事件变化先定位；warm 持续输 cold 时保留双种子，不无限重启。

**依赖／并行：** C01/C06；使用宏时依赖其 guard；非宏版可与 C05 并行。

**预计资源：** 单 CPU、2 GiB，无 GPU。

**成功后解锁：** 核数轴复用和跨核数宏边界。

## C08 — 竞争版蒸馏

**命题／Goal：** 专门化已验证模块，先保持固定候选流语义，再测完整质量—成本与解释损失。

**Branch／commit／输入：** `main@f27ef37b` → `codex/crg-c08-distill`；输入必须是前述已冻结产物提交与 manifest。

**修改范围：** 新 `src/solver_distilled/`、薄 CLI 和比较报告。

**禁止修改：** 不删保底、官方确认、错误分类和事件语义；不加预算掩盖质量损失。

**实验协议：** 固定候选流对照，随后最多12个预冻结 q/k 环境的同预算比较；最多96次 E0、1800秒测试窗口；冷启动、准备、回退、确认计入。

**输出：** ΔQ、ΔT、ΔM、失去的 Φ 分量、剩余决策日志、失败与尾部表现。

**验收：** 固定候选流零差异；建议质量损失中位数不超过0.5%、最差不超过2%；保底不退化；端到端至少1.5倍，内存不恶化。

**失败／停止条件：** 语义差异立即停快路径；无净收益不采用；最多两轮有界修正。

**依赖／并行：** 等 schema、guard、routing 稳定后进行；不能提前把研究接口固化。

**预计资源：** 首版单 CPU、4 GiB，无默认 GPU 依赖。

**成功后解锁：** 自包含、三问／核数参数化、保留 E0 确认的竞争版候选。

# Definition Amendments：提议，尚未采用

## DA-01：D29 的“Official Speedup”命名与官方 Q3 对照

**原定义：** 对所有 q、k，以固定 B(G) 除以当前 Makespan，称为 Official Speedup。

**发现的问题：** 题面 Q1/Q2 的固定单核点为1；Q3另外明确要求同核数无 L2／有 L2 的曲线和比值。仅统一 B/M 不能替代全部官方对照。当前仓库官方目标核对也明确区分这些口径。

**建议新定义：** 保留 CRG-19 作为共同的 *Baseline-normalized Speedup*；另定义官方 Q1/Q2 汇总，以及 Q3 的 CacheGain，并声明是同 plan 机制对照还是不同 solver 的最终对照。

**影响：** 峰值 reference、多核面板、C05/C07/C08 的指标表；不影响 primitive 或结构连通证明。未经批准前，正文继续按 D29 计算工作指标，额外保留 Q3 必需对照。

## DA-02：D01 的失败行为与 Makespan 投影

**原定义：** F 从合法方案输入域映射到完整行为，但合法方案不保证执行成功。

**发现的问题：** 通过 plan 检查后仍可能发生官方运行错误，此时不能给一个普通 Makespan。

**建议新定义：** 完整行为明确区分成功分支和官方失败前缀／错误分支；Makespan 投影仅在成功分支定义。外部进程 timeout、服务错误另记，不能归为官方语义失败。

**影响：** 局部响应的未定义值、C02执行域、C03观测、C06路由和C08验收。当前正文所有数值命题已限制在执行成功域，因此不需要等待 amendment 才开始 C01。

## DA-03：D00-1 中 H 与运行环境

**原定义：** H 是官方 evaluator 的冻结代码身份。

**发现的问题：** 同源码在不同 Python／运行库／浮点编译选项下，不能预设属于同一个零差分映射。

**建议新定义：** 将 H 细化为源码身份加语义相关运行环境契约，或给 E 增加显式运行环境项。

**影响：** exact/W 缓存身份、跨平台等价、C03/C06/C07/C08。未经批准前仍保留你的五元环境定义，但严格等价结论只适用于**另行共同冻结并记录的运行环境**，不默认跨平台。
