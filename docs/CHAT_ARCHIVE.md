# 完整聊天与 AI 附件归档

每个网页 Chat 在 `AI chats/` 下用一个稳定目录。根目录只放 README、带 UTC 时间的完整问答/消息核对快照及 manifest；AI 生成的原文件放 `附件/`，文件名前加 `rNN-`。不再按轮次套目录。用户上传的已有题面、源码等只保留名称/仓库入口，不重复下载。示例见 [四路入口](../AI%20chats/README.md)。

## 实际可用的导出方式

2026-09-25 再核时，IAB 的 `tab.content.export()` 仍不支持；下列 `capture_chatgpt_dom.js` 所依赖的旧 `group/scroll-root` 与 `data-message-id` 已不在当前 ChatGPT 页面中。它是**旧版页面的历史工具**，不能直接用于这次 project 全量复核。旧版已取得的独立消息清单仍可逐 ID 对照；本次新会话只能取得当前网页公开 DOM，未获得独立服务端全页清单。不读取 cookie、token、隐藏应用状态或私有接口。

### 2026-09-25 当前页面复核

1. 先在 project 列表清点所有可见 chat，再逐个打开，核对 URL 与 project 面包屑。在内置浏览器用实际滚轮向上触发历史分页，直到首条用户消息可见、`Loading older messages` 消失；随后逐步向下遍历至末条。只设 `scrollTop` 可能不触发旧页加载。
2. 累计当前分支每轮可见的用户 ID、最终答复 ID、正文 DOM、文件控件与停止/无答复状态。虚拟列表会卸载离屏内容；采集顺序可能是“首次遇见顺序”，**不能直接当会话时间顺序**。必须用首末 ID、网页顺序与已有独立清单/旧快照校正。`AI chats/PROJECT_INDEX_20260925.md` 记录本次实际边界。
3. 经检查的本地 v2 capture 由 `scripts/archive_project_chat_v2.py` 渲染为追加的 Markdown 和 `消息校验-<UTC>.json`。例如：

   ```sh
   python3 scripts/archive_project_chat_v2.py capture.json 'AI chats/<Chat>/完整问答-<UTC>.md' 'AI chats/<Chat>/消息校验-<UTC>.json'
   ```

   脚本拒绝覆盖文件、未到末尾、未核首轮、轮数/首末 ID 不符或明显截短的正文。P3 首轮使用此前独立消息清单补齐，逐轮注明来源；不能将这个合成快照标成全 DOM 原件。
4. `top_stable`、末尾遍历和逐 ID 核验仍只是**当前选中分支的可见公开内容**。不包括隐藏推理、已删除消息、未选中再生成版本、将来的新增轮次。没有独立服务端清单时，必须在 README 和 manifest 明示，不能声称服务器端绝对完整。

### 旧版页面使用记录

1. 打开目标 ChatGPT 会话并等回答结束。检查 URL，保持该会话选中分支不变。
2. 在该页面执行 [capture_chatgpt_dom.js](../scripts/capture_chatgpt_dom.js)。普通浏览器可以在开发者控制台运行自己审阅过的脚本；有受支持 Browser 工具的 Agent 可通过其文档公开的 CDP `Runtime.evaluate` 执行同一脚本。脚本只滚动读取当前聊天，最后恢复滚动位置并下载 JSON，不发送消息或改聊天内容。
3. 脚本触顶检查历史分页，再遍历滚动区；每次保存已经渲染的消息 ID 和最长正文，避免离屏卸载丢失。两轮稳定只是观察，**不是服务端历史完整的证明**。超时、仍生成、结构不识别会保留疑点或报错，不能当成功。脚本最长约 48 秒；工具调用超时后，先检查下载结果，不立即重复运行。
4. 独立抓取会话全部页的消息清单。例如 Codex `read_thread` 用真实 conversation ID，不加 local host，逐页读到 `hasMore=false`，按时间正序保存 `id/page/turns`。该接口每条最多 20000 字符：触限的消息须用完整 DOM 正文；不能拿“无下一页”证明正文没截断。
5. 用标准库转换器生成 Markdown：

   ```sh
   python3 scripts/export_chatgpt_archive.py export capture.json 'AI chats/<Chat>/完整问答-<UTC>.md' --native native-chronological.json
   ```

   `native-chronological.json` 字段为 `id`（会话 ID）、`page` 和正序 `turns`；每个 turn 的 `items` 保存原始 userMessage/agentMessage。可从工具结果结构化转换，不能补造原文。没有独立清单也可导出，但文件会标记“不能确认全文完整”。脚本拒绝覆盖已有快照、消息遗漏/重排、角色不符、仍生成或未完成分页观察。TeX 从网页 `data-math-source` 或 MathML annotation 保留，代码缩进与表格转换单独测试。
6. 最后人工核对每轮开头/结尾、超长段落和数学公式，检查附件清单。DOM 可能改变，任何自动脚本都不能永久保证网站完整性；页面变化时先检查采集结构，不放宽检查。

首次 2026-09-23 快照四路共 35 条消息（19 问、16 答），与独立清单逐 ID/顺序/角色一致，3 条触限长答由网页补齐。当前最新消息计数以 `AI chats/README.md` 及各目录 manifest 为准，不沿用首次计数。原始 DOM 捕获留在执行机器的下载目录；仓库的消息核对快照保留正文与网页 Markdown，不包含无关侧栏、认证信息或用户上传图片字节。引用编号无法自动还原时保留原标记，并附网页实际可见的外部链接；不编造引用。

## 附件与版本

- 只下载 AI 回答实际提供的文件。以原会话 URL、message_id、原文件名/可见按钮和原 sandbox 路径（若可取得）记录来源。预览打开不等于下载；读取落盘字节、大小、SHA-256，ZIP 再验 CRC。压缩包里的脚本只是研究资料，不因归档而运行。
- 同一文件在正文多次引用可共用一个原件；清单记录全部来源消息。直接下载的文件与包内文件同哈希时可以复用；由原 ZIP 提取的文件注明容器与准确成员路径，不冒称另行下载。
- 超过 48 MiB 的 ZIP 仅按原字节切片，清单记每片及完整 ZIP 的哈希。`restore` 子命令按明确顺序拼接并核原始哈希，不自动解压、不执行内容。
- 每次追问、续答、重新生成、编辑、勘误都追加时间快照和 manifest `versions`，注明 `previous`、新增消息 ID 与更正范围；旧原件保留，README 更新最新入口。当前选中分支之外、已删除内容和隐藏推理不在网页导出范围，必须明确，不把当前分支当所有分支。
- 有失效附件时记录 missing 和具体原因；不从摘要重建数字。新实验与旧历史缺失分开。原文的错误结论也保留，以勘误链接说明，不能静默改成正确答案。
- 完成后提交 PR，发布固定 SHA，通知受影响成员并同步队长研究镜像。成员仍使用组织主库；其他会话按角色阅读索引和相关原文，不自动导入全部历史。归档完成、成员已读、实验复现与最终验收分别记录。
